## TL;DR

**一句话：大家训多轮 agent 时都盯着"熵"看它稳不稳，但这篇发现熵会骗人——模型可以做到"每个问题内部看着很多变"（熵很高、很健康），却在不同的输入上写出几乎一样的话（对输入无感）。这叫 template collapse（模板崩塌）。ROOT 在于熵只测了「同为一道题内部的多样性」，没测「不同题之间能不能区分」；把推理质量按信息论拆成 H(Z) = I(X;Z) + H(Z|X) 就一目了然——MI 那一项崩了，熵那一项还很好看。作者给了个**复用训练 rollout、零额外模型**的 MI 代理（用一条推理链去反查它是哪道题生成的），并解释了机制：奖励方差低 → 任务梯度弱 → KL/熵正则主导 → 跨输入的差异被抹平（SNR 视角）。对策是 SNR-Aware Filtering：每轮按"同题内奖励方差"排序，只在高信号的那部分题上做更新。结果：跨 4 种算法、0.5B\~7B、文本与图像输入全面涨，且每步时间还降了 26%\~41%。**

- **诊断（Q1）**：熵指标测的是 `H(Z|X)`（题内多样性），漏了 `I(X;Z)`（跨输入可区分性）。推理状态被分成四象限：**Diverse Reasoning**（都高，理想）、**Template Collapse**（题内高、跨输入低，**现有指标的盲区**）、Compressed Reasoning（题内低、跨输入高）、Low-Entropy Collapse（都低）
- **MI 代理（零额外开销）**：把同一 batch 里所有推理链对**所有输入**做 teacher-forced 打分，形成 `L_{i,k,j}=log p(Z_{i,k}|X_j)`，然后比 matched 与 marginal。两个主力：**Retrieval-Acc**（用推理链反查是哪个输入，崩塌时掉到随机水平 1/P=1.56%）和 **MI-ZScore-EMA**（连续稳健版）。**全部复用训练 rollout，不需要额外模型或额外推理**
- **一个重要反差**：MI 代理与最终任务表现**正相关**（Trajectory MI-ZScore 斯皮尔曼 **+0.39**），而熵类指标是**负相关（−0.11 \~ −0.14）——方向都是反的**
- **机制（Q2）**：梯度拆成 `g_total = g_signal + g_task-noise + g_reg`；由 Cauchy–Schwarz 得 `|g_task(x)| ≤ √(Var(R|X=x)·C)`——**奖励方差低 → 任务梯度几乎消失，而 KL/熵正则的梯度跨桶恒定**，于是正则主导更新，把跨输入的差异抹平（但熵正则同时**维持**了题内多样性，所以熵上看不出问题）
- **对策**：SNR-Aware Filtering，用同题内奖励方差当 SNR 的轻量代理，按 top-ρ 保留高信号 prompt 再更新。**top-p（自适应，信号普遍弱时能整批拒绝）优于 top-k（固定比例）**
- **结果**：PPO 平均 67.6 **(+6.9)**、DAPO 67.4 (+2.9)、GRPO 67.5 (+3.7)、Dr.GRPO 55.8 (+0.8)；跨模型规模（0.5B/1.5B/7B）、模型族（Llama3.2-3B）、**多模态（Qwen2.5-VL-3B：图像输入 +35.8、文本输入 +29.8，提升最大）**；RV 计算只占迭代时间 **<0.1%**，过滤后每步时间反而降 **26%\~41%**
- **主题轮换**：今日**推理 / agentic**（按序列从多模态 RL（9/15 MIRL）切出；上次是 9/8 GiGPO）

## 一、先看例子（大白话：什么叫"看着很多变，其实对输入无感"）

> **铺垫**：多轮 agent 训练里，大家习惯盯两个数——**奖励**（结果稳不稳）和**熵**（推理过程多不多样）。逻辑是：熵掉得厉害 = 推理塌缩了 = 危险信号。这篇说：**这个习惯会漏掉一整类失效。**

> **场景**：让 agent 玩推箱子，两种模型都训到"熵很健康"：

> **A 模型（真在推理）**：遇到"箱子在左边"就想左边，遇到"箱子在右边"就想右边——**换个局面，推理就跟着变B 模型（模板化）**：不管什么局面，都在说"我要避免卡住…""我要仔细规划步骤…""这是个好问题…"——**每句话都很流畅、而且同一局面里它也换着说法（所以熵很高），但换个局面，它说的话基本一样**

> **熵能看出 B 模型有问题吗？看不出。** 因为熵算的是"**在同一个输入下，输出分布有多分散**"——B 模型在同一局面里确实换着说法，熵很正常。

> **这就是 template collapse（模板崩塌）**：推理链在**同一个输入内部**看起来多样，但**跨输入**几乎无差别。论文一句话点破：

> **"熵只测量「同一个输入内的多样性」，它没法告诉你推理到底有没有在回应不同的输入。"**

**论文的做法**：把多样性按信息论拆开——

> **H(Z) = I(X;Z) + H(Z|X)**

> **模板崩塌 = 左边很高、右边趋近于零。**

（Figure 1：左边对比"输入驱动"与"模板化"；右边把推理状态按 `H(Z|X)` 和 `I(X;Z)` 两个轴分成四个象限）

**四象限（论文的核心图，值得记住）**：

## 二、动机：为什么熵不够，以及怎么便宜地测 MI

### 2.1 MI 代理：用"反查"来做，零额外成本

- 真正的 MI 对高维 token 序列没有闭式解，作者用**检索**的思路做代理：

  - 对同一 batch 的 P 个 prompt、每个 G 条推理链，**把所有推理链对所有输入**做 teacher-forced 打分，得到打分矩阵 `L_{i,k,j} = log p_θ(Z_{i,k} | X_j)`
  - 抽出两个长度归一化量：`matched`（这条推理链在**自己那道题**下的逐 token 对数似然）和 `marginal`（在**整个 batch 均匀混合**下的逐 token 对数似然）
- **核心直觉**：如果推理真的模板化了，那"这条推理链在哪道题下都差不多"——`matched ≈ marginal`，MI 就趋近 0
- **两个主力代理**（Table 1 还列了 MI-Est / MI-Seq-Est / MI-ZScore / Recall@k 等变体）：

  - **Retrieval-Acc（离散、可解释）**：用推理链反查是哪个输入生成的；崩塌时掉到**随机水平 1/P（P=64 时 = 1.56%）**，等于有一个绝对参照
  - **MI-ZScore-EMA（连续、稳健）**：`(matched − marginal)/σ_EMA`，ε=1e-3、α=0.9，做 z-score + EMA 平滑
- **工程上的关键好处**：**全部复用训练 rollout 里已有的 (X_i, Z_i,k) 对，不需要额外模型、不需要额外推理**——所以它能当"在线监控"而不是事后分析

### 2.2 一个很有冲击力的反差

- MI 代理与**最终任务表现**的斯皮尔曼相关：**Trajectory MI-ZScore +0.39**
- 而**熵类指标是负相关：−0.11 \~ −0.14**
- **也就是说：熵不仅在"漏"，它的方向甚至可能是反的**（熵下降有时候只是模型变得更专注更自信，那是 RL 的正常结果）

## 三、方法：SNR 机制 + 按奖励方差过滤

### 3.1 机制：为什么模型会走向模板

- **把梯度拆成三份**（Table 2）：`g_total = g_signal + g_task-noise + g_reg`

  - **g_signal**：同题内不同轨迹的奖励差异 → **这才是真正带任务信息的信号**（prompt 级，可控）
  - **g_task-noise**：采样与环境的随机性（prompt 级，不可控）
  - **g_reg**：KL 与熵正则项，**对每条链均匀收缩、和输入无关**（chain 级，可控）
- **理论依据**：对某个输入 x，由 Cauchy–Schwarz 可得`|g_task(x)| ≤ √( Var(R | X=x) · C )`——**奖励方差低，任务梯度就弱；而正则梯度不受奖励方差影响，一直那么大**
- **于是因果链闭合**：奖励方差低 → 任务梯度弱 → **正则主导更新** → 跨输入差异被抹平（MI 掉），**但熵正则同时在维持题内多样性（H(Z|X) 不降）** → 正好就是"模板崩塌"的签名

![▲ 论文 Figure 2：SNR 视角下的 RL 更新——左：总梯度分解为任务梯度（随同题内奖励方差变强）与正则梯度（与输入无关）；右：高奖励方差→强任务梯度、高 SNR；低奖励方差→正则主导、更新方向杂乱、推理变得与输入无关](/images/paper-reading/2026-09-16-ragen-2/2026-09-16-d39-2.webp)

### 3.2 实证：把题按奖励方差分六桶，看三种梯度（Figure 3）

**三种梯度在奖励方差桶 Q1\~Q6 上的行为（PPO 与 GRPO 一致）**：

1. **任务梯度范数随奖励方差单调上升**（高方差题给出强判别性梯度）
2. **奖励方差接近 0 时，任务梯度几乎消失**，但仍残留一点点
3. **正则梯度范数跨所有桶基本恒定**——它不关心你做的是哪道题

→ **低方差桶里的更新几乎完全由"输入无关的正则"驱动**。当训练里大量出现这种题，模型就学会了"满足正则（多样、流畅）但忽略具体输入"，模板崩塌由此产生。

![▲ 论文 Figure 3：把题按同题内奖励方差分成 Q1–Q6 六桶（上 PPO、下 GRPO）——(a) 奖励方差；(b) 任务梯度范数随桶单调上升；(c) 正则梯度范数跨桶恒定](/images/paper-reading/2026-09-16-ragen-2/2026-09-16-d39-3.webp)

### 3.3 对策：SNR-Aware Filtering

- 每次迭代：① rollout 采样 ② 算**同题内奖励方差**（当作 SNR 的轻量代理）③ 按方差排序，**只保留 top-ρ 比例的 prompt** 做策略更新
- **用 top-p（自适应）而不是 top-k（固定比例）**：top-p 在"整批信号都弱"时能**整批拒绝**，top-k 无论信号好坏都固定留一部分
- 工程细节：应用保留率 ρ 时，相应缩小有效 minibatch 并把每步 loss 按 ρ 缩放，**保持优化步长可比**
- **几乎免费**：RV 的计算只占单次迭代时间的 **<0.1%**，不需要任何额外模型或额外 rollout

![▲ 论文 Figure 4：SNR-Aware Filtering 工作流——① rollout 采样与奖励评估 ② 计算同题内奖励方差（示例 RV=9.0/1.0/5.0）③ 按 top-p 累计排序阈值筛选，只在高信号 prompt 组上做更新](/images/paper-reading/2026-09-16-ragen-2/2026-09-16-d39-4.webp)

> **炸裂之处**：**它用一个"已经存在但大家没用的量"（同题内奖励方差）当筛选器**——只要 G>1 就天然有这个量，零成本；而且过滤之后**每步时间反而降了 26%\~41%**（因为进入梯度计算的组变少了）。**这是一个"既提效又提点"的改动**，不是取舍。

### 4.3 诊断视角：MI 是"早期预警"（Figure 5）

- **(b) 是全场最有信息量的一张图**：**Retrieval-Acc（MI 代理）在没有过滤时早期就快速下滑**（掉到 0.2 附近），而 **(c) 推理熵却在同段时间里"往上飙"**

  - **MI 早崩、熵还好看** → 正是模板崩塌的签名
  - 而且 **MI 的下降明显早于任务表现的下降** → **MI 是早期预警信号**
- 三种干预对比（熵正则 0.003 / KL 正则 0.0003 / **top-p 过滤 p=0.9**）：**过滤版在"保持任务表现"和"维持检索准确率"上都最好**；而加大熵正则/KL 反而更快把 MI 压下去
- 行为层面还有一个特征：**推理长度在 8 个环境上单调下降**（越训越短、越公式化）；另外**格式有效性（format validity）和崩塌基本解耦**——所以"格式没问题"不等于"没崩"

## 五、Limitations & 批判性思考（论文自述 3 条 + 我的阅读）

1. **（论文自述）SNR 分解假设"任务信号"与"正则噪声"可以干净分离**，但实践中它们可能通过梯度累积耦合
2. **（论文自述）全部是单 agent 实验**——模板崩塌在**多 agent RL** 里如何传播仍是开放问题
3. **（论文自述）有能力的模型可能"骗过"过滤准则**——故意抬高奖励方差来换更新机会，长期训练值得监测（**这是最值得警惕的一条**）
4. **（我的阅读）结果口径是"baseline 峰值 + 增益"**：用训练过程中的**最高点**而不是最终值来汇报，容易挑到噪声高点——和 MIRL（#37）那篇一样的问题。**没看到多种子误差棒**（正文我未见到 ± 或 seed 说明）
5. **（我的阅读）收益强依赖任务性质**：Sokoban / FrozenLake 涨得猛，MetaMathQA / Countdown 几乎为 0（因为已接近饱和或奖励方差本来就高）。**换到"奖励本来就稠密且饱和"的任务上，方法可能没收益**——论文的四个任务里有两个其实没验证到这个方法的价值
6. **（我的阅读）反例没有被深入解释**：GRPO 在 FrozenLake −3.0、7B 在多个环境小退，论文只给了平均是正的；**"什么时候过滤反而有害"缺分析**
7. **（我的阅读）规模偏小**：主实验 3B + 400 迭代；7B 只在 PPO 下测；没有 32B/70B 级验证
8. **（我的阅读）MI 代理的假设**：Retrieval-Acc 的"随机水平 1/P"依赖 P（这里 P=8 时是 12.5%，论文举例用 P=64 的 1.56%）——**不同 batch 组成下这个绝对参照的解释要小心**

## 七、启发与待跟进

> **核心启发**：
> 1. **"多样性"要分成两种看**：**题内多样性**（熵测的）和**跨输入可区分性**（MI 测的）。前者高不代表后者高——**"看着很多变的样板话"是最危险的失效形态，因为它骗过了所有现成指标**
> 2. **正则项是"输入无关"的破坏力**：KL 与熵正则对每条链均匀收缩，**与输入无关**。当任务信号弱，它就成了主导力量，把"对不同输入的响应"抹平——**这解释了为什么"加大熵正则"反而更快把 MI 压下去**
> 3. **免费的信号往往就在手里**：奖励方差（G>1 自动有）、验证 loss（TMS）、MI（复用 rollout）——**三个都不需要额外模型或额外推理**。做后训练时应该优先把这些"已有但没用"的量接进监控
> 4. **提效与提点可以同向**：过滤掉低信号 prompt 后，每步时间降 26%\~41%、表现还更好——**"少算"和"算得对"在这类场景里并不冲突**

### 待跟进 checklist

- [ ] **熵 vs MI 的 A/B（最想做的实验）**：在 OPD 场景里，把"教师熵门控"（EOPD 式）换成"MI 门控"，看多轮任务上谁更稳——这篇提供的 MI 代理**直接复用 rollout，不需要额外模型**，改造成本很低

- [ ] **MI 监控接入日常训练日志**：只加一个 Retrieval-Acc（几行代码，batch 内交叉打分），先观察它在自己的任务上是否真的先于指标下滑

- [ ] **奖励方差过滤的最小改动版**：不换算法，只在现有 GRPO/DAPO 里加"按同题方差保留 top-p prompt"，验证在**自己的任务**上是否也涨（注意论文的反例：稠密饱和任务上可能没收益）

- [ ] **gaming 风险的压力测试**：论文自述"模型可能故意抬高奖励方差来骗过滤"——构造一个能这样做弊的环境，看过滤准则会不会被玩坏

- [ ] **多 agent 场景**：论文只做了单 agent，**多 agent 信用分配下模板崩塌怎么传播**是明确留白（和 GiGPO 的多 agent 空白重合）

- [ ] **与 GiGPO 叠加**：组内按 step 分锅（GiGPO）× 组间按方差筛 prompt（RAGEN-2）——两个正交维度，值得一起试

## 八、今日阅读结论

RAGEN-2（ICML 2026 Oral，Northwestern + Stanford + Microsoft 等 8 家）指出了多轮 agent RL 里一个**被所有现成指标漏掉的失效**：**模板崩塌**——模型在同一个输入内部看起来很多变（**熵很健康**），但在不同输入上写出几乎一样的话（**对输入无感**）。它用信息论把多样性拆成 `H(Z) = I(X;Z) + H(Z|X)`，指出熵指标只测了后一项；并给出一个**复用训练 rollout、零额外成本**的 MI 代理（用推理链反查它来自哪道题，崩塌时掉到随机水平）。机制层面它用 SNR 视角解释：**奖励方差低 → 任务梯度被 Cauchy–Schwarz 界住而变弱 → 与输入无关的 KL/熵正则主导更新 → 跨输入差异被抹平，但熵正则同时维持了题内多样性**——所以熵上看不出异常（Figure 3 用六桶奖励方差实打实展示了"任务梯度随方差涨、正则梯度恒定"）。对策 **SNR-Aware Filtering** 非常轻：用**同题内奖励方差**当 SNR 代理，按 top-p 保留高信号 prompt 再更新；**RV 计算只占迭代时间 <0.1%，过滤后每步时间反而降 26%\~41%**。结果跨 4 种算法、0.5B\~7B、Llama 与 Qwen、文本与图像输入全面验证（PPO 平均 67.6 **+6.9**；多模态组图像输入 **+35.8**），但也有一批反例（GRPO 在 FrozenLake −3.0）。**对你 lib 的价值有两层**：① **它直接挑战了你库里的"熵工具链"**（EOPD/REOPOLD/MM-Snowball 都用熵），给出了"多轮场景下熵方向可能是反的（−0.11\~−0.14 vs MI 的 +0.39）"这个必须回应的证据；② 它和昨天的 MIRL 连成一条线——**MI 正在成为后训练里的通用诊断/筛选信号**。

> **今日一句**：多轮 agent 训练里，**熵会骗人**——模型可以做到"每道题内部看着很多变（熵很健康），却在不同题上写出几乎一样的话"。这篇把它命名为**模板崩塌**，用信息论拆开：熵只测了"题内多样性"，漏掉了"跨输入可区分性"（MI）；而机制是**奖励方差低 → 任务梯度被压弱 → 与输入无关的正则主导更新**，把输入依赖抹平。对策朴素到只有一行：**用同题内奖励方差（免费的量）筛掉低信号 prompt 再更新**——跨 4 算法 / 0.5B\~7B / 文本与图像全面涨（PPO 平均 +6.9，多模态图像输入 +35.8），而且**每步时间还降了 26%\~41%**。论文：arXiv:2604.06268（**ICML 2026 Oral**）· 笔记挂在 lib 中 · 2026-09-16

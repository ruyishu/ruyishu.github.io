## TL;DR

<strong>一句话：现在的交互式世界模型把"过去的像素帧"当记忆（滑动窗口 or 关键帧检索），但每帧像素只是世界的一个<strong>部分、冗余、视角相关</strong>的投影，所以窗口一超出就崩。PERSIST 换掉记忆的载体——让世界模型维护一个<strong>持久的隐式 3D 状态</strong>（世界帧 w + 相机 c），相机当"记忆检索键"，3D 状态经几何投影后当渲染条件。结果是<strong>记忆成本固定、几何一致性 by construction</strong>。</strong>

- <strong>最刺眼的一组对照（FVD↓，越低越好，600 帧）</strong>：Oasis <strong>875</strong>（像素滑窗）→ <strong>PERSIST 148</strong>（持久 3D 状态）→ <strong>PERSIST+w₀ 104</strong>（再给一张对齐好的初始 3D 帧）
- <strong>而且这是在"信息更少"的前提下赢的</strong>：baseline WorldMem 被喂了<strong>前 400 帧的真值帧与相机</strong>去填充它的记忆库，而 PERSIST <strong>只需要一张初始帧 ⟨o₀, c₀⟩</strong>
- <strong>FID 曲线最能说明问题</strong>：Oasis 在 t 约 150 就冲出坐标上限 250；WorldMem 前 400 帧看着还行，<strong>400 帧后从 50 直接跳到 180</strong>；PERSIST 全程稳在 <strong>125</strong> 左右，PERSIST+w₀ 约 105
- <strong>用户研究（28 人、800+ 次评分、1–5 分）</strong>：PERSIST+w₀ 总体 <strong>3.0</strong> → PERSIST / PERSIST-S 2.6 → Oasis 1.9 → WorldMem 1.5
- <strong>三个"白送"的新能力</strong>：① 从单张图生成<strong>多样且连贯</strong>的初始 3D 世界（屏外区域每次外推都不同）② <strong>生成中途直接在 3D 空间改世界</strong>（改地形、改生物群系、插一棵树）③ <strong>屏外动态</strong>：看不见的地方也在演化，还会长出屏内可见的后果（没被观察的洞穴进水，水流到玩家脚下）
- <strong>反而更快</strong>：PERSIST-S 单帧 <strong>2672ms</strong>，比 Oasis（3007ms）和 WorldMem（6387ms）都快（因为用了 KV cache）。其中<strong>几何投影只要 0.63ms</strong>——几乎免费
- <strong>论文自己承认的最大限制</strong>：<strong>训练期依赖真值 3D 监督</strong>（只能在能给出 3D 标注的仿真器/数据集上用）；且 3D 状态只覆盖<strong>以 agent 为中心的有限区域</strong>
- <strong>值得记一笔的"指标会说谎"案例</strong>：把相机换成真值（Camera-GT）后 <strong>FVD 几乎等于完整模型（152 vs 141）</strong>，但实际会<strong>穿地形、悬空</strong>——FVD 抓不到这类物理不一致
- <strong>主题轮换</strong>：今日<strong>世界模型</strong>（按序列从多模态推理 / 感知（9/25 VLM-CapCurriculum）切出；上次该主题是 9/18 MindJourney）

## 一、先看例子（大白话：把"相册"换成"沙盘"）

> 💡 <strong>铺垫</strong>：交互式世界模型要一边生成、一边响应你的操作，所以"好不好"不看单帧画质，而<strong>看它能不能长期维持一个持续存在的环境</strong>。
>
> 现在的主流做法是<strong>自回归视频扩散</strong>：拿"过去 K 帧像素"当条件，生成新的一帧。问题在于——<strong>硬件卡死了 K</strong>。

> <strong>把这件事想成"记忆的载体选错了"：</strong>
>
> <strong>现在的方法像个只能看照片的人。</strong>你要它记住房间，它就把过去拍的照片贴在眼前（滑动窗口），或者从相册里翻出最像的那一张（关键帧检索）。
>
> <strong>但照片有三个天生毛病</strong>：① 每张只是房间的<strong>一个角度</strong>，同一个角落重复拍一百张也不会多出信息 ② 相册越大，<strong>翻出"对的那张"越难</strong> ③ 照片只记录<strong>拍到的那一秒</strong>——你没拍的那个角落后来发生了什么，它完全不知道。
>
> <strong>PERSIST 的做法：给它一个沙盘。</strong>一个以自己为中心、固定大小的 3D 方块（48³ 体素），里面存着"这一片空间里有什么"的抽象表示。于是任务变成三件事：
>
> <strong>① 沙盘会演化</strong>（世界帧模型 W\_θ）<strong>② 人在沙盘里走到哪、朝哪看</strong>（相机模型 C\_θ）<strong>③ 按这个视角拍一张照</strong>（世界到像素：几何投影 + 一个学出来的"着色器" P\_θ）。
>
> <strong>好处一句话：记忆的成本是固定的（就那一个方块），而一致性是"造出来的"而不是"学出来的"。</strong>

![▲ 论文 Figure 1：PERSIST 的单步流程。从当前条件（动作、世界帧、相机、像素 latent、初始帧）→ 世界去噪器生成新的 latent 世界帧 → 相机模型预测新视角 → 世界投影算子把 3D 特征投到屏幕空间 → 像素去噪器用像素对齐的 3D 特征引导生成新帧 → 回到起点循环。下方四个 3D 沙盘依次对应这条链路的中间产物](/images/paper-reading/2026-09-28-persist/2026-09-28-d47-1.webp)

<strong>论文里的真实例子（Figure 2）——"相机就是记忆的查找键"：</strong>

- 同一个 3D 世界帧（图中白色方块区域），在 <strong>t = 0 / 20 / 45 / 60</strong> 四个时刻被 agent 从不同位置、不同角度观察
- 图中<strong>黑框三角是相机视锥</strong>，<strong>彩色体素</strong>是被投影算子从整个 3D 状态里<strong>取出来</strong>、真正用于生成下方画面的那一部分特征
- 所以：<strong>世界帧 w 是"记忆"，相机 c 是"从记忆里取哪一块"的键</strong>——同一个 3D 状态，换个视角就取出不同的依据来渲染

## 二、动机：不是"检索得不够好"，是"记忆载体选错了"

- <strong>场景变了</strong>：过去的视频生成是"被动"的；交互式生成要求模型对外部干预做出有意义的响应。这时<strong>真实感不只由单帧画质决定，而由"生成体验能否长期维持一个持续的环境和稳定动态"决定</strong>
- <strong>主流路线</strong>：自回归视频扩散 + causal attention。它有三个天然的吸引力——天然支持实时动作条件、可以无限生成、能直接吃下大规模视频建模的进展 → 因此成了当前<strong>神经游戏引擎</strong>的骨干
- <strong>但它有两个被硬件锁死的约束</strong>：① 条件在<strong>高维视觉观测</strong>上，算力很贵 ② 能塞进上下文的过去帧数被死死卡住（即使已经用 VAE 压过空间/时间分辨率），<strong>实际上只够几秒</strong>
- <strong>于是大量工作都在研究"怎么把有限窗口填好"</strong>——最主流是从过去观测的<strong>记忆库里检索关键帧</strong>（如 WorldMem 会跟踪相机状态、检索与当前相机最匹配的历史帧）
- <strong>论文指出的根本缺陷（这是全文的立论）</strong>：关键帧检索有一个内在毛病——<strong>每一帧像素观测只提供"世界在某一时刻的部分、冗余、视角相关"的信息</strong>。记忆库越大，"找出相关证据"就越难。所以问题不是"检索得不够好"，而是<strong>载体本身不适合当状态</strong>
- <strong>灵感来自传统 3D 引擎</strong>：真正的游戏引擎靠"从一个持续演化、动态更新的 3D 状态直接渲染像素"来保持连贯 → <strong>那就把这个机制学出来</strong>

## 三、方法：定义代理状态 → 三个组件 → 拼起来

### 3.1 关键定义：代理状态 s̃ = ⟨w, c⟩

<strong>为什么不去追真正的隐藏状态 s？</strong>论文给了两条理由：s 可以任意复杂、甚至<strong>完全不可测</strong>（在游戏里，s 就是程序的内存内容，拿到了也未必有助于恢复像素）；就算拿到了 s，去学观测函数 Ω: S → O 本身也是同等难的问题。

- <strong>于是定义代理状态</strong> <strong>s̃ = ⟨w, c⟩</strong>：<strong>w = 世界帧</strong>（以 agent 为中心、固定空间区域的表示）+ <strong>c = 相机状态</strong>（agent 在这个 w 里的视角）
- <strong>它不是真隐藏状态的完美替代，但在 3D 环境里是个有效的建模选择</strong>，因为它带来两个好处（论文原文两条）： 
  - <strong>① 简化信息检索</strong>：w 当<strong>动态空间记忆模块</strong>，c 当<strong>空间查找键</strong>，把重建 o\_t 所需的空间信息取出来。c 本身就编码了"投影到屏幕空间"所需的信息，<strong>不需要知道真正的观测函数</strong>
  - <strong>② 改善动态预测</strong>：跟踪 w 和 c 便于建模那些<strong>从像素难以推断</strong>的动态——比如与<strong>屏外物体</strong>的交互/碰撞，或者<strong>被遮挡区域</strong>如何随时间变化

### 3.2 三个组件（各自独立训练，推理时直接拼装、零微调）

<strong>① 世界帧模型 W\_θ（绿色，686M）</strong>

- 每步采样：<strong>w\_t 由「过去 K 帧的世界帧、动作、相机、像素 latent」共同决定</strong>
- 参数化 = <strong>rectified flow</strong> + <strong>causal Diffusion Transformer</strong>（交错 spatial / temporal / cross-attention 模块）
- <strong>为 3D 做的两处改造</strong>：spatial 模块改成处理三个空间维度；<strong>把 RoPE 空间嵌入换成"每个体素 token 质心的 XYZ 绝对位置嵌入"</strong>
- 动作与相机用 MLP 联合嵌入 → 加到去噪时间步嵌入上 → 通过 <strong>AdaLN</strong> 注入每个模块；像素 patch 与由相机算出的 <strong>Plücker embedding</strong> channel-wise 拼接后经 <strong>cross-attention</strong> 注入
- <strong>最关键的一个设计</strong>：<strong>W\_θ 支持"世界帧条件为空"</strong> → 推理时可以直接从 ⟨o₀, c₀⟩ 生成初始世界帧 w₀，<strong>也就是推理期不需要任何真值 3D</strong>（训练期仍然需要）

<strong>② 相机模型 C\_θ（红色，极小）</strong>

- 相机 = <strong>10 维向量 c = ⟨pos(3), rot(6D 连续旋转), fov(1)⟩</strong>
- 1D causal transformer + RoPE 时序嵌入；因为相机只沿 pitch/yaw 旋转，输出层<strong>重参数化为残差</strong> ⟨pos, Δpitch, Δyaw, Δfov⟩，用 MSE 训练
- 极便宜：见后文效率表，相机预测只占 <strong>21.9ms/帧</strong>

<strong>③ 世界到像素生成（蓝色）——把 P\_θ 当成"学出来的着色器"</strong>

- <strong>投影算子 R(c, w) = (w2D, d)</strong>：把 3D 特征投到屏幕空间，得到<strong>按深度排序的体素特征栈</strong> w2D 与<strong>线性深度</strong> d；屏幕尺寸与像素 latent <strong>严格对齐</strong>
- 像素帧由 P\_θ 采样生成，条件是"投影后的 3D 特征 + 动作 + 过去的像素 latent"
- P\_θ 的角色是<strong>学出来的 deferred shader</strong>：额外负责 3D latent 给不了的东西——纹理、光照、粒子效果、屏幕空间 overlay……这样它既能学任意渲染函数，又被"依赖 w2D"这个事实<strong>逼着保持空间一致</strong>
- <strong>一个刻意的偏置</strong>：给 w2D 分配<strong>比像素 latent 更多的通道数</strong>，<strong>逼模型把 3D latent 帧当成主要信息来源</strong>（而不是可有可无的辅助）

### 3.3 缓解 exposure bias（"分离训练还能拼起来"的关键）

- 问题：训练时 denoiser 条件在<strong>真值 latent</strong> 上，推理时条件在<strong>自己的预测</strong>上 → exposure bias
- 用 <strong>diffusion forcing</strong> 训练每个 denoiser，让它们对自己预测带来的偏差更鲁棒
- 更麻烦的是：推理时 W\_θ 依赖 P\_θ 的 latent、P\_θ 又依赖 W\_θ 的 latent（互相喂）。论文的办法是<strong>训练 W\_θ 时给像素 latent 加固定 10% 随机噪声，训练 P\_θ 时给世界帧 latent 加</strong>
- <strong>收益</strong>：三个组件可以完全<strong>分开训练</strong>，推理时直接拼装，<strong>不需要任何 fine-tune</strong>——这是整篇工程上最省事的组织方式

## 四、实验

### 4.1 主结果一：FVD 随 episode 长度（Table 1）

<strong>所有 baseline 和消融都共用同一套 VAE、同一个 rectified flow 训练形式、同一训练集</strong>——对照很干净。

| 方法 | 200 帧 | 400 帧 | 600 帧 |
|-|-|-|-|
| Oasis（像素滑窗） | 409 | 687 | 875 |
| WorldMem（关键帧检索） | 358 | – | – |
| No-3D-Upscale（不做 3D-VAE 上采样） | 216 | 231 | 247 |
| Camera-GT（直接用真值相机） | 161 | 152 | 152 |
| PERSIST-S（3D 去噪器缩小 8×） | 159 | 170 | 179 |
| <strong>PERSIST</strong> | <strong>129</strong> | <strong>141</strong> | <strong>148</strong> |
| <strong>PERSIST+w₀（额外给对齐好的初始 3D 帧）</strong> | <strong>80</strong> | <strong>93</strong> | <strong>104</strong> |

- <strong>像素历史路线一超窗口就崩</strong>：Oasis 从 409 一路涨到 875（FVD 越低越好）；<strong>Oasis 实质上就是"整个 3D 条件机制被拿掉"的消融</strong>
- <strong>No-3D-Upscale 的惩罚最大（216/231/247）</strong> → 从<strong>原生分辨率的 3D latent</strong> 渲染出高深度分辨率的 w2D、并保证 3D 与像素对齐，是关键的一环
- <strong>PERSIST-S 只略微变差</strong>（空间 token 减少 8×）→ <strong>3D 表示对空间压缩极其鲁棒</strong>（3D-VAE 加 3D-S 去噪器合起来最高 <strong>512× 压缩</strong>）
- <strong>⚠️ 一个"指标会说谎"的干净案例</strong>：<strong>Camera-GT 的 FVD 几乎等于完整模型（152 vs 141）</strong>，但论文发现直接给它真值相机会带来<strong>FVD 根本抓不到的物理不一致</strong>——agent 会穿地形、会悬空（Figure 11）

### 4.2 主结果二：逐帧 FID 与稳定性

![▲ 论文 Figure 6：逐帧 FID 随 episode 长度变化。Oasis 在 t 约 150 就冲出 250 的坐标上限；WorldMem 前 400 帧靠预填的真值帧维持，400 帧后跳到 180；PERSIST 全程稳在 125 左右，PERSIST+w0 约 105。PERSIST 开局的 FID 略高，是因为它要重新生成初始像素帧以保证与 3D 世界帧对齐](/images/paper-reading/2026-09-28-persist/2026-09-28-d47-3.webp)

### 4.5 三个"白送"的新能力

- <strong>① 从单张图生成 3D 世界</strong>：W\_θ 能从单张 RGB 帧推出一个合理的初始世界帧 w₀，并且<strong>对没看见的区域每次外推都不一样</strong>（outpainting 的多样性）→ 环境既多样又连贯
- <strong>② 生成中途在 3D 空间改世界</strong>：因为 w\_t 在任意时刻都能取出，可以<strong>暂停在第 t 步、手动编辑 w\_t，再用 ⟨w̃\_t, c\_t, o\_t, a\_t⟩ 重启生成</strong>——这提供了一种细粒度的控制接口
- <strong>③ 持久的世界动态</strong>：模型学会了建模<strong>自己会演化的环境过程</strong>；而且<strong>屏外的动态有时会成为屏内可见效果的因果驱动</strong>

## 五、Limitations &amp; 批判性思考

### 论文自述的限制（结论段 + 附录 E）

- <strong>依赖真值 3D 监督训练</strong> → 目前只能用在提供 3D 标注的仿真器/数据集上（论文给的出路是用 2D→3D 基础模型造合成标注）
- <strong>只维持有限区域的 3D 空间记忆</strong>（一个以 agent 为中心的固定大小方块）
- <strong>实现没有为推理速度优化，还做不到实时</strong>
- 附录 E 另提：<strong>exposure bias 尚未消除</strong>

### 我读出来的额外问题

- <strong>① "persistent spatial memory" 的说法比它实际做到的强</strong>：w 是以 agent 为中心的<strong>固定大小</strong>方块 → agent 走远之后，之前探索过的区域<strong>离开 w 就丢了</strong>。"持久"是"窗口内持久"，不是"永远记得"。论文在 limitation 里承认了范围有限，但<strong>正文标题级别的 "persistent" 容易让人误读</strong>；而且评测任务的动作策略是"平衡探索与重访"设计的，<strong>回访距离可能被控制在 w 的覆盖范围内</strong>——论文没有给出回访距离的分布
- <strong>② 真值 3D 依赖决定了适用面，而出路只停留在"展望"</strong>：体素世界天然有 3D；换到真实视频（只有像素）方法直接用不了。论文给的两条路线（2D→3D 基础模型造标注、从像素直接学 3D）<strong>都没有实验</strong>
- <strong>③ 主指标 FVD 被论文自己的用户研究削弱</strong>：PERSIST-S 在 FVD 上明确更差（179 vs 148），但用户<strong>完全感知不到</strong>（2.6 vs 2.6）；Camera-GT 的 FVD 几乎持平却会穿模。<strong>两个方向都说明 FVD 与"真实体验"脱钩</strong>——这削弱了 Table 1 作为核心证据的权威性
- <strong>④ Table 1 不是同等条件的对照</strong>：WorldMem 被给了<strong>前 400 帧的真值帧与相机</strong>去初始化记忆库，PERSIST 只给 1 帧——这对 PERSIST 有利（用更少信息赢了），但反过来说<strong>这不是"同预算"比较</strong>；而且 <strong>600 帧那一列根本没有 WorldMem 的数字</strong>（表里写 "–"），875 是 Oasis 的
- <strong>⑤ 最大的动机被写下来却没做实验</strong>：intro 明确说这类模型的潜力在于"<strong>在从数据学到的仿真器里安全地训练具身智能体</strong>"，摘要也说像素状态"给下游 agent 训练带来显著障碍"——<strong>但全篇没有一个 agent 训练实验</strong>。对这篇自己写下的最大承诺来说，这是最明显的缺口（也是最好的 follow-up）
- <strong>⑥ 训练成本不低，而且成本结构反常</strong>：合计约 <strong>49 GPU-天</strong>，其中 <strong>3D VAE 12 天、两个 denoiser 各 10 天</strong>——<strong>3D VAE 的训练成本接近一个去噪器</strong>，这件事本身说明 3D 表示的学习还远不成熟（对比 2D VAE 只要 4 天）
- <strong>⑦ 缺"空间记忆"的客观指标</strong>：论文声称在 spatial memory 上有 substantial improvements，<strong>但支撑它的是 FVD / FID / 用户评分这些间接证据</strong>。"回到同一位置/视角时几何是否一致"<strong>本来可以直接量化</strong>（深度误差、位姿误差、重访一致性），论文没做
- <strong>⑧ 只有一种环境</strong>：全部实验都在 Luanti 的体素世界里；对照片级真实场景、非体素几何（曲面、植被、粒子、水面）是否成立未知
- <strong>⑨ Camera-GT 那个反常现象值得单独做</strong>：给"更准的输入"反而产生更差的物理（穿模、悬空）——论文只用 Figure 11 定性解释，<strong>没有量化</strong>（比如统计穿模帧比例）。这其实是个很有意思的"模型假设与输入精度不匹配"的案例

## 六、与前文对照

> 🔗 <strong>一句话定位：lib 的世界模型线此前问的都是「世界模型用来干什么」——WPT 用在训练时、DeltaWorld 把它做小、RLVR-World 用 RLVR 训它、MindJourney 用在推理时。这篇第一次问「世界模型的状态应该长什么样」：把状态从像素历史换成持久的 3D 结构。</strong>

### 6.1 与 lib 世界模型四部曲的关系

- <strong>WPT（训练时用世界模型）</strong>：用世界模型给策略当训练环境。PERSIST 正是它需要的"环境"，<strong>而且 PERSIST 的 intro 自己就把"训练 agent"写成了动机，却一个实验都没做</strong> → <strong>两篇之间有一条现成的、没人填的实验缝</strong>
- <strong>DeltaWorld（把世界模型做小）</strong>：PERSIST 里有一个同源结论——<strong>3D 表示对空间压缩极其鲁棒（最高 512×），真正关键的是"渲染分辨率"（3D-VAE 的上采样）</strong>。也就是说<strong>"压哪里"比"压多少"重要</strong>，这与 DeltaWorld "只压变化量"是同一哲学的两个面
- <strong>RLVR-World（用 RLVR 训世界模型）</strong>：那篇把世界模型的训练当 RLVR 问题；PERSIST 走的是纯监督 / flow matching 路线。<strong>两者正好是"训练目标"与"状态表示"两条正交轴</strong>——把 RLVR 用在 PERSIST 的 3D 世界上（奖励换成几何一致性 / 回访一致性）是一个直接可做的组合
- <strong>MindJourney（推理时用世界模型）</strong>：那篇在推理时"想象"轨迹来增强空间推理。PERSIST 提供的是推理时<strong>可查询、可编辑的 3D 状态</strong> → MindJourney 的"想象"可以变成"<strong>在 PERSIST 的世界帧里做规划</strong>"，而投影只要 <strong>0.63ms</strong>，成本上完全可行

### 6.2 与 OPD / 推理主线的对照（这条线最有意思）

- <strong>核心隐喻是相通的</strong>：PERSIST 论证"像素观测只是隐藏状态的<strong>部分、冗余、视角相关</strong>的投影，所以不该直接拿它当状态"；RAGEN-2（9/16）论证"<strong>熵</strong>只是 Z 的条件熵，看不出跨输入的信息丢失"。<strong>两篇都在做同一件事——指出那个"看起来方便的代理量"其实测的不是你在意的东西，然后去找真正的信息载体</strong>
- <strong>"给信息该从哪儿取"定一个显式结构</strong>：PERSIST 里 <strong>相机是查找键、世界帧是记忆</strong>；OPD 里 <strong>教师 KL 是信号、token 是载体</strong>。两篇都不肯让模型"隐含地学出该看哪"
- <strong>与 VGS（8/21）的直接类比（同一种工程哲学的第二次出现）</strong>：VGS 发现 OPD 的两个梯度（语言先验 vs 视觉接地）近正交，于是<strong>显式把梯度掰到视觉子空间</strong>；PERSIST 发现 3D 与像素两个条件源里 3D 才是主要来源，于是<strong>给 w2D 分配比像素 latent 更多的通道来强制偏置</strong>。<strong>两篇都用"架构上的通道/权重偏置"替代"期望模型自己学出偏好"</strong>
- <strong>"指标会说谎"已经是第三次出现</strong>：本篇的 Camera-GT（FVD 持平却有物理错误）→ RAGEN-2 的"熵健康但 MI 崩了" → MoCA 的"用普通 LLM judge 反而更差"。<strong>lib 里"代理指标与真实目标脱钩"已经构成一条反复出现的暗线，这本身就值得写成一篇独立的 observation</strong>
- <strong>与 VLM-CapCurriculum（9/25）的呼应</strong>：那篇说"<strong>先看清楚再想</strong>"（感知是脚手架）；这篇说"<strong>先把世界的结构存对，再谈生成</strong>"（结构是脚手架）。<strong>两篇都在反对"用更长的计算或更多的上下文去弥补表示上的缺失"</strong>——一个在输入侧、一个在状态侧

### 6.3 与"记忆机制"这条线

- lib 里 JitRL（9/24）用<strong>检索经验库</strong>当记忆，PERSIST 用<strong>持久 3D 状态</strong>当记忆 → <strong>这是"记忆载体"的两个极端</strong>：一个是离散的经验条目、一个是连续的空间状态
- <strong>两条路的约束刚好互补</strong>：JitRL 的记忆库<strong>只增不减、没有淘汰机制</strong>（我上次指出的最大缺口）；PERSIST 的记忆<strong>成本固定、但覆盖范围有限</strong>。<strong>"记忆的代价"是两条路各自的核心约束</strong>
- <strong>本篇给 JitRL 那条线的启发</strong>：如果记忆不是"存下来的东西"而是"<strong>一个会自己演化的状态</strong>"，那么"什么时候该丢"这个问题就<strong>自动消失了</strong>——但换来的代价是"范围有限"

## 七、启发与待跟进

> 💡 <strong>今天最该带走的一条</strong>：当"把那个方便的量塞进上下文"开始失效时，正确的动作往往<strong>不是"塞得更多 / 检索得更好"，而是换一个更适合当状态的东西</strong>。这篇没有发明更强的模型，它只是把"记忆"从像素换成了 3D 结构，然后一致性就不再需要"学出来"，而是"造出来"。

### 方法启发（可迁移）

- <strong>① "代理状态"是一套很好用的论文论证结构</strong>：论文明确说"真隐藏状态 s 可能任意复杂甚至不可测，所以我们定义 s̃ = ⟨w, c⟩"，然后论证它为什么有效。<strong>这个"不追求真值、只追求有效"的论证方式可以直接搬到任何"隐变量该用什么表示"的问题上</strong>
- <strong>② "通道/权重的显式偏置"比"期望模型自己学出偏好"更可靠</strong>：给 w2D 多于像素 latent 的通道（本篇）、把梯度掰向视觉子空间（VGS）——<strong>同一个招数的两次成功</strong>
- <strong>③ "分离训练 + 推理拼装"的工程价值</strong>：三个组件各自独立训练（加 10% 噪声增强来对齐分布），推理时直接拼、<strong>零微调</strong>——这是大模型流水线里最省事的组织方式
- <strong>④ "把可解析的交公式、不可解析的交网络"</strong>：几何投影用确定性算子，只要 <strong>0.63ms</strong>；只有着色/纹理/光照这些"没有闭式表达"的部分才交给神经网络。<strong>这个分工是全文工程上最漂亮的地方</strong>
- <strong>⑤ 一个"指标会说谎"的干净可引用案例</strong>：Camera-GT 的 FVD 与完整模型几乎持平（152 vs 141），但会穿模悬空。<strong>如果你在自己项目里遇到"指标涨了但看起来不对"，这篇给了现成的引用</strong>

### 待跟进（按性价比排序）

- <strong>① 【最高性价比】补上"用世界模型训练 agent"这个缺口</strong>：论文自己把"在学到的仿真器里安全训练具身智能体"写成最大动机，却<strong>一个 agent 训练实验都没做</strong>。在 PERSIST 的仿真器里跑一个 RL agent，与"在真 Luanti 里跑"对比（sim-to-sim 版本）——<strong>动机是论文自己写的，实验是别人可以做的</strong>
- <strong>② 把"空间记忆"变成可量化的客观指标</strong>：定义"<strong>回访一致性误差</strong>"（回到同一位置/视角时，生成帧与真值的几何/深度误差），替代 FVD 这类间接证据。<strong>同时能正面回答"w 的覆盖范围到底够不够"</strong>（现在只有 limitation 里的定性承认）
- <strong>③ 用 RLVR 训 PERSIST 的 3D 世界</strong>：把 RLVR-World 那条线的奖励换成几何一致性 / 回访一致性，看能否替代纯 flow matching 目标——<strong>这是 lib 两条世界模型线最自然的交叉点</strong>
- <strong>④ 干掉真值 3D 依赖</strong>：用 2D→3D 基础模型造合成 3D 标注，在真实视频上训（论文画了饼没做）——<strong>这是把方法从"体素游戏"推向"任意视频"的关键一步，也是这条路线的胜负手</strong>
- <strong>⑤ w 的有限范围 vs 无限记忆</strong>：论文附录 E 提出"3D memory bank"（多个世界帧拼接/检索）。<strong>这正好接上 JitRL 的"记忆管理"问题</strong>：3D 记忆库的淘汰 / 合并策略应该长什么样
- <strong>⑥ "3D 空间当编辑界面"能不能泛化</strong>：改 w\_t 就能改世界（地形/生物群系/物件），而且投影只要 0.63ms。<strong>这个思路可以搬到别的内容生成任务上</strong>（把"能解析的结构"暴露成可编辑接口）
- <strong>⑦ 跨环境验证</strong>：从体素世界扩到照片级真实场景 / 非体素几何（曲面、植被、粒子、水面）——论文的限制①实际上把这条路堵着
- <strong>⑧ 量化 Camera-GT 的反常</strong>：统计穿模 / 悬空帧比例，做成一个"输入更准反而更差"的干净案例（<strong>对做 OPD/蒸馏的人特别有共鸣：教师信号更准，不等于学生学得更好</strong>）

## 八、今日阅读结论

> 🎁 <strong>今日一句</strong>：<strong>记忆不该是"过去看过的照片"，而应该是"世界本身的一个会演化的状态"——一旦把状态换对，一致性就不再需要"学出来"，而是"造出来"。</strong>

- <strong>这篇的核心贡献是"换了状态的载体"，不是"做了更强的模型"</strong>：三个组件加起来（世界去噪器 686M + 像素去噪器 460M + 很小的相机模型）不算大，训练流程还是标准的 rectified flow + DiT。改变的是<strong>条件在什么上</strong>
- <strong>它给出的最一般性命题</strong>：<strong>"条件该用什么"比"条件得更多"更重要</strong>；一旦条件对了，<strong>记忆成本可以固定、几何一致性可以 by construction</strong>
- <strong>它同时留下一条很硬的边界</strong>：这一切建立在"<strong>有真值 3D 监督</strong>"上——<strong>在能拿到 3D 的世界里非常强，在只有像素的世界里还用不了</strong>。这条边界的宽度基本决定了这篇工作的最终影响面
- <strong>最诚实的评价</strong>：<strong>结果（600 帧 FVD 148 vs Oasis 875、用户研究全面领先、还更快）是硬的</strong>；但"世界模型用来训练 agent"这个它自己写下的最大动机，<strong>一个实验都没做</strong>——这既是它的缺口，也是别人现成的机会
- <strong>对项目的直接价值</strong>：① "代理状态"的论证结构可直接套用 ② <strong>3D 记忆库 + JitRL 式记忆管理</strong>是现成的交叉点 ③ "把可解析的交公式、不可解析的交网络"（投影 0.63ms）这个分工值得抄 ④ lib 里"<strong>指标会说谎</strong>"已经出现三次，可以考虑写成一条独立的观察

## TL;DR

<strong>一句话：现在的 VLA 几乎都是"看得到才能做"——目标一旦挪出摄像头视野，机器人就卡死。SOMA 的做法不是让模型"脑补"看不见的东西，而是先让头部相机主动扫一圈，把看到的物体（语义+3D 位置）固化成一块<strong>持久空间记忆</strong>，之后操作时不管目标在不在眼前，都能从记忆里把它"查"出来，边操作边更新这块记忆。</strong>

- <strong>最刺眼的一组数（Figure 4，5 个真实世界视野外任务，Pick 阶段）</strong>：Task 2（可见→不可见）Pick 成功率 <strong>35% vs 最强 baseline GR00T N1.5 的 25%</strong>；Task 5（双臂协同）Pick <strong>30% vs 20%</strong>——<strong>5 个任务 SOMA 全部第一</strong>
- <strong>比成功率更有意思的是"行为变了"（Table 1）</strong>：首次锁定目标的时间 <strong>First-Fixation Time 平均快 40%–59%</strong>，头部搜索路径长度 <strong>短 40%–57%</strong>，<strong>抓取尝试次数少 40%–57%</strong>——最难的 Task 5（双臂）上 GR00T 要试 <strong>3.7 次才抓到，SOMA 只要 1.6 次</strong>
- <strong>消融证明"记忆"比"扫描"本身更关键（Table 2）</strong>：只扫描不建记忆（Scan+GR00T）SR <strong>18.5%</strong>；不扫描只建记忆（No-Scan SOMA）<strong>19.8%</strong>；扫描但记忆不更新（Scan-only）<strong>24.1%</strong>；<strong>完整版（扫描+记忆+动态更新）28.3%</strong>——<strong>光扫一遍不维护记忆几乎没用，持续更新才是大头</strong>
- <strong>仿真上同样成立</strong>：RoboCasa GR1（300 条演示）SOMA <strong>52.0%</strong> 平均成功率，超过 GR00T N1.5（44.3%）、StarVLA（20.2%）、Diffusion Policy（39.2%）；SimplerEnv 视觉匹配 <strong>63.2%</strong>，超过 OpenVLA-OFT（63.0%）、RoboVLM（60.6%）
- <strong>记忆组件消融（Table 5）</strong>：去掉几何位置编码 <strong>49.3%→45.1%</strong>；去掉物体语义 <strong>→43.7%</strong>；<strong>去掉动态更新机制掉得最多 →41.5%</strong>——三个部件里，"持续更新"单项损失最大
- <strong>工程细节很实在</strong>：真机是自研人形平台（两条 7-DoF Realman ZM73 机械臂 + 2-DoF 云台头 + 3 个 Intel RealSense D435，边缘端 Jetson AGX Orin 64GB）；训练 32×H200，批大小 60，3 万步；每任务只给 <strong>400 条</strong>真机演示

## 一、先看例子（大白话：东西挪出视线，不等于世界上没有它）

> 💡 <strong>铺垫</strong>：现在的 VLA（视觉-语言-动作模型）大多是"看图说话再动手"——给一张当前画面 + 一句指令，模型直接出动作。这套流程有个默认前提：<strong>指令里提到的东西，此刻一定在画面里</strong>。
>
> <strong>这篇论文说：这个前提在真实场景里经常不成立。</strong>

> <strong>把这件事想成找钥匙：</strong>
>
> 你让一个人"把粉色杯子放进篮子"，<strong>但粉色杯子不在他面前的桌子上，而是在他身后的桌角</strong>。
>
> <strong>现在的 VLA 是这样的人</strong>：他只会盯着眼前这块桌子找。眼前没有，他就卡住，反复在原地找，甚至直接"卡死"——论文原话就是 <em>Stucking</em>。
>
> <strong>SOMA 想让机器人变成另一种人</strong>：找不到的时候，<strong>先转头扫一圈整个房间</strong>，把"哪里有什么东西"记在脑子里（这就是空间记忆）。之后不管粉色杯子在不在眼前，他都知道"刚才扫过，它在右后方桌角"，<strong>直接转头过去拿，而不是对着空气发愣</strong>。

![▲ 论文 Figure 1：现有 VLA 的视野外局限。图中蓝色锥形是机器人头部相机的视野，锥形之外（红框标出的「Invisible Objects」）就是看不见的区域。人类说「把粉色杯子放进篮子」，但粉色杯子恰好在视野外，机器人回答「找不到指定物体（卡死）」](/images/paper-reading/2026-10-12-soma/2026-10-12-d54-1.webp)

## 二、动机：空间推理代替不了真的看过一眼

- <strong>问题的起点</strong>：绝大多数 VLA 训练在<strong>固定视角</strong>（单个静态相机或第三人称视角）的桌面操作场景上——这么做是因为<strong>标定简单、状态估计稳定、采集数据不需要多视角协调</strong>
- <strong>但这个简化带来一个隐含假设</strong>：<strong>指令里提到的目标，在决策时刻一定在当前相机视野里</strong>。这个假设从根上限制了模型对<strong>暂时被遮挡或移出视野的物体</strong>进行推理的能力
- <strong>已有的补救方案也不够</strong>：靠 MLLM 的<strong>空间推理</strong>去"猜"看不见的目标在哪（论文点名了几类相关工作）——但这种推理<strong>很脆弱</strong>：只有在还有部分视觉证据或相关线索时才可靠，<strong>一旦目标完全移出视野，空间推理的质量会迅速恶化</strong>。推理出的位置一旦偏离物理真实，误差会沿着"感知→动作"这条链条一路传递下去，导致定位不准、动作错位，最终任务失败
- <strong>论文的核心立论</strong>：<strong>没有被真正观测过的物体，光靠模型容量和推理深度是补不回来的</strong>——缺的不是"想得更深"，而是"<strong>获取过视野外的空间证据，并把它保留在一个持久的场景表示里</strong>"
- <strong>于是 SOMA 建立在两个设计原则上</strong>：① 一个<strong>可动的头部相机</strong>，能主动获取工作空间的多个视角 ② 一个<strong>全局空间记忆</strong>，把各个角度扫到的东西整合成统一、可查询的空间-语义表示

## 三、方法：扫描建档 → 动态刷新 → 按指令取用

![▲ 论文 Figure 2：SOMA 框架总览。(A) Spatial Memory Construction——操作前，若指定物体不在当前视野，机器人主动扫描场景，用 DINOv3（语义）+ YOLO（检测）+ VGGT（几何）构建统一的空间-语义记忆 M₀；(B) Dynamic Memory Refinement——交互过程中，新观测到的信息通过「相似度感知」融合进记忆，得到刷新后的当前记忆；(C) Contextual Memory Retrieval——语言引导的查询通过交叉注意力选择性地激活相关记忆区域，为基于 DiT 的动作解码器提供上下文线索](/images/paper-reading/2026-10-12-soma/2026-10-12-d54-2.webp)

### 3.1 Spatial Memory Construction（扫描建档）

- <strong>触发条件</strong>：指令里提到的目标，在当前相机画面里<strong>用轻量检测器找不到</strong> → 机器人启动<strong>主动头部扫描</strong>（按预定义轨迹转头），采集一段多视角扫描视频 <strong>V</strong>，每隔 N 帧均匀采一帧，得到子集 <strong>Ṽ</strong>
- <strong>每一帧并行跑三条互补管线</strong>： 
  - <strong>VGGT</strong>（几何先验网络）——估相机位姿 + 场景粗几何
  - <strong>YOLO</strong>（语义感知模块）——出 2D 检测框 + 物体类别
  - <strong>DINOv3</strong>（语义编码器）——出高维视觉特征
- <strong>把每个检测框变成一个"实例"</strong>：裁出框内特征做空间平均池化 → 得到外观嵌入；再用 VGGT 预测的相机位姿，把 2D 框"抬升"到<strong>全局 3D 场景坐标系</strong>下的 3D 框
- <strong>跨视角去重合并</strong>：按"<strong>DINOv3 外观余弦相似度 + 3D 框空间一致性</strong>"做同类实例关联，超过阈值就合并，外观和几何都取平均——<strong>解决同一个物体被不同角度拍了好几次的问题</strong>
- <strong>兜底机制</strong>：某一帧没检测到物体时，注入<strong>可学习的占位嵌入 + 伪框</strong>，避免记忆因为漏检而变得稀疏
- <strong>最终每个物体实例是一个三元组</strong> <strong>(外观 fₖ, 类别 cₖ, 3D 框 bₖ)</strong>，组合成记忆 token：<strong>m⁰ₖ = Φ\_mem(fₖ) + Φ\_pos(bₖ)</strong>（外观语义 + 可学习的 3D 位置编码相加）。<strong>所有物体的记忆 token 合起来就是 Overview Scene Memory M₀</strong>

### 3.2 Dynamic Memory Refinement（动态刷新）

- <strong>问题</strong>：操作过程中场景会变——物体被挪动、被遮挡、或者出现了新物体，<strong>M₀ 不能一直原封不动用下去</strong>
- <strong>做法</strong>：每一步用头部相机的当前观测，走和 3.1 一样的感知管线，得到当前帧的记忆 token <strong>Mᵗ</strong>；对每个新观测到的实例，去上一步的记忆 <strong>Mᵗ⁻¹</strong> 里找同类且满足关联条件的旧实例做匹配（<strong>一次观测最多匹配一个记忆，一条记忆每步最多被一次观测更新</strong>）
- <strong>匹配上了就用"自适应相似度融合"更新</strong>：算语义相似度分 <strong>sᵏⱼ</strong> 和动态融合分 <strong>gᵏⱼ</strong>（都过 sigmoid），两者相乘得到更新系数 <strong>αᵏⱼ = gᵏⱼ · sᵏⱼ</strong>，再做时间上的<strong>指数滑动平均（EMA）</strong>：<strong>mᵗₖ = αᵏⱼ·mᵗⱼ + (1−αᵏⱼ)·mᵗ⁻¹ₖ</strong>
- <strong>这个设计的巧妙之处</strong>：相似度分负责"这还是不是同一个物体"，融合分负责"这次该相信新观测多少"——<strong>两者相乘，小的视角抖动会被压下去（更新系数小），物体真的被挪动了才会快速换成新状态（更新系数大）</strong>
- <strong>没匹配上的怎么处理</strong>：新出现的实例<strong>直接追加成新记忆条目</strong>；<strong>旧记忆里没被匹配上的实例原样保留</strong>——<strong>这正是"看不见≠不存在"的工程落地</strong>：目标只是暂时离开视野，不是从记忆里被删除

### 3.3 Contextual Memory Retrieval（按指令取用）

- 把 VLM 产出的视觉-语言 token <strong>X\_vl</strong> 当成<strong>查询（Query）</strong>，把当前的空间记忆 <strong>M̂ᵗ</strong>（先经对齐层投影到同一空间）当成<strong>键值对（Key/Value）</strong>
- 标准<strong>交叉注意力</strong>：<strong>X\_boost = softmax(QKᵀ/√C)·V</strong>——每个视觉-语言 token 会<strong>按需去记忆里挑相关的空间线索</strong>，查到的结果和当前感知特征融合
- <strong>融合后的特征 X\_boost 作为全局上下文，连同原始视觉-语言 token、机器人状态、带噪动作一起喂进多层 DiT 模块</strong>，再经动作解码器输出未来一段动作序列

<strong>这张表最关键的读法</strong>：<strong>"只扫描不建记忆"几乎没有用</strong>（18.5%，甚至不比没扫描的 No-Scan 高多少）；<strong>"扫了、建了记忆、但操作中不更新"</strong>能明显改善（24.1%）；<strong>真正把分数拉上去的是"持续更新"这一步</strong>（24.1%→28.3%）。论文自己的结论是：<strong>扫描只是给了一个有用的初始覆盖面，真正的收益来自持久空间记忆本身以及它的持续刷新，不是扫描动作本身</strong>。

## 五、Limitations &amp; 批判性思考

### 论文自身没有写的（没有独立 Limitations 章节）

论文从 Conclusion 直接跳到 Acknowledgements 和 Impact Statement，<strong>没有一句自我批评</strong>。以下是我读完方法与实验后自己整理的问题点：

1. <strong>触发机制很"硬"，依赖一个轻量检测器先判断"看不见"。</strong>如果这个检测器本身误判（比如把目标误识别成别的类别、或者光照变化导致漏检），SOMA 会在<strong>目标明明在视野里</strong>的情况下触发不必要的扫描，或者在<strong>目标真的不在</strong>时误以为看到了——论文没有报告这个检测环节本身的误差率，也没做它对下游成功率的敏感性分析
2. <strong>扫描阶段的代价被轻描淡写了。</strong>主动头部扫描本身要花时间（真机场景下尤其明显），论文的效率对比（First-Fixation Time 等）都是<strong>扫描完成之后</strong>算起的，<strong>没有把扫描本身耗费的时间计入端到端任务耗时的对比</strong>——"更快锁定目标"和"更快完成任务"不是一回事
3. <strong>仿真里的"扫描"被简化成了第一帧。</strong>论文写明"For simulation experiments, the overview memory is constructed from the first frame of each trajectory"——<strong>仿真实验里压根没有真正的多视角主动扫描</strong>，RoboCasa/SimplerEnv 上的提升更多来自"持久记忆+动态更新"这套机制本身，<strong>和真机实验里"扫描建档"这个核心设计是脱钩的</strong>，混在一起报告容易让读者误以为两边验证的是同一件事
4. <strong>真机对照组的训练演示量是否对等没有写清楚。</strong>论文说"每任务采集 400 条真机演示"用于训练<strong>所有对比模型</strong>，但 StarVLA / SpatialVLA / GR00T N1.5 是否都在<strong>完全相同</strong>的 400 条数据、相同的训练步数下训练，论文没有给出逐方法的训练细节核对表
5. <strong>记忆的容量和检索质量在复杂场景下会怎样，没有测。</strong>论文的真机场景里物体数量不多（从图里看每个任务最多几个干扰物），<strong>没有报告"记忆里积累了几十甚至上百个物体实例后，检索精度会不会下降"</strong>——这正是"持久记忆"类方法的经典压力测试，PERSIST（9/28 读过）也只在"以 agent 为中心的有限区域"内验证，SOMA 同样没有测试记忆规模的上限
6. <strong>"代码即将开源"的真实状态未知。</strong>论文摘要写"Code will be released soon"，仓库 github.com/Hoantrbl/SOMA 存在，但<strong>写作时内容状态未经核实</strong>，复现门槛（尤其是自研人形平台这部分）客观上偏高
7. <strong>头部相机的运动策略是预定义的，不是学出来的。</strong>"按预定义轨迹扫描"意味着<strong>扫描路径本身没有被优化</strong>——一个更智能的系统或许应该学会"往哪扫最可能找到目标"，而不是固定走一遍整个房间

## 六、与前文对照

> 🔗 <strong>一句话定位</strong>：lib 的具身智能线上一篇是 9/3 的 <strong>HiF-VLA</strong>（给 VLA 装"时间维度"的记忆——用运动向量压缩历史帧，解决马尔可夫假设下的"时间近视"）。<strong>SOMA 补的是另一个维度——空间维度：不是记"刚刚发生了什么"，而是记"视野之外还有什么"。</strong>而这个问题，恰好是 9/28 读过的世界模型论文 PERSIST 关心的同一类问题，只是换成了真机场景。

### 6.1 与 PERSIST（9/28 #46）——"持久空间记忆"这条线的第二次出现，而且走的是互补的路

| 维度 | PERSIST（世界模型，9/28） | SOMA（VLA，本篇） |
|-|-|-|
| <strong>要解决的问题</strong> | 交互式世界模型的长期几何一致性——像素帧只是部分、冗余、视角相关的投影 | VLA 的视野外操作——相机帧只是部分、视角相关的观测，看不到就当不存在 |
| <strong>记忆是什么</strong> | 以 agent 为中心的<strong>隐式 3D 体素状态</strong>（48³ 网格），端到端学出来的 | 离散的<strong>物体级记忆 token 集合</strong>（外观+3D 框+类别），由现成感知模型（YOLO/DINOv3/VGGT）拼装 |
| <strong>怎么取用记忆</strong> | 相机位姿当检索键，几何投影把 3D 状态投到当前视角 | 语言指令的 token 当查询，<strong>交叉注意力</strong>去记忆里检索相关物体 |
| <strong>训练代价</strong> | 需要训练期的<strong>真值 3D 监督</strong>（只能用于能导出 3D 的仿真器） | 用<strong>现成的预训练感知模型</strong>（VGGT/YOLO/DINOv3）直接构建记忆，不需要专门训一个 3D 表示 |
| <strong>验证场景</strong> | 游戏引擎（Luanti）里的生成式世界 | <strong>真实机器人</strong> + 两个标准仿真基准 |

<strong>两句话读完这对对照</strong>：PERSIST 要的是"让世界模型自己拥有一个随处可用的 3D 状态"，这个状态是<strong>端到端学出来的、训练代价很重</strong>；SOMA 要的是"让 VLA 在操作时记得起扫过的东西"，这个记忆是<strong>靠现成感知模型拼装出来的、更轻量，但覆盖面也更窄（只记物体级实例，不记完整几何）</strong>。<strong>"持久空间记忆"这个思路正在从世界模型渗透到 VLA，这是具身智能里一条值得继续追的暗线。</strong>

### 6.2 与 HiF-VLA（9/3 #13）——时间记忆 vs 空间记忆，VLA 记忆的两个维度

- <strong>HiF-VLA</strong> 解决的是"<strong>时间近视</strong>"：VLA 的马尔可夫假设只看当前帧，HiF-VLA 用运动向量（MV）把历史帧压缩成"后见"上下文，再预测未来运动向量当"洞察"——它记的是<strong>时间线上发生过什么</strong>
- <strong>SOMA</strong> 解决的是"<strong>空间盲区</strong>"：当前视野只覆盖一部分空间，SOMA 把扫过的空间固化成记忆——它记的是<strong>空间上哪里有什么</strong>
- <strong>两者是正交的两个轴</strong>：一个沿时间轴压缩，一个沿空间轴扩展覆盖面。<strong>一个真正完整的 VLA 记忆系统大概需要两者都要</strong>——既要记得"刚刚发生了什么"，也要记得"视野之外还有什么"。这是具身智能记忆机制里一个明显可以合并的方向，目前没人把两者放一起做

### 6.3 与 WorldPlay（10/9 #52）——"记忆重构"思路的又一次迁移

- WorldPlay 的记忆设计是"时域记忆 + 空域记忆"的双路结构（最近几个 chunk 保流畅、非相邻历史帧按几何相关性采样防漂移），再加一招"时间重构图"把久远记忆的位置编码重写成贴近当前的小值
- SOMA 的 <strong>Dynamic Memory Refinement</strong> 本质上在做同一类事——<strong>用相似度感知的自适应系数决定"这次该信多少新观测、留多少旧记忆"</strong>，只是载体从"视频 chunk"换成了"物体实例"
- <strong>两篇的共同直觉</strong>：持久记忆不能是"从头重建"或者"原样堆叠"，必须有一套<strong>按相关性/相似度自适应融合</strong>的机制，否则会在"记太死（跟不上场景变化）"和"记太活（没有持久性）"之间失衡——这正是 SOMA 自己的消融（Table 2，Scan-only 不如 Full）证明的那件事

### 6.4 与 BSBT/MoCA（8/31 #26）、PAPO 等"看错 vs 想错"主线的一个新变体

- BSBT/MoCA 关心的是"多模态推理里，答错是因为没看清还是没想明白"——这类工作假设<strong>目标就在图里，只是模型没看清或没想对</strong>
- <strong>SOMA 处理的是更前置的一类失败</strong>：<strong>目标根本不在当前的图里</strong>，不是"看错了"而是"<strong>没得看</strong>"。这类失败在纯感知/推理类工作里一般被当成"域外"或者直接假设不会发生，<strong>SOMA 把它当成一等问题正面解决</strong>

## 七、启发与待跟进

### 7.1 启发

1. <strong>"看不见不等于不存在"值得当成一条通用设计原则。</strong>很多系统（不只是 VLA）默认"当前输入里没有的信息就不存在"，SOMA 的做法提醒我们：<strong>先问一句"这个信息我是不是曾经获取过、只是现在不在眼前"，再决定要不要重新获取</strong>——这条原则在多轮对话、长程 agent 任务里同样适用
2. <strong>记忆系统的"更新策略"往往比"记什么"更关键。</strong>Table 2 和 Table 5 两个独立的消融都指向同一个结论：<strong>静态建一次记忆的收益有限，持续、自适应地刷新才是大头</strong>。这和 WorldPlay 的"重构式记忆"、Forget-Me-Not 的"回放策略"是同一类教训的第三次出现——<strong>"记忆"类方法的核心难点几乎总是在"更新机制"，不在"存储结构"</strong>
3. <strong>把现成的感知模型拼装成结构化记忆，是比"端到端学一个记忆表示"更轻的路。</strong>SOMA 没有训练任何新的 3D 表示网络，直接用 YOLO+DINOv3+VGGT 三个现成模型分工（语义/外观/几何），只训练了"怎么把它们的输出变成记忆 token、怎么检索"这两个轻量模块。<strong>这是"工程落地优先"路线的一个干净样本</strong>，和 PERSIST 的"端到端学 3D 状态"形成鲜明对比
4. <strong>"行为指标"比"成功率"更能说明问题。</strong>Table 1 的首次锁定时间、搜索路径长度、抓取尝试次数，比单纯的成功率更能证明"模型是不是真的学到了空间记忆的使用方式"，而不是靠更多试错撞对答案——这是一个值得在其他任务上借用的评测思路

### 7.2 待跟进（按性价比排序）

1. <strong>把 HiF-VLA 的时间记忆和 SOMA 的空间记忆合并。</strong>两者是正交的轴，架构上看不出明显冲突——时间记忆处理"马尔可夫假设"，空间记忆处理"视野绑定假设"，<strong>合在一起可能解决 VLA 记忆问题的更大一块版图</strong>，这是目前 lib 里最直接能提出的组合实验
2. <strong>测试记忆规模的上限。</strong>SOMA 现在的真机场景物体数量不多，一个值得做的压力测试是：<strong>把场景物体数量从几个增加到几十个，看记忆检索的精度曲线怎么掉</strong>——这正是论文完全没有报告的部分，也是"持久记忆"类方法共同的软肋（PERSIST 同样没测规模上限）
3. <strong>学一个"该往哪扫"的策略，取代预定义扫描轨迹。</strong>当前的头部扫描路径是固定的，一个更智能的版本应该能根据<strong>指令里的物体类别先验</strong>（比如"杯子一般在桌面附近而不是天花板）去优化扫描顺序，减少扫描本身的时间开销——这也直接回应批判里提到的"扫描代价被忽略"的问题
4. <strong>把扫描耗时计入端到端任务时间，重新评估"效率优势"的真实幅度。</strong>这是一个很便宜的复核实验：只需要把 Table 1 的指标起点从"扫描完成后"挪到"任务开始时"，就能看出 SOMA 的真实效率优势是否被扫描阶段的额外开销部分抵消
5. <strong>把这类"物体级空间记忆"用到多 Agent 协作场景。</strong>如果多个机器人共享同一块空间记忆（而不是各自维护一份），理论上可以让"一个 agent 扫过的区域，另一个 agent 不需要重新扫"——这是具身智能 + 多 Agent 交叉的一个尚无人做的方向

## 八、今日阅读结论

> 🎁 <strong>今日一句</strong>：<strong>VLA 的"视野外失明"不该靠模型"硬猜"去补，该靠一块能持续更新的空间记忆去记——而三个独立的消融实验（真机 Table 2、仿真 Table 5、以及两者共同的结论）都在说同一件事：记忆这件事，<u>怎么更新</u>比<u>怎么存</u>更重要。</strong>

- <strong>这篇最本质的贡献是把"视野外操作"明确立为一个独立问题</strong>，并给出了一个工程上干净、不需要重新训练底层感知模型的解法——扫描建档、相似度感知刷新、交叉注意力检索，三步都用现成组件拼装
- <strong>第二个贡献是一组反复被印证的行为证据</strong>：成功率涨了，但更有说服力的是<strong>首次锁定更快、搜索路径更短、抓取次数更少</strong>——这些指标说明模型是真的"知道东西在哪"，不是靠更多试错撞上去的
- <strong>最诚实的评价</strong>：真机结果很扎实（5 任务全面领先、行为指标全线改善），仿真结果也支撑了核心机制的普适性；但<strong>① 没有独立 Limitations 章节，所有边界条件要靠读者自己扒 ② 仿真里的"扫描"被简化成第一帧，和真机的核心设计实际上脱钩 ③ 记忆规模上限、扫描本身的时间成本都没有被测过</strong>
- <strong>对项目的直接价值</strong>：① <strong>"持久空间记忆"是具身智能里继 PERSIST（世界模型）之后第二次出现的同类思路</strong>，值得作为一个小专题继续追踪 ② 与 HiF-VLA 的时间记忆合并是最直接能提出的下一步实验 ③ "行为指标优于单纯成功率"的评测思路可以迁移到其他任务的消融设计里

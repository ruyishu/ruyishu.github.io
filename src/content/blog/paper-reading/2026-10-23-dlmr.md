## TL;DR

<strong>一句话：MLLM 想得越长越瞎，这不是某个模型的 bug，而是「单一增长上下文」这个范式的结构性必然——softmax 注意力要在长度为 n\_t 的上下文上归一化，所以图像 token 上的总注意力天然以 O(L\_v/n\_t) 衰减到 0。DLMR 的解法是给模型挂两份「潜在记忆」：一份存可复用的视觉证据、一份存已推出的约束，再加一个离散路由器决定「这一步要不要回忆、回忆哪份、花几个 token」。主干全程冻结，只训记忆和路由器，三阶段训练。</strong>

- <strong>最刺眼的一组数（Table 1，Reasoning 四项平均）</strong>：Qwen2.5-VL-7B <strong>46.61 → 56.45</strong>（DLMR RL），InternVL-3-8B <strong>48.27 → 63.08</strong>；同期最强基线 Visual-RFT 只有 <strong>50.76 / 55.02</strong>
- <strong>通用榜也涨，而且涨得有点多</strong>：Qwen2.5-VL-7B 的 General 平均 <strong>64.67 → 71.07</strong>（MMVet <strong>63.30 → 73.85</strong>）；InternVL-3-8B <strong>71.51 → 79.01</strong>（MMVet <strong>75.08 → 85.91</strong>）
- <strong>而且更省</strong>：平均生成 token 比最接近的 Visual-RFT 少 <strong>9.7%</strong>，比 SFT 少 <strong>4.2%</strong>（Fig 6）
- <strong>核心机制</strong>：两份 <strong>input-agnostic</strong> 的潜在记忆 <strong>Z^v</strong>（视觉证据）与 <strong>Z^r</strong>（推理约束）；<strong>Memory Injector</strong> 把选中的 k 个 latent 上下文化成 k 个 memory token；<strong>Router</strong> 输出离散动作 <strong>(s\_t, k\_t)</strong>，s∈{v,r}、k∈<strong>{4,8,16}</strong>，还可以选「不注入」
- <strong>一个很便宜的工程约束</strong>：<strong>只在 delimiter（分隔符）处才允许注入</strong>，且总注入次数有上限 N\_max —— 不是每步都注入，而是「一段推理写完才回忆一次」
- <strong>三阶段训练</strong>：① Latent 预热（两个教师的对齐损失 + 交叉负例 hinge + 分离项，防止两份记忆塌成一份）② Injector 训练（混合不同类型与预算，SFT 或 RL）③ Router 训练（GRPO）。<strong>主干 θ 全程冻结</strong>
- <strong>诊断（Fig 1）</strong>：vanilla 的图像注意力在生成过程中一路衰减到接近 0；DLMR 在「回头看图」的那些峰上明显更高，而且整条曲线更长（同样的题用更少 token 就答完了）
- <strong>✅ 仓库有完整的三阶段训练管线</strong>（<strong>train.sh</strong> 的 stage1/2/3/all、<strong>evaluate.sh</strong>、<strong>main.py</strong>、YAML 配置、tests，27 commits、21 star）<strong>⚠️ 但没有 released checkpoint、没有数据、没有 LICENSE</strong>，且 README 默认底座写的是 <strong>Qwen2.5-VL-3B</strong>（论文主实验其实是 7B / 8B）

## 一、先看例子（大白话：想得越长，越忘了自己在看什么）

> 💡 <strong>铺垫</strong>：让 MLLM 解一道多步的图形推理题，它写了几百个 token 之后，往往开始「自己跟自己说话」——<strong>前面在图里看到的东西，后面提都不提了</strong>。这个现象大家都知道，但通常归因成「模型不够强」。
>
> <strong>这篇给了一个结构性解释：它不是不够强，是这个范式注定会忘。</strong>

![论文 Figure 1：生成过程中模型分配给图像 token 的归一化注意力。橙色是原始 Qwen2.5-VL-7B，蓝色是 DLMR。三条曲线都有峰（说明模型确实会「回头看图」），但原模型的峰一路走低、最后几乎贴地；DLMR 在同样的回头点上峰值明显更高，而且整条曲线在 750 token 内就结束了](/images/paper-reading/2026-10-23-dlmr/2026-10-23-d63-1.webp)

> <strong>把这件事想成你在抄一份很长的资料：</strong>
>
> <strong>你的桌子只有一页纸的位置。</strong>每抄一段新的，就得把前面那段推到旁边。<strong>抄到第十页的时候，第一页已经掉到桌子外面了。</strong>
>
> <strong>这不是你记性差，是桌子太小。</strong>
>
> <strong>DLMR 的做法：在桌边放两个小抽屉</strong>——一个存「我在原件上看到的」，一个存「我抄出来的结论」。<strong>每次写完一段，抬头看一眼抽屉</strong>，需要哪个开哪个。

<strong>论文把这个「桌子太小」写成了一个式子</strong>：softmax 注意力要满足 <strong>Σ\_i α\_{t,i} = 1</strong>，所以平均权重是 1/n\_t。只要模型不越来越尖锐地盯住开头那段图像前缀，<strong>图像 token 上的总注意力 A^img\_t ≈ L\_v/n\_t，随 t 增大单调趋向 0</strong>。

<strong>这句话的含义很重</strong>：它不是说「某个模型有 bug」，而是说<strong>任何用单一增长上下文的 MLLM，都逃不掉这个数学必然</strong>。想不瞎，只能显式加记忆。

## 二、动机：现在的做法都还在同一个笼子里

- <strong>已有的补救</strong>：靠提示词引导模型「再看一眼图」、靠训练让模型学会重述视觉信息、或者接一个检索模块
- <strong>但论文的判断是</strong>：这些方法<strong>都还绑定在「单一增长上下文」这个机制上</strong>——它们只是让模型在文本里多写几遍「我看到图里有个圆」，<strong>并没有真正阻止长程遗忘</strong>
- <strong>认知科学的类比</strong>：人解复杂题时，<strong>「我看到了什么」和「我推出了什么」是分开记的</strong>——两个缓冲区，按需回看。而现在的 MLLM 把两者<strong>全塞进一条文本流</strong>
- <strong>于是需要两样东西</strong>：① 一份<strong>解耦的表示</strong>，能分别存「可复用的视觉证据」和「在变的推理约束」② 一个<strong>依赖状态的控制器</strong>，决定什么时候取、取多少

## 三、方法：两份记忆 + 一个路由器 + 三阶段

![论文 Figure 2：左侧是推理时的流程——冻结的 MLLM 主干在解码，遇到分隔符时路由器从「视觉记忆」或「推理记忆」里选一类、选一个预算 k，Memory Injector 把这 k 个 latent 变成 memory token 塞回上下文；右侧是三阶段训练：Stage I 用两个教师做对齐/交叉负例/分离；Stage II 随机选记忆类型与预算训 injector；Stage III 用 GRPO 训路由器](/images/paper-reading/2026-10-23-dlmr/2026-10-23-d63-2.webp)

### 3.1 两份记忆：Z^v 和 Z^r

- <strong>两份都是 input-agnostic 的</strong>（所有输入共享，不是每张图各存一份），形状 M\_s × d —— 这是它参数极少的根本原因
- <strong>Z^v</strong> 存「可复用的视觉证据」，<strong>Z^r</strong> 存「中间结论与约束」
- 给定预算 k（比如 4/8/16），取这份记忆的前 k 个向量

### 3.2 Injector：把记忆变成 token

- 输入是当前上下文嵌入 E\_t + 选中的 k 个 latent；输出是 <strong>k 个 memory token</strong>
- 实现很省：<strong>在冻结主干的副本上加 LoRA</strong>，让 latent 通过自注意力去「读」当前上下文，再取最后 k 个状态
- 这些 token <strong>被追加到当前上下文</strong>，然后照常用冻结主干预测下一个 token —— <strong>主干一个参数都没动</strong>

### 3.3 Router：这一步要不要回忆

- <strong>动作是离散的</strong>：<strong>a\_t = (s\_t, k\_t)</strong>，s ∈ {视觉, 推理}，k ∈ {4, 8, 16}，外加<strong>「不注入」</strong>
- <strong>只在 delimiter（分隔符）处才允许注入</strong> —— 也就是「一段推理写完了」这个时刻，而不是每一步
- 另有<strong>总注入次数上限 N\_max</strong> —— 双重的开销控制
- 不满足条件就<strong>确定性退回普通解码</strong>

### 3.4 三阶段训练（主干全程冻结）

| 阶段 | 做什么 |
|-|-|
| <strong>Stage I</strong><br>Latent 预热 | 让两份记忆先「学会各存各的」。用<strong>两个教师</strong>分别给出视觉池化表示 t\_v 与推理池化表示 t\_r，学生侧注入记忆后得到 z\_v、z\_r，损失 = <strong>正对齐（1 − cos）+ 交叉负例 hinge（惩罚错配）+ 分离项（惩罚 z\_v 与 z\_r 太像）</strong>。<strong>分离项是关键</strong>——不然两份记忆会塌成一份 |
| <strong>Stage II</strong><br>Injector 训练 | 在推理数据上训 injector + 两份记忆（<strong>路由器此时关闭</strong>），并<strong>随机/交替地换记忆类型与预算</strong>，让 injector 在各种开销下都稳。可用 SFT 或 RL（GRPO） |
| <strong>Stage III</strong><br>Router 训练 | 用 <strong>GRPO</strong> 训路由器，让它学会在什么状态下该回忆哪份、花几个 token |

## 四、实验

### 4.1 主结果：两个底座都大幅提升

<strong>Reasoning 四项平均（MMMU / MathVerse / MathVision / MathVista）</strong>

| 方法 | Qwen2.5-VL-7B | InternVL-3-8B |
|-|-|-|
| Vanilla | 46.61 | 48.27 |
| CoT | 47.21 | 51.51 |
| CCoT | 47.30 | 50.82 |
| SFT | 47.53 | 50.82 |
| GRPO | 50.29 | 54.33 |
| Visual-RFT | 50.76 | 55.02 |
| RCTS-RAG | 49.19 | 51.65 |
| <strong>DLMR（SFT）</strong> | <strong>53.84</strong> | <strong>59.04</strong> |
| <strong>DLMR（RL）</strong> | <strong>56.45</strong> | <strong>63.08</strong> |

<strong>7B 上 +9.84 分、8B 上 +14.81 分</strong>（相对 vanilla），而且<strong>比 GRPO / Visual-RFT 这类也在训的方法高一截</strong>——不只是「练了就好」。

### 4.2 通用能力也涨，而且涨得有点多

<strong>MMVet 从 63.30 到 73.85（+10.55）</strong> —— <strong>一个记忆机制让通用 VQA 涨 10 分，这个幅度值得警惕</strong>（见第五节的批判）。

### 4.3 而且更省

![论文 Figure 6：在四个推理基准上，每样本平均生成的 token 数（Qwen2.5-VL-7B）。DLMR 在保持最强能力的同时，平均比 Visual-RFT 少 9.7%、比 SFT 少 4.2% 的 token](/images/paper-reading/2026-10-23-dlmr/2026-10-23-d63-3.webp)

<strong>这个结果是自洽的</strong>：既然不用在文本里反复重述「我看到了什么」，<strong>推理链自然就短了</strong>——和 10/22 那篇 CapCurriculum「感知变好 → 推理链短 20.8%」是同一个道理的两种实现。

### 4.4 诊断：缝在哪儿

<strong>Fig 1 是全文最有说服力的一张图</strong>：两条曲线的<strong>峰位置几乎重合</strong>（说明「什么时候该回头看图」这件事模型本来就知道），<strong>差别在峰的高度</strong>——原模型的峰一路走低，DLMR 能维持在更高水平。<strong>这正好对应它「不改变何时回忆、只改善能回忆起多少」的设计。</strong>

## 五、Limitations

### 论文自述的：<strong>没有</strong>

⚠️ <strong>本篇没有独立的 Limitations 章节</strong>——§6 Conclusion 之后直接就是 Acknowledgments 与 Impact Statement。<strong>照实写，不硬凑。</strong>

### 我读出的 6 条

1. <strong>⭐ 通用榜涨得太多，需要解释</strong>：MMVet <strong>63.30 → 73.85（+10.5）</strong>、MMStar 62.60 → 68.67。<strong>一个「记忆注入」机制让通用 VQA 涨 10 分，这在参数高效方法里异常漂亮</strong>。要么基线没调够，要么记忆里混进了数据集特定的捷径。<strong>论文完全没讨论这一点</strong>
2. <strong>⭐ 仓库和论文对不上，作为 baseline 要打折</strong>：论文主实验是 <strong>7B / 8B</strong>，<strong>仓库 README 默认写 3B</strong>；<strong>没有任何 released checkpoint</strong>；没有 LICENSE。<strong>「能跑通」和「能复现论文数字」是两件事</strong>
3. <strong>缺 router 的对照</strong>：正文里我没看到「随机 router」「固定每隔 N 步注入」「只注入一种记忆」这三组对照。<strong>没有它们，说不清那 9.84 分里 router 学到的部分占多少</strong>
4. <strong>「只在 delimiter 处注入」是个强假设</strong>：依赖模型<strong>自己生成分隔符</strong>。如果模型不按格式输出（或者换了 prompt 风格），<strong>注入机会直接消失</strong>。论文没测这个鲁棒性
5. <strong>记忆是 input-agnostic 的，那它到底存了什么？</strong> 所有输入共享同一组 latent——这确实省参数，但它<strong>更像一组「全局提示向量」而不是真正的「这张图的记忆」</strong>。论文的 memory specialization 分析需要非常仔细才能区分「真的在存视觉证据」和「学会了某种通用解码偏置」
6. <strong>没有独立 Limitations 章节</strong>——一篇 Spotlight 该有

## 六、前文对照

> 🔗 <strong>一句话定位</strong>：这是<strong>和 10/16 的 AFIP 同一个诊断、两种相反解法</strong>的一对；也是本周四篇里，唯一一篇把「为什么视觉注意力会衰减」<strong>从经验现象升级成数学必然</strong>的工作。

### 6.1 与 AFIP（10/16）：同一个病，两种相反的治法

|   | AFIP（10/16） | DLMR（本篇） |
|-|-|-|
| 诊断 | 解码越往后，图像注意力越低（VAR 下降） | <strong>同一个现象</strong>，但给出结构性解释 A^img ≈ L\_v/n\_t |
| 解法 | <strong>推理期手动补</strong>：改注意力矩阵（training-free） | <strong>训练期装设备</strong>：训两份记忆 + 路由器 |
| 成本 | 每步都要算，且要改注意力（<strong>因此被我们的新门槛排除</strong>） | 只在 delimiter 处注入，token 还更省 |

<strong>这两篇放在一起看，能得出一个挺硬的判断</strong>：<strong>「视觉注意力衰减」不是通过推理期打补丁能根治的，因为它的根在 softmax 归一化 + 单一上下文这个结构里。</strong>AFIP 的法子能缓解症状，但 DLMR 指出的才是病因。

### 6.2 本周四篇的位置

| 日期 | 论文 | 它管的是哪一环 |

<strong>四篇串起来是一条完整的流水线</strong>：<strong>先能看见（CapCurriculum）→ 看见了存下来（DLMR）→ 需要时去查（DoF 的工具）→ 内部有几何支撑（SpatioLM）</strong>。

### 6.3 与 SpatioLM（10/21）：同一种工程范式

两篇都是 <strong>「冻主干 + 挂旁路 + 只训小参数」</strong>：SpatioLM 挂的是几何模块（6×50M），DLMR 挂的是记忆 + 注入器 + 路由器。<strong>差别是</strong>：SpatioLM 解决「空间表示」，DLMR 解决「长程保持」。<strong>同一个配方，攻两个不同的能力缺口</strong>——这本身说明这个范式在这个领域已经成型了。

### 6.4 在 lib 的「记忆形态」谱系里

这条线已经攒了很长一串：JitRL 经验库 / PERSIST 持久 3D 状态 / Forget-Me-Not 回放缓冲 / WorldPlay 重构上下文 / SOMA 物体级空间记忆 / iVGR Rollout Archive / EAPO 自写文字记忆 / AFIP 历史视觉注意力记忆 / <strong>DLMR 双潜在记忆</strong>。

<strong>DLMR 补上的是两个新东西</strong>：① <strong>记忆分了类型</strong>（视觉 vs 推理，而且用分离项强制它们不塌成一份）② <strong>记忆有预算</strong>（这一步花 4 个还是 16 个 token 去回忆，由路由器决定）。<strong>之前的所有记忆机制都是「固定形态、固定开销」，它是第一个把「回忆」变成可分配资源的。</strong>

## 七、启发与待跟进

### 启发

1. <strong>那个 O(L\_v/n\_t) 的推导很值钱</strong>：它把「视觉注意力衰减」从<strong>经验现象</strong>升级成<strong>结构性必然</strong>。<strong>任何用单一增长上下文的 MLLM 都逃不掉</strong>——这句话可以直接引用，也可以用来解释你自己模型上的「越推越瞎」
2. <strong>「分开存观测和约束」是可迁移的设计</strong>：不只 vision-language，纯文本推理也能用（论文自己也说能迁移到 text-only）。<strong>本质是给模型一个显式的「工作记忆」，而不是让它把所有东西都写在草稿纸上</strong>
3. <strong>「只在 delimiter 处注入」是个很便宜的工程约束</strong>：不是每步都注入，而是「一段推理写完才回忆一次」。<strong>降低开销 + 提高稳定性 + 不干扰局部解码</strong>，这个 trick 可以直接抄到任何记忆/工具注入的场景
4. <strong>「记忆预算」是新的超参维度</strong>：k ∈ {4,8,16} + N\_max。<strong>「这一步值得花多少 token 回忆」</strong>比「固定注入」细一个量级
5. <strong>⚠️ 看通用榜涨幅要警惕</strong>：+10 分的通用 VQA 提升，对参数高效方法来说过于漂亮，<strong>通常是基线设置或数据泄漏的信号</strong>
6. <strong>⚠️ 仓库和论文的规模要对上</strong>：README 写 3B、论文报 7B/8B、没有 checkpoint —— <strong>这种「能跑但跑不出论文数字」的仓库，作为 baseline 的价值要打折</strong>

### 待跟进（按性价比）

1. 【最该补的对照】<strong>随机 router / 固定步长注入 / 只注入一种记忆</strong> —— 三组对照才能说清路由器学没学到东西，以及那 9.84 分里多少来自「有记忆」、多少来自「会分配」
2. <strong>查通用榜 +10 分的来源</strong>：是不是基线没调、或者记忆里编码了数据集特定信息。<strong>这个数字如果站不住，主结论的说服力会被连累</strong>
3. <strong>测 delimiter 格式的鲁棒性</strong>：让模型不输出分隔符，注入机会消失，性能掉多少？<strong>这决定了它在真实产品里能不能用</strong>
4. <strong>把 O(L\_v/n\_t) 这个论证拿去用</strong>：如果自己做长链视觉推理，这个式子可以直接解释「为什么越推越瞎」，甚至可以用来设计「注入频率该随长度怎么变」

## 八、结论

> 🎁 <strong>今日一句</strong>：<strong>MLLM 想得越长越瞎，不是模型不够强，是「单一增长上下文」这个范式注定会忘——softmax 要在长度 n\_t 上归一化，图像 token 的总注意力天然以 O(L\_v/n\_t) 衰减到 0。DLMR 给它挂两份潜在记忆（一份存视觉证据、一份存推理约束），再加一个离散路由器，只在分隔符处决定「要不要回忆、回忆哪份、花几个 token」。主干全冻，三阶段训练。7B 上推理均分 46.61 → 56.45，8B 上 48.27 → 63.08，而且 token 还更省。</strong>
>
> <strong>三个值得抄的设计</strong>：① <strong>记忆分类型 + 分离项</strong>（防止两份记忆塌成一份）② <strong>只在 delimiter 处注入</strong>（便宜的工程约束）③ <strong>记忆预算 k ∈ {4,8,16}</strong>（把「回忆」变成可分配资源）。
>
> <strong>最该记住的一条</strong>：<strong>它和 AFIP（10/16）是同一个诊断的两种相反解法</strong>——AFIP 在推理期手动补注意力（治症状），DLMR 指出根在结构里、必须在训练期装设备（治病因）。<strong>而它和本周另外三篇串起来，是一条完整的流水线：先能看见（课程）→ 看见了存下来（记忆）→ 需要时去查（工具）→ 内部有几何支撑（模块）。</strong>
>
> <strong>最大的保留</strong>：<strong>通用榜涨了 10 分（MMVet 63.30 → 73.85），但论文一句没解释</strong>；而且<strong>仓库默认 3B、论文报 7B/8B、没有任何 released checkpoint</strong> —— 作为 baseline 的可复现性要打折。

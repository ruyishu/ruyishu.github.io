> 2026-10-14 · 文献阅读 #55 · 方向：<strong>多模态 RL</strong> · <strong>别让模型把坐标写出来：「往哪儿看」应该被内化进文字推理</strong> · HKU + ByteDance + HKUST · ICML 2026 Poster

## TL;DR

<strong>一句话：为了让多模态模型看清细节，现在流行「边推理边报坐标框」。但论文实测发现：推理时强制它输出坐标框，反而比「纯文字推理」更差。iVGR 的做法是同时训两条流——一条必须报框、一条纯文字——再用一个「一致性奖励」把文字流往那条报了框的高质量轨迹上拉。结果是：推理时不用报框了，但模型对图像的注意力反而更强。</strong>

- <strong>最刺眼的一组数（Table 1，不改任何参数、只改推理 prompt）</strong>：TreeVGR-7B 用<strong>纯文字 CoT 平均 75.7，用接地 CoT 只有 74.7</strong>；DeepEyes-7B <strong>75.1 vs 74.1</strong>——<strong>两个模型都是「不报框」更好，8 个基准里赢 6 个</strong>，而它们<strong>从来没有被训练过纯文字 CoT</strong>
- <strong>为什么（Figure 2，用人工标注的框分组）</strong>：DeepEyes <strong>只有在框很准（IoU &gt; 0.5）时</strong>接地才赢过文字；框一不准，接地就掉到文字以下 → <strong>框不准 = 往推理里灌视觉噪声</strong>。TreeVGR 更彻底：<strong>在所有 IoU 区间，纯文字都不输</strong>
- <strong>核心机制（双流 + 一致性奖励）</strong>：同一条 query 采两组 rollout——<strong>接地流</strong>（必须报框，奖励 = 格式 + 答案 + 框 IoU）和<strong>文字流</strong>（纯文字，奖励 = 格式 + 答案 + <strong>一致性</strong>）。一致性分由外部 LLM judge 打分：描述完全一致 1.0 / 单处偏差 0.7 / 复合偏差 0.3 / 明确矛盾 0.0
- <strong>主结果（Table 2）</strong>：Qwen2.5-VL-7B <strong>70.1 → 76.6（+6.5）</strong>；Qwen3-VL-8B <strong>76.2 → 80.6（+4.4）</strong>；Qwen3-VL-32B <strong>79.6 → 82.9（+3.3）</strong>；7B 在 V\* 上 86.4，超过此前 SOTA <strong>2.6 分</strong>；图表/多学科榜 <strong>62.9 → 65.4</strong>
- <strong>「内化」的证据（Table 10，最后一层对图像 token 的注意力）</strong>：只训文字流 <strong>0.0959</strong> / 只训接地流 <strong>0.1113</strong> / <strong>iVGR 用文字推理 0.1239</strong>——<strong>不报框的那个，反而最看图，甚至超过必须报框的那个</strong>
- <strong>消融里藏着一个不太好看的数（Table 5）</strong>：只训接地流、用文字测 = <strong>71.1</strong>；<strong>双流但没有一致性奖励 = 71.0</strong>——<strong>「多了一条流」这件事本身几乎没贡献</strong>！真正涨分的是<strong>一致性奖励（71.5）</strong>和<strong>Rollout Archive（72.4）</strong>
- <strong>工程上很实在的一个小设计（Rollout Archive）</strong>：把每条 query 历史上框最准的那条接地轨迹存成一个存档；<strong>前 160 步命中率为 0，第 2 个 epoch 约 30%，第 3 个 epoch 约 50%</strong>——冷启动后自动生效，几乎零成本
- <strong>⚠️ 论文有独立 Limitations 章节（3 条）</strong>：① 需要 bbox 标注 ② 依赖外部 LLM judge（会幻觉）③ 训练时没接裁剪工具，接地流在超高分辨率下会漏细节，限制了参考轨迹的质量
- <strong>⚠️ 一个必须点明的矛盾</strong>：论文的<strong>核心结论是「不要显式报框」</strong>，但它<strong>训练时用的监督、以及最后吹的 test-time scaling，全都建立在「模型还能报框」之上</strong>——它是「让模型会报框但平时不许报」，不是「让模型不会报框」

## 一、先看例子（大白话：有些东西，心里知道就行，别写在纸上）

> 💡 <strong>铺垫</strong>：多模态模型看太小的东西会看漏（比如一张高分辨率图里的一辆小车、一个仪表盘数字）。现在主流的补救办法是让它<strong>别光用嘴说，还要用手指出位置</strong>——在推理过程里直接输出一个坐标框 <strong>\[x1,y1,x2,y2\]</strong>，或者调用裁剪工具把那一小块放大再看。
>
> <strong>注意：上面这句「指出位置」用的是「手」，不是「嘴」。</strong>

> <strong>把这件事想成老师教学生做一道看图题：</strong>
>
> <strong>方案 A（现在流行的做法）</strong>：规定学生答题时必须写「我看了左上角那个区域（坐标 12,34,56,78）」，然后才作答。
>
> <strong>问题来了</strong>：如果他<strong>框写错了</strong>呢？——他本来心里觉得是黄色的车，一写坐标框到了旁边一辆白车上，后面的推理就<strong>全跟着错</strong>。这个错误不是"想错"，是"<strong>被自己写出来的坐标带沟里了</strong>"。
>
> <strong>方案 B（iVGR 的做法）</strong>：允许他写坐标照常练（这也是个有用的技能），但<strong>要求他用纯文字再答一遍</strong>，并且<strong>两条答案必须说的是同一件事</strong>。训完之后<strong>考试时把坐标那一栏去掉</strong>——他还是能看对地方，但不用写出来了。

![论文 Figure 1：三种范式。(a) 工具裁剪式——模型输出坐标并调用裁剪工具，把局部图拼回上下文推理；(b) 显式接地式——直接在推理链里输出坐标框，不用外部工具；(c) iVGR——双流训练，用一致性奖励把「文字流」往高质量的「接地流」上对齐，从而把定位能力内化进文字推理](/images/paper-reading/2026-10-14-ivgr/2026-10-14-d56-1.webp)

## 二、动机：不是「接地没用」，是「推理时强制接地」这件事有问题

- <strong>接地 CoT 的两种实现</strong>：① <strong>工具裁剪</strong>（DeepEyes 一类）——输出坐标后调外部工具裁出来，与原因拼在一起再推理；② <strong>显式输出框</strong>（TreeVGR 一类）——直接在推理链里吐坐标，省掉外部工具
- <strong>问题在于：这两种做法的"推理期有效性"此前没有被严格检验过</strong>。论文把现成模型拿来，<strong>不改一个参数，只换推理 prompt</strong>（文字 CoT 的 prompt 见论文附录 A），结果就是上表——<strong>文字反而更好</strong>
- <strong>论文据此提出假设</strong>：<strong>定位能力可以被内化进文字 CoT，而强制显式接地反而对"答对"这个主目标造成干扰</strong>
- <strong>然后用 IoU 分组把机理挖出来了（Figure 2）</strong>：在 HR8K 上<strong>人工标注目标框</strong>，按生成框与真值框的 IoU 把问题分桶，看每个桶内的准确率：

![论文 Figure 2(a) DeepEyes：只有裁剪质量高（IoU 大于 0.5）时，带工具的接地 CoT 才超过文字 CoT；框一不准就掉到文字以下](/images/paper-reading/2026-10-14-ivgr/2026-10-14-d56-3.webp)

![论文 Figure 2(b) TreeVGR：在所有 IoU 区间，文字 CoT 都不输给接地 CoT——定位能力已经隐含在文字推理中，显式接地只是额外负担](/images/paper-reading/2026-10-14-ivgr/2026-10-14-d56-4.webp)

- <strong>DeepEyes（工具式）</strong>：接地在 <strong>IoU &gt; 0.5</strong> 时才赢，低 IoU 时输 → <strong>裁剪不准就是往推理里灌视觉噪声</strong>
- <strong>TreeVGR（输出框式）</strong>：<strong>所有 IoU 区间文字都不输</strong> → 结论更强：<strong>定位能力本来就在，强制写出来是纯负担</strong>
- <strong>于是目标变成</strong>：<strong>既要保留"会看"的能力，又要在推理时不依赖显式输出</strong>——这就是双流训练想干的事

## 三、方法：两条流、一个裁判、一个存档

![论文 Figure 3：方法总览。同一条 query 分别用「接地 CoT prompt」和「文字 CoT prompt」采两组 rollout——接地流拿格式/答案/框奖励，文字流拿格式/答案/一致性奖励；中间从接地流里按「格式合法 + 答案正确 + 框奖励大于阈值」选出高质量参考轨迹（存进 Rollout Archive），交给 LLM Judge 给文字流打一致性分](/images/paper-reading/2026-10-14-ivgr/2026-10-14-d56-5.webp)

### 3.1 双流训练（Dual-Stream）

- 同一条 query <strong>q</strong>，用<strong>两套 prompt</strong> 各采 N 条 rollout：<strong>接地流 O^b</strong>（必须报框）、<strong>文字流 O^t</strong>（纯文字）
- <strong>关键工程约束：不比基线多花算力</strong>——每批的 B/2 条 query 被复制一份、分别用两套 prompt 去采，<strong>总 rollout 数不变</strong>
- 两条流各自用 <strong>GRPO 的组内归一化</strong>算优势

### 3.2 三种奖励

| 奖励 | 怎么算 |
|-|-|
| <strong>R\_format</strong> | 严格符合 &lt;think&gt;…&lt;/think&gt;&lt;answer&gt;…&lt;/answer&gt; 结构记 1，否则 0 |
| <strong>R\_acc</strong> | 答案与真值一致记 1，否则 0（两条流都有） |
| <strong>R\_box</strong>（只给接地流） | <strong>双向 IoU 匹配</strong>——一半查召回（每个真值框，找最像的预测框）、一半查精确（每个预测框，找最像的真值框），两者取平均。这样既罚「漏框」也罚「乱报框」 |
| <strong>R\_consistency</strong>（只给文字流） | 外部 LLM judge（Qwen2.5-72B）给文字 CoT 与参考接地 CoT 打语义一致性分，四档：<strong>1.0 完全一致 / 0.7 单处偏差（要么漏、要么多）/ 0.3 复合偏差（又漏又多）/ 0.0 明确矛盾</strong>；存档为空时记 0 |

### 3.3 参考轨迹怎么选（这一步决定了整个方法的质量）

- <strong>挑选条件</strong>：接地 rollout 必须同时满足 ① 格式合法 ② 答案正确 ③ <strong>R\_box &gt; τ（τ=0.3）</strong>——<strong>三条都满足才配当"参考"</strong>
- <strong>Rollout Archive（存档）</strong>：因为一个 batch 内的策略质量会起伏，把每条 query <strong>历史上框最准的那条</strong>接地轨迹存下来，逐步用更准的替换掉旧的： <br>Z\_archive(q) ← argmax<sub>z ∈ {存档, 本轮最佳}</sub> R\_box(z)
- <strong>为什么必须有这一步</strong>：如果只用"本轮恰好出现的那条"，那么<strong>本轮运气不好（比如早期根本没有合格轨迹）时，文字流就会被喂垃圾参考</strong>。论文实测：<strong>前 160 步存档命中率为 0</strong>（还在攒），第 2 个 epoch 约 <strong>30%</strong>，第 3 个 epoch 约 <strong>50%</strong>'
- <strong>数据侧还有一条兜底</strong>：<strong>77.3% 的 query 最终都能拿到 IoU ≥ 0.3 的参考</strong>，只有 11.4% 落在 \[0,0.1)、11.3% 落在 \[0.1,0.3)

### 3.4 工具加持的推理期扩展（test-time scaling）

- 双流训练<strong>保留了模型"会报框"的能力</strong>，所以推理时可以反过来用它：
- 三步走：① 让模型生成接地 CoT、抠出所有预测框 → ② 用裁剪工具裁出若干局部图，<strong>额外再拼一个"并集裁剪"（把所有预测框的最小外接矩形也裁一份，用来保留物体间的空间关系）</strong> → ③ 把原图 + 各个局部裁剪 + 并集裁剪 一起喂进去，用<strong>纯文字 CoT</strong> 推一遍

## 五、Limitations

### 论文自述的 3 条

- <strong>① 需要 bbox 标注</strong>，增加标注负担。论文给的缓解方案：复用现成检测数据集（如计数任务）+ 用现成检测器做伪标注；并强调<strong>缺少框的任务不会拖累性能</strong>（Table 12）
- <strong>② 依赖外部 LLM judge</strong>，judge 会幻觉、影响一致性奖励的准确性。缓解：加大 judge 规模（Table 7）、多次采样取平均（Table 9）
- <strong>③ 训练时没接裁剪工具</strong>，接地流在超高分辨率/极细粒度内容上会幻觉或漏检，从而限制了参考轨迹的质量。论文的建议是<strong>把接地流换成"带裁剪工具增强的推理机制"</strong>，这样参考会更准更细

### 我读出的 5 条（按重要性）

1. <strong>「内化」的证据偏弱，缺反事实实验</strong>：Table 10 只用<strong>最后一层的注意力分数</strong>从 0.0959 涨到 0.1239 来论证"内化"。但<strong>注意力高不等于看对了</strong>——完全可能是"看得更用力但看错了"。真正该做的是<strong>遮蔽关键区域，看纯文字流的掉分幅度是否接近接地流</strong>。这个实验论文没做
2. <strong>「双流」结构本身几乎不贡献分（Table 5 的 (4) vs (5)）</strong>：只训接地流 71.1，加上第二条文字流但不给一致性奖励 71.0。<strong>论文的叙事是"双流训练"，但消融显示真正有用的是奖励设计，不是双流结构</strong>——这个反差值得点明
3. <strong>一致性奖励和 Rollout Archive 的贡献没有分离</strong>：+0.5 vs +0.9，<strong>Archive 的边际贡献更大但没有单独消融</strong>。而且 Archive「挑一条最准的历史轨迹」这件事本身，与"一致性奖励"在概念上是可分离的两个想法
4. <strong>通用能力有回退，论文没讨论</strong>：32B 的 RealWorldQA <strong>−3.0</strong>、POPE <strong>−0.6</strong>；8B 的 CV-Bench-3D <strong>−2.5</strong>。对一篇主打"细粒度涨分"的论文来说，这些回退需要说明是否可接受
5. <strong>成本没被认真记账</strong>：论文强调"总算力与单流持平"（把 B/2 的 query 复制两份），但<strong>多出来的 4×A100 专门跑 judge、以及 39h vs 35h 的额外时长</strong>，在"K×A100×小时"这个口径下并非持平；且 <strong>judge 的额外算力没有被纳入对比</strong>

### OpenReview 审稿人已点出的 2 条（与我的判断重合）

- <strong>① 高分辨率下接地流自己就会漏细节</strong>（因为它只输出 bbox、不裁剪），此时文字流可能被"教错"——论文<strong>没有分析这个失败模式</strong>
- <strong>② 增益归因不清</strong>：最终训练集里额外加了 OpenMMReasoner + ArxivQA 的文字推理数据，<strong>难以区分涨分来自机制还是来自额外领域数据</strong>。（论文 Table 12 的 37K-only 对照算是部分回应：+2.0）

## 六、前文对照

> 🔗 <strong>一句话定位</strong>：iVGR 是 lib 里<strong>「一个模型、两种条件、把一条流对齐到另一条流」这个骨架的第三例</strong>——前两例是 SDPO（9/30，环境反馈当特权条件）和 π-Distill（10/13，动作当特权条件）。而且它给"条件无法对齐"提供了<strong>第三种解法</strong>。

### 6.1 与「同模型双条件」家族（SDPO / π-Distill）—— 骨架相同，对齐手段不同

| 工作 | 两种条件 | 怎么对齐 | 代价 |
|-|-|-|-|
| <strong>SDPO（9/30）</strong> | 有无环境反馈 f | 同一模型对同一答案二次前向打分，<strong>靠概率差当优势</strong> | 无外部模型，但要二次前向 |
| <strong>π-Distill（10/13）</strong> | 有无特权信息（动作） | <strong>共享参数 + KL 双向拉</strong>（教师被拽向学生、学生被拉向教师） | 无外部模型，但要调 α |
| <strong>iVGR（本篇）</strong> | 报框 / 不报框 | <strong>外部 LLM judge 打一致性分当奖励</strong>，只有单向（文字流向接地流靠） | <strong>要额外 4×A100 跑 judge</strong>，且 judge 会幻觉 |

<strong>把这三篇并排看，能看出一个清晰的设计空间</strong>：<strong>"条件无法对齐"时有三种解法</strong>——① <strong>改条件</strong>（WorldPlay 10/9：把教师的上下文改造成学生的样子）② <strong>不改条件，改用 KL 显式惩罚漂移</strong>（π-Distill）③ <strong>不改条件，改用外部裁判打一个"语义一致"的分数</strong>（iVGR）。<strong>iVGR 是三者里唯一引入外部模型的，也因此是唯一可以"部分对齐"的</strong>（0.7、0.3 这些中间档就是"允许不一致但扣分"）。

### 6.2 与多模态 RL 的信用分配家族

- <strong>与 POLIA（10/5）最值得并读</strong>：两篇都用 <strong>IoU</strong>，但用途完全相反—— <strong>直接进优势 vs 先变成一个语义分数再进优势</strong>。iVGR 走后者，代价是多一个会幻觉的裁判，好处是<strong>信号能覆盖"框位置对但内容读错"这类 IoU 抓不到的错误</strong>（见前面 Figure 5 右例）
  - <strong>POLIA</strong>：用 GT 框算 IoU 做<strong>物体级 intrinsic advantage</strong>，直接把细粒度信号注入优势 → <strong>框是"奖励"</strong>
  - <strong>iVGR</strong>：用 IoU 只挑"够格的参考轨迹"，再由 judge 把参考翻译成文字流的奖励 → <strong>框是"参考"，中间隔了一层 judge</strong>
- <strong>与 BSBT / MoCA（8/31）</strong>：MoCA 的问题框架是"<strong>看错了还是想错了</strong>"，然后把奖励按模态路由。<strong>iVGR 提供了一个新病例：看对了、也报对了框，但"把框写出来"这个动作本身带偏了后面的推理</strong>——不是看错也不是想错，是<strong>表达形式反过来污染了内容</strong>
- <strong>与 PCD（8/17）/ VGS（8/21）</strong>：这两篇都在 OPD 的梯度层拆"感知 vs 推理"的分量（PCD 做软 AND 门、VGS 把梯度掰向视觉子空间）。<strong>iVGR 给出的是同一问题的"推理期版本"：不是怎么分配梯度，而是"要不要在输出里把感知结果显式写出来"</strong>——结论是<strong>不要</strong>，而且能不写还让注意力更高
- <strong>与 ACTIVE-O3（8/27）</strong>：ACTIVE-O3 用纯 RL 训模型<strong>主动选区域放大看</strong>（外部工具路线）；<strong>iVGR 是它的镜像：内化路线</strong>——把"往哪儿看"变成隐式的，同时<strong>保留报框能力当 test-time scaling 的备胎</strong>。ACTIVE-O3 是"学会用工具"，iVGR 是"学会不用工具但要会"
- <strong>与 Forget-Me-Not（9/29）</strong>：Rollout Archive 是一种<strong>极简的记忆形态</strong>——只存"每条 query 历史上最好的一条轨迹"，没有淘汰策略、没有容量控制。<strong>它的命中率曲线（0 → 30% → 50%）说明这类记忆是"自举式"生效的</strong>，可作为 lib「记忆形态」谱系里最轻的一档

### 6.3 「分锅家族」新增一格

lib 现有轴：<strong>BSBT 模态 / PCD 因果阶段 / GiGPO 时间步 / MIRL 生成阶段 / InstructVLA 参数子集 / MoCA 模态+奖励路由 / Forget-Me-Not 模块 / SDPO token×词表 / POLIA 视觉物体 / GraphGPO 状态-动作边 / π-Distill 教师-学生角色</strong>。

<strong>iVGR 新增的是「跨数据流的对齐」</strong>——<strong>锅不在某个 token、某个物体、某一层，而在"两条不同 prompt 下的轨迹之间该谁向谁靠"</strong>。这条轴和前面所有轴都正交：<strong>你可以同时用 POLIA 的物体级优势 + iVGR 的跨流一致性</strong>。

## 七、启发与待跟进

### 启发

1. <strong>「让模型说出来」和「让模型知道」是两件事——而且强制说出来可能有害。</strong>这条可以直接推广成一个大问题：<strong>哪些中间结构该内化，哪些该外显？</strong>坐标框是一种，还有检索 query、计划、中间变量、子问题分解。iVGR 只回答了"坐标框不该外显"这一格，而且给了一个判据：<strong>外显的那个结构如果本身有错（框不准），错误会沿着推理链放大</strong>——所以<strong>外显结构的"出错代价"是决定要不要外显的关键变量</strong>
2. <strong>「跨流一致性奖励」是个可以搬走的模板</strong>：一个模型在两套 prompt 下产出两种轨迹 → 挑出高质量那条 → 用裁判给另一条打"语义一致"分 → 当奖励。<strong>比改教师上下文（WorldPlay）和显式 KL 惩罚（π-Distill）都更"软"</strong>，代价是要一个外部裁判。<strong>它最大的优势是能表达"部分一致"</strong>（0.7 / 0.3 这两档），而 KL 惩罚只有"多远"没有"哪一类不一致"
3. <strong>Rollout Archive 是性价比很高的稳定器</strong>：只存"每条 query 历史最佳的一条轨迹"，前 160 步自动攒着、之后约 50% 命中率，直接贡献 +0.9。<strong>它解决的是一个普遍问题：在线采样时"本轮没采到好样本"会让对照信号整体失效</strong>——用一个持久存档兜底
4. <strong>对"注意力分数当内化证据"要警惕</strong>：Table 10 那种论证（0.0959 → 0.1239）在 lib 里会越来越常见。<strong>以后看到"注意力提升了"，应该先问一句：有反事实实验吗？遮住关键区域掉分了吗？</strong>
5. <strong>一个值得反过来问的问题</strong>：iVGR 的对齐是<strong>单向</strong>的（文字流向接地流靠）。那反过来让<strong>文字流去教接地流</strong>呢？——文字流在"读标牌文字"这类任务上明显更强（Figure 5 右例），<strong>双向一致性奖励有可能同时把框变准、把内容读对</strong>。这是一个直接可做的实验

### 待跟进

1. 【最贴合主线】<strong>把"条件对齐"的三种解法做成对照矩阵</strong>：改条件（WorldPlay）/ KL 惩罚（π-Distill）/ 外部裁判一致性（iVGR）——分别在什么条件下更优？<strong>唯一的空位可能是"多模态版"：图像条件不一致时（VLM OPD 里师生看的区域不同）用哪种？</strong>而 iVGR 恰好就是这个空位的一个现成答案
2. <strong>补 iVGR 缺的两个消融</strong>：① 有 Archive 但去掉一致性奖励（分离两者贡献）② 双流结构保留但两条流都只给答案奖励（检验"双流"到底有没有用）
3. <strong>把「内化"做反事实检验</strong>：遮挡关键区域，比较纯文字流与接地流的掉分幅度；再看纯文字流的注意力是否落在正确区域（而不只是"注意力总量更大"）
4. <strong>把"强制外显中间结构是否有害"做成系统性课题</strong>：坐标 / 检索 query / 计划 / 中间变量 / 子问题 —— 逐个测，并总结判据（我猜关键变量是"外显结构的出错代价 × 主任务的优化预算"）
5. <strong>双向一致性奖励</strong>：让文字流也去校准接地流（预期收益：框更准 + 内容读对）
6. <strong>把 judge 换成"模型自己二次前向"</strong>（学 SDPO 的做法）以省掉 4×A100，并对照成本与效果
7. 复核那两个"回退"是否真实：32B RealWorldQA −3.0 是评估噪声还是能力回退

## 八、结论

> 🎁 <strong>今日一句</strong>：<strong>这篇论文最值钱的不是方法，是那个反直觉的观察——让模型把"往哪儿看"写出来，反而会让它答得更好？不，是更差。因为写出来的坐标一旦错了，就会把后面的推理一起带进沟里；而定位能力其实早就隐含在文字推理里了。</strong>
>
> <strong>iVGR 的解法是「让它会写但不许写」：两条流一起训，用裁判打的一致性分把文字流拉向那条报了框的好轨迹。而全文最讽刺的一个数字是——它主打"双流"，但消融里"只训接地流"71.1 对"双流但没有一致性奖励"71.0，多出来的那条流本身几乎没贡献。</strong>

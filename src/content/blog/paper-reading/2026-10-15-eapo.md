## TL;DR

<strong>一句话：agent 在环境里"多探一探"直觉上应该有帮助，但论文实测发现——粗暴地鼓励探索，性能反而掉。原因是现有方法把「打探信息」和「做决定」纠缠在同一个策略里，agent 分不清哪里真需要探。EAPO 的做法是：把这两件事在输出格式上拆开（多出 &lt;explore&gt; 和 &lt;memory&gt; 两个字段），学一个奖励模型给"值得探的动作"单独发奖励，并在分组时把「探索动作」和「执行动作」分开算优势。</strong>

- <strong>最刺眼的一组数（Table 1，AndroidWorld 上"朴素加探索"的效果）</strong>：GRPO / DAPO / GiGPO / LAMER 四个方法 × 三个模型尺度 = <strong>12 个格子里 7 个下降</strong>；<strong>LAMER 三格全降</strong>（61.2→56.3、61.5→58.2、61.0→57.3）
- <strong>论文的诊断</strong>：现有 test-time scaling 方法<strong>把探索和动作选择纠缠在单一策略里</strong>，导致 agent 在"其实已经想清楚了"的状态下还在瞎探，<strong>积累低价值信息、反而把最关键信号淹没了</strong>。而人天然把"打探信息"和"最终决策"分开
- <strong>顺带对熵开了一炮</strong>：很多工作用熵当探索信号，论文指出<strong>「熵并不忠实反映信息增益」</strong>——高熵可能只是模型不确定，诱导出的却是无信息量甚至冗余的转移
- <strong>方法四件套</strong>：① <strong>结构化输出</strong>——在 &lt;think&gt;/&lt;action&gt; 之外新增 <strong>&lt;explore&gt;</strong>（候选动作/环境试探）和 <strong>&lt;memory&gt;</strong>（已访问状态的累积摘要）② <strong>贝叶斯探索奖励</strong>——用变分推断近似"给定当前状态、这套探索-记忆配置对任务成功的后验"，取 max{立即利用, γ²·前瞻探索}，防过度保守 ③ <strong>探索感知分组</strong>——按「环境状态 s + <strong>访问深度 κ</strong>」聚类，把探索动作和执行动作分开算优势 ④ <strong>两阶段训练</strong>——SFT 先学"回退"能力，再上 EAPO 版 GRPO
- <strong>主结果（Table 2）</strong>：ALFworld <strong>61.26 → 76.02</strong>（LAMER → EAPO-8B）、WebShop <strong>47.74 → 65.58</strong>、AndroidWorld <strong>61.76 → 82.05</strong>、OSWorld <strong>55.60 → 64.29</strong>（超 Claude-4-Sonnet 的 62.88）；<strong>2B 的 EAPO 在 AndroidWorld 就到 76.36，超过所有 baseline</strong>
- <strong>消融很硬（Table 8，2B）</strong>：去掉<strong>探索奖励</strong> ↓20.9\~26.6；去掉 <strong>exploration-aware grouping</strong> ↓<strong>11.2\~24.9</strong>；去掉格式奖励 ↓7.4\~18.3——<strong>三个组件都是承重的，分组这一项单独就值 11–25 分</strong>
- <strong>成本</strong>：约 <strong>+30%</strong> 训练开销；<strong>8×H800</strong>
- <strong>⚠️ 一个要指出的过度声明</strong>：论文说 EAPO「在所有 4 个环境上都持续超过 baseline」，但<strong>在最小尺度上不成立</strong>——2B 的 ALFworld 58.50 低于 LAMER 61.26，OSWorld 50.34 远低于 Claude-4-Sonnet 62.88（<strong>表格自己的 ↓ 箭头就标出来了</strong>）。到 4B/8B 才全面领先
- <strong>⚠️ 论文自述 1 条限制</strong>：依赖<strong>人工指定的结构化探索/记忆表示</strong>，可能限制探索策略的表达能力，不适应需要更灵活信息获取方式的任务（<strong>Limitations 只有一段</strong>）

## 一、先看例子（大白话：先打听，还是先下手？）

> 💡 <strong>铺垫</strong>：现在的 agent 会"在环境里多试几步"再决定——比如在手机 App 上先点开某个菜单看看里面有什么，再决定下一步怎么走。这被叫做 <strong>test-time scaling / 主动探索</strong>。
>
> <strong>直觉上这肯定有用。但论文说：粗暴地让它多试，反而更差。</strong>

> <strong>把这件事想成一个刚到新城市的人找一家店：</strong>
>
> <strong>低效的做法（现在的方法）</strong>：每条街都拐进去看一眼，怕漏掉什么。结果<strong>走了一小时，脑子里塞满"这条街有家便利店""那条街有个邮筒"</strong>——真正要紧的那家店在哪，反而被淹没了。
>
> <strong>有效的做法（人本来就会的）</strong>：先想"我到底缺什么信息"——缺的是"这家店在哪条街"。那就<strong>只去问人、只找路牌</strong>，其余的不用看。<strong>拿到答案就走，不再多逛。</strong>
>
> <strong>EAPO 想让 agent 学会第二种。</strong>

<strong>论文用一组数据证明"第一种真的更差"（Table 1，AndroidWorld）：</strong>

| 方法 | Qwen-VL-2B | Qwen-VL-4B | Qwen-VL-8B |
|-|-|-|-|
| GRPO | 52.3 → 55.1 | 56.1 → 58.4 | 55.4 → <strong>52.9 ↓</strong> |
| DAPO | 56.8 → <strong>54.6 ↓</strong> | 60.6 → <strong>58.5 ↓</strong> | 61.7 → 63.1 |
| GiGPO | 56.0 → <strong>53.1 ↓</strong> | 59.7 → 61.8 | 58.8 → <strong>56.7 ↓</strong> |
| LAMER | 61.2 → <strong>56.3 ↓</strong> | 61.5 → <strong>58.2 ↓</strong> | 61.0 → <strong>57.3 ↓</strong> |

<strong>12 个格子里 7 个下降，LAMER 更是三格全降。</strong>——"让它多探索"这个直觉，在实测里是<strong>净负的</strong>。

## 二、动机：探索和执行被纠缠在同一套参数里

- <strong>论文的诊断</strong>：现有 test-time scaling 方法<strong>把"探索"和"动作选择"混在同一个策略里</strong>，导致 agent 无法识别哪里真需要探索，<strong>在已经理解清楚的状态下也会无差别地探索</strong>。这种保守策略让 agent 积累低价值信息，<strong>反而把最关键的信息信号淹没了</strong>
- <strong>人的对照</strong>：人天然会<strong>把"打探信息"和"最终决策"分开</strong>——先判断环境的哪部分不确定，再有选择地去探、把这些不确定解决掉。当 agent 遇到<strong>偏离训练分布的不熟悉状态</strong>时，这种分离尤其有价值
- <strong>为什么"直接提示它多试"不行</strong>：论文试过——让 agent 在遇到陌生状态时不断尝试替代动作直到信息足够。结果是它<strong>既没有能力找到有价值的动作，也没有能力把探到的信息用起来</strong>
- <strong>🔑 顺带批评了一条热门路线：用熵当探索信号不够</strong>。论文原话的意思是：<strong>熵并不忠实反映信息增益</strong>——高熵可能只说明模型自己不确定，随之而来的是<strong>无信息量或冗余的转移</strong>，产生不了有意义的探索
- <strong>于是问题变成三个</strong>：① 怎么让"探索"成为推理过程里一个显式的环节？② 怎么<strong>量化一个探索动作到底有多少用</strong>？③ 怎么在优化时不让探索动作被系统性低估？

## 三、方法：拆格式、发奖励、改分组、先学会退

<strong>EAPO 由四块组成，前两块解决"怎么表示与怎么打分"，后两块解决"怎么训才不偏"。</strong>

### 3.1 拆格式：给探索和记忆各开一个字段

![论文 Figure 5：系统提示模板。在原有的 <think> 与 <action> 之外，新增 <explore>（要探什么、可以试哪些候选动作）和 <memory>（把已访问过的页面/状态整理成累积摘要）两个字段](/images/paper-reading/2026-10-15-eapo/2026-10-15-d57-1.webp)

- 每步的输入变成 <strong>s̃ = \[任务 g; 当前状态 s; 上一步的探索 e\_{t−1}; 累积记忆 m\_{t−1}\]</strong>；输出变成 <strong>ã = \[探索 e; 记忆 m; 动作 a\]</strong>
- <strong>&lt;explore&gt;</strong>：写下"我还缺什么信息 + 为此准备试哪些候选动作"——<strong>把试探变成推理过程的一部分</strong>
- <strong>&lt;memory&gt;</strong>：把访问过的状态与拿到的信息整理成结构化摘要，<strong>当成一个可以跨多步引用的外置工作记忆</strong>
- <strong>论文特别强调（Remark 4.1）</strong>：<strong>这个格式只约束"放哪"，不约束"写什么"</strong>。它的价值在于让 agent 显式区分<strong>决策 / 信息获取 / 状态总结</strong>三件事，并且——<strong>格式让"探索类奖励"有了可靠的落点</strong>（否则在非结构化输出里根本没法把奖励归到某一步的探索上）

### 3.2 发奖励：用变分推断给"值得探的动作"定价

核心难题：<strong>怎么量化一个探索动作的效用？</strong>直接跑 online rollout 拿经验回报有个两难——<strong>采样少了方差大（策略随机性），采样多了算力和交互成本爆炸</strong>。

论文的切入点是贝叶斯视角：定义后验 <strong>p(e\_{t−1}, m\_{t−1} | s\_t, success)</strong>——<strong>"在当前状态 s\_t 下，这套探索-记忆配置能带来任务成功的概率"</strong>。概率越高，说明这套探索-记忆能提供足够的信息增益去解决当前的不确定性。据此定义：

> <strong>R\_explore = max{ q\_φ(e\_{t−1}, m\_{t−1} | s\_t) , γ² · q\_φ(e\_{t−1}, \[m\_{t−1}, s\_{t+1}\] | s\_t) }</strong>

- <strong>第一项 = 立即利用</strong>：用现有记忆就够解决问题时的效用
- <strong>第二项 = 主动探索</strong>：把新观测到的状态 s\_{t+1} 拼进记忆后的效用
- <strong>max 的作用</strong>：<strong>既给"该探"的动作正信号（第二项赢），也给"已经够了、别探了"的动作正信号（第一项赢）</strong>——这就同时治了"不肯探"和"过度探"两种病
- <strong>γ² 折扣很关键（Remark 4.3）</strong>：探索的收益不是立即的（至少要一步看到新状态、再一步才能用上信息）。<strong>加 γ² 惩罚，逼 agent 只在"预期收益大于延迟成本"时才探</strong>——防止"为了更全面的记忆而多探"这种纯浪费
- <strong>怎么求 q\_φ</strong>：真后验不可解，用一个可学的变分代理 q\_φ(e, m | s) 去逼近，最小化 KL(q ‖ p(·|·,success))；用变分推断推出代理目标 <strong>max β·E\[Q(s,e,m)\] − KL(q(·|s) ‖ p(·|s))</strong>，再用 REINFORCE 优化。<strong>它被当作一个"策略"来训（选最优的探索-记忆配置），KL 项当约束防止塌缩</strong>
- <strong>两个大好处</strong>：① 因为是"对记忆建分布"而不是逐动作估回报，<strong>对策略随机性稳健</strong> ② <strong>把奖励估计从环境交互里解耦出来</strong>——不需要昂贵的 online rollout，可扩展到大任务
- <strong>论文还给了一个理论说法（Remark 4.4）</strong>：把记忆与探索当作推理过程的隐变量，则该目标对应<strong>成功率对数似然的下界</strong>，所以最大化它就是在最大化任务成功率
- <strong>总奖励</strong>：R = R\_task（episodic 成败 0/1）+ α₁·R\_format（是否严格遵循结构化模板）+ α₂·R\_explore

### 3.3 改分组：探索动作必须和执行动作分开算优势 ⭐

- <strong>问题一：agent 缺"回退"能力</strong>。如果一步走岔了，它不会像人一样点"返回"按钮退回上一步。于是<strong>探索动作的奖励和它不可逆的下游后果纠缠在一起，好处被系统性低估</strong>
- <strong>问题二（更本质）：GRPO 里探索动作和执行动作混在同一个组里</strong>。论文原话：这<strong>模糊了"收集信息"与"执行目标"两类行为的区别，使相对优势估计被误导</strong>——<strong>即使探索对长期成功是必要的</strong>
- <strong>做法</strong>：GRPO 通常按"同一个状态"分组。EAPO 说光按状态还不够，引入 <strong>访问深度 κ</strong>：

> <strong>κ(s\_t) = Σ\_{k&lt;t} I\[ s\_k = s\_t \]</strong>（同一个环境状态到目前为止被访问过几次）<br><strong>分组：G(s, ν) = { 转移样本 | 环境状态 = s 且 访问深度 = ν }</strong>

- <strong>为什么要带访问深度（Remark 5.1）</strong>：<strong>探索动作的回报天然低于"探完之后真正执行的那个动作"</strong>（因为有折扣）。如果不分阶段直接同组比较，<strong>就会系统性低估探索的价值</strong>——论文实测这会让探索度显著崩塌。把访问深度编进分组键后，<strong>动作只和"信息阶段相近"的动作比</strong>，探索的贡献才被公平评价
- <strong>优势计算</strong>：在 G(s, κ) 组内做标准化，得 <strong>Ã = (R − mean(R)) / std(R)</strong>

### 3.4 先学会退：两阶段训练

- <strong>阶段一（SFT 学回退）</strong>：让一个 teacher LLM 看「当前状态 s′ + 上一个状态 s」生成回退动作 a，<strong>只有真能恢复到原状态的三元组 (s′, s, a) 才收进数据集 D</strong>；然后用带"回退指令"的 prompt 做标准 SFT。 <br>——<strong>目的：让探索从"一次性的高风险行为"变成"可逆的行为"</strong>
- <strong>阶段二（EAPO 版 GRPO）</strong>：在 3.2 的奖励下、按 3.3 的分组方式做策略优化
- <strong>论文自己澄清（附录 D.7.6）</strong>：去掉 SFT 会明显掉分，<strong>但这不是说 SFT 贡献了最终性能，而是它作为一个"使能组件"</strong>——探索的准确性和回退能力本来就是耦合的：<strong>就算学会了有效探索，没有回退能力，探到的信息也没法被正确利用</strong>。这句澄清挺诚实

## 五、Limitations

### 论文自述（只有一段）

- <strong>依赖人工指定的结构化探索与记忆表示</strong>。这些表示在整个训练过程中是手工写死的，<strong>可能限制探索策略的表达能力</strong>，也让它在需要更灵活信息获取方式的任务上适应性不足

### 我读出的 7 条

1. <strong>「在所有 4 个环境上都持续领先」是过度声明</strong>：最小尺度（1.7B/2B）在 ALFWorld 和 OSWorld 上都低于最佳基线（↓2.76 / ↓12.54）。<strong>表格是诚实的（箭头标了），正文的措辞不诚实</strong>
2. <strong>奖励代理 q\_φ 的可 hack 性完全没分析</strong>：R\_explore 是一个<strong>学出来的代理</strong>，不是真值。论文既没做 reward hacking 分析（agent 会不会学会"写出让 q\_φ 高分但实际没用的探索-记忆"），也没给 q\_φ 单独的训练成本。<strong>这是全文最大的未验证点</strong>
3. <strong>「访问深度 κ」依赖环境状态可判定</strong>：文本环境（ALFWorld/WebShop）里"同一状态"好定义，<strong>GUI 环境里什么叫"同一个页面状态"论文没说清</strong>——是截图哈希？DOM 树？还是别的？这直接影响分组键能否成立
4. <strong>「探索度」这个核心指标的定义没写清</strong>：Figure 3 的纵轴是 Exploration Degree，但正文与附录都没给公式。<strong>而"探索度更高"是论文用来论证"学会探索"的主要证据</strong>
5. <strong>+30% 开销没有绝对口径</strong>：只给了相对数，没给墙钟时间、GPU 小时或与 baseline 的等算力对照
6. <strong>缺同期工作的对照</strong>：同一批 ICML 2026 里就有 <strong>T²PO</strong>（同题：把 agentic RL 的不稳定归因于"低信息量动作"）与 <strong>ARLArena/SAMPO</strong>（系统研究 agentic RL 稳定性），<strong>都用 ALFWorld/WebShop 当环境，却一个都没比</strong>
7. <strong>SFT 阶段的数据规模、teacher LLM 是谁、D 有多大都没说</strong>——而论文自己承认去掉 SFT 会明显掉分，说明它是承重环节

## 六、前文对照

> 🔗 <strong>一句话定位</strong>：EAPO 是 lib 里「agentic RL 信用分配」这条线的<strong>第二篇</strong>（前一篇是 10/6 的 GraphGPO），而且两条线的轴<strong>完全正交、可叠加</strong>。它同时也是「把纠缠的两件事拆开」这个思路在 lib 里的<strong>第三次出现</strong>。

### 6.1 与 GraphGPO（10/6）—— 同题、正交的两把刀 ⭐

|   | GraphGPO（10/6） | EAPO（本篇） |
|-|-|-|
| <strong>诊断</strong> | 轨迹级信用分配太粗：失败的轨迹里也可能有好的步 | 分组太粗：<strong>探索动作和执行动作混在一组比</strong>，探索被系统性低估 |
| <strong>改哪里</strong> | 改<strong>优势从哪算</strong>——把所有轨迹拼成图，用图上最短路径距离算边优势 | 改<strong>怎么分组</strong>——按「状态 + 访问深度」聚类，让探索只和探索比 |
| <strong>相互正交</strong> | 改的是分子（优势的来源） | 改的是分母的参照系（和谁比） |

<strong>两篇可以合起来用</strong>：EAPO 的分组给出"该和谁比"，GraphGPO 的图距离给出"比的时候用哪个优势"——<strong>理论上可以直接叠加，这是一个现成的实验</strong>。

### 6.2 与 GiGPO —— 直接修正

GiGPO 的核心是"把不同轨迹里<strong>相同状态</strong>的步聚成一个组再标准化"。<strong>EAPO 说光按状态还不够</strong>：同一个状态下，<strong>"第 1 次到这里"和"第 5 次回到这里"的回报结构完全不同</strong>（后者多半是探索走了回头路，回报天然被折扣压低）。<strong>必须把访问深度也编进分组键</strong>，否则探索动作会被系统性低估——消融显示这一条值 11–25 分。<strong>这是对 GiGPO 分组方式的直接升级。</strong>

### 6.3 「把纠缠的两件事拆开」在 lib 里的第三次出现

| 工作 | 被拆开的两件事 | 怎么拆 |
|-|-|-|
| <strong>SDPO（9/30）</strong> | "第一次答"与"看过反馈后重答" | 同一个模型分饰两角，用概率差当优势 |
| <strong>π-Distill（10/13）</strong> | "开卷（有特权信息）"与"闭卷" | 共享参数 + KL 双向拉 |
| <strong>EAPO（本篇）</strong> | "打探信息"与"执行决策" | 输出格式拆字段 + 独立的探索奖励 + 分开分组 |

<strong>三篇的共同母题</strong>：<strong>当一个策略同时承担两种性质不同的职责时，把它显式拆开、分别给信号，比让它们混在一起学更有效。</strong>——<strong>这正在变成一条方法论，值得记下来</strong>。

### 6.4 与其他相邻工作

- <strong>与 ACTIVE-O3（8/27）</strong>：ACTIVE-O3 训的是"<strong>主动放大看</strong>"（视觉上选区域）；<strong>EAPO 训的是"主动去环境里探"（交互上做试探）</strong>——都是"主动获取信息"，一个在感知层、一个在行动层
- <strong>与 AutoTool（8/28）</strong>：AutoTool 教 agent"<strong>怎么选工具</strong>"；EAPO 教 agent"<strong>什么时候该去打听</strong>"——前者是选择能力，后者是时机判断
- <strong>与 T²PO（同期 ICML 2026 Spotlight，未读）</strong>：<strong>同题对手</strong>。T²PO 也认为 agentic RL 的不稳定来自"策略持续生成既不减不确定性也不推进任务的低信息量动作"，但它的药是：<strong>token 级监控不确定性动态、触发"思考干预"；turn 级识别无探索进展的交互并动态重采样</strong>。而 EAPO 的药是<strong>学一个奖励 + 改分组</strong>。<strong>同诊断、不同药，值得连起来读</strong>
- <strong>lib 的「记忆形态」谱系新增最轻一档</strong>：<strong>&lt;memory&gt; 是 agent 自己手写的外部化文字工作记忆</strong>——比 Forget-Me-Not（9/29）的轨迹回放缓冲还要轻。目前已集齐：JitRL 外挂经验库 / PERSIST 3D 状态 / Forget-Me-Not 回放缓冲 / WorldPlay 重构上下文 / SOMA 物体级空间记忆 / iVGR Rollout Archive / <strong>EAPO 自写文字记忆</strong>
- <strong>分锅家族新增一轴</strong>：现有各轴（BSBT 模态 / PCD 因果阶段 / GiGPO 时间步 / GraphGPO 状态-动作边 / POLIA 视觉物体 / π-Distill 教师-学生角色 / iVGR 跨数据流对齐）之外，<strong>EAPO 新增「动作类型 × 访问深度」</strong>——锅不在某个 token 或某个物体，而在"<strong>这一步是探索还是执行</strong>"

## 七、启发与待跟进

### 启发

1. <strong>「不该一视同仁地探索」是一个可以搬走的诊断。</strong>论文的原始观察是：让 agent 多探反而掉分。把它抽象一下就是——<strong>当同一个策略里混着两种回报结构不同的动作时，任何"统一"的优势估计都会系统性地亏待其中一种</strong>。EAPO 用"访问深度"识别出了这种差异。<strong>这个诊断比它的具体配方更值钱</strong>
2. <strong>"访问深度"当分组键是极便宜的修正。</strong>GiGPO 之后所有人都在按状态分组，EAPO 只加了一个"同状态访问了几次"就把探索动作的估值救回来（+11\~25 分）。<strong>改动量约等于零，收益巨大——这类"改分组键"的工作值得专门去找</strong>
3. <strong>"学一个奖励给探索定价"是把不可微信号变可用的通用手法</strong>，但代价是引入了可被 hack 的代理。<strong>论文恰好没做 hacking 分析</strong>——这正是复现时第一个该验证的东西
4. <strong>熵 ≠ 信息增益</strong>。这个批评值得单独记：一大批 agentic RL 工作在用熵当探索信号，EAPO 指出高熵可能只代表「模型不确定」，并不必然带来有用信息。以后看到"用熵引导探索"要先问一句：<strong>熵高真的等于信息多吗？</strong>
5. <strong>「使能组件」和「性能来源」要分清。</strong>论文主动澄清 SFT 回退的作用是"使能"而非"贡献"——<strong>这种自我澄清在 agentic RL 论文里很少见，值得学</strong>。它对应一个更一般的检查：<strong>消融掉某个组件时掉分，不代表这个组件是性能来源——可能只是别的组件离开了它就转不动</strong>

### 待跟进（按性价比）

1. 【最贴合主线】<strong>把 EAPO 的「访问深度分组」和 GraphGPO 的「图距离优势」合起来</strong>——一个改"和谁比"、一个改"比什么"，理论上正交可叠加，且两篇代码都开源。这是<strong>成本最低、故事最完整</strong>的一个实验
2. <strong>复现 Table 1「朴素加探索会掉分」</strong>（12 格里 7 格下降）。这是个很反直觉的起点，<strong>而且它是全文动机的地基</strong>——如果复现不出来，整篇的立论要重估
3. <strong>做奖励代理 q\_φ 的 reward hacking 分析</strong>：构造"写得很像探索但实际无效"的 &lt;explore&gt;/&lt;memory&gt; 文本，看 q\_φ 会不会给高分、策略会不会学它
4. <strong>把「访问深度」搬进多模态 agentic</strong>：GUI 里"同一个状态"怎么判定？（截图哈希？可访问性树？）<strong>这是复现的第一道坎</strong>
5. <strong>与 T²PO 做正面对照</strong>：同诊断、不同药（T²PO 是启发式触发 + 重采样，EAPO 是学奖励 + 改分组），<strong>在同样的 ALFWorld/WebShop 上比一比，能直接回答"要不要学一个奖励模型"</strong>
6. <strong>补算力口径</strong>：+30% 到底是什么的 30%（墙钟？FLOPs？），以及和 baseline 的等算力对照
7. <strong>把「探索度」的定义找出来</strong>（或向作者要）——它是核心论证指标却没有公式
8. 反向验证：如果<strong>不拆格式</strong>、只在 prompt 里口头要求"必要时才探索"，会不会也能拿到一部分收益？（这能分离"格式拆字段"和"奖励+分组"各自的贡献）

## 八、结论

> 🎁 <strong>今日一句</strong>：<strong>「让他多探探」听起来是好事，实测 12 个格子里有 7 个反而掉分——因为探索和执行被纠缠在同一套参数里，agent 分不清哪儿该探。EAPO 就做三件事：输出里多开 &lt;explore&gt; 和 &lt;memory&gt; 两个字段把两件事在形式上拆开、用一个变分推断学出的奖励给"值得探的动作"单独定价、分组时按「状态 + 访问深度」把探索动作和执行动作分开算优势。</strong>
>
> <strong>数据上它站得住</strong>：8B 相对最强训练基线在三个环境上净涨 8.7–14.8 分，2B 就在 AndroidWorld 打赢 72B 模型，消融里三个组件全部承重（分组单独值 11–25 分）。<strong>但它自己的表格也说了实话</strong>——最小尺度上 ALFWorld 与 OSWorld 都低于最佳基线，正文那句"在所有环境上持续领先"是打了折的。
>
> <strong>最值得带走的一条</strong>：<strong>和大上周读的 GraphGPO 恰好构成 agentic RL 信用分配的两把正交的刀——一个改"优势从哪算"，一个改"和谁比"。</strong>而"把纠缠的两件事拆开"这个母题，在 lib 里已经是第三次出现（SDPO 拆开卷/闭卷 · π-Distill 拆有/无特权信息 · EAPO 拆探索/执行）。

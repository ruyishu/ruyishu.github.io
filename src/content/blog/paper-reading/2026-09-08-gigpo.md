## TL;DR

**一句话：GRPO 在多轮 agent 训练上失效——它把整条轨迹当成一个整体算 advantage，无法告诉模型"到底哪一步走错了"；GiGPO 造了个"组中组"：除了把完整轨迹分成一组算"整局分"（macro），还回溯找出不同轨迹里**到达过相同环境状态**的那些步，把"从同一个状态出发的不同动作"聚成 step 级小组，在组内算"这一步分"（micro）——两级 advantage 叠加，零额外 rollout、零 critic、显存时间几乎不变，ALFWorld +13.3%、WebShop +10.6%、搜索 QA 7B 平均 47.2%。**

- **核心问题**：group-based RL（GRPO/RLOO）在单轮数学任务封神，但 agent 是多步、长程、稀疏延迟奖励——一条轨迹几十步几千 token，错了不知道怪哪一步；GRPO 的"轨迹级单一 advantage"给不出单步反馈
- **方法（两级组内 advantage）**：① **Episode 级（macro）**：N 条完整轨迹一组，GRPO 式组内归一化（≈轨迹总质量）；② **Step 级（micro）**：**anchor state grouping**——跨轨迹找"相同环境状态 s̃"（hashmap 离线聚合，**零额外 rollout**），从同一状态出发的不同动作 + 折扣回报聚成 step 组，组内归一化得单步相对 advantage；两级相加（ω=1）
- **结果**：ALFWorld 1.5B 72.8→86.1（+13.3）/ 7B 77.6→90.8（+13.2，超 PPO 80.4）；WebShop 1.5B 56.8→67.4（+10.6）；搜索 QA（NQ+HotpotQA 训、7 榜含 OOD）：3B 42.1%（vs ZeroSearch 31.7）/ 7B 47.2%（vs 39.1）；同 GRPO 显存/rollout、时间开销 <0.002%
- **主题轮换**：今日**推理 / agentic / 多 Agent**（按序列从多模态 RL（9/7 CFPO）切出；与 BSBT/PCD 的"分锅"主线一脉相承——这次分的是"时间的锅"）

## 一、先看例子（大白话：agent 训练为什么"怪不到具体哪一步"）

> **铺垫**：LLM agent = 模型在环境里多轮行动（在模拟家里找东西、在购物网站上买东西、搜索多跳答题）。训练它 = RL。GRPO 这类方法在"一道数学题一次答完"上很强，但 agent 是"一串动作做完一个任务"——问题就出在这。

> **场景**（论文 Figure 3 的 WebShop 例子）：模型在购物网站买目标商品。

> **GRPO 怎么看**：τ1 成功（+1）、τ2 失败（0），组内一归一化，τ1 整条轨迹得正 advantage、τ2 整条得负。**但 τ1 里"先点错第 2 个"这个动作也被一起表扬了**——GRPO 分不清"成功轨迹里哪个动作是功臣、哪个是拖油瓶"。

> **GiGPO 怎么看**：两条轨迹**都到达过同一个页面状态**（搜索结果页）。把"在这个页面上做的不同动作"聚成一组：点第 1 个（→成功，高折扣回报）、点第 2 个（→绕路，中）、点下一页（→失败，低）——组内一归一化，得到**单步排序：点第 1 个 > 点第 2 个 > 点下一页**。这就是"每一步该得多少功/过"的细粒度反馈。

## 二、动机：agent 训练缺"单步分锅"

### 2.1 GRPO 的封神与失灵

- GRPO/RLOO 单轮封神（数学）：同一题采 N 条完整答案 → 组内归一化 → 整条轨迹一个 advantage
- 但 agent 任务：一条轨迹可长达 **50 步、2 万+ token**（ALFWorld）——环境只在终点给成败（稀疏），甚至奖励延迟
- **整条轨迹一个 advantage 的问题**：给不了单步反馈。成功轨迹里可能有错误动作（绕路），失败轨迹里可能有正确动作（走到一半环境抽风）——GRPO 全按轨迹终局一锅端

### 2.2 天然解法不可行

- 想给单步反馈，最直接：**每个状态都额外 rollout 多个动作**（Figure 1 中间）→ 每步都要多次 LLM 前向 + 还要评估"没真执行的动作"的奖励——**成本爆炸**

### 2.3 核心洞察

- 既然同任务、同初始状态 rollout 了 N 条轨迹，**很多环境状态会自然重复出现**（跨轨迹、甚至同轨迹内多次）——把这些"相同状态"当免费锚点，零成本重构出 step 级小组
- 核心问题：*能否在零额外 rollout 的前提下，把"整局分"拆成"每步分"？*

> **炸裂点**：不要额外 rollout、不要 critic、不要改变采样——**只是把已有的 N 条轨迹拿 hashmap 离线按"状态"重新分组**，就从"每轨迹一个 advantage"免费升级成"每步一个 advantage"。数据没用完就扔？GiGPO 说：轨迹之间重复的状态，就是免费的 step 级对照组。

## 三、方法：组中组（Group-in-Group）

### 3.1 两级组结构

- 对任务 x 采 N 条完整轨迹 {τ1…τN}（同初始状态）
- **Episode 级组 G_E**：N 条轨迹按整局回报 R(τi) 归一化 → **macro advantage A_E**（≈GRPO 原样，管"整局质量"）
- **Step 级组 G_S(s̃)**：把"状态相同"的步聚一起 → **micro advantage A_S**（管"这一步好不好"）
- 总信号：`A_GiGPO = A_E + ω·A_S`（ω=1，无需调）

### 3.2 Anchor State Grouping（零成本的免费小组）

- U = 轨迹组里出现的**所有不同环境状态**；每个唯一状态 s̃ 是一个 anchor
- `G_S(s̃) = {(a_t^(i), R_t^(i)) | s_t^(i) = s̃}`——把所有轨迹里"从这个状态出发的动作"聚成组
- 实现：**纯离线 hashmap 按键分组，无一次额外 LLM 前向**

> **论文原句（Sec 4.2）**："Unlike per-state rollout, this procedure incurs no extra rollouts: it is entirely offline and requires only lightweight key-based grouping using hashmaps. Each group G_S(s̃) contains multiple instances of the same environment state paired with potentially different actions."——零额外 rollout 的实现，本质是把"同状态-不同动作"当免费对照组

- 注意用**折扣回报** R_t = Σ\_{k≥t} γ^(k-t)·r_k（不是即时奖励——稀疏环境下即时奖励全是 0，折扣回报才能体现"这一步对未来的影响"）

### 3.3 归一化两种口味（F_norm）

- **w/ std**：组内 (R − mean)/std（同 GRPO 风格）——适合简单任务
- **w/o std**：F_norm=1，即 **leave-one-out 无偏估计**——难任务上 std 缩放会放大困难步的梯度，去掉更稳（消融：Look/Pick2/WebShop 上 w/o std 更好）

### 3.4 与逐状态 rollout 的边界

- 有相似但非相同状态的任务（QA 检索上下文文本化）→ 用**相似度分组**（最长公共子序列 > 0.9 即视为同组）替代精确匹配

> **三个观察**：① **anchor 状态是天然免费的**——只要同任务采 N 条，状态重复概率极高（WebShop 里"搜索结果页"每条轨迹都路过）；② **折扣回报把稀疏奖励"抹匀"到每一步**——单步分 = 从这一步往后的期望回报，比即时奖励可训得多；③ **A_E + A_S 互补**——A_E 稳（整局对错很明确）、A_S 细（单步优劣），缺一不可（消融证明）。

## 四、实验

### 4.1 ALFWorld + WebShop（Table 1，3 seeds 平均）

| 方法（Qwen2.5-7B） | ALFWorld All ↑ | WebShop Score ↑ | 备注 |
|-|-|-|-|
| GPT-4o / Gemini-2.5-Pro（闭源 prompting） | 48.0 / 60.3 | 23.7 / 35.9 | 闭源提示词也能赢开源 baseline |
| PPO（带 critic） | 80.4±2.7 | 68.7±5.1 | 要训价值网络、调参重 |

- **1.5B 也显著**：ALFWorld GRPO 72.8 → GiGPO(w/o std) 86.1（+13.3）、WebShop 56.8 → 67.4（+10.6）——小模型更受益于细粒度信号
- 单任务细节：7B 的 Pick 94.4→97.7、Look 66.1→82.7（w/ std）等，难任务全涨

### 4.2 搜索增强 QA（Table 2，NQ+HotpotQA 训练，7 榜含 4 个 OOD）

- Qwen2.5-3B：**42.1%** avg（vs R1-Instruct 27.1 / Search-R1 32.5 / ZeroSearch 31.7）

- 用相似度 anchor 分组（LCS>0.9）+ E5 retriever、N=5 × max 4 turns

- 两级都全 → 最好；**F_norm 任务相关**：简单任务 w/ std、难任务 w/o std

### 4.4 成本（卖点）

- 与 GRPO **同显存、同 rollout、时间开销 <0.002%**——anchor 分组是离线 hashmap，几乎零成本（对比"逐状态 rollout"方案的不可承受成本）

## 五、Limitations & 批判性思考（论文有独立小节 + 我的阅读）

1. **论文自述（核心限制）**：依赖**状态匹配**构建 anchor 组——复杂环境下"相同状态"难检测（噪声/细微差异）；极端情况**无状态重复时 A_S=0，自然退化成 GRPO**（下限有保底）
2. **相似度分组是补丁**：QA 用的 LCS>0.9 启发式，文本状态近似匹配的语义误判率未量化；论文自指 embedding/结构等价是未来方向
3. **状态可观察假设**：GiGPO 的 anchor 靠"可识别状态"——部分可观测（POMDP）或状态被压缩进历史记忆的 agent（浏览器截图、长对话）里，"相同状态"定义本身存疑
4. **折扣回报 γ 的选择**：论文主实验没细报 γ 敏感性——长程任务 γ 太近 1 会让单步分≈整局分（退化）、太近 0 又只看即时奖励，边界没扫
5. **只测了文本状态环境**：ALFWorld/WebShop/QA 都是文本/结构化状态；视觉 agent（截图型）没验证
6. **multi-agent 未覆盖**：题目"LLM Agent Training"但实验全单 agent——多 agent 协作场景的信用分配（谁贡献大）未涉及（用户若想延伸注意这点）

## 七、启发与待跟进

> **核心启发**：
> 1. **"免费的对照组"藏在数据冗余里**：同任务 N 条轨迹间的重复状态 = 天然的 step 级对照实验，不需要多花一分采样——"先问数据里已有什么，再决定要不要补采样"是个普适效率原则
> 2. **分锅的粒度要和任务的时间尺度匹配**：单轮任务轨迹级够用，多轮 agent 必须 step 级——**信号的粒度分辨率要跟上决策的粒度**
> 3. **两级信号的互补性**：粗信号（A_E）给稳定性、细信号（A_S）给精度——删任何一级都掉，粗中有细才稳准兼得（和 GNDPO 尺度 + VGS 方向的"叠加哲学"同构）

### 待跟进 checklist

- [ ] **GiGPO × OPD（多轮蒸馏）**：student agent 的 OPD 也用 anchor-state 分组路由教师信号——"相同状态下的不同动作，教师偏好哪个"就是免费的 step 级蒸馏权重

- [ ] **状态匹配升级**：embedding 语义匹配替代 LCS>0.9（论文自指的坑）——多模态/截图状态怎么定义"相同"

- [ ] **γ 敏感性 + 部分可观测**：POMDP/记忆压缩场景 anchor 可行性（浏览器截图 agent）

- [ ] **扩展到 multi-agent**：论文没做多 agent——"谁贡献大"的信用分配（CCPO/C³ 那类反事实法）和 GiGPO 的 step 分锅能否合成"agent 维度 × 时间维度"的二维分锅

- [ ] **消融补全**：ω 权重没扫（固定 1）——A_E:A_S 的比例是否任务相关

## 八、今日阅读结论

GiGPO 是"agent 长程 RL 的细粒度分锅"（NeurIPS 2025，南洋理工 Bo An 组）：诊断出 GRPO 在 agent 任务上的死穴——整条轨迹一个 advantage，给不了单步反馈；然后掏出一个近乎免费的解法：**同任务 N 条轨迹间的重复状态就是天然的 step 级对照组**，hashmap 离线一聚，就从"每轨迹一分"免费升级到"每步一分"（macro 保稳定 + micro 保精细，ω=1 直接相加）。结果 ALFWorld +13.3%、WebShop +10.6%、搜索 QA 7B 47.2% 全面超 PPO/GRPO，成本 <0.002% 时间、零额外 rollout。和你 lib 的分锅谱系一脉相承：BSBT 分模态的锅、PCD 分因果阶段的锅、**GiGPO 分时间的锅**——同一"监督信号精细化"哲学在不同轴上的投影，也是 RL-Cap 那张"细粒度过程信号"药方在 agent 任务线的落地。对 OPD 主线的直接钩子：**anchor-state 分组可以搬进多轮蒸馏做 step 级路由**，这是现成选题。

> **今日一句**：GRPO 只会给整条轨迹打分，agent 错了不知道怪哪一步——GiGPO 发现同任务的多条轨迹里藏着免费的"相同状态"，把它们聚成 step 小组一归一化，每一步的功过就出来了，一分钱采样没多花。论文：arXiv:2505.10978（NeurIPS 2025）· 笔记挂在 lib 中 · 2026-09-08

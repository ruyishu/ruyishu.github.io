## TL;DR

<strong>一句话：想把 72B 大模型的 agent 本事教给 7B 小模型，传统做法是让老师把整条解题轨迹演一遍、学生照抄，但小模型一抄就容易在某一步走歪、后面越错越远。这篇反过来：让学生自己先做，老师看完整条轨迹，只把「第一个错的那一步」改掉，学生从改好的那一步继续自己走完；走通了才留下当训练数据。之后做 RL 时，也只从「第一个错步之前」开始滚，并且多给「复现了老师那一步」一点奖励。</strong>

- <strong>方法名 SCoRe</strong>（Student-Centered one-step Reinforcement）：三段流水线 = 少量老师轨迹冷启动 SFT → 「学生做、老师改第一个错步」造数据再 SFT → 从错步前缀出发的短程 GRPO。老师是 Qwen2.5-72B-Instruct
- <strong>主结果（Qwen2.5-7B-Instruct，8 个数学和多跳问答榜的平均）</strong>：照抄老师轨迹的 BC <strong>43.0</strong>，BC 之后接普通 GRPO <strong>48.2</strong>，接 ARPO <strong>49.2</strong>，SCoRe 只做 SFT 阶段 <strong>46.1</strong>，SCoRe 做完 RL <strong>52.3</strong>。对照：72B 老师靠提示词用工具 <strong>51.1</strong>，DeepSeek-V3（671B）<strong>54.0</strong>
- <strong>深度搜索（Qwen3-8B 非思考模式，GAIA / HLE / xBench / WebWalker 平均）</strong>：BC <strong>22.8</strong>，BC+GRPO <strong>22.2</strong>（反而略低），BC+ARPO <strong>25.8</strong>，SCoRe-RL <strong>30.5</strong>；72B 提示 <strong>27.3</strong>，V3 <strong>32.4</strong>
- <strong>消融</strong>：去掉「从错步前缀开始」的短程 rollout，平均 <strong>52.3 → 48.4</strong>；去掉「复现老师那一步」的奖励，<strong>52.3 → 49.7</strong>
- <strong>⚠️ 先说几个坑</strong>：① 数学和深搜的打分裁判是 Qwen2.5-72B-Instruct，<strong>和老师是同一个模型</strong>；② AIME 每榜只有 30 题，论文自己的两张表里同一类模型在 AIME25 上能差 8.6 分（见第五节）；③ 它不是 token 级 OPD，老师只在「第一个错步」出手一次；④ 仓库：<strong>5 star、没有 license、没放权重</strong>，最后推送在 2026-01-29，比 camera-ready（2026-07-23）早半年

## 一、先看例子（大白话：同一道题，「老师演一遍」vs「老师只改一步」）

> 🧮 <strong>题目（论文附录 Table 9，数学）</strong>：BA = AD = DC，D 在线段 BC 上，∠ACD = 22.5°，求 ∠ABC。答案 45°。

<strong>传统做法（老师演、学生抄）</strong>：72B 老师把「想 → 写代码 → 看输出」整条演完，7B 学生照着学。问题是学生的水平和老师差一截，哪怕学得很像，推理时只要某一步走歪，后面就在一个老师从没演示过的局面里瞎走，错误越滚越大。

<strong>SCoRe 的做法</strong>：

1. <strong>学生先自己做</strong>。第 1 步它写了：AD = DC 所以三角形 ADC 是等腰，然后算 <strong>∠CAD = 180 − 2×22.5 = 135</strong>，输出 135.0。这一步错了（等腰三角形里 AD = DC，相等的两个角是 ∠CAD 和 ∠ACD，应该直接是 22.5°）
2. <strong>老师看完整条轨迹，只改这一步</strong>：改成「∠CAD = ∠ACD = 22.5°」，代码输出 22.5
3. <strong>学生从改好的这一步继续自己走</strong>：第 2 步它自己算出 ∠ABC = ∠ADB，输出 <strong>45.0</strong>，答对
4. <strong>答对了，这条「学生前缀 + 老师那一步 + 学生后半段」整条轨迹才留下来</strong>当训练数据。学生通关，间接证明老师改得对

搜索题（附录 Table 10）同理：问「Smoke On The Water 的表演者拿过什么奖」，学生查到 Deep Purple，又查到几个奖，最后随口交了 Ivor Novello 奖，错。老师只改最后这一步，让它去核实 Rock and Roll Hall of Fame，学生接着确认并交卷。

## 二、动机

- <strong>数据和学生水平错配</strong>：老师轨迹里的推理跳步、知识量学生根本接不住（论文说的 reasoning gap 和 knowledge gap）
- <strong>行为克隆的累计误差</strong>：沿用 Ross 等人 2011 年的经典结论，每步错误率 ε、轨迹长 H，总损失最坏按 O(H²ε) 涨
- <strong>直接上 RL 又不稳</strong>：agent 的轨迹长、奖励只有最后「对 / 错」一个数，方差大。论文的原话是想让学生「从模仿走到真正自己解题」，所以 SFT 之后还要接 RL
- <strong>想要的东西</strong>：训练数据难度刚好贴着学生当前水平（论文叫 capability matching），而且一眼能看出学生<strong>卡在哪一步</strong>（deficiency localization，错步前缀 + 老师那一步）

## 三、方法

![论文 Figure 2。左（a）：学生做、老师找第一个错步并回滚、学生从改好的那步重新生成，产出完整轨迹用于 SFT，以及错步前的正确前缀和关键步用于 RL。右上（b）：带修正的 SFT。右下（c）：以正确前缀为起点的 RL，奖励有三档，最终答对给 1，复现老师那一步给 0.5，只是和原错步不同且格式对给 0.1](/images/paper-reading/2026-11-06-score/2026-11-06-d74-2.webp)

### 3.1 阶段一：冷启动 BC

先用老师造一小批完整轨迹。老师先写一个 first\_thought 计划，再按「想 → 代码 → 观察」循环，只留最终答对的（拒绝采样）。<strong>搜索 2,031 条 + 数学 2,080 条 = 4,111 条</strong>，约占全部种子题的 20%。这一步只是让学生学会格式，别一上来就崩。

### 3.2 阶段二：Mentored Problem-Solving（学生做、老师改）

- 学生独立跑完整条轨迹；若答错，老师（72B，靠提示词）读完整条轨迹，找出<strong>第一个偏离正确路径的步骤</strong>，把它替换成改正后的一步
- 学生从「错步之前的正确前缀 + 老师那一步」继续生成；后面如果又错，老师再改一次，<strong>最多改 5 次</strong>
- 最后答对 = 老师的改动被验证；改了 5 次还不行的叫 <strong>Hard-to-Teach</strong>，不用于 SFT，<strong>留 10% 给 RL</strong>，让学生自己探索
- 老师出手很省：只需改 1 次时，一次干预（提示加输出）平均 <strong>811 个 token（数学）/ 1,260 个 token（搜索）</strong>，需要改 2 次时涨到 1,275 / 2,046；多数题 0 或 1 次就够（见第四节图 3）

产出两类监督：整条修正后的轨迹用于<strong>带修正的 SFT</strong>（搜索 4,990 条 + 数学 5,019 条）；每个错步形成一对「同一前缀下，老师那一步好于学生原来那一步」，主要给 RL 当起点和奖励用。

### 3.3 阶段三：短程 RL

- <strong>从错步前缀开始 rollout</strong>：不再从题目头部开始滚，而是从 σ1…σ(k−1) 之后开始，水平线从 H 缩到 H−k+1，方差更小
- <strong>三档奖励</strong>：最终答案对 → 大奖励（图 2 标 1）；否则，复现了老师那一步 → <strong>R\_key = 0.5</strong>；没复现但和原来的错步不同、且格式对 → <strong>R\_format = 0.1</strong>；其他 0
- R\_key 的取值是在 {0.3, 0.5, 0.7} 里、用 <strong>2k 条样本</strong>在数学榜上小规模挑出来的
- 奖励怎么判：论文说用 Qwen2.5-7B-Instruct 当轻量 LLM 判官，判「生成的和参考的是否语义等价」。仓库里的 reward\_function.py 还有一个<strong>单独的 LLM 判官 prompt 来判「两步是不是功能等价」</strong>（读代码读出来的，正文只说动作等价可以用代码和执行结果可靠判断）
- RL 数据里：5,271 条搜索 + 5,639 条数学，其中 Hard-to-Teach 约占 10%

### 3.4 论文给的理论

- Theorem 4.1：BC 的损失上界 c(π\_E) + H(H−1)/2 · ε，即 O(H²ε)
- Theorem 4.2：SCoRe 在学生自己的状态分布下每步错误率不超过 ε，则上界降到 c(π\_E) + H · ε，即 O(H)
- Theorem 4.3：从第 k 步之后开始滚，策略梯度方差的上界随 k 增大而单调变小

怎么读：RL 阶段的两个新设计各自贡献 <strong>3.9（短程 rollout）和 2.6（关键步奖励）</strong>。注意「RL 不用短程 rollout」这一行平均是 48.4，<strong>和第 4.1 节的 BC+GRPO（48.2）几乎一样</strong>，也就是说：SCoRe-SFT 虽然比 BC 高 3.1，但各自再接「普通」RL（从题目头开始滚、只看最终答案）之后，两条线几乎打平（48.4 对 48.2）。SFT 阶段拉开的差距，到 RL 之后基本被抹平，最后的领先主要来自 RL 阶段的两个新设计。注意这两个数字起点不同，是我拿来对照的，论文没有这么比。

### 4.4 其他数字

- <strong>老师出手频率（图 3a）</strong>：数学题 <strong>71.0%</strong> 学生自己就做对了，1 次修正 <strong>15.3%</strong>，2 次及以上 <strong>2.7%</strong>，Hard-to-Teach <strong>11.0%</strong>；搜索题分别是 <strong>58.8% / 25.3% / 2.2% / 13.7%</strong>。绝大多数题根本不需要老师，大部分成本花在少数难题上

## 五、Limitations

### 5.1 论文自述（有独立 Limitations 小节，两条）

- 没有消除累计误差。O(H) 只是在所述假设下的条件性刻画，不是保证分布偏移在实践里被解决
- 依赖老师质量。弱老师会让可用训练数据变少，但验证机制（学生要能通关）通常能过滤掉错误的修正，所以影响更多是在数据产量上，而不是监督质量上

### 5.2 我读出的问题

1. <strong>裁判和老师是同一个模型</strong>：数学、深搜的对错由 Qwen2.5-72B-Instruct 判，老师也是它，RL 奖励里的语义判官是 Qwen2.5-7B-Instruct。裁判偏爱老师风格答案的可能性，论文没有做任何检验。附录 Table 7 补了精确匹配，但只用在和 Agent Distillation 的那张小表上，主表没有
2. <strong>小榜单噪声被当成结论</strong>：AIME 每榜 30 题。<strong>论文自己两张表里就有证据</strong>：Table 3 里只用 20% 老师轨迹的 BC init，AIME25 是 <strong>23.3</strong>；Table 1 里用全部老师轨迹的 BC，AIME25 只有 <strong>14.7</strong>。少数据反而高 8.6 分，说明这类榜单随便就能波动近 10 分。SCoRe-SFT 在 AIME25 上还比 BC init <strong>掉了 4.6 分</strong>（23.3 → 18.7）。所以 AIME 列的增益别当真，OlymMath、MATH500 和平均分更可信一些
3. <strong>比较不对等，老师成本没有总账</strong>：BC 基线用全部老师轨迹，SCoRe 的老师还要额外做「找第一个错步 + 改写」，每次 811 到 1,260 个 token，最多改 5 次，再加上让 72B 当裁判，论文没给老师总调用量的对比。「消融是算力对齐的」只说了 MPS 数据和 GRPO 流程相同，没有对齐老师成本。GRPO、ARPO 数字多半抄自别人的论文，数据和预算不一定一致
4. <strong>「72B 老师」是没有微调过的提示词版本</strong>：表里的 72B 是用 TIR 提示词直接用工具，学生 52.3 超过它 51.1，是超过「一个没做过 agent 训练的 72B」，而不是超过「训练好的 agent」。DeepSeek-V3 54.0 就没超过。摘要写 closes the gap，数字上对 72B 成立，对 V3 不成立
5. <strong>理论和方法有距离</strong>：O(H) 那条是在「学生自己的状态分布下单步错误率 ≤ ε」的假设下直接推出 H·ε，难点（这个 ε 在 SFT 之后到底多大、会不会随 H 变）被假设掉了。Theorem 4.3 是方差上界，随 k 单调，但论文没测实际的梯度方差
6. <strong>短程 RL 的前缀不是当前策略生成的</strong>：RL 起点是 MPS 阶段由 BC 初始化的学生生成的「错步前缀」，RL 训练过程中学生一直在变，前缀还是旧的。这和标题强调的「student-centered / on-policy」有张力，论文没讨论前缀过期的影响
7. <strong>关键步奖励靠 LLM 判官判等价</strong>：「复现老师那一步」给 0.5，实现上是另一个 LLM 判官 prompt 判两步是否功能等价。判官松了，学生不用真学会就能拿 0.5；判官紧了，换种写法的正确步也拿不到。论文没分析这一项的误判率
8. <strong>对 OPD 的胜出证据很弱</strong>：Table 8 里 OPD 平均 24.2，只比 BC（22.8）高 1.4，说明那个 OPD 基本没训起来。老师换成了 Qwen3-32B，实现细节没写，仓库里也没这个基线的代码。拿它来说「SCoRe 优于 OPD」站不住，作者自己的解释是「预算有限」
9. <strong>数字小打架</strong>：附录 D 写 BC 初始化用了「5K samples」，附录 C 列的是 2,031 + 2,080 = <strong>4,111</strong> 条；正文说 20% 全老师标注、80% 走 MPS 再对半分给 SFT 和 RL，附录 C 的 SFT 是 10,009 条、RL 是 10,910 条，4,111 ÷ (4,111 + 10,009 + 10,910) 约 <strong>16%</strong>，不是 20%
10. <strong>评测规模偏小且基本单次</strong>：HQA、2Wiki、MuSiQ 各 200 条，Bamboogle 125 条，GAIA 103 条，xBench 100 条，没有多种子方差；深搜只用搜索摘要片段、没有打开网页，和真实 deep research 有差距
11. <strong>仓库问题</strong>：见文献信息表。最影响复现的三项：没有权重、搜索线的 RL 数据和搜索服务缺失、Table 8 三个基线没代码；而且仓库没有 license，直接当 baseline 改之前要先问清楚

## 六、前文对照

- <strong>Video-OPD（11-03）</strong>：那篇是学生答一次、老师<strong>逐 token</strong> 打分，老师信号稠密，但要求老师和学生共用 tokenizer、能给 logits。SCoRe 的老师只出手一次、改一步文本，信号稀疏，但老师可以是任意 API 模型，还有「学生通关才算数」这道验证。对比落到<strong>老师能提供什么</strong>这一列：logits（OPD）还是改写后的一步文本（SCoRe）
- <strong>π-Distill（10-13）</strong>：那篇处理的是闭源老师不给思维链、只能用「动作」蒸馏。SCoRe 恰好相反，<strong>需要老师读得到学生的思考过程</strong>才能指出哪一步错，所以对黑盒 API 老师也可行，但要把学生整条轨迹发给老师
- <strong>NPR（11-05）、SDFT（11-04）</strong>：这两篇是「没有外部老师，模型自己当自己的老师」。SCoRe 是本周唯一一篇外部大老师只在关键一步出手的，成本结构完全不同：前两篇的老师是免费的，SCoRe 的老师按调用次数收费
- <strong>SDPO（09-30）、GiGPO（09-08）、HiPER（10-30）</strong>：都在解决 agent RL 里「功劳该记在哪一步」。SDPO 靠环境反馈当老师做稠密信用分配，GiGPO 靠相同状态分组零额外 rollout 算步级优势，HiPER 靠层级结构。SCoRe 的办法最土：<strong>把 rollout 起点直接挪到出错的那一步，再给那一步额外奖励</strong>，不用改 advantage 的算法，代价是要有一个能指出第一个错步的老师
- <strong>REOPOLD（08-26）</strong>：也是「7B 学生追平大老师」，但那里的老师是 32B 且逐 token 提供信号。两篇的「追平」口径都要看老师到底是哪个版本、怎么用

## 七、启发与待跟进

- <strong>值得当 baseline 吗</strong>：思路可迁移（要有「能判对错的最终验证」和「能指出第一个错步的老师」就行），数据、造数据代码、SFT 配置、数学 RL 配方都放了，单机 8 卡能跑完 SFT 和 RL，老师可以走 API 或用 llamafactory 本地起 72B。但没有权重、没有 license、搜索线缺数据，<strong>搭起来要自己补三块</strong>
- <strong>最想验证的</strong>：① 把关键步奖励换成不依赖 LLM 判官的版本（比如代码任务直接比执行结果，数学比最终答案和中间量），看 0.5 的收益还剩多少 ② 把老师那一步换成 token 级 OPD 信号，看哪个更稳 ③ 补一张老师 token 总消耗对比表（BC vs SCoRe），再说「省」还是「贵」 ④ 前缀会过期的问题：每隔几步用当前策略重新 MPS 一次，对比固定前缀
- <strong>下周接着读 ④ 推理 / Agentic</strong>：SCoRe 本身也算 agentic，本周借它收尾蒸馏主题；下周可以顺着它的基线 ARPO 和 Tool-Star 往下读

## 八、结论

<strong>这篇的价值是一个很具体、很便宜的想法：老师别整条演，只在学生第一次走偏的地方拉一把，再让学生自己跑通。</strong>数据上有三个相对扎实的信号：同样训练题量下 SFT 比 BC 高 3.1（43.0 → 46.1），RL 阶段两项设计各自 +3.9 和 +2.6，深搜上 BC+GRPO 22.2 对 SCoRe-RL 30.5。但判官和老师同源、AIME 列噪声大、老师成本没算账、OPD 基线没训起来，这几点会让「追平 72B」的说法打折。仓库能用来起步，不能直接当成品。

> 💡 <strong>今日一句：</strong>老师不必替学生把整条路走一遍，在学生第一次走偏的地方拉一把就够了；但这一拉到底值多少，要等判官换成不是老师的、成本账摊开了才算数。

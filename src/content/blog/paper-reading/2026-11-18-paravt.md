## TL;DR

<strong>一句话：长视频问答的 agent 以前是「截一段、看一眼、再截下一段」，一轮只调一次截片段工具。ParaVT 让 8B 模型在一轮里同时发 3～4 个截片段调用，交给共享权重的「分身」并行去看、各写一段文字小结，再汇总作答。真正的难点不在架构，而在 RL：直接上 GRPO，模型几步之内就把格式写崩、把工具全扔了。作者给了两个补丁，合称 PARA-GRPO。</strong>

- <strong>两个病</strong>：① 格式崩坏：SFT 学会的 &lt;tool\_call&gt; 在温度 0.7 采样下退回成 Qwen3-VL 自带的 &lt;tool\_code&gt;，&lt;/think&gt; 不闭合、&lt;answer&gt; 消失，格式分从贪心解码下的 1 掉到约 0.1；② 不调工具：64 帧概览已经够答很多题，调不调工具得分一样，7 步之内每条回答的工具调用数掉到接近 0
- <strong>两个补丁</strong>：① 探索锚定：强制每条回答以 &lt;think&gt; 开头，再给格式分加一项「think 闭合 +0.4、think 开了没关 −0.3、think→answer 完整 +0.3」，权重 0.5；② 帧数门控：每道题随机只给 4/8/16/32/64 帧概览，帧少时不截片段就答不对，调工具才有分差
- <strong>主结果（Qwen3-VL-8B 底座）</strong>：LongVideoBench 52.2 → <strong>60.4</strong>，LVBench 33.1 → <strong>39.8</strong>，MLVU 58.3 → <strong>65.0</strong>；VideoMME 只涨 1～2 分，MMVU 68.0 → 68.6；并行比串行省 43% 提示 token，平均延迟 80.1 → 48.5 秒
- <strong>算力与仓库</strong>：<strong>单机 8 张 ≥80GB 卡</strong>（7 卡训练 + 1 卡 SGLang 采样），AReaL 框架；SFT、RL、评测脚本，97K SFT 数据、4.4K RL 数据、8B 权重都放了
- <strong>主要问题</strong>：① RL 相对 SFT 冷启动只涨 0.4～2.4 分，作者自己在 Limitations 里承认；② 不做冷启动、直接 PARA-GRPO 的结果几乎和完整版一样，和「必须冷启动」的说法打架；③ 训练时分身返回文字小结，评测时截出的帧直接塞回主模型，没有分身，「多 agent 互相纠错」没在评测里出现；④ 训练时平均每条回答 0.21 次工具调用，推理时 99.6%～100% 的题都调工具，所谓「不需要就不调」没有体现

## 一、先看例子（大白话：90 分钟球赛里谁踢进了那脚凌空）

论文开头的例子：给一场 90 分钟的足球比赛，问「哪位球员打出了决定比赛的凌空抽射？」64 帧均匀抽下来，平均 84 秒才一帧，进球那几秒大概率没被抽到。

<strong>老办法（串行，LongVT 那一路）</strong>：模型先看 64 帧概览，猜「可能在 0:10–1:20」，调一次 crop\_video 把这段重新密采样、帧塞回上下文；看完觉得不对，再截 2:00–2:50；再截 3:30–4:30。每截一次，上下文多 5K 左右视觉 token，主模型要整个重新读一遍。第一刀截错了，后面都在错误的基础上往下找。

<strong>ParaVT（并行）</strong>：模型看完概览，一轮里直接写出三个调用：

1. crop\_video(0:10–1:20)
2. crop\_video(2:00–2:50)
3. crop\_video(3:30–4:30)

三个片段同时交给三个「分身」（就是同一个模型，换一个固定的「请总结这段视频」提示，只看自己那段帧），每个分身回一段不超过 512 token 的文字小结。主模型拿到三段小结，发现第 2 段说「没有射门」、第 1 和第 3 段都提到某位球员，交叉对照后作答。

所以「并行」带来两件事：一是主模型只生成一次就派出所有截片段，平均主模型调用次数从 4.23 降到 2.40；二是一段截错了还有别的段兜底。

![论文 Figure 3。（a）串行：每轮截一段，每段给上下文多加约 5K token，第一段截错一路错到底。（b）并行：主 agent 一轮派出 3 个截片段给 3 个分身同时看，其中一段截错（红叉）可被另外两段纠正](/images/paper-reading/2026-11-18-paravt/2026-11-18-d82-1.webp)

## 二、动机

- <strong>串行工具调用有三个硬伤</strong>：截错一段没人纠正；多轮下来上下文越堆越长，长上下文模型对中间信息利用不均；每截一次就要主模型多生成一轮，延迟线性增长
- <strong>想当然的做法跑不通</strong>：在 Qwen3-VL-8B 上做完 SFT 冷启动、直接上 GRPO，出现两个连在一起的病（Figure 1）
- <strong>病一：格式崩坏</strong>。贪心解码下格式很好，一到 τ=0.7 采样，模型就把 SFT 教的 &lt;tool\_call&gt; 换回 Qwen3-VL 预训练里自带的 &lt;tool\_code&gt;，think 不闭合、answer 不写。解析不出工具调用，GRPO 的优势就是在一堆坏样本上算的，工具调用拿不到任何信用
- <strong>病二：工具必要性缺口</strong>。64 帧概览已经能答对不少题，调不调工具得分差不多，GRPO 没有理由偏向调工具，模型 7 步之内学会「不调工具直接答」这条捷径，而准确率在 0.45～0.74 之间来回晃
- <strong>「工具先验悖论」</strong>：作者拿工具先验更弱的 Qwen2.5-VL-7B 用同样超参跑，格式一直接近完美（约 0.85），但 520 步里一次工具都不调。于是说：强工具先验帮助探索、却和 SFT 教的格式抢；弱先验格式稳、但不探索。作者自己也写了，这只是一对模型的对比，不能把「先验强弱」和其他差异分开

![论文 Figure 1。左：贪心解码时格式正确、格式分为 1；GRPO 温度 0.7 采样下改写成 tool_code、闭合标签丢失、没有 answer，格式分约 0.10。右：GRPO 前 9 步，每条回答的工具调用数从 0.15 一路掉到 0.05 以下，任务准确率在 0.45 到 0.74 之间震荡](/images/paper-reading/2026-11-18-paravt/2026-11-18-d82-2.webp)

## 三、方法

### 3.1 架构：一个模型，两种角色

主 agent 在一轮里输出 K 个 &lt;tool\_call&gt;，每个指定一个时间窗。RL 采样时，每个调用启动一个「分身」：当前策略模型的一次全新单轮调用，输入只有该窗口 1 fps、最多 16 帧、224×224 的画面，加一个固定、和问题无关的「总结这段」提示。K 个分身并发跑，回复截到 512 token，以 &lt;tool\_response&gt; 形式拼回主 agent 上下文。

<strong>分身的生成不进 loss</strong>：奖励只给主 agent 的整条回答，优势只加在主 agent 的 token 上。也就是说 RL 只教「什么时候派、派哪几段、怎么汇总」，分身只是因为共享权重被顺带改变。

### 3.2 数据：97K SFT + 4.4K RL

<strong>SFT 97K 条</strong>：LLaVA-Video-178K 抽 50K 普通视频问答；Charades-STA 12K 直接时间定位 + 6K 改成并行调用的定位轨迹；LongVideo-Reason 5K 长视频推理；并行工具轨迹 22.5K（LongVT 自己的 15K 轨迹、Gemini-2.5-Flash 蒸馏 5K、MUSEG 多段定位 2.5K）。含工具的样本占 30%。作者试过 212K、工具占 14% 的版本，工具调用反而更弱。

<strong>串行改并行的转换</strong>：LongVT 原始轨迹是一轮一刀。作者逐条检查相邻两次截片段：时间窗不重叠、返回内容互不引用（如「看 00:30–00:50」和「看 02:10–02:25」），就合并到同一轮；「根据上一段结果再细化时间」这种有依赖的保持串行。然后把每个工具返回的帧换成文字小结，对齐 RL 时分身输出文字的格式。<strong>注意</strong>：转换后只有 MUSEG 平均每轮约 4.4 个调用，其余来源平均接近 1 个，因为 LongVT 原本大多只截一刀。

<strong>RL 4,406 条</strong>：LongVT 开放问答 1,606 + Video-R1 选择题 1,600 + Charades-STA 定位 1,200。离线去掉答案超过 15 个词的 55 条，以及冷启动模型 8 条全错的 7 条。

### 3.3 PARA-GRPO 补丁一：探索锚定（治格式）

- <strong>强制开头</strong>：每条回答的前几个 token 固定为 &lt;think&gt;\\n，杜绝不思考直接答或直接调工具
- <strong>Answer 后缀分</strong>：只要最后有 &lt;answer&gt; 块就给分，中间结构乱一点也不白干
- <strong>锚定项</strong>：R\_anchor = 0.4×\[think 闭合\] − 0.3×\[think 开了没关\] + 0.3×\[完整的 think→/think→answer 流程\]，乘 0.5 加进格式分。和按标签计数给分的做法不同，它专门<strong>惩罚「开了不关」</strong>
- 作者试过把 SFT 目标直接改成 &lt;tool\_code&gt;，结果 RL 时模型又反过来更常写 &lt;tool\_call&gt;，说明两套工具表示在打架，换标签没用，所以保留原生标签、只管结构闭合

### 3.4 PARA-GRPO 补丁二：帧数门控（治偷懒）

每道题采样前，从 {4, 8, 16, 32, 64} 里均匀抽一个数 n，这道题的 8 条 rollout 都只看 n 帧概览。帧少时，靠截片段把证据找回来的 rollout 得分更高，组内就出现了「调工具 vs 不调」的分差；n=64 时保留「不需要就不调」的空间。作者提醒：帧少的题占比太低信号太稀，太高又会逼出过度调用。

### 3.5 奖励

R = R\_acc + 1.0×R\_fmt + R\_tool。R\_acc 按任务：选择题精确匹配、定位题时间 IoU、开放问答 token 级 F1。R\_fmt 基础部分：think 内容 ≥10 字符 +0.2，有 &lt;answer&gt; +0.3，有 &lt;/answer&gt; +0.2，think→tool 顺序正确 +0.3，标签成对 +0.1，再加 0.5×R\_anchor。R\_tool 奖励格式正确的工具调用。另有 reward\_bias −0.2、reward\_scaling 10。回答里 300 字符内出现 5 个以上 &lt;|im\_start|&gt; 直接判 0 分。

## 五、Limitations

<strong>作者自述（附录 A）</strong>：

- RL 阶段的主要贡献是训练时格式和工具使用的稳定，而不是在冷启动之上带来大的贪心评测涨幅
- 「先验强弱」的证据只来自 Qwen2.5-VL vs Qwen3-VL 一对模型，不是受控实验；完整流程只在 Qwen3-VL-8B 上验证过，弱先验底座上格式机制能迁移但长不出工具行为
- 只评测了 crop\_video 一种工具，换成文本检索、场景图、音频转写是否有效未知

<strong>我读出来的问题</strong>：

- <strong>RL 涨幅小，而且和噪声同一量级</strong>。冷启动 → 完整版在六列上只涨 0.4～2.4 分；Table 7 显示同一配置不同步数之间就有 ±1～2 分的波动（LVBench 39.0～41.2，MMVU 67.5～69.6）。全文单次运行、没有方差，很多消融差距（如 VideoMME 无字幕 62.0 vs 62.1）在这个波动之内
- <strong>「必须冷启动」和「不冷启动也一样」打架</strong>。正文说从底座直接做 RL 产不出可解析的 rollout，所以必须 SFT；但 Table 4 里「只做 PARA-GRPO（不冷启动）」的分数 62.0 / 69.4 / 58.6 / 39.3 / 64.7 / 68.5，和完整版 62.1 / 69.4 / 60.4 / 39.8 / 65.0 / 68.6 几乎一样。如果是真的，97K SFT 数据的价值要重新评估；作者没解释
- <strong>训练和评测不是一套系统</strong>。训练时截片段交给分身、回文字小结；附录 B 写明评测时截出的帧直接返回给调用模型，没有分身。标题和 Figure 3 主打的「多 agent、互相纠错」在 Table 1 的数字里并没有被测到；Block C 的「并行 vs 串行」也只是同一 checkpoint 换调用方式，没有和一个按串行方式训练的同底座模型比
- <strong>「不需要就不调」没有兑现</strong>。帧数门控的说法是 n=64 时可以不调工具。但评测全用 64 帧概览，99.6%～100% 的题都调了工具、每轮 3～4 刀；而训练时 κ 只有 0.21。训练行为和推理行为差得很远，说明推理时的工具调用更多是 SFT 习惯，不是 RL 学到的「按需调用」
- <strong>格式其实还是很差</strong>。完整版训练时平均格式分 0.41，最好的第 19 步 answer 闭合率也只有 41.1%（样本只有 56 条）。正文说格式分峰值 0.64，但 Figure 4 前 50 步的蓝线最高约 0.45，0.64 出现在哪一步图里看不到
- <strong>数字对不上的地方</strong>：Table 4 说冷启动 κ=2.50，Figure 1(b) 里 RL 第 0 步的工具调用数却只有 0.15；Table 3 写单卡峰值显存 165～185 GB，而附录说用的是 ≥80GB 的卡，单卡怎么放下没说明
- <strong>比较对象偏弱</strong>：表里除 Qwen3-VL-8B 外的开源模型基本都是 Qwen2.5-VL-7B 底座，「6/7 列领先」有相当一部分是底座代差；各基线还用了作者统一的提示和协议，和原报告设置不同
- <strong>训练很慢</strong>：每步约 50 分钟，每步只有 7 道题 × 8 条；Figure 5 画了 520 步，按这个速度要 18 天左右单机。单机 8 卡能跑，但时间成本不低

## 六、前文对照

| 前文 | 做法 | 和 ParaVT 比 |
|-|-|-|
| OmniAgent（11-16） | 长视频里 7B omni 模型一轮轮决定看哪段画面、听哪段音频，看完写笔记扔原片；TAURA 按每轮熵加权优势 | 都是「长视频别全看、主动去截」。OmniAgent 多轮串行、靠笔记压上下文；ParaVT 一轮并行、靠分身小结压上下文。LVBench 上 OmniAgent 报 50.5、ParaVT 报 39.8，但帧数和评测协议不同，不能直接比 |
| Open-o3-Video（11-17） | 单轮不调工具，在思考里写「物体 + 框 + 第几秒」 | 路线相反：Open-o3-Video 只在已抽帧里指证据；ParaVT 能去拿没抽到的帧。ParaVT 的输出没有可核对的证据位置 |
| Context-Folding（11-09） | agent 开分支干活、干完只留一句总结，FoldGRPO 加过程惩罚 | 「分身只回小结」和「分支只留总结」是同一个思路；区别是 ParaVT 的分身是并发的、而且分身的生成不进 loss |
| DoF（10-20）/ MED（10-29） | 工具是训练期脚手架 / 把「变强」和「会用工具」拆开算 | 正好可以拿来审 ParaVT：涨分大头在 SFT，RL 阶段工具调用数接近 0.2，到底多少分来自工具本身、多少来自 SFT 数据，用 MED 的拆法算一下才清楚 |
| PRISM（08-12） | 在 SFT 和 RL 之间插一段黑盒 OPD 预对齐，减小分布漂移 | ParaVT 正文直接对比了 PRISM：同样是「SFT 学的东西一到 RL 就漂」，PRISM 在交接处补，ParaVT 在 RL 过程中用奖励拉 |
| GDPO（10-26） | 多奖励 RL 里先各自标准化再相加 | ParaVT 把准确率、格式、锚定、工具四项奖励直接相加再组内标准化，正是 GDPO 指出的会互相淹没的做法，可以直接换上试试 |

## 七、启发与待跟进

- <strong>最便宜的起点</strong>：直接拿 ParaVT-8B 权重和评测脚本，在评测时真的启用分身（截片段→分身小结→主模型），和现在的「帧直接回主模型」对比，看「多 agent 互相纠错」到底值多少分
- <strong>补一个对照</strong>：把评测概览帧也随机缩到 8/16 帧，看 ParaVT 是不是在帧少时多调、帧多时少调；如果两种情况都 100% 调工具，帧数门控的「按需」说法就站不住
- <strong>锚定奖励可以单独搬走</strong>：「think 开了没关就扣分 + 强制 think 开头」几行代码，适用于任何 tool-native 底座（Qwen3-VL 做 think-with-image、zoom 工具）遇到的格式崩坏，可以在图像任务上验证
- <strong>帧数门控的图像版</strong>：每道题随机降分辨率，逼模型调 zoom 工具，和 ZwZ（11-02）、ACTIVE-o3（08-27）的放大看路线对比
- <strong>待查</strong>：不冷启动的 PARA-GRPO 具体怎么跑出可解析 rollout；放出的 checkpoint 是第几步；多种子方差；分身是否应该也进 loss（现在只训主 agent）

## 八、结论

ParaVT 把长视频 agent 从「一轮截一段」改成「一轮截几段、分身并行看」，并指出 tool-native 底座上直接做 GRPO 会出现格式崩坏和不调工具两个病，用强制 think 开头 + 惩罚不闭合标签、每题随机缩概览帧数两个补丁压住。8B 模型在 LongVideoBench 上从 52.2 到 60.4，推理延迟降 40%；数据、权重、SFT/RL/评测脚本齐全，单机 8 卡能跑，是做「多模态 agent RL 稳定性」最顺手的 baseline 之一。

需要打折看的地方：涨分大头来自 SFT 冷启动，RL 只多给 0.4～2.4 分且没有方差；不冷启动的结果几乎一样；评测时没有分身，多 agent 的卖点没被测到；推理时几乎题题调工具，「按需调用」没有体现。

> 💡 <strong>今日一句</strong>：这篇最值钱的不是「并行」，而是把 agentic RL 里两个常见的坑（格式被底座先验拉回去、工具调不调都一样所以不调）说清楚了，并给了几行就能抄走的补丁。

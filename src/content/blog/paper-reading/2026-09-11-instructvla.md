## TL;DR

**一句话：VLA（看图→听话→动手）的老毛病是"学了动手就忘了说话"——在操作数据上微调之后，模型原本的多模态理解能力（OCR、常识、图表问答）会被冲掉，甚至掉到 0。这篇的解法是把"动手"当成"指令跟随"的一个组成部分来训：用一个 1.5B 的 VLM 骨干（Eagle2-2B）加一套 MoE 适配（语言 LoRA + 动作 LoRA 两个专家，按隐藏态动态加权），两阶段训练（先动作预训练、再 VLA-IT 指令微调），配上自造的 650K 条 VLA 指令语料。结果：多模态理解不但没掉还小幅超过原 VLM（MMMU 44.2 vs 43.1），操作上比 SpatialVLA 强、在自建基准 SimplerEnv-Instruct 上比微调过的 OpenVLA 高约 96%、比"GPT-4o 当外挂大脑"的 OpenVLA 高约 29%；关键是"让它先想一遍再动手"（textual reasoning）能再涨 36.1%。**

- **核心问题**：VLA 的三大障碍——① **任务干扰/灾难性遗忘**（训操作 → 丢多模态能力）② **数据稀缺**（带丰富多模态监督的操作数据几乎没有）③ **方法缺失**（没有把多模态推理"翻译"成动作生成的机制）
- **方法（VLA-IT）**：① 架构：单个 VLM 同时输出"文本回复"和"latent action"（N 个可学习 action query 从 VLM 隐状态里抽取）→ 再由一个**独立的 flow matching 动作专家**解码成动作（解耦低层控制与高层理解）；② **MoE 适配**：两个 LoRA 专家（语言 / 动作）+ 一个 scalar head 预测门控系数 λ，让模型在"推理模式"和"动作模式"之间自动切换；③ 两阶段训练：Stage-1 动作预训练（只训 650M：latent action embedding + 动作 LoRA，同时用 **language motion** 语言描述低层动作做监督）；Stage-2 VLA-IT（加语言 LoRA + scalar head，共 220M 可训，在通用多模态数据 + 操作数据 + 650K VLA-IT 语料上联合训练，多模态:动作 = **1:7**）
- **数据**：**650K 条 VLA-IT 标注**（用 GPT-4o 对每条轨迹的 3 帧 + 指令标注），四类：场景描述、问答、指令改写（改写/属性指代/换词）、上下文创建（隐含意图、多步进度线索）
- **基准**：自建 **SimplerEnv-Instruct**——80 个零样本任务 / 1.1K trials，分两套：任务聚合（50 任务，考语言与视觉多样性泛化）+ 情境推理（30 任务，考上下文推理与子目标分解）
- **结果**：多模态理解不退化反升（MMMU 44.2 vs 原 VLM 43.1）；SimplerEnv-Instruct 平均 46.2 vs OpenVLA(FT) 23.9（约 +96%）、vs OpenVLA(FT)+GPT-4o 35.6（约 +29%）；真机 +23.3%（原子指令）/ +41.7%（few-shot 推理）/ +46.7%（zero-shot 推理），数学推理是 π0 的 2.5 倍；LIBERO 平均 95.8（1.5B 小模型）
- **最反直觉的一条**：**"不许想，直接动手"比"先想一遍再动手"差 36.1%**——显式文本推理让操作成功率大涨（Generalist w Think 47 vs w/o Think 34，Figure 7b）
- **主题轮换**：今日**具身智能（VLA）**（按序列从世界模型（9/10 RLVR-World）切出；上次具身是 9/3 HiF-VLA——那篇补"时间记忆"，这篇补"语言推理 + 不丢多模态能力"）

## 一、先看例子（大白话：VLA 的"学了动手忘了说话"）

> **铺垫**：VLA = 给机器人装一个"看图 + 听话 + 出动作"的模型。通行做法是拿一个已经很强的多模态大模型（VLM，会看图说话、会 OCR、会做图表问答），再拿机器人操作数据去微调它，让它学会动手。

> **场景**：你有一个很会"看图说话"的 VLM——你给它一张厨房照片，它能告诉你"台面上有刀、砧板、彩色塑料食物，还有炉灶"。**微调它学会"把刀放砧板上"之后，发生了什么？**它确实会动手了 ✅**但它忘了怎么说话** ❌——你再问它"杯子是什么颜色"，它答不上来；让它读图上的字，也不会了。

> 论文 Table 1 把这个病钉得很死：

| 模型 | MMMU ↑ | MMStar ↑ | OCRBench ↑ | MMB ↑ |
|-|-|-|-|-|
| OpenVLA 7B（原生） | 0.0 | 0.0 | 0.0 | 0.0 |
| OpenVLA 7B（微调后） | 26.0 | 28.2 | 2.5 | 18.9 |
| ECoT 7B（把 CoT 塞进操作数据） | 16.2 | 19.1 | 0.0 | 0.9 |
| **InstructVLA-Generalist（1.5B）** | **44.2** | **56.2** | **814** | **76.1** |

- **读表**：OpenVLA 原生模型在多模态理解上**全是 0**（它就不是个通用 VLM）；微调后恢复了一点但还是残废（OCRBench 2.5，等于不会读字）；**InstructVLA 用 1.5B 就拿到了 44.2 / 56.2 / 814 / 76.1——不但没退化，还小幅超过它的骨干 Eagle2**（43.1 / 56.4 / 818 / 74.9）
- **最直接的反例**：**"不许想，直接动手"比"先想一遍再动手"差 36.1%**——同一模型，打开文本推理（Generalist w Think 47）vs 关掉（w/o Think 34），操作成功率直接差一个档

## 二、动机：三大障碍

### 2.1 病灶

- **① 任务干扰 / 灾难性遗忘**：多模态理解与操作控制之间存在冲突，训操作就把语言理解冲掉（论文点名 French 1999 的 catastrophic forgetting）
- **② 数据稀缺**：带**丰富多模态监督**（描述、问答、推理）的操作数据集几乎没有——现有操作数据只有"动作 + 一句指令"
- **③ 方法缺失**：缺少有效机制把"多模态推理"真的转化为"动作生成"

### 2.2 前人的两条路，都不彻底

- **路线 A：统一自回归共训**（RT-2、Magma）——把视觉语言和操作数据混着训。问题：**轻视了具身推理**；而且论文的消融显示**通用 VLM 语料与具身场景存在域差**（GPT-4o 当指令解释器也会出错）
- **路线 B：把 CoT 塞进操作数据**（ECoT、Emma-X）——依赖动作预训练架构 + 结构化推理格式（子任务、grounding）。问题：表达力受限、**照样灾难遗忘**、甚至**练不出通用多模态能力**（Table 1 里 ECoT 的 OCRBench = 0.0）

### 2.3 核心问题

- *怎样在获得操作能力的同时不侵蚀 VLM 的多模态推理？反过来，这种推理又如何增强操作？*

> **这篇的答案一句话**：**把"动手"重新定义为"指令跟随"的一部分，用两个参数专家（语言 / 动作）分开管两件事，用 650K 条带推理标注的操作语料把两者焊起来。** 结果是在"不退化"这件事上直接碾压：OpenVLA 微调后 OCRBench 2.5 → InstructVLA 814（约 300 倍）。

## 三、方法：一个 VLM + 两个专家 + 两阶段训练

![](/images/paper-reading/2026-09-11-instructvla/2026-09-11-d36-2.png)

▲ 论文 Figure 2：模型架构——(1) 语言回复（VLM 自回归生成）(2) latent action（MoE 适配产出）(3) 动作（动作专家 flow matching 解码）；SigLIP 供 VLM，DINOv2+FiLM 供动作专家

### 3.1 架构（Figure 2）

- **一个 VLM 同时干两件事**：既输出**文本回复**（保留语言与多模态推理），也输出**latent action**——用 N 个可学习的 action query `Q ∈ R^{N×D}` 去注意 VLM 的隐状态，抽出任务相关的 `C ∈ R^{N×D}`。语言侧用交叉熵损失 L_LM 监督
- **MoE 适配（核心设计）**：语言和动作本来会互相打架，于是给 LLM 骨干挂**两个 LoRA 专家**（一个学"生成助手回复"，一个学"生成 latent action"），再用一个 **scalar head** 根据隐藏态预测门控系数 λ_i，动态加权混合：`h = W₀x + Σ_{i=0}^{K} B_iA_ix · α_i · λ_i`——相当于**让模型自己决定"现在是推理模式还是动作模式"**
- **独立的动作专家（flow matching）**：为了把"低层控制"与"高层理解"彻底解耦，动作不由 VLM 直接生成，而是交给一个紧凑的 12 层 transformer：输入 DINOv2 图像特征 + latent action + 加噪动作 + 可选本体感觉（proprioception），用 **FiLM** 把视觉特征按 latent action 调制，块间因果注意力、块内非因果；训练目标为 flow matching

### 3.2 两阶段训练（Figure 2 + Table 16）

- **Stage-1 动作预训练（Expert）**：在异构操作数据（RT-1、Bridge）上，**同时预测动作（flow matching）和 language motion（语言描述低层动作，交叉熵）**，损失直接相加 `L = L_LM + L_FM`。**只训 650M 参数**（latent action embedding + 动作 LoRA）

  - **language motion 是什么**：把 6D 运动原语 `v ∈ {−1,0,1}^6` 翻译成自然语言（Table 12 给了完整映射表），让 VLM 用语言去"理解"低层动作——这是"动作可被语言监督"的关键接口
- **Stage-2 VLA-IT（Generalist）**：加**语言 LoRA + scalar head**（与 Stage-1 的动作 LoRA 合起来构成 MoE 适配），**只训 220M**；在通用多模态数据 + 操作数据 + 650K VLA-IT 语料上联合训练，**多模态 : 操作 = 1:7**（论文强调这是 ECoT/ChatVLA 的 1:3 的两倍多模态比例，即"用更少的额外算力保住多模态能力"）

### 3.3 数据：650K 条 VLA-IT 语料（Figure 3）

![](/images/paper-reading/2026-09-11-instructvla/2026-09-11-d36-3.png)

▲ 论文 Figure 3：VLA-IT 语料四类标注——左侧原数据；中间「具身场景理解」（场景描述 + 问答）；右侧「指令理解与规划」（指令改写：工具/材质/外观；上下文创建：情境/新动作/长程）

- 用 **GPT-4o** 对每条轨迹的 **3 帧 + 对应指令**做标注，分四类：

  - **具身场景理解**：① 场景描述（captioning）② 问答（QA，同一 episode 内一致的问答对）
  - **指令理解与潜在动作规划**：③ **指令改写**（paraphrasing / 属性指代 / 换词，如"把切割工具放砧板上"→"我会把刀放到砧板上"）④ **上下文创建**（隐含用户目标或多步进度线索，逼模型推断意图）
- 论文特别强调：**ground-truth 指令对标注准确性至关重要**——GPT-4o 没有真值指令时标注会明显退化（Table 13/14 用实验证明），这也是它反驳"直接用 GPT-4o 当外挂大脑"的依据

### 3.4 推理加速（工程细节）

- **并行解码**：文本用贪心直到第一个 action query token 出现，**剩下的 action query 在一次前向里并行解出**
- **缓存**：语言回复按时间稳定性缓存；latent action 也可缓存（每两个 expert step 生成一次，性能损失极小）
- 实测（Table 19，不含 action chunking）：带语言 **2.51 Hz** → 只出动作 **3.50 Hz** → latent action 缓存 **4.96 Hz**

### 4.3 真实世界（Figure 5）

![](/images/paper-reading/2026-09-11-instructvla/2026-09-11-d36-5.png)

▲ 论文 Figure 5：真实世界实验——WidowX-250 零样本（Bridge 厨房环境）+ Franka Research 3 few-shot；含数学推理任务（「52/2=? 答案是 26，所以我拿黄色积木」）

- 平台：**WidowX-250**（零样本，Bridge 厨房环境）+ **Franka Research 3**（few-shot，货架抓取、杂乱桌面、数学任务）
- 结果：原子指令（直接指令、同域物体）上两者相当，InstructVLA 比 OpenVLA **+23.3%**；**推理类指令**（名人识别、OCR、工具推断）上 OpenVLA 大幅掉分，InstructVLA 领先 **+41.7%（few-shot）/ +46.7%（zero-shot）**；数学与推理任务上是 π0 的 **2.5 倍**（π0 接近随机猜）
- 论文一句很实在的话：**"不许想直接做"和"先想再做"在原子任务上差不多，但一到推理任务就分家了**

### 4.4 消融：四个反直觉结论

## 五、Limitations & 批判性思考（论文自述 + 我的阅读）

1. **只有单轮、短程（论文自述）**：现有 VLM 擅长长上下文与多轮对话，但本作没做"操作与推理交错的多轮交互"；作者把"长程 + 用户干预 + 推理-动作交替"列为未来工作——**这恰恰是我觉得最大的缺口**
2. **任务原语太基础（论文自述）**：受数据集（RT-1/Bridge）与仿真器能力限制，任务基本只有 open/close、pick/place；缺少灵巧技能；而标准 VLM 基准动辄上千任务，这里规模小
3. **（我的阅读）"不退化"的对比基准偏弱**：Table 1 里最强的对照是 8B 的 Magma 和 7B 的 ECoT，InstructVLA 是 1.5B。**规模没对齐**——如果拿同级 1.5B 的共训基线来比，"不退化"这个结论会更硬
4. **（我的阅读）Instruction-following 的评价口径含自建基准**：SimplerEnv-Instruct 是自己造的 80 任务基准，+96%/+29% 这些数字都在自家基准上；LIBERO/真机是外部验证，但真机只有两个平台、样本量不大
5. **（我的阅读）思维链的代价没有充分报告**：打开 think 涨 36.1%，但推理速度从 4.96 Hz 掉到 2.51 Hz（减半）。**"想一遍"的延迟成本对真机闭环控制是真问题**，论文只给了速度表，没给"何时该想/何时不该想"的策略分析
6. **（我的阅读）650K 语料是 GPT-4o 标注的**：论文自己承认 GPT-4o 在具身场景会犯错（所以强调用真值指令约束），但**标注本身的错误率上限没有被系统测量**——这直接决定数据的质量天花板

## 七、启发与待跟进

> **核心启发**：
> 1. **防遗忘的两种武器，这篇都用了**：架构侧（MoE 双专家，让"说话"和"动手"各有各的参数）+ 数据侧（1:7 的多模态:动作配比，且多模态标注要**带推理**而不只是 image-caption）。**光混数据不够（Magma 就是反例），得有"能力用来干什么"的标注**
> 2. **"语言化中间表示"是万能接口**：动作 → language motion（6D 运动原语 → 自然语言），使得 VLM 能用自己最擅长的东西（语言）去学自己最不擅长的东西（连续控制）。这个套路可以搬到很多地方
> 3. **冻结小专家、只调大骨干**：Figure 6(a) 显示冻结动作专家效果持平——**训练预算要花在"理解"那一侧**（这也和 HiF-VLA 的"小模块"思路一致）
> 4. **显式推理有真实的成本**：+36.1% 性能 vs 速度减半（4.96 → 2.51 Hz）。**"什么时候值得想一下"本身就是一个该被研究的问题**（可以设计成自适应策略）

### 待跟进 checklist

- [ ] **"想不想"的自适应策略**：什么条件下开 think 收益最大（论文给了结论没给策略）——可否用"指令复杂度/不确定性"当触发器（和 EOPD/REOPOLD 用熵做触发是一套思路）

- [ ] **MoE 门控的可解释性**：scalar head 预测的 λ 在"推理模式 vs 动作模式"上到底怎么分布？能不能画出"每一步在哪个模式"的轨迹——这是**最像 credit assignment 的地方**

- [ ] **OPD 版 VLA**：用教师 VLA（大模型/大专家）在学生的 rollout 上做 on-policy 蒸馏，看能否同时拿到"不遗忘 + 操作强"——InstructVLA 用 SFT 做到了不遗忘，**OPD 是否更省数据？**

- [ ] **RL 后训练叠加**：MoE 保能力 + 离线 RL（RTG/优势加权）能不能叠——具身圈的下一步大概率在这里

- [ ] **规模对齐的对照实验**：拿同级 1.5B 的共训基线来比"退化程度"，把 Table 1 的结论钉死

- [ ] **动作侧的 KV/表征复用**：latent action 缓存已经省算力（3.50 → 4.96 Hz），和 DeltaWorld 的"只编码变化"（#28）是同一类效率思路，能否搬到 VLA 的动作生成

## 八、今日阅读结论

InstructVLA（ICLR 2026，上海 AI Lab + 浙大 + 中科大）把 VLA 的核心矛盾点破了：**在操作数据上微调，会把 VLM 的多模态能力冲掉——OpenVLA 微调后 OCRBench 只有 2.5，而 InstructVLA 是 814。** 它的解法很干净：**把"动手"当成"指令跟随"的一部分**，用 Eagle2-2B（1.5B）做骨干，挂一对 LoRA 专家（语言 / 动作）由门控系数动态切换，两阶段训练（先动作预训练 + language motion 监督，再 VLA-IT 指令微调），220M 可训参数，配上 650K 条带推理标注的操作语料。结果：多模态理解不退化反升（MMMU 44.2 > 骨干 43.1），SimplerEnv-Instruct 上比微调 OpenVLA 高约 96%、比"OpenVLA + GPT-4o 外挂大脑"高约 29%，LIBERO 平均 95.8（1.5B 逼近 7B 的 OFT），真机推理类指令领先 41.7%\~46.7%。**对你 lib 的价值**：它是"防遗忘"这条线在具身场景的样板（架构侧 MoE + 数据侧 1:7 配比 + 推理标注），而 **language motion 这个"把动作语言化"的接口**，本质和 OPD 找"可监督的中间表示"是同一招——你想做"具身版 OPD"的话，这是现成的锚点。

> **今日一句**：VLA 的老毛病是"学会了动手就忘了说话"——这篇把动手重新定义成指令跟随的一个组成部分，用两个参数专家（说话/动手）分工、用 650K 带推理的操作语料把两者焊起来，结果 1.5B 的小模型既不丢脑子（MMMU 44.2 > 骨干 43.1）又能打败"7B + GPT-4o 外挂"；最扎心的一条是——**让它先想一遍再动手，成功率直接涨 36.1%**。论文：arXiv:2507.17520（ICLR 2026 · 三重一手确认）· 笔记挂在 lib 中 · 2026-09-11

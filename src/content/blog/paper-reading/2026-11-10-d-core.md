> 2026-11-10 · 每日读论文 #75 · 本周领域 <strong>推理 / Agentic</strong>（第 4 周第 2 篇）· <strong>复杂工具调用别在 think 里空转，先把任务拆开再做</strong> · 阿里云 · ICML 2026 Poster

## TL;DR

<strong>一句话：带 think 的推理模型在单轮选工具上还行，一到多轮复杂工具调用就爱在思考里反复 Wait、不拆步骤，作者把这叫 Lazy Reasoning。D-CORE 分两步治：先用自蒸馏逼它按子任务写轨迹，再用带熵的 DA-GRPO 把被蒸馏压掉的反思找回来。</strong>

- <strong>名字</strong>：D-CORE = Decomposing tasks and Composing Reasoning processes。训练分两段：自蒸馏 SFT + Diversity-Aware GRPO（奖励方差塌成接近 0 时，用 token 熵顶上优势，避免梯度消失）
- <strong>主结果（Qwen3-8B / 14B，BFCLv3 与 τ-Bench）</strong>：D-CORE-8B 在 BFCLv3 平均 <strong>77.7%</strong>（相对 Qwen3-8B 的 66.3 为 +11.4，多轮 33.0→63.8，+30.8），超过 xLAM2-8B 的 72.0（文中说「超过最强 8B 基线 5.7 个点」）。D-CORE-14B 平均 <strong>79.3%</strong>，比 xLAM2-70B 的 78.4 高 0.9。τ-Bench 上 8B 从 29.0 到 <strong>47.6</strong>（+18.6），Airline 从 23.2 到 44.4
- <strong>关键消融</strong>：只对 Qwen3-8B 做 GRPO，多轮掉到 26.8（-6.2）。自蒸馏 4 万条后再 GRPO，多轮到 67.4、τ 到 45.2。再加上 DA-GRPO（α=0.1, δ=0.5）综合平均最高（文中 Avg 57.6），但多轮是 63.8，<strong>低于前面普通 GRPO 的 67.4</strong>
- <strong>⚠️ 先说几个坑</strong>：① Table 1 和 Table 3 里 Qwen3-8B 的 Relevance / Irrelevance 两列数字对调了（79.1 和 77.8）；② 「14B 以 5 倍小的体量刷新 70B SOTA」只是 BFCLv3 平均比 xLAM2-70B 高 0.9，τ-Bench 上 51.3 仍低于 o1 的 63.9；③ 自蒸馏并不是完全不靠老师，过滤时要用参考轨迹 Y\*，对不上就丢弃；④ 论文没有独立 Limitations 章节

## 一、先看例子（大白话：把「拷文件到新目录」拆成三步）

> 🧪 <strong>题目（论文 Figure 1 / 附录 Figure 11，BFCLv3 Multi-Turn Base 第 1 题）</strong>：把 Quarter1\_Reports 目录里的所有文本文件，拷到一个新目录 Archived\_Quarter1 里。

<strong>Qwen3-8B 直接做</strong>：在 &lt;think&gt; 里写了 <strong>1,616</strong> 个 token，来回 Wait、However、再检查一遍，最后一次调用里把 mkdir 和 cp 糊在一起，路径还不对，结果打叉。

<strong>先拆成三个子任务再做</strong>（附录用 Decomposed Prompting 做的人工演示，后面 D-CORE 要把这套变成模型自己会的本事）：

1. 用 find 把目录里的文本文件找出来（思考 367 token）
2. 用 mkdir 建 Archived\_Quarter1（思考 185 token）
3. 再逐个 cp 过去（思考 247 token）

三段加起来 <strong>799</strong> token，大约是原来的一半，而且三步都做对了。作者的意思很直白：<strong>模型不是不会调用工具，是面对组合任务时不肯先拆，于是把算力浪费在反复嘀咕上。</strong>

## 二、动机

![论文 Figure 2。Qwen3（Think / No-Think）和专用工具模型 xLAM2 的对比。并行调用和 Irrelevance 上，打开思考的 Qwen3 更好；多轮和 τ-Bench 上，xLAM2 明显把 Qwen3 甩开](/images/paper-reading/2026-11-10-d-core/2026-11-10-d76-3.webp)

- <strong>单轮还行，多轮不行</strong>：Figure 2 里，打开思考的 Qwen3-8B 在 BFCL Parallel 到 81.2，超过 xLAM2-8B 的 56.2；但 Multi-Turn 只有 21.4（xLAM2-8B 是 69.2），τ-Bench 也是 26.7 对 35.0。关掉思考更差。作者的判断：推理能帮模型看清「这句话要用哪些工具」，但帮不上「多轮对话里把一件组合任务做完」
- <strong>Lazy Reasoning 是什么</strong>：他们在 BFCLv3 上对每道题采 20 条轨迹，把 &lt;think&gt; 切成四种行为——任务分解、反思、验证、演绎。Figure 3a 显示，多轮轨迹里任务分解很少，反思特别多（多轮反思占比 48.3，数学题只有 18.6 量级）。Figure 3b：多轮答错的样本里，有 <strong>45%</strong>（8B）/ <strong>34%</strong>（32B）被标成 Lazy Reasoning；单轮 Parallel / Irrelevance 这个比例只有个位数。定义依赖「token 又长、反思又多」的经验阈值，附录 A.2.4 自己也承认这是事后概念
- <strong>子任务一多就塌</strong>：把单子任务拼成多子任务，准确率随子任务数下降（Figure 3c）。反过来，人工按分解提示改写成逐步执行，Qwen3-8B 的多轮准确率从 36.0 提到 <strong>49.5</strong>（Figure 3d）。所以作者认为：懒，是因为不会拆

![论文 Figure 3。（a）多轮里反思很多、分解很少；（b）答错样本中 Lazy Reasoning 比例，多轮和 τ-Bench 明显高于单轮；（c）子任务越多准确率越低；（d）人工分解能把多轮准确率抬上去](/images/paper-reading/2026-11-10-d-core/2026-11-10-d76-4.webp)

## 三、方法

![论文 Figure 4。自蒸馏流水线：复杂工具数据拆成原子子任务，逐个生成思考和工具调用，再拼回完整轨迹，拿去 SFT](/images/paper-reading/2026-11-10-d-core/2026-11-10-d76-5.webp)

### 3.1 自蒸馏：让模型给自己写「拆开再做」的轨迹

- <strong>拆任务</strong>：把系统策略、工具集、对话历史和当前问题交给同一个 LRM，让它输出子任务列表 S。这里会喂参考轨迹 Y\* 和 few-shot。算法 1 写得很硬：如果子任务个数和 Y\* 对不上，这条直接丢掉
- <strong>逐步执行</strong>：顺序依赖的子任务就一轮轮跑，工具结果写回下一轮输入；可并行的一起生成；完全不该调工具的，就让模型解释为什么不能拆
- <strong>拼回来再 SFT</strong>：把子任务、思考、调用和工具返回拼成一条完整轨迹，做标准 next-token 损失。多轮样本会按轮切开，只对最后一轮算损失，再用 packing 拼到 16,384
- <strong>「不用更强老师」这句话要打折</strong>：老师确实不是另一个更大的模型来写思考，但过滤和分解都靠 Y\*。Table 6 里，不用参考轨迹时分解成功率 73.8、τ-Bench 只有 20.3；加上 GT 轨迹和 few-shot 才到 93.2 / 37.1。用 Qwen3-Max 伪标签也能到 92.8 的成功率，但 τ-Bench 掉到 29.6

![论文 Figure 5。（a）自蒸馏之后奖励标准差几乎堆在 0 附近，普通 GRPO 的优势会没了；（b）Qwen3-8B-SD 熵最高的 token，包括 But、imagine、consider、perhaps 这类反思词](/images/paper-reading/2026-11-10-d-core/2026-11-10-d76-6.webp)

### 3.2 DA-GRPO：奖励方差塌了以后，用熵把梯度续上

- <strong>问题</strong>：自蒸馏让轨迹变整齐，组内奖励标准差接近 0，GRPO 的优势 A 也接近 0，更新停摆。Figure 5a 就是这件事
- <strong>做法</strong>：当某 token 的优势 A 小到阈值 ζ（正文写 10^{-8}，附录直接写 A=0）时，不用 A，改用熵项 ψ(H)=min(α·H\_detach, δ)。H 是当前策略在词表上的熵，反向传播时断开，只当缩放系数。优势不为 0 的位置仍走普通 GRPO
- <strong>作者的说法</strong>：这样既避免学习停滞，又会抬高熵较大的反思类 token 的概率。定理写在附录 A.7。奖励沿用 ToolRL：格式 + 结构 + key + value 四项相加
- <strong>超参</strong>：主结果取 α=0.1、δ=0.5。α 太大（1.0）时反思 token 更多，但奖励反而低于普通 GRPO（Figure 6）

## 五、Limitations

⚠️ 本篇没有独立 Limitations。正文从 Related Work 直接进 Conclusion，只在结尾提了「扩展到多模态」和「探索更高效的 RL」。下面是读出来的问题。

- <strong>两张主表数字打架</strong>：同一组 Qwen3-8B 基线，Table 1 的 Relevance / Irrelevance 是 79.1 / 77.8，Table 3 写成 77.8 / 79.1。列对调了一次，后面增量就不好逐格信
- <strong>DA-GRPO 的卖点和多轮主指标不完全一致</strong>：宣传重点是复杂多轮工具调用，可 Table 3 里普通 GRPO 的多轮（67.4）高于最终采用的 DA-GRPO（63.8）。综合平均赢了，多轮这一列没有
- <strong>SOTA 表述偏满</strong>：14B「超过 70B、小 5 倍」只是对 xLAM2-70B 的 BFCLv3 平均 +0.9。多轮和 τ-Bench 都还没追上更大的专用工具模型或 o1
- <strong>自蒸馏不是零监督</strong>：算法 1 明确依赖参考轨迹 Y\* 做长度过滤；Table 6 说明没有 GT / few-shot 时，下游分数会掉一截。和「完全从模型自身引出分解能力」的说法有距离
- <strong>图、公式、脚本不完全对齐</strong>：Figure 6 图例是 δ=1.0，正文 Table 3、附录 A.6 和仓库脚本是 δ=0.5（附录还把 δ 写成 σ）。优势函数正文用 A&lt;ζ，附录用 A=0。附录 Figure 11 右侧三列的步骤说明和工具调用看起来错位
- <strong>Lazy Reasoning 的定义偏事后</strong>：先看到答错、思考又长又爱反思，再打上这个标签。附录自己写这是 a posterior concept，用阈值筛。作为分析故事可以，作为可复现的定量定义偏软
- <strong>仓库和论文承诺有缝</strong>：训练脚本和 8B 权重是有的，但 4 万条全量数据没有在公开数据集页上确认到；权重在个人 HF 账号；顶层 README 几乎不指向训练入口
- <strong>Non-Live 略降</strong>：把能力往多轮搬的时候，单轮 Non-Live 掉了 2.4 个点，文中没有认真讨论这个代价

## 六、前文对照

- <strong>和 11-09 Context-Folding</strong>：昨天那篇管的是长任务上下文怎么折叠；这篇管的是多轮工具调用里思考过程怎么组织。一个砍上下文，一个砍无效思考。都是 agent 自己要学会的过程控制，不是换底座
- <strong>和 08-28 AutoTool</strong>：AutoTool 解决「工具库会变，怎么选没见过的工具」；D-CORE 假设工具集给定，解决「多轮组合任务不会拆」。一个偏选工具，一个偏拆步骤，可以拼
- <strong>和 10-29 MED、10-15 EAPO</strong>：MED 要把「模型变强」和「会用工具」拆开算贡献；EAPO 要把「打探信息」和「做决定」分开训。D-CORE 则是把「分解」和「反思」拆开训。三者都在批评：只看最终对错，过程会学歪
- <strong>和 10-20 DoF、09-16 RAGEN-2</strong>：DoF 说工具可能只是训练期脚手架，学完就不用了；RAGEN-2 说多轮 agent RL 会模板崩塌。D-CORE 的自蒸馏也有类似风险——轨迹变整齐之后奖励方差塌掉，所以才要 DA-GRPO 把反思加回来

## 七、启发与待跟进

- <strong>可直接接着做的</strong>：仓库已经有 8 卡 DA-GRPO 脚本。值得试的改动包括：① 把 Table 3 里「平均最高、多轮不是最高」这件事做干净，看看过程奖励能不能同时保住分解和多轮；② 少依赖 Y\*，用模型自己的分解再加可验证过滤；③ 把 4 万条数据是否真的放出核对清楚，缺的话先用 sample 和脚本路径复现一小份
- <strong>和自己工作的接口</strong>：如果你已经在跑工具调用 RL，这篇最有用的不是 DA-GRPO 那两项定理，而是「先看组内奖励标准差是不是已经塌了」。塌了再上普通 GRPO，可能会像他们的 ToolRL 基线那样把多轮打坏
- <strong>不必急着跟的</strong>：14B 超 70B 的口号，以及把 Lazy Reasoning 百分比当成核心卖点——定义偏软，引用时要带上他们自己的阈值说明

## 八、结论

D-CORE 把一个挺常见的现象说清楚了：推理模型在复杂工具调用里不是不想，是不会先拆，于是把 token 耗在反复 Wait 上。自蒸馏把分解灌进去，DA-GRPO 再把反思接回来，8B 在 BFCLv3 平均到 77.7、多轮 +30.8，这条主线是扎实的。但表与表对不齐、SOTA 说法偏满、自蒸馏仍吃参考轨迹，这些都要记在旁边。作为 8 卡可复现的工具调用 baseline，值得留。

> 💬 <strong>今日一句</strong>：复杂工具调用里，模型常常不是不会用工具，是不肯先把任务切开，于是在 &lt;think&gt; 里把 Wait 说了一千六百遍。

## TL;DR

<strong>一句话：PPO / GRPO 判断一次更新「走太远」的办法，是看被采样的那个 token 新旧概率的比值有没有超出 \[0.8, 1.28\] 这类区间。这篇论文说这个尺子在大词表上是歪的：罕见 token 从 0.0001 涨到 0.01，比值 100，直接被裁掉，其实只挪了 0.01 的概率；常见 token 从 0.99 掉到 0.80，比值 0.81，照样放行，却挪了 0.19。DPPO 把「比值」换成「概率差」（二元 TV）或二元 KL，超过阈值才屏蔽。</strong>

- <strong>改动有多小</strong>：只改 loss 里决定「这个 token 要不要算梯度」的那个 0/1 mask，别的都不动。Binary-TV 版就是一行：正优势时 π−μ &gt; δ 才屏蔽，负优势时 μ−π &gt; δ 才屏蔽（μ 是推理引擎采样时的概率，π 是训练时的概率）
- <strong>稳定性诊断</strong>：DeepSeek-R1-Distill-1.5B 在 1460 道它本来就会做的 MATH 题上训，不设信任域的 PG-IS、CISPO 都会因为训推不一致越积越大而崩；把信任域锚在「重算的旧策略」上（MiniRL）也会崩；真正搞崩训练的只是负样本里不到 0.5% 的大幅更新
- <strong>主结果（只有曲线，没有表）</strong>：Qwen3-30B-A3B-Base 不开 R3 时，AIME24 Avg@32 训到 200 步左右，GRPO-ClipHigher 约 0.46，DPPO 约 0.56；DPPO 不开 R3 也比开了 R3 的 GRPO（约 0.50）高。RLHF：Qwen3-4B-Instruct-2507 的 AlpacaEval 2.0 LC 胜率 59.39 → GRPO 77.05 → <strong>DPPO 80.90</strong>
- <strong>仓库</strong>：sail-sg/Stable-RL（77 star，Apache-2.0）是一整棵改过的 verl，loss 写在 core\_algos.py；<strong>verl 官方已合并 DPPO-Binary-TV / KL</strong>，带 Qwen3-30B-A3B 的 Megatron 启动脚本。没有权重，没有 8B 以下的启动脚本，论文没写用了几张卡
- <strong>主要问题</strong>：① 论文自己的反例（0.99 → 0.80，挪 0.19）在主实验 δ=0.2 下 DPPO-TV <strong>同样放行</strong>；② 用的二元 / Top-K 近似是真散度的<strong>下界</strong>，拿下界判断「没出界」保证不了真的没出界，理论和做法之间有缝；③ 第 7.2 节说 Qwen3-4B 用 HH-RLHF 训，附录 Table 2 的图注却写 UltraFeedback；④ 全部是单次曲线、没有方差，8B 上两者峰值几乎一样，差距主要来自 GRPO 后期掉分

## 一、先看例子（大白话：为什么 PPO 的尺子是歪的）

同一个位置，模型要选下一个 token。论文第 4.2 节给了两个 token：

- <strong>罕见 token</strong>（比如解题里一个关键的「Wait」）：采样时概率 0.0001，更新后变成 0.01。比值 = 0.01 / 0.0001 = <strong>100</strong>，远超 1.28，PPO 直接把它的梯度裁掉。但它实际只挪了 <strong>0.0099</strong> 的概率质量
- <strong>常见 token</strong>：采样时 0.99，更新后 0.80。比值 = 0.808，在 \[0.8, 1.28\] 里，PPO 放行。但它挪走了 <strong>0.19</strong> 的概率质量，是前一个的 19 倍

信任域原本的意思是「新旧两个分布别差太远」，衡量分布差多远的是 TV 或 KL 散度，不是单个 token 的比值。比值只是 TV 的一个单样本估计，在小概率 token 上噪声特别大。

论文还统计了 Qwen3-4B-Base 用 GRPO 训到第 50 步时<strong>最常被裁掉的 token</strong>（附录 D）：the、数字 1 / 4 / 6、+ = 这些数学符号，还有 Wait、Next、Since、Thus 这种推理连接词。也就是说，被 PPO 拦下来的恰好是解题时最要紧的那批词。

DPPO 的做法：同样两个 token，Binary-TV 看的是 |π−μ|。罕见 token 是 0.0099，远小于 δ，放行；常见 token 是 0.19，阈值 0.15 时屏蔽。

## 二、动机

- <strong>LLM 的 RL 天然是 off-policy 的</strong>：推理引擎（vLLM / SGLang）采样，训练引擎（FSDP / Megatron）算梯度，两边参数一样，算出来的概率也会不一样（训推不一致）；一批数据还要切成多个 mini-batch 更新几次。所以必须管住「新策略离采样策略多远」
- <strong>训推不一致在小概率 token 上最严重</strong>：Figure 2 用 Qwen3-30B-A3B-Base、同一套参数，比较两个引擎给出的概率。按比值看，小概率 token 的比值散到 0.6～1.4，大概率 token 收得很紧；按 TV 看，各处都在 0.06 以内。也就是说，光是引擎的数值误差就会让罕见 token 频繁触发 PPO 的裁剪
- <strong>已有补丁都是治标</strong>：DAPO 的 Clip-Higher 把上界从 1.2 调到 1.28；CISPO 干脆不屏蔽、只截断权重。作者认为前者是手调参数，后者等于不要信任域，都没碰到根子：比值本身不是好尺子
- <strong>理论上的补课</strong>：经典 TRPO 的改进下界是给带折扣、无限长的 MDP 推的，LLM 是不打折、有限长、只在结尾给奖励，1/(1−γ) 直接变成无穷大。作者重新推了 LLM 场景下的性能差恒等式和两条下界（第 3 节）

![论文 Figure 2。Qwen3-30B-A3B-Base，训练引擎与推理引擎参数完全相同。横轴是采样时的概率 μ。左：比值 π/μ 在小概率 token 上散到 0.6～1.4；右：TV 散度在各个概率段都不超过约 0.06](/images/paper-reading/2026-11-23-dppo/2026-11-23-d85-2.webp)

## 三、方法

### 3.1 理论：LLM 版的信任域下界

- 定理 3.1：新旧策略的回报差 = 一阶代理目标 L′ − 误差项 Δ，Δ 由逐 token 比值连乘构成，是精确等式
- 定理 3.2 给两条下界：① J(π)−J(μ) ≥ L′ − 2ξT(T−1)·(最大 TV)²；② J(π)−J(μ) ≥ L′ − 4ξ·(每条回复上逐 token TV 之和的期望)。T 是回复长度，ξ 是最大奖励绝对值
- 结论：只要每个位置的 TV 小，代理目标就靠得住。第 ② 条对长回复更紧，也正好对应「逐 token 控制散度」的做法

### 3.2 DPPO 的 mask

- 目标函数和 PPO 一样是 Σ M\_t · r\_t · Â\_t，只换 M\_t：<strong>Â&gt;0 且 r&gt;1 且 D&gt;δ</strong> 时置 0；<strong>Â&lt;0 且 r&lt;1 且 D&gt;δ</strong> 时置 0；其余为 1。即只在「已经往远离的方向走且走太远」时屏蔽，往回走的更新从不拦
- 把 D 换成 |r−1| 就退化回 PPO，所以这是一个严格的推广
- <strong>锚点必须是采样时的 μ</strong>（推理引擎吐出来的概率），而不是训练引擎重算一遍的旧策略。这样还能省掉重算那一遍，作者引前作说约省 25% 训练开销

### 3.3 散度怎么算得起

- 完整词表 15 万维，每个位置都存两份分布太占显存，所以做了两种近似：
- <strong>Binary</strong>：只分「被采样的 token」和「其他所有 token」两类。TV = |μ(a)−π(a)|；KL = μ log(μ/π) + (1−μ) log((1−μ)/(1−π))。开销几乎为零，代码就是一行
- <strong>Top-K</strong>：取采样策略概率最高的 K=20 个 token 加上被采样的 token，其余合成一类再算 TV / KL。K=20 是因为 vLLM 最多返回 20 个候选的 logprob
- 附录 B 证明两种近似都是真散度的<strong>下界</strong>；Figure 11 / 18 显示 Top-K 和 Binary 效果差不多，所以主实验全用 Binary

## 四、实验

### 4.1 稳定性：三个问题（DeepSeek-R1-Distill-Qwen-1.5B，1460 道 MATH 题）

这 1460 道题初始模型都能做对，稳定的算法训练准确率应该冲到 100%。比较 PG-IS、PG-TIS（即 CISPO）、GRPO-ClipHigher、MiniRL、MiniRL-TIS 和两个 DPPO。

- <strong>学习率 1e-6 这么小，还要信任域吗？要</strong>：PG-IS、CISPO 不设信任域，训推不一致的均值从约 0.004 一路涨到 0.01～0.02，随后崩掉；DPPO 两个变体不一致始终压在约 0.003，训练奖励接近 1.0。GRPO-ClipHigher 撑到约 2700 步也崩了
- <strong>信任域锚哪儿？锚采样策略 μ</strong>：MiniRL 锚在重算的旧策略上，照样崩；把稳定的 DPPO-KL 改成锚重算策略，同样崩（Figure 4）
- <strong>谁搞崩的？负样本里的少数大幅更新</strong>：从会崩的 PG-IS 出发，只屏蔽「负优势且采样 token 概率被压低超过 0.5」的更新，就足以稳住；这类坏更新只占 <strong>不到 0.5%</strong>。放宽到 0.8，或改锚重算策略，都稳不住
- 顺带发现：截断重要性权重（TIS）反而更不稳，PG-TIS、MiniRL-TIS 比不截断的版本崩得更早。作者的解释和裁剪一样：被截断的多是小概率 token

### 4.2 效率：放开小概率 token 的哪一头（Qwen3-1.7B-Base，DAPO 数据）

- 对采样概率低于 α 的 token 取消裁剪：α=0.1 时训练奖励明显比 GRPO 涨得快；被裁掉的 token 概率基本都低于 0.15、熵偏高
- 只放开上界（Relax-high，相当于极端版 Clip-Higher）：熵保持住了，效率没怎么提升；只放开下界（Relax-low）：前期涨得最快，但后来熵塌缩掉分；<strong>两头都放（Relax-both）最好</strong>。这和 DAPO「放开上界」的直觉相反，作者说放开下界（负梯度）才是提速的关键

### 4.4 其他实验

- <strong>RLHF</strong>：奖励模型 Skywork-Reward-Llama-3.1-8B，Gemma-2-9B-It + UltraFeedback、Qwen3-4B-Instruct-2507 + HH-RLHF 两组，DPPO 奖励涨得更快更高。AlpacaEval 2.0（Table 2）：初始 LC 59.39 / WR 69.38 / 平均长度 3147；GRPO 77.05 / 72.20 / 1756；<strong>DPPO 80.90 / 79.93 / 2003</strong>

## 五、Limitations

### 5.1 论文自述

⚠️ 本篇没有独立 Limitations。正文只在第 8.2 节说 DPPO 和「提高精度、对齐引擎实现」这类工程手段正交、可以叠加，Impact Statement 是模板句。

### 5.2 我读出来的问题

- <strong>论文自己的反例，主实验参数下照样放行</strong>：开头的卖点是「0.99 → 0.80 挪了 0.19，PPO 不拦」。可 Binary-TV 的判据就是 |π−μ| &gt; δ，主实验和附录 F.3 / F.5 都用 δ=0.2，0.19 &lt; 0.2，DPPO 同样不拦。只有 verl 官方脚本默认的 0.15 才拦得住。DPPO 真正大幅改变的是罕见 token 那一侧（放开），「收紧大概率 token」在 δ=0.2 下几乎只在挪动超过 0.2 时才生效
- <strong>理论和做法之间有缝</strong>：定理 3.2 的保证要求真实 TV 小；而 Binary 和 Top-K 被证明是真散度的<strong>下界</strong>。用下界判断「没超过 δ」，并不能推出真散度没超过 δ，所以严格说 DPPO 并没有落实定理里的信任域。第 ① 条下界的系数是 2ξT(T−1)，回复长度 T=16384 时约 5 亿倍，基本没有约束力
- <strong>RLHF 那段的数据集前后对不上</strong>：第 7.2 节和 Figure 10 写 Qwen3-4B-Instruct-2507 用 HH-RLHF 训，再拿去测 AlpacaEval；附录 Table 2 的图注写的是「Qwen3-4B-Instruct-2507 with UltraFeedback」。另外一个 4B 模型宣称「AlpacaEval 2.0 社区榜新 SOTA」，评委和对比范围都没交代，属于过度声明
- <strong>没有一个数字表，没有方差</strong>：五组大实验全部只给训练曲线，单次运行，没有多种子；最终分数只能从图上读。8B 上 DPPO 和 GRPO 的峰值几乎一样（约 0.34 vs 0.33），所谓「更好的收敛性能」主要是 GRPO 在 800 步后掉分，如果按验证集早停，差距会小很多
- <strong>比较对象偏弱</strong>：基线只有 GRPO-ClipHigher 和 CISPO。同期同样改裁剪 / 掩码的方法（GSPO 序列级比值、10-27 读过的 NSR、各种 IS 掩码）都没比；Thinking 版 30B 上 CISPO 和 DPPO 打平甚至更高，正文却一句「基线频繁不稳」带过
- <strong>「单机 8 卡能跑吗」没给答案</strong>：论文只写 H 系列 GPU，没有卡数和训练时长；verl 官方脚本是 30B-A3B + Megatron，8B、4B、1.7B 的配置都没放，要自己从 GRPO 脚本改 loss\_mode 和 δ
- <strong>命名不统一</strong>：原仓库 loss\_mode 叫 dppo\_binary\_tv，verl 主仓库叫 dppo\_tv；δ 在配置里复用 clip\_ratio\_low / clip\_ratio\_high 两个字段，照着 GRPO 习惯填 0.2 / 0.28 会得到一个不对称的 δ，容易踩坑
- <strong>稳定性诊断的场景太顺</strong>：1460 道「初始模型全会做」的题，奖励理论上会冲到 1，这是作者前作设计的压力测试，能看出谁崩，但和真实 RLVR 里「大量难题、奖励稀疏」差别很大

## 六、前文对照

| 前文 | 它怎么做 | 和 DPPO 的关系 |
|-|-|-|
| 10-27 NSR（Clipping Bottleneck） | 判决仍用原比值，只给被判出界的 token 乘一个 U(0.9, 1.1) 的随机数，有机会被「捞回」界内 | 同一个病：比值裁剪误杀了有用的 token。NSR 不换尺子、在边界上随机救人；DPPO 直接换尺子。NSR 有 7B / 8B 启动脚本，DPPO 有 verl 官方支持，两者都只改 core\_algos.py，可以在同一套 Qwen3-8B 配置下直接比 |
| 10-26 GDPO | 多奖励 RL 里先各自归一化再相加 | 同样是「改一处、被 verl 官方收录」的类型。GDPO 改优势怎么算，DPPO 改哪些 token 算梯度，两者正交可叠加 |
| 09-16 RAGEN-2 | 多轮 agent RL 的模板崩塌，用奖励方差过滤 | 都在找「训练为什么崩」。RAGEN-2 归因到数据侧低方差提示，DPPO 归因到负样本上不到 0.5% 的大幅更新和训推不一致 |
| 11-18 ParaVT（PARA-GRPO） | 视频 agent 的 GRPO 格式崩坏，用锚定奖励和帧数门控治 | 那篇是从奖励设计上修崩溃，这篇是从优化器信任域上修。ParaVT 用的 AReaL 是异步训练，训推不一致更大，换上 DPPO 的 mask 是个自然实验 |

## 七、启发与待跟进

- <strong>最值得带走的</strong>：①「信任域锚在采样时的 μ，不要锚重算的旧策略」，顺带省一次前向；②「拦负样本里把高概率 token 狠狠压下去的那一小撮更新」就能稳住训练。这两条几乎不花代价，任何 GRPO 系实验都可以默认打开
- <strong>想复现</strong>：用 verl 主仓库的 GRPO 脚本，Qwen3-4B-Base 或 8B-Base + DAPO-Math-17k，改 actor.policy\_loss.loss\_mode=dppo\_tv、clip\_ratio\_low = clip\_ratio\_high = 0.15 或 0.2，batch 128、每题 8 条、lr 1e-6、回复 8k，先看 800 步以后 GRPO 会不会像 Figure 9 那样掉分
- <strong>待查</strong>：Table 2 到底是 UltraFeedback 还是 HH-RLHF；δ=0.15 和 0.2 在 8B 上是否有差（附录只在 30B 上扫过）；多种子下 8B 的峰值差距是否显著；单机 8 卡跑 8B、8k 回复要多久
- <strong>能往下做的</strong>：① 用 Top-K 或在线估计的真 TV 替代下界，补上「保证不出界」那一环；② 把 δ 做成随训练自适应（按当前训推不一致的水平调）；③ 和 NSR、GSPO 在同一配置下正面比，看「换尺子」和「边界随机救人」能不能叠加；④ 多模态 GRPO（上周那几篇视频 / 图像 RL）训推不一致更严重，换上 DPPO mask 看格式崩坏会不会减少

## 八、结论

DPPO 指出了一个所有人每天都在用、却很少有人细看的地方：PPO / GRPO 的裁剪按单个 token 的概率比值判断走没走远，在 15 万词表上这把尺子对罕见 token 太严、对高频 token 太松。把它换成概率差或二元 KL，代码只改一行，verl 已经官方收录；稳定性分析给了两条很实用的结论：信任域要锚采样时的概率，崩溃主要来自负样本上极少数大幅压低。

需要打折看的地方：论文自己举的「0.99 → 0.80」在主实验 δ=0.2 下照样放行；用来算散度的近似是下界，和定理的保证对不上；全部结果只有单次曲线，8B 上峰值几乎持平；RLHF 段的数据集名前后不一致，「新 SOTA」说法过头；没有卡数和小模型的启动脚本。

> 💡 <strong>今日一句</strong>：把 GRPO 的 loss\_mode 换成 dppo\_tv 只要一行，值得在自己的每个 RL 实验里当默认对照，但别指望它在 8B 上把峰值抬高很多，它主要是让训练不再后期掉分。

## TL;DR

<strong>一句话：GRPO / RLOO 给一组回答算一个「平均分」当基线，整条回答所有 token 共用。OTB 改成每个位置 t 单独算一个基线：同组各条回答的回报，按「这条回答写到第 t 个 token 为止累计有多不确定」加权平均。越不确定（梯度越大）的回答权重越大，基线就越贴近它自己的回报，它的优势就被压小，梯度方差跟着降下来。不确定度只用前向输出的概率算（1 − 2π + Σπ²），不需要额外反向。</strong>

- <strong>改动在哪</strong>：只改优势估计一处。A\_t = G\_t − B\_t，B\_t = Σ\_i G\_t^(i)·W\_t^(i) / Σ\_i W\_t^(i)，W\_t = 从第 1 个到第 t 个 token 的 (1 − 2π\_j + Σπ\_j²) 累加。不除标准差，没有 KL、没有熵正则
- <strong>主结果（Table 1，各方法全程峰值，avg@32）</strong>：Qwen3-8B-Base 单轮数学 AIME24 GRPO 31.35 / OPO 35.31 → <strong>OTB 37.29</strong>，AIME25 25.31 → 30.31；Qwen2.5-7B 多轮工具推理（TIR）AIME24 SimpleTIR 37.91 → <strong>41.46</strong>，AMC23 71.25 → 79.45
- <strong>卖点</strong>：GRPO 和留一均值基线在 Qwen3-8B-Base 上约 350 步梯度范数暴涨后崩掉，OTB 跑到 1700 多步还稳；组大小 N=4 的 OTB 追平 N=32 的 OTB，论文据此说 token 消耗省 66.03%（单轮）/ 68.32%（TIR）
- <strong>仓库</strong>：已合进 volcengine/verl 主仓库，adv\_estimator=optimal\_token\_baseline（多轮用 tir\_optimal\_token\_baseline），附 Qwen3-8B 单机 8 卡示例脚本和文档。没有权重、没有论文同口径脚本（DAPO-Math-17k / 8192 / N=16）、没有 TIR 脚本和评测脚本
- <strong>主要问题</strong>：① 「最优」是对一个替代目标的最优：真实方差里的交叉项是靠「梯度一致性」假设近似掉的，Σπ² 代理又靠「梯度各向同性回传」假设，不是摘要说的「从第一性原理」严格最优；② 无偏性论证说 B\_t 不依赖 y\_t，但实际的 B̂\_t 用了本条回答自己的 W\_t（里面含 π(y\_t)）和自己的回报，N=4 时这个自身项占 1/4 权重以上，论文只一句「O(1/N) 偏差」带过，也没做留一版对照；③ 「N=4 追平 N=32、省 66% token」是 OTB 自己和自己比，N=32 那条曲线只跑了约 230 步就停了，图里没有 GRPO 在 N=4 下的曲线；④ Table 1 取全程峰值、单次运行，GRPO/RLOO 崩溃前的峰值和 OTB 稳定后的峰值比，单轮里 OTB 比 OPO 在 AMC23、MATH500 只高 0.55 / 0.12；⑤ verl 实现里有论文没写的 handle\_zero\_tail 规则

## 一、先看例子（大白话：同一组里谁更「乱」，基线就更向谁靠）

一道题采 4 条回答，奖励只在结尾给：A、B 答对（1 分），C、D 答错（0 分）。下面的不确定度数字是我编的，用来说明机制，不是论文里的。

- <strong>GRPO</strong>：基线 = 平均分 0.5。A、B 每个 token 优势 +0.5，C、D 每个 token −0.5（再除以标准差变成 ±1），从第一个 token 到最后一个都一样
- <strong>OTB 在第 100 个 token</strong>：四条回答写到这里累计的不确定度 W 分别是 A=5、B=10、C=40、D=15（C 一路犹豫、低概率 token 多）。基线 = (1×5 + 1×10 + 0×40 + 0×15) / 70 ≈ 0.21。于是 A、B 这一位置优势 +0.79，C、D 只有 −0.21。C 最乱，基线被它拉向 0，它自己挨的罚就小
- <strong>OTB 在第 600 个 token</strong>：A 在第 300 个 token 已经写完退出，只剩 B、C、D，W 变成 B=30、C=60、D=90，基线 = 30/180 ≈ 0.17，B 拿 +0.83，C、D 拿 −0.17。同一条回答在不同位置拿到的优势不一样，这就是「逐 token 基线」
- <strong>只剩错误回答的位置</strong>：如果 B 也写完了，只剩 C、D 两条错的，基线 = 0，C、D 后半截的优势是 0，完全不挨罚。这一条是我按公式推出来的，论文没讨论

![论文 Figure 6：OTB 示意。每个位置 t 只在还没结束（非 EOS）的回答上，用回报 G_t 和累计不确定度 Ŵ_t 求加权平均得到 B_t](/images/paper-reading/2026-11-26-otb/2026-11-26-d88-1.webp)

Figure 6 的要点在右半边：第 t 步第一条回答已经输出 EOS，它就不参与这一位置的基线；GRPO 的组均值则是整条回答一个数，不管谁先结束。

## 二、动机

- <strong>长程 RL 的崩溃</strong>：作者在 Qwen3-8B-Base 全在策略训练里观察到，GRPO 和留一均值基线（RLOO）先正常涨几百步，然后梯度范数突然暴涨、AIME25 一路掉到接近 0（Figure 1）。他们把原因归到梯度方差：回答越长，得分函数 S(τ) = Σ s\_t 像随机游走一样方差越大；奖励只在结尾给，又让每一步都乘同一个高方差的回报
- <strong>组均值基线的毛病</strong>：一组回答里每条的「总能量」‖S(τ)‖² 差别很大（Figure 3），组均值把它们当成同样有信息量
- <strong>经典最优基线（OGB）也不够</strong>：Weaver &amp; Tao 那一系的最优全局基线 = 按总能量加权的回报均值，但 ① 要逐条算梯度范数，贵；② 不因果：写到一半时还不知道整条的总能量；③ 不同回答的能量排序会随位置交叉变化（Figure 4：第 100 步和第 600 步排序完全不同），整条一个权重表达不了
- <strong>已有近似 OPO</strong>：用回答长度代替梯度范数。作者的 Figure 11 显示长度一样的回答能量差很多，组内甚至是越长能量越低，所以长度代理不靠谱

![论文 Figure 1：Qwen3-8B-Base 单轮数学。左：梯度范数（对数轴），GRPO 和留一均值基线在约 350 步（虚线）暴涨；右：AIME25，两者随后崩掉，OTB 稳定在 0.29～0.31](/images/paper-reading/2026-11-26-otb/2026-11-26-d88-2.webp)

## 三、方法

### 3.1 每个位置的最优基线

- 改用因果形式的策略梯度：Σ\_t s\_t (G\_t − B\_t)，G\_t 是从 t 往后的回报（只有结尾奖励时 G\_t 就等于最终奖励 R）
- 定义「已实现能量」W\_t = Σ\_{j≤t} ‖∇log π(y\_j)‖²，即写到第 t 个 token 为止累计的梯度平方范数
- 把「最小化梯度方差」近似成逐位置最小化 E\[W\_t (G\_t − B\_t)²\]，求导得 B\_t\* = E\[G\_t W\_t\] / E\[W\_t\]（Theorem 4.1）。这一步的近似（交叉项靠「梯度一致性」假设合并）放在附录 C
- 实际用组内样本估计：B̂\_t = Σ\_i G\_t^(i) Ŵ\_t^(i) / Σ\_i Ŵ\_t^(i)，只在第 t 位还有效（非 padding）的回答上求和

### 3.2 不做反向也能估梯度范数（Logit-Gradient Proxy）

- 对 logits 的梯度是 δ\_t = e\_{y\_t} − π\_t，它的平方范数有闭式：ŵ\_t = 1 − 2π(y\_t) + Σ\_v π(v)²
- Σπ² 用 exp(logsumexp(2·logits) − 2·logsumexp(logits)) 算，前向时顺手得到。模型越有把握（π(y\_t) → 1），ŵ\_t → 0
- 为什么能代替全参数梯度：最后一层梯度 = δ\_t h\_tᵀ，h\_t 是 RMSNorm 输出、范数近似常数 √d，所以最后一层梯度范数 ∝ ‖δ\_t‖；再<strong>假设</strong>主干网络各向同性地回传梯度，推到全参数。因为基线是加权比值，常数因子会约掉

### 3.3 配套

- <strong>TIS 扩展</strong>（附录 D）：如果开了截断重要性采样，权重改成 ρ̄²·W\_t
- <strong>TIR 版</strong>：verl 里单独一个 tir\_optimal\_token\_baseline，先按 response\_mask 把工具返回的 token 剔掉，只在模型自己生成的 token 上累计能量，并且按「第 k 个模型生成的 token」对齐算基线，而不是按绝对位置。这一实现细节论文里没写
- <strong>代码里多出来的规则</strong>：verl 实现默认 handle\_zero\_tail=True，同组里最长那条比第二长多出来的那段，基线直接置 0（否则只有它自己，基线等于自己的回报、优势恒为 0）。论文正文和附录都没写这条

### 4.3 消融

- <strong>代理换成长度</strong>（Figure 13）：OGB 和 OTB 用长度代理都早早崩溃；OGB 换成 Logit-Gradient 代理能延后崩溃，但最终还是崩，作者归因于整条一个权重
- <strong>累计能量 vs 只看当前 token</strong>（附录 F.5，Figure 20）：只用 ŵ\_t 不累计的版本在单轮和 TIR 都打不过累计版，作者拿来反证「得分函数前后相关」
- <strong>更大模型</strong>（附录 F.4，Figure 19）：Qwen3-14B-Base 单轮、Qwen3-8B-Base TIR 只给了曲线，没有数字表
- <strong>缺的</strong>：没有「留一版 OTB」（基线里去掉本条回答自己）；没有 GRPO / RLOO 在 N=4 下的曲线；没有把 handle\_zero\_tail 关掉的对照；没有不同 seed 的方差

## 五、Limitations

⚠️ 本篇没有独立 Limitations 章节（结论里一句「future work 会在搜索引擎等更多任务上验证」，Impact Statement 是套话）。

### 5.1 我读出来的问题

- <strong>「最优」打了折扣</strong>：摘要说「from first principles」推出最优基线，正文 5.1 节说「exact solution」。但被最小化的 E\[W\_t(G\_t − B\_t)²\] 本身是真实方差的近似（附录 C 用「梯度一致性」假设合并交叉项），Σπ² 代理又依赖「主干各向同性回传梯度」这个没验证的假设。准确的说法是「在两个近似下的最优」
- <strong>无偏性论证和实现脱节</strong>：5.1 节说 B\_t 只依赖 x 和 y\_&lt;t，所以无偏。可实际的 B̂\_t 是组内估计，用到了本条回答自己的 Ŵ\_t（ŵ\_t 里有 π(y\_t)，依赖当前 token）和自己的 G\_t。N=4 时自身项占比不小，论文一句「O(1/N) 有限样本偏差，和 GRPO 一样」带过。RLOO 正是为了去掉这个自身项才留一的，这里没有留一版本对照
- <strong>省 token 的账是自己比自己</strong>：66.03% / 68.32% 是 N=4 的 OTB 对 N=32 的 OTB。N=32 的曲线约 230 步就停了，没跑到收敛；图里也没有 GRPO 在 N=4 下的表现，「标准方法小组会早崩」这句没有直接证据
- <strong>峰值对峰值</strong>：Table 1 取全程峰值，基线崩溃前的峰值和 OTB 长训后的峰值比，涨幅里混着「训得更久」。和最强基线 OPO 比，AMC23 / MATH500 只差 0.55 / 0.12，单次运行、无方差，分不清是不是噪声
- <strong>代码里有论文没写的规则</strong>：verl 实现默认 handle\_zero\_tail=True，最长那条单独多出来的尾巴基线置 0。按 0/1 奖励，这段如果是对的就拿满 +1，如果是错的仍然是 0 优势。论文不提这条规则，也就没有它的消融；多轮版的 docstring 写「Default: False」，函数签名却是 True，文档自相矛盾
- <strong>错误回答的长尾不挨罚</strong>（我按公式推的，没实验）：一组里所有正确回答都结束后，剩下的位置只有错误回答，基线等于它们的奖励，优势全是 0。也就是说错误回答比组内所有正确回答都长的那一截完全不受罚，这和 GRPO（整条都罚）差别很大，可能是 OTB 回答长度更稳的部分原因，也可能放任长而错的回答，论文没分析
- <strong>仓库口径对不上论文</strong>：示例脚本是 GSM8K+MATH、回复 2048、N=8，论文是 DAPO-Math-17k、8192、N=16；TIR 的 SimpleTIR 配置、评测脚本都要自己补。论文没写卡数和训练时长，8192 长度、N=16、全在策略在单机 8 卡上要跑多久只能自己估

## 六、前文对照

| 之前读过 | 它做什么 | 和 OTB 的关系 |
|-|-|-|
| 11-23 DPPO | 按概率实际变化量（TV / KL）决定哪些 token 被屏蔽，也把崩溃归到训推不一致 | 两篇都在治「长训崩溃」，DPPO 从信任域下手（哪些 token 不更新），OTB 从基线下手（优势减多少）。都已合进 verl 主仓库，可以同时开：dppo 的损失 + optimal\_token\_baseline 的优势，没人做过这个组合 |
| 11-25 ResRL | 用同组正确回答的隐状态子空间给错误回答的 token 定罚的轻重 | 都是「同一条回答里不同 token 拿不同优势」。ResRL 的权重来自隐状态几何、只作用于负样本；OTB 的权重来自 Σπ²、正负都改，而且是改基线不是乘系数。ResRL 是 verl 0.5 fork，要叠加得把它那 150 行搬进主仓库 |
| 11-24 AntiSD | 看过答案的自己当老师，逐 token 加一个 PMI 信号 | AntiSD 要多一次带特权上下文的前向，OTB 不需要额外前向，只要前向时多存一个 Σπ²。两者都绕开价值模型做 token 级信用分配 |
| 10-27 NSR（Clipping Bottleneck） | 救回被 PPO 裁剪丢掉的近边界 token 信号 | NSR 管裁剪带来的偏差，OTB 管基线带来的方差，一个偏差一个方差，正交 |
| 09-08 GiGPO | agent 多轮里按相同状态再分组，给每一步单独算优势 | 都在给 GRPO 的整条优势做细分。GiGPO 靠「状态相同」找对照组，只适用于有离散状态的环境；OTB 不需要状态匹配，文本推理里也能用 |

## 七、启发与待跟进

- <strong>最值得带走的</strong>：基线不必整条一个数。用前向就能拿到的 1 − 2π + Σπ² 当每个 token 的「梯度大小」，累计起来给组内回答加权，就能得到逐位置的基线，成本几乎为零
- <strong>想复现</strong>：拉 verl 主仓库，用 examples/otb\_trainer/run\_qwen3\_8b\_fsdp.sh，Qwen3-8B 单机 8 卡；要对齐论文就把数据换成去重 DAPO-Math-17k、max\_response\_length=8192、ROLLOUT\_N=16，底座换 Qwen3-8B-Base。同一脚本改 ADV\_ESTIMATOR=grpo 就是基线，评测 avg@32 要自己写
- <strong>待查</strong>：关掉 handle\_zero\_tail 会怎样；GRPO 在 N=4 下多久崩；留一版 OTB（基线里去掉本条）和原版差多少；「错误长尾不挨罚」在实际训练里占多大比例
- <strong>能往下做的</strong>：① 做留一版，消掉自身项偏差；② 把 W\_t 换成附录里提到但没做的交叉项版本 Σ⟨δ\_k, δ\_t⟩₊；③ 和 DPPO 的屏蔽、ResRL 的负样本加权叠加，看方差和偏差两头一起压能不能再涨；④ 搬到搜索 / 网页 agent 等更长程的多轮任务（作者自己说的 future work）

## 八、结论

OTB 把 GRPO 的「整组一个平均分」换成「每个位置一个加权平均」，权重是每条回答写到当前为止累计的不确定度，只用前向的 Σπ² 就能算。在 Qwen3-8B-Base 单轮数学和 Qwen2.5-7B 工具推理上，它让本来几百步就崩的训练稳定跑到上千步，峰值 AIME24 37.29（GRPO 31.35）、TIR AIME24 41.46（SimpleTIR 37.91），N=4 就能达到 N=32 的水平。实现已经进了 verl 主仓库，改一个 adv\_estimator 就能用，是本周最容易直接拿来当 baseline 的一篇。

需要打折看的地方：「最优」建立在两个近似假设上；组内估计用了自身项，无偏性论证不严；省 token 的结论是 OTB 自己和自己比；主表取峰值、单次运行，对 OPO 的部分优势在噪声范围内；代码里还有论文没写的 handle\_zero\_tail。复现时建议同时跑留一版和关掉 zero\_tail 的版本。

> 💡 <strong>今日一句</strong>：基线也可以逐 token 算，权重用前向就有的 Σπ²，几乎白送；但「最优」「无偏」都是近似意义上的，拿来当 baseline 之前先补一个留一版对照。

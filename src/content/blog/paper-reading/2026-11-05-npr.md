## TL;DR

<strong>一句话：想让 4B 模型像 MapReduce 一样把一道题拆成几路同时想、再汇总，以前的做法（Multiverse）要靠 DeepSeek-R1、Gemini 2.5 Pro 这类大老师造数据。这篇不要老师：先用 RL 逼模型自己写出「分头想」的格式，再把它自己答对的轨迹挑出来做 SFT（这就是「自蒸馏」），最后用改过的 RL（PAPO）在真正并行的解码下继续练。</strong>

- <strong>新意在哪</strong>：并行推理不再是「模仿老师的顺序推理、硬塞进并行格式」，而是<strong>模型用自己的话学会拆题</strong>；配套一个能稳定跑并行 RL 的推理引擎（改 SGLang 的显存回收、token 计数、非法分支）
- <strong>主结果（8 榜平均，Qwen3-4B 非思考模式）</strong>：底座 <strong>39.9 → NPR 64.4（+24.5）</strong>，这就是摘要里「最高 +24.5%」的来源
- <strong>⚠️ 换成强底座就没那么亮</strong>：Qwen3-4B-Instruct-2507 底座 <strong>63.7 → NPR 65.0（+1.3）</strong>；HMMT25 <strong>31.0 → 30.8</strong> 甚至略降
- <strong>自蒸馏数据 vs 老师数据</strong>：同样 parallel SFT，Multiverse 的 s1.1-8k 训出 <strong>50.1</strong>，自蒸馏的 orz-8k 训出 <strong>59.0（+8.9）</strong>；⚠️ 但摘要和 README 写的是「高 10.1」，表里算出来是 8.9
- <strong>并行 RL vs 顺序 RL</strong>：同一个起点，DAPO 顺序 RL <strong>62.0</strong>，PAPO 并行 RL <strong>65.0（+3.0）</strong>
- <strong>速度</strong>：AIME25 上每秒 token 数 <strong>646.8 → 2979.8（4.6 倍）</strong>；⚠️ 量的是吞吐，不是「答完一道题要几秒」
- <strong>✅ 仓库</strong>：MIT，112 star / 18 fork；三个阶段的训练代码（npr-zero / npr-beta / npr-rl，基于 verl）+ 评测脚本 + <strong>6 个权重</strong>（两种底座 × 三个阶段）都在；单机 8 卡的配置。<strong>⚠️ 没放自蒸馏出来的训练数据，论文没写用了几张卡、训了几步</strong>

## 一、先看例子（大白话：同一道几何题，顺序想 vs 分头想）

> 🧪 <strong>题目（论文附录 Case #2）</strong>：三角形 ABC 的高 AD 和 BE 交于 H，∠BAC = 54°，∠ABC = 52°，求 ∠AHB。答案 106°。

<strong>普通模型（顺序 CoT）</strong>：先试一种方法，写到一半「Wait」，换第二种，再换第三种……三种思路<strong>排成一条长队</strong>，每个 token 都要等前面所有 token 写完。

<strong>NPR 的写法</strong>：输出里多了一层「计划—分头执行—汇总」的结构：

1. <strong>先列计划</strong>（&lt;guideline&gt; 里三条 &lt;plan&gt;）：① 用垂心夹角的性质 ② 找圆内接四边形做角度追踪 ③ 直接用结论 ∠AHB = 180° − ∠C
2. <strong>三路同时写</strong>（三个 &lt;step&gt;）：靠特制的注意力 mask，<strong>第 2 路看不见第 1 路</strong>，三路的位置编号也从同一个点重新起算，所以三路可以在<strong>一次前向里并排生成</strong>，共用前面题目和计划的 KV 缓存。三路各自得出 106°
3. <strong>汇总</strong>（&lt;takeaway&gt;）：三种方法都是 106°，一致
4. <strong>再来一轮</strong>：新的 &lt;guideline&gt; 安排两路验证（角度追踪、内角和），再汇总，给出最终答案

<strong>为什么快</strong>：顺序写时 token 一个接一个；并排写时同一时刻有几路在出 token。论文量的 AIME25 吞吐：顺序模型 <strong>646.8 token/秒</strong>，NPR <strong>2979.8 token/秒</strong>。

<strong>这篇真正想解决的</strong>：怎么让 4B 模型学会写这种结构，<strong>而且不靠大老师造数据</strong>。直接让 Qwen3-4B-Instruct 按这个格式答，AIME25 从 <strong>47.5 掉到 17.5</strong>（Figure 4），格式本身就把它搞懵了。

<strong>⚠️ 顺手看一眼这个例子本身</strong>：三路其实算的是同一个 180° − 74°，第二路中间还「Wait」了两次。<strong>「三条独立策略」更像同一个解法换了三种说法</strong>，并行省下的是时间，不一定换来了真正不同的思路。

## 二、动机

- <strong>已知</strong>：「往深想」（长 CoT）之外，「往宽想」（同时探索几条路）越来越重要；但 Best-of-N、Self-Consistency 是几条完全独立的采样，<strong>不共享 KV，开销线性涨</strong>
- <strong>前人卡在三处</strong>：① 推理引擎（vLLM、SGLang）不管并行分支怎么开、怎么合；GRPO 类 RL 的裁剪还会把控制分支的特殊 token 的梯度裁掉 ② 有的方法靠手写的分治规则，各路独立采样，不共享 KV ③ <strong>Multiverse 能做真并行，但训练数据是 DeepSeek-R1、Gemini 2.5 Pro 的顺序推理改写成并行格式</strong>，学生学的是「老师的顺序思路硬塞进并行框」，作者叫它「智能天花板」
- <strong>这篇的想法</strong>：<strong>不要老师</strong>。让模型自己先摸出格式，再拿自己答对的轨迹教自己，最后在真并行解码下用 RL 练

## 三、方法

![项目页总览图（对应论文 Figure 2）。阶段一：指令模型用 DAPO 做格式 + 正确性 RL，得到 NPR-ZERO，此时仍是顺序解码、只是格式像并行。阶段二：从 NPR-ZERO 拒绝采样，只留答对且格式合法的轨迹，回到原始指令模型上做带并行注意力 mask 和位置编码的 SFT，得到 NPR-BETA。阶段三：从 NPR-BETA 出发，用 NPR 引擎并行采样、只用正确性奖励，按 PAPO 更新，得到 NPR](/images/paper-reading/2026-11-05-npr/2026-11-05-d73-1.webp)

### 3.1 输出格式（Map–Process–Reduce）

&lt;guideline&gt; 里若干 &lt;plan&gt;（每条一句话的独立策略）→ 每条 plan 对应一个 &lt;step&gt;（独立展开）→ &lt;takeaway&gt;（比较、汇总、决定下一步）；可以嵌套多轮，最后给 \\boxed 答案。比 Multiverse 的格式精简。

### 3.2 阶段一：用 RL 逼出格式（NPR-ZERO）

- 不给任何并行示范，只在 prompt 里说明格式，用 DAPO 训
- 奖励：格式不过关扣 0 到 2 分；格式过关后答对 +1、答错 −1
- 这时还是<strong>顺序解码</strong>，后面的 step 能看见前面的 step，作者叫它「模拟并行」。<strong>这个模型只用来造数据</strong>，不往下接着训

### 3.3 阶段二：自蒸馏 + 并行 SFT（NPR-BETA）

- <strong>拒绝采样</strong>：NPR-ZERO 每题采多条（脚本最多试 8 次、每题留 1 条），只留「答案对」且「格式合法」的
- <strong>换上真并行的 mask 和位置编码</strong>（沿用 Multiverse 的做法，附录 Algorithm 1 和 2）：同一个 guideline 下的几个 step 互相看不见，位置编号对齐；再加一批专门的特殊 token 表示这些标签
- 在<strong>原始指令模型</strong>上做标准 SFT，得到 NPR-BETA
- ⚠️ 注意这里的「自蒸馏」是<strong>离线的拒绝采样 SFT</strong>（STaR / RFT 那一类），不是本周前几篇那种学生采样、老师逐 token 打分的 on-policy 蒸馏

### 3.4 阶段三：并行 RL（PAPO）

![项目页 PAPO 示意（对应论文 Figure 3）。上：普通 GRPO，顺序输出、组内归一化、带参考模型 KL。下：PAPO，用并行推理引擎生成 G 条并行输出，每条是若干轮「列计划、几路推理、汇总」，奖励只看最终答案，优势改为 batch 级归一化，去掉参考模型](/images/paper-reading/2026-11-05-npr/2026-11-05-d73-2.webp)

四处改动：

1. <strong>用 NPR 引擎采样</strong>：保证每条轨迹严格符合并行结构
2. <strong>结构过滤</strong>：不用文本格式检查器（作者说它总会漏掉边角情况），直接用 SFT 阶段那套 mask / 位置编码判断；过滤后奖励就只剩正确性（对 +1、错 −1）
3. <strong>batch 级方差</strong>：格式不合法的被过滤掉后，组内方差常常塌掉，所以分子仍减组内均值，分母换成整个 batch 的标准差（Lite-PPO 的做法）
4. <strong>特殊 token 必须有梯度</strong>：裁剪会把控制分支开合的 token 的梯度裁掉，结构就学坏了。所以<strong>去掉裁剪</strong>；去掉裁剪后重要性采样比不稳，就<strong>干脆不用重要性采样，严格 on-policy</strong>，loss 里的比值写成 π / sg\[π\]（数值恒为 1，只留梯度）

### 3.5 NPR 引擎（工程修补）

- <strong>KV 缓存重复释放</strong>：分支多了以后共享的 radix 树路径会被回收两次，导致上下文错乱、显存泄漏。改成超预算就立即清空重分配
- <strong>token 预算算少了</strong>：原实现只按最长那一路计数，实际总消耗约是分支数倍，会超 max\_new\_tokens。改成按分支数记总账
- <strong>非法分支结构</strong>：加一个分支前的轻量格式校验
- <strong>step 里局部重复</strong>：只在 &lt;step&gt; 里加 1.02 的重复惩罚，guideline 和 takeaway 不加

## 五、Limitations

<strong>⚠️ 本篇没有独立 Limitations</strong>，结论后直接是 Impact Statement。以下全是读出来的。

### 我读出的 8 条

1. <strong>⚠️「+24.5%」靠的是弱底座（最要紧）</strong>：+24.5 来自 Qwen3-4B 的<strong>非思考模式</strong>（底座 39.9）。换成 Instruct-2507，8 榜平均只 +1.3，HMMT25 还掉 0.2。而 Qwen3-4B 最强的<strong>思考模式被排除在外</strong>（理由是不能做 SFT），所以「4B 并行推理比 4B 顺序推理强多少」这个问题，表里其实没回答
2. <strong>⚠️「自蒸馏数据比老师数据好」混了题目分布</strong>：MV-4B 用 s1.1-8k，NPR-BETA 用 orz-8k，<strong>题目本身就不一样</strong>。+8.9 里有多少来自「自己的话」，有多少来自「ORZ 的题和测试集更像」，分不开；缺一组「同一批 ORZ 题、用老师造并行数据」的对照。另外摘要和 README 说 +10.1，Table 2 算出来是 +8.9，数字打架
3. <strong>并行格式本身几乎不涨分</strong>：顺序 SFT 58.2 vs 并行 SFT 59.0，只 +0.8，AMC23 还掉 5.7。Instruct 版并行 SFT 后比底座低 4.7。所以<strong>并行结构主要换来的是速度，准确率靠的是数据和 RL</strong>，论文的叙事把两者揉在一起了
4. <strong>⚠️ 速度口径偏松</strong>：Table 3 量的是 token/秒（吞吐），不是「答完一道题的时间」；并行解码总 token 数会变多（引擎那节自己说约是分支数倍），却<strong>没报每题总 token 和端到端延迟</strong>。teaser 里拿来比的 Multiverse 标的是 <strong>32B</strong>，4B 比 32B 吞吐高本来就是常识
5. <strong>「100% 真并行」是设计出来的</strong>：引擎强制结构、RL 前还把不合格式的轨迹过滤掉，触发率 100% 几乎是必然；对照只拿了 MV-32B，没拿同尺寸的 MV-4B。更该量的是<strong>各路是不是真的不同</strong>（Case #2 三路算的是同一个 180° − 74°），这一点没有指标
6. <strong>⚠️ PAPO 的四处改动没有一个单独消融</strong>：batch 级方差、去裁剪、去重要性采样、结构过滤，哪个起作用不知道；NPR 引擎的四个修补也没有「不修会怎样」的数字。去掉重要性采样后，PAPO 基本就是带 batch 归一化优势的 REINFORCE，「novel algorithm」说重了。而且公开 run.sh 里仍是 grpo + clip 0.2，<strong>论文算法和脚本对不对得上要自己核</strong>
7. <strong>复现信息缺</strong>：论文没写 GPU 数量、型号、每阶段步数、拒绝采样后剩多少条；单次运行无方差；论文说三阶段都用 8k 题，采样脚本是对 57K 全量采
8. <strong>命名撞车</strong>：PAPO 这个名字 lib 里 8/18 已经有一篇（Perception-Aware Policy Optimization，多模态 RL），两者毫无关系，引用时要标清

<strong>一句话串起来</strong>：本周四篇的「老师」越来越弱：ZwZ 和 Video-OPD 用大模型，SDFT 用「自己 + 示范」，NPR 只剩「自己 + 对错」。信号越弱，越要靠 RL 和工程把结构撑住。

## 七、启发与待跟进

1. <strong>💡 想让模型学一种新输出结构，又没有老师数据</strong>：先用格式奖励的 RL 把结构逼出来，再拿它自己答对的轨迹做 SFT。这个两步走比直接套格式（AIME25 17.5）好得多，可以搬到任何「新格式」上（工具调用格式、多 agent 对话格式）
2. <strong>💡 训练里有「控制结构的特殊 token」时，先查裁剪有没有把它们的梯度裁掉</strong>：NPR 认为这是结构学坏的主因，检查成本很低（统计这些 token 的 clip 比例）
3. <strong>💡 格式过滤之后组内方差会塌</strong>：任何「先过滤再算 GRPO 优势」的流程都该看一眼有效组的比例，必要时换 batch 级方差
4. <strong>💡 评并行推理时，同时报吞吐、每题总 token、端到端延迟三个数</strong>，只报 token/秒会高估
5. <strong>待跟进</strong>：① 补「同一批 ORZ 题、老师造并行数据」的对照，分清 +8.9 是题目还是自蒸馏的功劳 ② PAPO 四处改动逐个消融，尤其是「去裁剪」和「严格 on-policy」 ③ 量各路分支的相似度，看「三条独立策略」到底有多独立 ④ 和 Qwen3-4B 思考模式在等 token 预算下比一次 ⑤ 核对公开 run.sh 与论文 PAPO 是否一致

## 八、结论

<strong>方向有意思，工程很扎实</strong>：不靠大老师，4B 模型自己学会了「列计划、分头写、再汇总」，AIME25 吞吐 4.6 倍，仓库三个阶段的代码和 6 个权重都在，是能接着做的 baseline。

<strong>要打折的地方</strong>：+24.5% 来自弱底座，强底座只 +1.3；最大的一块增益来自换了训练题，和「自蒸馏」本身分不清；并行格式本身只多 0.8 分；速度是吞吐不是延迟；PAPO 和引擎修补都没有消融；没有 Limitations。

<strong>今日一句</strong>：<strong>并行推理先省下的是时间，不是思路；想让几路真的想得不一样，还得另外想办法。</strong>

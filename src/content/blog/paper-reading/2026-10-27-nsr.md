## TL;DR

<strong>一句话：RLVR 训练不稳，大家以为是梯度太大；这篇做了个干净的对照实验，发现<strong>跟梯度大小几乎无关，是那个「0 或 1」的裁剪判决在丢信号</strong>。于是改法只有一句——<strong>对被判出界的 token，给它一次摇骰子回门内的机会</strong>。</strong>

- <strong>诊断一（幅度无关）</strong>：给梯度乘噪声、去归一化，<strong>峰值 Pass@1 几乎不变</strong>（DAPO 约 37%、A 约 38%、B 约 36.8%）→ <strong>数值尺度不是瓶颈</strong>
- <strong>诊断二（决策敏感）</strong>：同样大小的噪声，<strong>只搅乱「进不进」这个判决</strong> → 训练直接崩（熵塌缩）；<strong>只搅动执行值、判决保持干净</strong> → 稳定且涨分（约 40% vs 37%）
- <strong>诊断三（只有"救"有用）</strong>：把两种效应对拆开——<strong>只救被误判出界的</strong>能复现全部收益；<strong>只把本来合格的推到界外</strong>毫无收益而且熵飙升
- <strong>方法（Eq. 9）</strong>：判决仍用原 ratio；只对<strong>被判出界</strong>的 token 抽 \`z \~ U(1−δ, 1+δ)\`，若 \`r·z\` 回到可信域就放行，否则照旧裁掉。<strong>δ=0.1</strong>
- <strong>结果（AIME24 Pass@1）</strong>：Qwen2.5-Math-7B <strong>35.83 → 40.76（+4.93）</strong>；Qwen3-8B <strong>37.29 → 43.65（+6.36）</strong>；Qwen3-30B-A3B <strong>54.17 → 58.65（+4.48）</strong>
- <strong>AMC 涨得更多</strong>：7B <strong>69.28 → 76.74（+7.46）</strong>、8B 71.42 → 74.92、30B 81.66 → 85.09
- <strong>跨域也涨</strong>：GPQA 7B <strong>39.27 → 42.99</strong>；MMLU-Pro 30B <strong>72.08 → 74.27</strong>
- <strong>⭐ 最关键的消融（Table 3，3 次独立运行）</strong>：<strong>随机救（40.76±1.56）＞ 确定性软衰减 k=2（38.68±2.13）＞ 只放行不改幅度（37.84±1.67）＞ DAPO（35.83±1.18）</strong> → <strong>"随机"本身是有效成分，不只是"变软"</strong>
- <strong>理论</strong>：在期望意义上，NSR 等价于一个 <strong>约 O(1/r²) 的梯度衰减</strong>（Proposition 6.1 / Corollary 6.2）
- <strong>✅ 有独立 Limitations 章节</strong>（少见，值得记一笔）
- <strong>⚠️ 仓库很薄</strong>：github.com/qwenpilot/NSR <strong>3 star、2 commits、无 LICENSE、无权重、无数据</strong>；实现是内置一整棵 verl + 两个 recipe 脚本
- <strong>⚠️ 论文自称"消耗数十万 GPU 小时"</strong>，但方法本身是<strong>一个 20 行左右的改动</strong>，换 1.5B–7B 单机就能验
- <strong>主题</strong>：<strong>RL / 后训练</strong>（本周第 2 篇）。选它：阿里 Qwen Pilot 主力组（Jingren Zhou 在列）、改动极小、<strong>天然适合当 baseline 继续做</strong>

## 一、先看例子（大白话：差半步就被判出局）

> 💡 <strong>铺垫</strong>：RLVR 的训练目标里有一道「可信域」的门槛——这一 token 的策略变化幅度，必须在 (1−ε, 1+ε) 之内，否则<strong>整条梯度直接扔掉</strong>。
>
> <strong>问题是：这道门是硬开关，没有中间地带。</strong>

![论文 Figure 1：左＝诊断。对梯度幅度做干预几乎没影响（红）；对裁剪判决做干预影响巨大（蓝）。右＝机制。略微出界的 token（灰色叉）通过随机扰动被拉回界内（紫点），重新获得梯度](/images/paper-reading/2026-10-27-nsr/2026-10-27-d66-1.webp)

> <strong>想象一场考试，及格线 60 分。</strong>
>
> <strong>考 59 分的，和考 20 分的，被判成同一种结果：零分，不给任何反馈。</strong>
>
> <strong>但 59 分那个人其实只差一点点，他的错误里还有大量可学的信息；20 分那个人才是真的跑偏了。</strong>
>
> <strong>现在的裁剪就是这么干的——它是个「进/不进」的二元开关，分不清「差半步」和「差很远」。</strong>

<strong>论文原话</strong>：hard clipping 这个 binary keep/drop 机制，<strong>"indiscriminate regarding the degree of violation"</strong>——对偏离程度完全不敏感。

## 二、动机：大家都以为是"梯度太大"，其实不是

RLVR 训练不稳是公认的痛点，尤其在 GRPO/DAPO 这一类目标上：

- <strong>熵塌缩</strong>：模型越训越不敢探索
- <strong>后期崩</strong>：分数冲到一半突然掉
- <strong>过拟合到短答案</strong>：长度先涨后掉

常见的归因有两个：<strong>梯度数值太大</strong>，或者<strong>裁剪阈值设得不对</strong>。

<strong>这篇的做法是先做因果实验，再动手改</strong>——这一点比大多数"我也改一行"的论文扎实。

## 三、方法：三步诊断，一步修

### 3.1 第一步：证明"幅度"不是瓶颈

他们给梯度乘噪声、甚至去掉归一化，看训练结果：

| 设置 | 峰值 Pass@1 |
|-|-|
| 标准 DAPO | ≈37%（第 140 步） |
| 干预 A（扰动幅度） | ≈38%（第 280 步） |
| 干预 B（去归一化） | ≈36.8%（第 140 步） |

<strong>三个数字在同一水平线</strong>——曲线有波动，但天花板没变。

<strong>于是可以排除"数值尺度"这个假设。</strong>

### 3.2 第二步：把"判决"和"执行"拆开

这是全文最巧的一步。他们把同一个 importance ratio 的两个角色分开：

| 角色 | 干什么 |
|-|-|
| <strong>r\_dec（法官）</strong> | 决定这个 token <strong>进不进</strong>门（产生 0/1 的 mask） |
| <strong>r\_exec（执行者）</strong> | 决定进去之后<strong>更新多大</strong> |

标准算法里两者<strong>绑死</strong>（r\_dec = r\_exec = r）。他们引入一个扰动 z，让它俩可以独立：r\_exec = r\_dec · z。

<strong>然后做两个对照（同样大小的噪声）：</strong>

- <strong>搅乱判决（C）</strong>：z 同时作用在两边 → 边界附近的判决被随机翻转 → <strong>训练崩，熵塌缩</strong>
- <strong>只搅执行（D）</strong>：判决保持干净，只让更新幅度抖动 → <strong>稳定，而且涨分（约 40% vs 37%）</strong>

<strong>同样的噪声，一个崩一个涨 —— 这就把因果锁死在"判决"上了。</strong>

![论文 Figure 3：左＝DAPO 基线 vs 搅乱判决（C，虚线蓝，崩掉）vs 只搅执行（D，灰虚线，涨分）；右＝熵曲线，C 直接塌缩](/images/paper-reading/2026-10-27-nsr/2026-10-27-d66-2.webp)

### 3.3 第三步：确认是"救"有用，"推出去"没用

扰动会同时造成两种效应，他们用条件掩码把它们拆开：

| 效应 | 是什么 | 结果 |
|-|-|-|
| <strong>Rescue（救）</strong> | 本来被判出界，被噪声拉回界内 | <strong>复现全部收益</strong>，熵保持稳定 |
| <strong>Push-out（推）</strong> | 本来合格，被噪声推到界外 | <strong>毫无收益</strong>，还可能略降，<strong>熵明显上升</strong> |

<strong>结论很干净</strong>：收益来自"把被误杀的好信号捞回来"，不是"把更新放大"。

![论文 Figure 5：左＝只救（黄）追上完整方法、只推（紫）与基线齐平；右＝只救的熵稳定，只推的熵大幅上升](/images/paper-reading/2026-10-27-nsr/2026-10-27-d66-3.webp)

### 3.4 最后一步：NSR 本体

判决照旧用原 ratio（保可信域语义），只对被判出界的 token 抽一个随机因子：

<strong>z \~ U(1−δ, 1+δ)，令 r\_exec = r\_dec · z</strong>

<strong>然后用哪个值？三种情况（Eq. 9）：</strong>

| 情况 | 用什么 |
|-|-|
| 本来就在界内 | <strong>用它自己</strong>（完全不动，和基线一致） |
| 界外，但 r·z 回到界内 | <strong>用 r·z</strong>（这就是"救"） |
| 界外，尝试后仍在界外 | <strong>照旧裁掉</strong> |

<strong>所以它不是一个"放宽可信域"的粗暴做法</strong>——<strong>界内的 token 一个都没动</strong>，只是给边界外的半步之遥一个概率性的机会。

<strong>超参只有一个：δ=0.1</strong>（即 z 在 0.9–1.1 之间）；<strong>计算开销可忽略</strong>（就是乘一下）。

### 3.5 理论：为什么随机比"变软"更好

![论文 Figure 4：把判决值 r_dec 和执行值 r_exec 放到二维平面上。黄色＝救援区（出界的被拉回）、紫色＝推出区（合格的被推出去）。标准训练所有点都在对角线上](/images/paper-reading/2026-10-27-nsr/2026-10-27-d66-4.webp)

他们证明了在期望意义上，NSR 等价于一种软裁剪：<strong>救援区的有效梯度按约 O(1/r²) 衰减</strong>，越出界衰减越快，很像一个平滑的坡。

<strong>但关键在于：如果只是这个坡，确定性软衰减应该一样好——实测并不是。</strong>

<strong>Table 3（3 次独立运行）给出了答案：</strong>

| 方法 | AIME24 Pass@1 |
|-|-|
| DAPO（基线） | 35.83 ± 1.18 |
| 只放行、不改幅度 | 37.84 ± 1.67 |
| 确定性软衰减 k=2 | 38.68 ± 2.13 |
| 确定性软衰减 k=3 | 38.96 ± 1.62 |
| 确定性软衰减 k=4 | 37.74 ± 2.11 |
| <strong>NSR（随机）</strong> | <strong>40.76 ± 1.56</strong> |

<strong>读法</strong>：

- <strong>"有信号在界外"是真的</strong>：只放行不改幅度就能从 35.83 到 37.84
- <strong>"变软"也有用</strong>：确定性衰减能到 38.7–39.0
- <strong>但随机还能再往上</strong>：40.76。<strong>说明"随机性"本身是有效成分，不只是"变软"</strong>

<strong>这是全文我最认可的一点</strong>：它先给了一个理论解释，然后<strong>用实验证明理论解释不够</strong>，再指出超出理论的那部分在哪。

## 四、实验

### 4.1 数学：三个规模全涨

| 模型（Pass@1） | AIME24 | AIME25 | AMC |
|-|-|-|-|
| Qwen2.5-Math-7B（DAPO） | 35.83 | 15.90 | 69.28 |
| <strong>+ NSR</strong> | <strong>40.76（+4.93）</strong> | <strong>17.57（+1.67）</strong> | <strong>76.74（+7.46）</strong> |
| Qwen3-8B（DAPO） | 37.29 | 27.39 | 71.42 |
| <strong>+ NSR</strong> | <strong>43.65（+6.36）</strong> | <strong>31.67（+4.28）</strong> | <strong>74.92（+3.50）</strong> |

| <strong>+ NSR</strong> | <strong>58.65（+4.48）</strong> | <strong>40.53（+2.09）</strong> | <strong>85.09（+3.43）</strong> |

<strong>三个规模、两种架构（Dense + MoE）、两种裁剪粒度（token 级 DAPO / 序列级 GSPO）都涨</strong> —— 覆盖面确实做够了。

### 4.2 通用：GPQA 涨得多，MMLU-Pro 小幅

| 模型 | GPQA | MMLU-Pro |
|-|-|-|
| 7B：DAPO → +NSR | 39.27 → <strong>42.99</strong> | 44.09 → <strong>46.45</strong> |
| 8B：DAPO → +NSR | 52.02 → <strong>53.16</strong> | 65.67 → <strong>66.41</strong> |

<strong>大模型上增益在收窄</strong>（30B 的 GPQA 只 +0.26）——这符合"救边界信号"的直觉：<strong>模型越强，被误杀的好 token 越少</strong>。

### 4.3 训练动态：熵更稳，回答更长

论文 Fig 6 显示三个规模的共性：

- <strong>收敛更快</strong>、峰值更高
- <strong>熵更稳</strong>，尤其 8B 上基线那个"熵尖峰"没有出现
- <strong>回答长度持续上升</strong> —— 被救回来的梯度鼓励更长的推理链
- <strong>clip fraction 下降</strong>（附录 Fig 10）→ 直接被裁掉的比例变少

## 五、Limitations

### 论文自述的（这条值得表扬：有独立章节）

1. <strong>范围限定</strong>：只覆盖<strong>基于裁剪的 RLVR + 可验证奖励 + 组相对优势</strong>；<strong>不声称</strong>能直接搬到有 value function 的标准 RL、稠密奖励、或无裁剪/KL-only 目标
2. <strong>多了一个超参 δ</strong>，不同裁剪宽度下的调参指南还没做
3. <strong>只测 Qwen 家族</strong>
4. <strong>NSR 与 MoE 路由、token 级 vs 序列级裁剪的交互</strong>研究不足

### 我读出的 4 条

1. <strong>⭐ 仓库太薄，作为 baseline 要打折</strong>：<strong>3 star / 2 commits / 无 LICENSE / 无权重 / 无数据</strong>。方法本身 20 行能重写，但<strong>没有可对比的产物</strong>——你想复现 40.76 得自己从零训
2. <strong>⭐ 增益主要在 Pass@1，Pass@16 提升很小</strong>：7B AIME24 的 Pass@16 只从 <strong>55.05 → 57.70（+2.65）</strong>，8B 更是 <strong>75.18 → 75.39（+0.21）</strong>。<strong>这说明它更多是"更容易采样到对的答案"，而不一定是"能力边界扩了"</strong>——这个区别在做 claim 时很重要
3. <strong>"更稳定"的证据要分开看</strong>：Table 3 里 NSR 的 Pass@1 标准差是 <strong>1.56</strong>，<strong>比 DAPO 的 1.18 还大</strong>。稳定性证据其实主要来自<strong>熵曲线</strong>，不是来自多次运行的方差。论文说 "best stability" 略强于数据
4. <strong>"数十万 GPU 小时"与"易复现"是两回事</strong>：论文用这句话建立可信度，但读者容易误判复现成本。<strong>实际复现只需一个 7B + 单机</strong>——这点该说清

| <strong>π-Distill</strong>（10/13） | 用<strong>教师分布</strong>替代奖励 | OPD 侧同样有裁剪问题（GSPO 版 NSR 就是给序列级裁剪用的），<strong>说明这个诊断对蒸馏式训练也成立</strong>——只是这篇没在 OPD 上验 |
| <strong>EAPO</strong>（10/15） | 改<strong>探索奖励</strong> | EAPO 是"给探索加信号"，NSR 是"别把已有信号删掉"。<strong>一个是开源，一个是节流</strong> |

<strong>一句话串起来</strong>：这一周两篇都是"<strong>改一行、见效快</strong>"——<strong>GDPO 说别把多奖励揉成一个数，NSR 说别把差半步的 token 直接判死</strong>。

## 七、启发与待跟进

1. <strong>⭐ 最值钱的是方法论，不是那个 δ</strong>：<strong>把"判决"和"执行"拆开做因果实验</strong>——这个套路能搬到任何"硬阈值 + 连续幅度"的地方（token 筛选、数据筛选、采样温度、梯度裁剪本身）。<strong>先证明哪个是瓶颈，再改</strong>
2. <strong>⭐ "救回来"比"放更宽"更安全</strong>：界内的 token 一动不动，只给界外一点点概率。<strong>这比直接把 ε 调大好得多</strong>——后者是全局放宽，前者是边界局部手术
3. <strong>⭐ 理论解释不够时，要敢说"超出理论的那部分是什么"</strong>：他们证明了 O(1/r²) 衰减，然后实验显示确定性衰减不如随机。<strong>这种"理论—反例—再解释"的结构，是审稿人最吃的</strong>
4. <strong>可直接抄的诊断清单</strong>：① 先给幅度加噪声，看有没有影响 ② 再给判决加噪声，看崩不崩 ③ 拆开救援/推出两种效应，看谁在起作用。<strong>三步就能判断你的训练不稳是不是边界判决造成的</strong>
5. <strong>待跟进</strong>：① 【最便宜】在 1.5B 上复现三档对照（DAPO / 确定性衰减 / NSR），验证结论是否随规模成立 ② 与 GDPO 叠加，看是否 1+1&gt;2 ③ 在 <strong>OPD/GSPO</strong> 这类序列级裁剪上试 ④ 扫 δ（论文只给了 0.1）

## 八、结论

<strong>这是一篇"诊断比方法更值钱"的论文。</strong>方法本身只有三行，真正贡献是那个对照实验：<strong>把"梯度大小"和"裁剪判决"分开，证明后者才是瓶颈。</strong>

<strong>证据面很宽</strong>（7B/8B/30B、Dense/MoE、token 级/序列级、数学+通用），<strong>但强度有限</strong>（增益主要集中在 Pass@1，Pass@16 几乎不动；仓库也很薄）。

<strong>今日一句</strong>：<strong>训练不稳，先别急着调学习率和阈值——先看清楚，是"更新太大"，还是"该给的机会被一刀切掉了"。</strong>

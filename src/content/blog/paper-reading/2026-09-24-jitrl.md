## TL;DR

<strong>一句话：LLM agent 部署后权重是冻结的，学不了新东西；常规 RL 能学，但贵得要命、还会灾难性遗忘。JitRL 的做法极端干脆——训练时一次梯度都不做：维护一本"经验笔记本"（非参数动态记忆），推理时检索出跟当前情况相似的旧经历来估优势，然后把这个优势<strong>直接加到模型的输出 logits 上</strong>。论文证明了这一步加法就是 KL 约束策略优化目标的精确闭式解。</strong>

- <strong>全部动作就一行公式</strong>：<strong>z'(s,a) = z(s,a) + β·Â(s,a)</strong> —— 把检索出来的优势乘以温度 β，加到原 logits 上。<strong>权重一个都不动</strong>
- <strong>理论三连</strong>：① <strong>Thm 4.1</strong>——加法 logit 更新是 KL 约束优化（π\* = argmax<sub>π'</sub>\[E<sub>a\~π'</sub>\[A(s,a)\] − (1/β)D<sub>KL</sub>(π'‖π\_θ)\]）的<strong>精确闭式解</strong> ② <strong>Thm 4.2</strong>——V̂/Q̂/Â 依概率收敛到真值（<strong>即使在非平稳策略下</strong>） ③ <strong>Thm 4.3</strong>——策略更新收敛到 KL 正则最优策略
- <strong>结果硬</strong>：WebArena 平均 <strong>46.98%</strong>（Final 51.35），<strong>超所有免训练基线</strong>（Static 35.63 / Memory 41.36 / Reflexion 41.08 / AWM 39.37 / EvoTest 39.24）；<strong>held-out WebArena-Lite 上 60.00 vs WebRL 46.06</strong>（WebRL 是花了 \~\$9900 训 Llama-3.1-70B 的强化学习方法）
- <strong>最炸的一组</strong>：Jericho <strong>Zork1 终局 69 分，而梯度 RL（GRPO，Qwen3-32B 逐游戏训练）只有 10 分</strong>；三个游戏 JitRL 全胜（Library 30 / Zork1 69 / Zork3 5）
- <strong>成本</strong>：<strong>JitRL \$290 vs WebRL \~\$9900 → 便宜约 34×</strong>（论文原话"over 30×"）；同表里其它免训练方法都在 \$200–250
- <strong>最有价值的一条消融</strong>：<strong>同一份记忆，"直接改 logits" 打赢"塞进 prompt"</strong>（Admin 49.46→52.31、Reddit 53.02→57.64）——上下文变长后模型注意力与指令遵循都会变差
- <strong>论文自述限制（3 条）</strong>：① 只能在基座提出的候选集上重新加权，<strong>无法发现基座永远不会生成的动作</strong> ② <strong>依赖 LLM evaluator</strong> 打逐步奖励，归因错了会反向拉低策略 ③ 状态表示与检索都基于文本，<strong>不适合空间推理/时序预测</strong>这类难文本化的任务

## 一、先看例子（大白话：给冻结的模型配一本"经验笔记本"）

> 💡 <strong>铺垫</strong>：一个 LLM agent 部署上线后，<strong>权重是冻结的</strong>——它没法像人一样"吃一堑长一智"。论文把它比作<strong>"一个没有在职培训的新员工"</strong>：同样的错误会反复犯。
>
> 要让它学，传统做法是<strong>重新训练</strong>（改权重）——但很贵，而且会把以前会的东西忘掉（灾难性遗忘）。
>
> <strong>JitRL 的替代方案：不改脑子，给它配一本笔记本。</strong>

> <strong>把 JitRL 想成"边干边翻笔记本"：</strong>
>
> <strong>① 每次做完一件事，写笔记。</strong>让另一个 LLM 当"评估员"，回看这一整条轨迹，给每一步打个分（这一步对最终成功贡献多少）→ 算出折扣回报记下来。
>
> <strong>② 下次要行动前，先翻笔记。</strong>看当前情况跟以前哪些情况像（检索出最相似的 k 条），读出"在这种情况里，做 A 后来平均得多少分、做 B 得多少分"。
>
> <strong>③ 算一下"哪个选项比平均更好"。</strong>这就是优势 Â = 某个动作的得分 − 当前情况的平均得分。
>
> <strong>④ 把"该选哪个"的念头临时调高一点。</strong><strong>z' = z + β·Â</strong> —— 只是把输出分数<strong>临时</strong>加上一项，<strong>脑子（权重）一动不动</strong>。
>
> <strong>做完继续写笔记，循环。</strong>

<strong>论文里的真实例子（Table 7）——"记忆纠正了模型的语义直觉"：</strong>

- <strong>找客户评论</strong>：模型直觉上想点 <strong>Catalog</strong>（语义上很顺），logit 0.90；但记忆说"评论其实在 <strong>Marketing</strong> 下面" → <strong>把 Catalog 压到 0.40、把 Marketing 抬到 1.40</strong> → 选了正确的
- <strong>找子版块里的帖子</strong>：模型想用全局搜索（0.95），但搜索常出噪声 → 记忆把它压到 0.45、把 <strong>Forums 抬到 1.80</strong> → 走确定性路径
- <strong>看商品清单</strong>：点 Products 会加载一个泛泛的页（0.95）→ 记忆说 <strong>hover</strong> 能直接展开子类 → 把 click(Products) 压到 <strong>−0.28</strong>、把 hover(Products) 抬到 0.90（<strong>连"操作类型"都被改了</strong>）

## 二、动机：想学，但既不想付训练费、也不想忘事

- <strong>根问题</strong>：agent 部署后权重冻结 → <strong>无法持续学习</strong>。论文引用 Hendrycks et al. 2025 的 "AGI Score"：当前 AI 系统最欠缺的能力正是<strong>"持续学习新信息"</strong>
- <strong>常规 RL 的三个代价</strong>：① 需要大量训练数据 ② 算力昂贵、且需要频繁更新才能跟上环境 ③ <strong>容易灾难性遗忘</strong>，把之前学会的能力一起弄坏
- <strong>另一条路是"免训练"方法</strong>（in-context learning 路线：Reflexion 自我反思、AWM 工作流记忆、EvoTest 进化式 prompt 优化）： 
  - 优点：便宜
  - 缺点：<strong>只是往 prompt 里拼上下文</strong>，<strong>缺乏数学保证</strong>，性能天花板明显
- <strong>所以论文要的是中间地带</strong>：<strong>既要有 RL 的理论保证（有闭式解、有收敛性），又要一次梯度都不做</strong>

## 三、方法

### 3.1 三步：建记忆 → 检索估价值 → 闭式改 logits

![▲ 论文 Figure 2：JitRL 框架总览。上半（推理）：环境 → 状态 s → Generator 产出候选动作 logits，同时从 Memory 检索经验 → 价值估计（V̂ / Q̂）→ 优势估计（Â）→ z' = z + βÂ → 更新后的 logits → 选动作 a²。下半（记忆更新）：完成轨迹 → Evaluator 打逐步奖励 → 折扣回报 G_t = Σγ^{u−t}r_u → 存回 Memory](/images/paper-reading/2026-09-24-jitrl/2026-09-24-d45-2.webp)

<strong>第 1 步 · 记忆构建 M = {(s\_i, a\_i, G\_i)}</strong>

- <strong>反思式逐步奖励</strong>：长轨迹上"分锅"很难，所以用 agent 的自省能力——每集结束时，一个 <strong>LLM Evaluator</strong> 回看整条轨迹 τ = (s₁,a₁,…,s\_T,a\_T)，产出<strong>逐步奖励</strong> E: τ → {r\_t}，r\_t 表示"动作 a\_t 对最终成功的个体贡献"
- <strong>折扣回报</strong>：<strong>G\_t = Σ\_{u=t}^{T} γ^{u−t} r\_u</strong>（γ 平衡即时与未来）
- <strong>状态构建</strong>：原始状态（完整 HTML DOM 树、啰嗦的游戏文本）太吵，先抽象成<strong>紧凑结构化状态</strong>。设计原则一句话：<strong>"把功能等价的状态映射到相似的表示"</strong>

<strong>第 2 步 · 测试时价值估计（用检索代替价值网络）</strong>

- 把当前观察抽象成状态 s，检索 <strong>top-k 相似邻居</strong>组成局部邻域 N(s)
- <strong>状态价值</strong>：<strong>V̂(s) = (1/|N(s)|) Σ\_{i∈N(s)} G\_i</strong>（邻域内回报的期望）
- <strong>动作价值</strong>分两种情况： 
  - <strong>已知动作</strong>（历史有证据，|N(s,a)| &gt; 0）：<strong>Q̂(s,a) = (1/|N(s,a)|) Σ\_{j∈N(s,a)} G\_j</strong>
  - <strong>没见过的动作</strong>：以概率 λ 给一个"不确定性下的乐观值" <strong>Q̂(s,a) = V̂(s) + α/|N(s)|</strong>（α/|N(s)| 是认知不确定性奖励：记忆覆盖稀疏时估计不可靠、值得探索；随着经验积累自动衰减 → 自然从探索转向利用）；以概率 1−λ 给 Q̂ = 0，防止过度探索
- <strong>测试时优势</strong>：<strong>Â(s,a) = Q̂(s,a) − V̂(s)</strong>（把动作价值对状态基线做中心化）

<strong>第 3 步 · 策略更新（闭式，这是全文的核心）</strong>

- 把它写成一个约束优化：<strong>π\* = argmax<sub>π'</sub> ( E<sub>a\~π'</sub>\[A(s,a)\] − (1/β) D<sub>KL</sub>(π'‖π\_θ) )</strong>——最大化期望优势，同时用 KL 拽住冻结的参考策略，保住语言能力
- <strong>闭式解</strong>：<strong>π\*(a|s) ∝ π\_θ(a|s) · exp(β·A(s,a))</strong>
- <strong>映射到 logit 空间</strong>（设 π\_θ(a|s) = Softmax(z(s,a))，对闭式解取对数）：<strong>z'(s,a) = z(s,a) + β·Â(s,a)</strong>
- <strong>于是"RL"退化成一件事：往 logits 上加一项</strong>——<strong>无梯度、无权重更新</strong>

### 3.2 三个定理（这是它能叫"RL"而不是"prompt 技巧"的原因）

| 定理 | 说了什么 |
|-|-|
| <strong>Theorem 4.1</strong><br>（更新最优性） | 加法 logit 更新 <strong>z'(s,a) = z(s,a) + β·Â(s,a)</strong> 是上述 KL 约束优化问题的<strong>精确闭式解</strong>——不是启发式，是解 |
| <strong>Theorem 4.2</strong><br>（估计一致性） | 对任意固定状态 s 与动作 a，<strong>V̂\_t、Q̂\_t、Â\_t 依概率收敛</strong>到真值 V^{π\_t}、Q^{π\_t}、A^{π\_t}（<strong>即使在非平稳策略序列 (π\_t) 下也成立</strong>） |
| <strong>Theorem 4.3</strong><br>（策略一致性） | 把前两个合起来：<strong>π̂\_t(·\\\|s) 依概率收敛</strong>到由真实优势诱导的 KL 正则最优策略 π\*\_t |

### 3.3 工程实现：黑盒模型也能用

- <strong>难点</strong>：很多黑盒模型不暴露 log-probabilities。论文给了两个变体： 
  - <strong>Token-level Logit</strong>：让 generator 从 k 个候选动作里输出序号 token（如 "1"、"2"），<strong>取这些 token 的 log-prob 当 logits</strong>
  - <strong>Verbalized Logit</strong>：对完全不暴露概率的模型，<strong>让 LLM 显式输出 0–100 的置信度，再变换成 logits</strong>

### 4.4 泛化与消融

- <strong>跨骨干（Table 4）</strong>：Gemini-2.5-flash / GPT-5-mini / DeepSeek-V3.2 三个骨干上 JitRL 都在多数格子上最好 → 机制<strong>与骨干无关</strong> 
  - GPT-5-mini：Admin 51.63、Reddit 57.36（终局）
  - DeepSeek-V3.2：Admin 54.35、Reddit 61.24（终局）

  - Admin：49.46（塞进 prompt）→ <strong>52.31（改 logits）</strong>
  - Reddit：53.02 → <strong>57.64</strong>
  - 论文归因：<strong>上下文一长，LLM 往往抓不住检索到的线索、也不再严格遵循指令</strong>；而直接调输出分布能确保"历史上的优势真的被用上"
- <strong>检索邻居数 k 的敏感性（Figure 4）</strong>：<strong>k ∈ \[8, 14\] 稳健</strong>；太小证据不足、估计方差大；太大引入过多噪声、拖慢收敛

## 五、Limitations &amp; 批判性思考

<strong>论文自述（有独立 Limitations 章节，共 3 条）</strong>：

1. <strong>依赖冻结的基座</strong>：JitRL 只在基座提出的<strong>候选集上重新加权</strong>，<strong>无法发现基座永远不会生成的动作</strong>
2. <strong>依赖 LLM Evaluator</strong>：如果评估员<strong>归因错误</strong>，优势估计就不准，<strong>可能反而拉低策略质量</strong>
3. <strong>不适合难以文本化的任务</strong>：状态表示与检索都基于文本；空间推理（如棋盘局面）或时序预测这类任务，文本检索<strong>抓不到状态间的相关相似性</strong>，记忆式价值估计会失效

<strong>Impact Statement 自述</strong>：记忆库存的是真实交互轨迹，<strong>可能无意中捕获敏感用户信息</strong>。

<strong>我的阅读（8 条）</strong>：

1. <strong>主表的骨干不对齐</strong>：Table 2 里 JitRL 用 Gemini-2.5-flash 对比 Llama-3.1-70B 的 WebRL → <strong>跨骨干比较</strong>；论文说附录 I / J.1 有同骨干对照，但正文这张表容易让人高估增益
2. <strong>换了种"忘记"</strong>：确实没有灾难性遗忘，但<strong>记忆库只增不减</strong>——论文测了"随记忆增长的推理开销"（Appendix Table 23），说明成本被意识到；但<strong>没有提出任何记忆淘汰/压缩机制</strong> → <strong>这是最明显的 open 方向</strong>
3. <strong>"零梯度"≠"零成本"</strong>：每条轨迹要 LLM Evaluator 打逐步奖励、要检索、要把候选动作映射成 token/置信度 → \$290 是 API 成本；而且 <strong>候选集大小 k 直接封顶了可控空间</strong>
4. <strong>候选集受限是硬天花板</strong>：限制第 1 条实质是说"<strong>只能在基座已有的选项里挑更好的</strong>"——这与 lib 里 RL-Cap #30 的"RL 只重排、不扩界"是同一个天花板，而且更极端（连梯度都没有）
5. <strong>奖励来自 LLM 自评，是单点故障</strong>：Reflective step-wise rewards 全依赖 Evaluator 的判断，论文<strong>没有测"Evaluator 出错时会怎样"</strong>——而这正是 MoCA #43 那篇刚刚警告过的（普通 LLM judge 导致 reward hacking）
6. <strong>只在文本 agent 任务上验证</strong>（WebArena + Jericho），<strong>没有多模态 / 具身 / 工具调用</strong>场景
7. <strong>超参扫描在附录</strong>：正文只给了 k 的敏感性（Figure 4）；λ、α、γ、β 的扫描在 Appendix Table 19–22 → <strong>正文没给主配置的 β 具体值</strong>
8. <strong>分数口径要小心</strong>：Jericho 三个游戏的 R\_max 差异巨大（Library 30 / Zork1 350 / Zork3 7），<strong>跨游戏比较只有"相对提升"有意义</strong>；而且只报了 50 集的均值与终局值，未见多种子误差棒

## 七、启发与待跟进

> 💡 <strong>核心启发</strong>：
>
> 1\. <strong>"策略改进"不一定要改参数。</strong>KL 约束策略优化有闭式解 → 最优策略就是在原 logits 上加 β·优势。<strong>对没有训练资源的场景（比如只有 2×L20 或纯 API 额度），这是一条真实可走的替代路线</strong>
>
> 2\. <strong>成本量级值得记住</strong>：\$290（API）vs \~\$9900（H200 训练）。<strong>如果要做"agent 持续学习"这条线，纯 API 打工是可行的</strong>
>
> 3\. <strong>修好"记忆管理"就是一篇新论文</strong>：论文明确测了记忆增长的推理开销，但<strong>没有淘汰机制</strong>。而 #42 的 U 型曲线正好提供了理论语言——<strong>"什么时候该丢记忆"可以问 iGCV 那套"零验证集早停"</strong>
>
> 4\. <strong>Evaluator 是单点故障，且已有现成解药</strong>：MoCA #43 的 Structured Verbal Verification（把"判断"变成"执行结构化协议"，一致率 78.6% → 92.3%）几乎可以原样搬来替换 JitRL 的自评
>
> 5\. <strong>最值得做的一个融合实验</strong>：JitRL 的 β·Â 与 OPD 的 β·(log π\_te − log π\_θ) 都在 logit 空间加项 → <strong>两者能不能叠加？</strong>（检索优势负责"这个动作历史上好不好"，教师 KL 负责"这个 token 像不像强模型"）

## 八、今日阅读结论

这一篇（<strong>ICML 2026 Poster</strong>，NUS 单机构 8 人）是 <strong>lib 里第一篇"零梯度 RL"</strong>。它要解决的问题很实在：<strong>LLM agent 部署后权重冻结、无法持续学习</strong>，而常规 RL 又贵又要命地会灾难性遗忘。JitRL 的做法是把策略改进整个搬到推理时：维护一本非参数记忆 <strong>M = {(s\_i, a\_i, G\_i)}</strong>（用 LLM Evaluator 打逐步奖励、算折扣回报 G\_t），推理时检索 top-k 相似经历估出 <strong>V̂ / Q̂ / Â</strong>（没见过的动作用"乐观值 + α/|N(s)|"鼓励探索），然后<strong>做一件极其简单的事——z'(s,a) = z(s,a) + β·Â(s,a)，把优势加到 logits 上</strong>。<strong>论文证明了这一步加法正是 KL 约束策略优化的精确闭式解（Thm 4.1）</strong>，并进一步证明价值估计与策略更新都一致收敛（Thm 4.2/4.3）——这是它能自称"RL"而不是"prompt 技巧"的底气。结果：<strong>WebArena 平均 46.98（超所有免训练基线）、held-out WebArena-Lite 60.00 vs WebRL 46.06、Jericho Zork1 终局 69 vs GRPO 的 10</strong>，三个骨干都见效，<strong>成本 \$290 vs \~\$9900（约 34×）</strong>。最讲透方法的一张表是 Table 7：<strong>JitRL 把语义上顺但实际错的选项压下去（Catalog 0.90→0.40）、把实际有效的抬上来（Marketing 0.70→1.40），甚至能把 click 换成 hover</strong>——它不生成新想法，它<strong>纠正语义先验</strong>。<strong>要打的两个折扣</strong>：① Table 2 是<strong>跨骨干对照</strong>（JitRL 用 Gemini-2.5-flash，WebRL 用 Llama-3.1-70B），正文容易高估增益 ② <strong>"零梯度"≠"零成本"</strong>，且它的自述限制第 1 条（无法发现基座永不生成的动作）是与 RL-Cap #30 同源的硬天花板。<strong>对你 lib 的价值</strong>：它的核心公式与 OPD/RLVR/MoCA <strong>落在同一个数学位置（在 logit 空间加一项）</strong>，只是"那一项"来自检索到的历史回报；而它"在基座候选集上只做重排却打赢梯度 RL"这个结果，正好给 RL-Cap #30 那条"重排不扩界"的结论<strong>补上了另一半：天花板是低的，但这块地远没耕完</strong>。

> 🔗 <strong>今日一句</strong>：LLM agent 上线后权重冻结、学不了新东西，而重新训练又贵又会忘事。JitRL 的思路极端直接：<strong>一次梯度都不做</strong>——给它配一本"经验笔记本"（非参数记忆），推理时检索相似经历算出优势，然后<strong>把 β·Â 直接加到输出 logits 上</strong>；论文证明了<strong>这一步加法就是 KL 约束策略优化的精确闭式解</strong>。结果它<strong>纯靠推理时优化就打赢了 WebRL（60.00 vs 46.06）和 GRPO（Jericho Zork1 69 vs 10），成本从 \~\$9900 降到 \$290（约 34×）</strong>。而它最诚实的地方是自述限制：<strong>只能在基座已有的选项里重排，发现不了基座想不到的动作</strong>——这正好是 RL-Cap 那条"重排不扩界"的工程极值形态。论文：arXiv:2601.18510（<strong>ICML 2026 Poster</strong>）· 代码开源 github.com/liushiliushi/JitRL · 笔记挂在 lib 中 · 2026-09-24

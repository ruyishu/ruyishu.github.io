## TL;DR

<strong>一句话：在线自蒸馏的做法是让模型看一眼正确答案，当自己的老师，再把不看答案的自己往老师那边拉。这篇论文发现，在 AIME 级别的数学题上这样做反而比纯 GRPO 差（Qwen3-8B 平均 30.6 vs 57.4）。原因是看过答案的老师对「顺着答案往下写」的词很有把握，对 Wait、Maybe、Alternatively 这种「再想想」的词很没把握，拉向老师就等于奖励抄近路、惩罚思考。AntiSD 把这个信号的方向反过来：离老师越远越加分，并用 JSD 的形状给加分封顶，再加一个熵门控防止跑飞。</strong>

- <strong>改动在哪</strong>：GRPO 的优势本来是每条回答一个数 A\_seq。AntiSD 给每个 token 再加一项：A = A\_seq − λ·φ(u)，u = 老师 log 概率 − 学生 log 概率，φ(u) = ½(softplus(u) − log2)。u 是负的（老师不认同、学生爱说）就加分，最多加 ½log2 ≈ 0.35；u 是正的（老师很认同）就扣分，不封顶。λ 最大 0.5
- <strong>门控</strong>：前 5 步不开，记下老师的中位熵 H\_warm；之后老师熵掉到 0.93·H\_warm 以下就关掉这一项，回升到 H\_warm 再打开（施密特触发）
- <strong>主结果（Table 1，avg@32）</strong>：五个底座全部超过 GRPO。Qwen3-8B <strong>57.4 → 65.7</strong>，HMMT25 39.2 → 54.4；Qwen3-4B-Instruct-2507 51.3 → 62.8（+11.5，论文的「最多 11.5 分」就是它）；Qwen3-30B-A3B 59.1 → 66.8；最强的 Olmo3-7B-Think 只 +2.1。到达 GRPO 最好成绩所需步数少 2～10 倍
- <strong>仓库</strong>：FloyedShen/AntiSD（35 star，Apache-2.0），verl fork，4 个底座 × {GRPO, SD, AntiSD} 共 12 个启动脚本 + 数据准备脚本 + 公开 wandb。没有权重、没有 30B 脚本、没有代码任务脚本
- <strong>主要问题</strong>：① GRPO 基线脚本的 loss 聚合是 seq-mean-token-mean，AntiSD / SD 是 token-mean 还加了 12000 长度掩码，论文却说「共享同一套配置」；② 代码里真正跑的是「按序列算 λ 的困惑度控制器 + 2σ 外的 u 直接置零 + ±5 截断」，比论文写的「λ = 门控 × 0.5」复杂得多；③ 附录 Table 6 里 Qwen3-8B 的「反向 KL 上升」一行和 Table 1 的「默认 SD（下降）」一行五个数字一模一样；④ 每个方法都按测试集挑最好的检查点、单次运行无方差，而且 AntiSD 的回答比 GRPO 长不少

## 一、先看例子（大白话：看过答案的老师为什么会教坏学生）

论文 Figure 1 的玩具例子：解 x² + 4x = 21。给老师看的「正确解」是：试 x = 3，9 + 12 = 21，所以 x = 3。

- <strong>默认自蒸馏</strong>：学生被拉向这个老师，学到的是「代个 3 进去，对了，结束」。答案对，但漏了 x = −7
- <strong>AntiSD</strong>：老师越笃定的词越扣分，老师越不认同的词越加分。学生被推着自己配方：(x+2)² = 25，x = 3 或 x = −7

![论文 Figure 1(a)。左：特权上下文 c（题目 + 试出来的解 x=3）；中：默认自蒸馏让学生照抄答案；右：反自蒸馏让学生自己找路，配方后得到 x=3 或 x=−7。注意图里写的是 min / max KL，正文方法实际用的是 JSD](/images/paper-reading/2026-11-24-antisd/2026-11-24-d86-1.webp)

真实数据上长什么样？作者在 Qwen3-4B-Instruct-2507 的 AIME25 回答上，把每个 token 的 u = log 老师概率 − log 学生概率 画出来（Figure 2）：

- <strong>红色（u ≫ 0，老师更认同）</strong>：Given、Assign、succeeds、holds、boxed。看过答案就知道接下来该这么写
- <strong>蓝色（u ≪ 0，老师不认同）</strong>：Wait、maybe、Another、Alternatively、look。老师已经知道答案了，觉得没必要再犹豫

按 Figure 2(b) 的位置粗估一个数字感受一下（示意数字，从图上读的）：「Wait」学生概率约 0.6、老师约 0.15，u ≈ −1.39。默认自蒸馏给它的 token 优势是 +u = −1.39，即<strong>惩罚</strong>；AntiSD 给 −φ(u) ≈ +0.24，乘 λ=0.5 后在 GRPO 优势上加 +0.12。一个「抄近路」的词，学生 0.3、老师 0.9，u ≈ +1.10，AntiSD 给 −0.35，乘 λ 后 −0.17。如果某个 Wait 的 u 掉到 −20（图 2(a) 里真有这种尾巴），反向 KL 上升会给它 +20 的权重，AntiSD 最多给 +0.35，这就是用 JSD 而不用反向 KL 的原因。

## 二、动机

- <strong>RLVR 的奖励太稀</strong>：一条几千 token 的回答只得一个 0/1，不知道是哪一步做对了。常见补法要么训一个过程奖励模型（PRM），要么找个更强的老师做在线蒸馏（OPD），都要额外模型
- <strong>在线自蒸馏很诱人</strong>：老师就是自己，只是 prompt 里多给了正确解和对错反馈。不用外部模型就有逐 token 信号。SDPO、OPSD、On-Policy Context Distillation 等一批工作在指令遵循、科学问答、工具调用上有效
- <strong>但在难数学题上不灵</strong>：已有诊断工作（Kim et al. 2026）报告自蒸馏在难数学上收益很小甚至掉分；作者在 4B～30B 五个模型上复现了同样现象，默认 SD 在每个模型上都输给 GRPO
- <strong>作者的解释</strong>：同一个模型看答案与不看答案的 log 概率差，正好是「下一个 token」与「答案」之间的条件逐点互信息 PMI(y\_t; c)。拉向老师 = 奖励被答案「暗示」的 token、惩罚被答案「否定」的 token，而后者恰好是搜索时需要的犹豫和回头

## 三、方法

### 3.1 先把自蒸馏的梯度写成「token 优势」

- 默认自蒸馏损失是每个位置的 KL(π\_S ‖ sg\[π\_T\])。对它求梯度（附录 Lemma 1），等价于给每个 token 一个优势 +u\_t，u\_t = log π\_T(y\_t) − log π\_S(y\_t)
- π\_S 和 π\_T 是同一个网络，只是 π\_T 多看了 c，所以 u\_t = log π(y\_t | x, c, y&lt;t) / π(y\_t | x, y&lt;t) = PMI(y\_t; c | x, y&lt;t)（Lemma 2）
- 两个观察：<strong>O1 方向错了</strong>，+u 奖励抄近路；<strong>O2 分布不对称</strong>，回答是学生采的，学生爱说而老师不爱说（u &lt; 0）的 token 被大量采到，而且尾巴很长

### 3.2 AntiSD 的三件事

- <strong>反方向</strong>：从「下降散度」改为「上升散度」，优势符号翻转
- <strong>用 JSD 而不是反向 KL</strong>：JSD 对应的 token 优势是 −φ(u)，φ(u) = ½(softplus(u) − log2)。u 小时 ≈ −u/4，和反向 KL 上升只差一个常数；u → −∞ 时封顶在 ½log2，正好压住 O2 说的那条长尾；u 大时线性扣分不封顶
- <strong>熵门控</strong>：上升散度不会自己停下来。老师的 token 熵（batch 中位数）低于 τ\_down 就关掉，回升到 H\_warm 再开。τ\_down = 0.93·H\_warm，H\_warm 取前 5 步（λ=0）的中位熵，五个模型共用 0.93
- 组合方式是加法：A\_{i,t} = A\_seq\_i − λ·sg\[φ(u\_{i,t})\]，λ = 门控 × λ\_max（论文 Algorithm 1）

### 3.3 特权上下文 c 长什么样（附录 C）

- 老师的输入 = 原题 + 「Your previous attempt:」后接一条正确解（同组里有人答对就随机抽一条，否则用数据集参考解，最多 3072 token，截断到出答案处）+ 「Previous assessment: Your answer is correct / incorrect.」+ 「Now solve this problem step by step.」，然后把学生原回答放在 assistant 位置重新打分
- 代码任务的反馈改成「Your code passes N of M test cases.」

### 3.4 代码里实际跑的比论文多

- λ 不是「开就 0.5、关就 0」：ca\_lambda\_mode=teacher\_perp，按<strong>每条序列</strong>的老师困惑度算 λ = clamp(0.1 × 2.0 × log(困惑度 / 目标), 0, 0.5)
- 门控信号是老师困惑度，不是正文写的老师熵（Table 3 脚注倒是写了「teacher-perplexity」）；重新打开的阈值是 1.07 × 预热中位数，正文写的是回到 H\_warm
- 还有自适应 u 截断：预热时记 u 的标准差 σ，之后 |u| &gt; 2σ 的 token 直接<strong>置零</strong>不给信号，再把 u 截到 ±5；以及 12000 token 的长度掩码。论文正文说「JSD 形状自带封顶，熵门控是唯一需要的稳定器」，和代码对不上

## 五、Limitations

### 5.1 论文自述（附录 E）

- PMI 解释只是每一步的局部刻画，不是对「上升 + 门控」整体目标的全局最优性结论，长程动态没有分析
- 只测了 Qwen3 和 Olmo-3 两个家族、4B～30B，代码只是初步试探；多轮 agent、LiveCodeBench、更丰富的特权信息（过程点评、部分得分）、30B 以上和多模态都留给以后

### 5.2 我读出来的问题

- <strong>基线配置不一致</strong>：仓库里三个模型的 grpo.sh 都写 loss\_agg\_mode=seq-mean-token-mean，实验名带「v25 … 4node」；对应的 antisd.sh / sd.sh 走 launch\_short.sh，用 token-mean、加 12000 长度掩码、实验名是「v33」。论文 Table 5 写「AntiSD 共享 GRPO / SD 的配置，只多门控参数」。loss 聚合方式本身就会影响长回答的梯度权重，论文没有做「GRPO + token-mean」的对照
- <strong>论文方法 ≠ 代码方法</strong>：论文说 JSD 自带封顶、门控是唯一稳定器、λ = 门控 × 0.5；代码是按序列的困惑度 λ 控制器（log 比值乘 0.2 再截到 \[0, 0.5\]）、|u| &gt; 2σ 置零、±5 截断、重新打开阈值 1.07 倍。读者按论文复现大概率复现不出来，要直接用仓库
- <strong>数字撞车</strong>：附录 Table 6 中 Qwen3-8B「rev. KL 上升」一行是 40.1 / 30.5 / 26.9 / 14.9 / 40.7、平均 30.6@200，和 Table 1 里「默认 SD（反向 KL 下降）」一行一字不差；正文第 4.3 节也用「去掉符号翻转（默认 SD）掉到 30.6」来论证。方向相反的两个方法结果完全相同，很像是复制错行，Qwen3-4B 上这两行就不一样（49.5 vs 45.9）
- <strong>按测试集挑检查点 + 单次运行</strong>：每个方法报的是 5 个评测基准平均分最高的那一步，没有验证集、没有多种子和方差。SD 在两个模型上的「最佳」是第 10 步，说明这个挑法对不稳定的方法尤其有利。AntiSD 优势大的模型上影响有限，但 Olmo3-7B-Think 的 +2.1 在这种挑法下不算稳
- <strong>GRPO 基线有点弱</strong>：Qwen3-4B-IT-2507 训完 GRPO 后 Minerva 从 43.4 掉到 33.2，Olmo3-7B-IT 只涨 2.6；在这样的基线上「加速 10 倍」要打折扣
- <strong>回答更长，没做等长比较</strong>：Figure 5 里 Qwen3-8B 的 AntiSD 回答长度 50 步就到约 10k token，GRPO 200 步才到约 7k；Qwen3-4B 上是约 11k vs 约 6k。一部分涨分可能就是「想得更久」，推理成本也更高，论文没给按长度或算力对齐的比较
- <strong>「思考词」的叙事是挑出来的</strong>：Figure 2(a) 里深蓝的除了 Wait，还有 :\\n\\n、wording、parse、Eight；Figure 2(b) 里 Let 离对角线并不远。论文没有统计训练后 Wait / Maybe 这些词的频率到底变了多少，「AntiSD 保护了思考 token」只停留在机理图上
- <strong>理论与做法脱节</strong>：第 5 节说逐 token 的 PMI 信号是势函数形式的奖励塑形，沿轨迹累加后不改变最优策略。这个结论只对线性的 +u 成立，AntiSD 用的是非线性的 −φ(u)，再加上按序列的 λ 和门控，「不改变最优策略」的保证不再适用
- <strong>其他小问题</strong>：图里模型名写 Qwen3-4B-IT-0527，正文写 2507；Table 5 说训练最大长度 32K，脚本里回复上限是 16384，Figure 5 里 Qwen3-4B 的 SD 长度也顶在约 16k，而正文说「顶满 32K」；Figure 1 写的是 min / max KL，方法是 JSD；PDF 首页仍标 Preprint，作者机构和注册信息对不上

## 六、前文对照

| 前文 | 它怎么做 | 和 AntiSD 的关系 |
|-|-|-|
| 09-30 SDPO | 把环境反馈和正确解放进 prompt 当老师，逐 token 拉向它做稠密信用分配 | AntiSD 正是在这条线上「唱反调」：老师构造、反馈模板基本沿用（论文引 \[7\] Hübotter et al.），仓库的配置文件还叫 sdpo.yaml、环境变量叫 SDPO\_ROOT。SDPO 在工具 / 科学问答上有效，AntiSD 说在难数学上要反过来 |
| 08-19 OPSD | 同一个模型看着答案教自己，在线自蒸馏 | AntiSD 的「默认 SD」基线就是这一类。两篇放一起看最有意思：同一个信号，一个往下降，一个往上升 |
| 11-04 SDFT | 看着示范当自己的老师，学新任务不忘旧本事 | SDFT 的目标是「贴近示范」，AntiSD 的论点是在需要搜索的任务上贴近示范会压掉探索。可以推测：示范越「唯一解」，SDFT 越可能遇到 AntiSD 说的问题 |
| 11-23 DPPO | 把 PPO 的比值裁剪换成按概率差 / 二元 KL 屏蔽 | 本周两篇都在改 GRPO 的 token 级细节：DPPO 改「哪些 token 算梯度」，AntiSD 改「每个 token 的优势」，正交可叠加。两者都是 verl 上的改动，但 AntiSD 是整棵 fork，要和 verl 主仓库的 dppo\_tv 放到一起需要自己合代码 |

## 七、启发与待跟进

- <strong>最值得带走的</strong>：「同一模型看答案与不看答案的 log 概率差 = 条件 PMI」这个视角很好用，不只用来蒸馏，也可以当作诊断工具，看一条回答里哪些 token 是被答案「暗示」出来的
- <strong>想复现</strong>：bash data/prepare\_antisd.sh，然后 recipe/antisd/run/qwen3-4b/antisd.sh 和 grpo.sh，单机 8 卡；必须设 WANDB\_API\_KEY（脚本强制要求，没有就退出）。先把 grpo.sh 的 loss\_agg\_mode 改成 token-mean 再跑一遍，看差距还剩多少
- <strong>待查</strong>：Table 6 那一行到底是不是复制错了（可以去公开 wandb 对一下）；AntiSD 的涨分有多少来自回答变长；12000 长度掩码和 2σ 置零各自贡献多少；单机 8×H20 跑 Qwen3-8B 200 步要多久
- <strong>能往下做的</strong>：① 门控现在是开 / 关，可以换成按 token 的平滑权重；② 特权信息换成过程点评或部分得分（论文自己列的方向）；③ 和 DPPO 的 mask 叠加，看是否互补；④ 多模态 RL 里「看过答案的老师」更容易只盯答案区域，可以试 AntiSD 是否能保住看图的 token

## 八、结论

AntiSD 抓住了一个很具体、也很反直觉的现象：在线自蒸馏的老师因为看过答案，会把「再想想」当成噪声来惩罚。作者把逐 token 信号解释为条件 PMI，把方向反过来，用 JSD 给奖励封顶，再用熵门控刹车，在五个 4B～30B 模型的数学 RL 上全部超过 GRPO，Qwen3-8B 平均 57.4 → 65.7，Qwen3-4B 51.3 → 62.8，脚本按「模型 × 方法」整齐给出，4B / 8B 单节点能跑。

需要打折看的地方：GRPO 基线和 AntiSD 用的 loss 聚合方式不同；代码里的稳定化手段比论文写的多很多；附录有一行数字和主表完全重复；每个方法都按测试集挑最好的检查点、单次运行；AntiSD 的回答明显更长。作为 baseline 很合适，但跑之前先把基线配置对齐。

> 💡 <strong>今日一句</strong>：看过答案的老师最会教「怎么抄」，AntiSD 的办法是反着听它的，这个想法值得试，但先把 GRPO 基线的 loss 聚合改成一样再下结论。

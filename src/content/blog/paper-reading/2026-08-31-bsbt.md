## TL;DR

*一句话：VLM 答错多模态题，到底是"看错了"（感知）还是"想错了"（推理）？——BSBT 把生成显式拆成交织的 <recognition>（感知）和 <think>（推理）块，用"盲测验证"（蒙眼文本推理器只靠感知文本答题）独立给感知打分，再按错误来源做模态感知的信用分配（MoCA）——7B 模型 9 榜平均 60.5（基础 51.9、GPT-4o 53.5），V 暴涨 +15.2、SlideVQA +19.4，感知与推理同时涨不跷跷板。*\*

- **核心问题**：多模态推理的"跷跷板效应"——增强感知往往以牺牲推理为代价；根因是**模态信用分配模糊**：答错时不知道是感知还是推理的锅
- **方法**：① 一个 system prompt 逼出 `<recognition>`/`<think>` 交织结构（不靠合成轨迹数据）；② **PV 盲测**——纯文本 Qwen2.5-14B 蒙住图像、只靠感知文本答题，答对=感知充分（R_P=1）；③ **SVV**——用结构化验证协议替代高方差 LLM judge（Acc 91.9% vs 79.1%）；④ **MoCA**——失败轨迹按 R_P 路由：bad thinking（R_O=0,R_P=1）→ 保护感知 token，bad seeing（R_O=0,R_P=0）→ 加重感知惩罚
- **结果**：MoCA (7B) 感知密集榜（V\* 86.6/HRBench 74.2/InfoVQA 87.0）+ 推理密集榜（MMMU 54.8/MathVista 73.8）**同时**涨，9 榜平均 60.5 > GPT-4o 53.5；MoCA-MiMO 平均 63.8；训练仅 16×H100、\~16h
- **主题轮换**：今日多模态推理/感知（与昨日 agentic、前日多模态 RL 区分）

## 二、动机：多模态推理的"跷跷板效应"

### 2.1 现象

- 架构/agentic 方案追求"带着图像思考"（多轮 function-calling、主动感知），但计算和工程负担重，且常出现**跷跷板效应**：感知涨一点、推理掉一块
- 大量投入换不来比例回报——**真正的瓶颈不是架构，是"不知道错在哪"**

### 2.2 根因：模态信用分配模糊

- VLM 失败时：是感知错（bad seeing）还是推理错（bad thinking）？
- 感知埋在潜在状态激活里、或与推理纠缠在最终文本里——**几乎不可能独立监督感知**
- 核心问题：*能否通过"外化感知 + 直接奖励感知"来提升多模态推理？*

> **炸裂点**：把 VLM 的生成空间显式拆成感知动作（`<recognition>`）和推理动作（`<think>`）两个子集——黑箱变成透明序列，错误的精确位置（看/想）暴露无遗，然后就能"按错误来源发奖励"。

## 三、方法：PV 盲测 + SVV 结构化验证 + MoCA 信用分配

### 3.1 交织感知-推理分解（Fig. 2）

- POMDP 视角：策略 π_θ 生成 `τ = (a_1,…,a_T)`，动作空间显式分成：

  - **感知动作 𝒜_P**：`<recognition>...</recognition>` 块，接地视觉事实、从图像提取证据
  - **推理动作 𝒜_R**：`<think>...</think>` 块，理解请求、分解问题、推断
- **不靠合成轨迹数据**：一个 task-agnostic system prompt 就能逼出这种格式，RL 再优化模型原生的分解能力

![图片展示了三种不同类型的测试示例。图(a)为“蒙眼推理者”测试，包含图像、问题及答案，如“图像3中，电子束发散度大于12 mrad”等。图(b)是“感知验证”测试，呈现图像、问题及答案，如“在状态R中，当另一个玩家选择行动T时，玩家选择行动Y的收益是多少？”等。图(c)是“结构化验证”测试，有图像、问题及答案，如“投诉收到的日期是什么时候？”等。这些测试示例与上下文提到的PV盲测、SVV结构化验证等方法相呼应，用于验证模型能力。](/images/paper-reading/2026-08-31-bsbt/2026-08-31-d27-2.png)

### 3.2 Perception Verification（PV）——"蒙眼推理者"测试（Fig. 1）

- **没有中间感知的 ground truth**，所以用功能定义：视觉细节是逻辑演绎的前提，**感知充分 = 推理可行**
- 机制：VLM 生成感知块 a_p → **纯文本推理器**（Qwen2.5-Instruct-14B）只拿问题 + 感知文本、**蒙住图像** → 若它能答对，说明感知文本是充分统计量：`R_P = 1`
- 理论：信息瓶颈代理——min I(V;A_p) − β·I(A_p;Y)，感知块超 800 token 罚
- 与人类一致性：**86.31%，κ=0.707（substantial）**；主要失败是保守性假阴性（9.19%）

### 3.3 Structured Verbal Verification（SVV）——替代 LLM judge

- 现状：规则验证器精确但脆（67.0 Acc），LLM judge 灵活但高方差（>20% 不一致）
- SVV：给验证器一个**结构化自然语言算法**（验证协议）——识别答案类型 → 提取 boxed 内容 → 类型化打分 → 输出 `\boxed{score}`；一个通用协议覆盖大多数场景
- 效果（VP-Challenge-Set, N=273）：**Acc 91.9% / F1 92.7% / 一致性 92.3%** vs LLM Prompting（79.1/82.4/78.6）

### 3.4 MoCA（Modality-Aware Credit Assignment）——按错误来源路由奖励（Fig. 1）

- 轨迹回报：`R(τ) = R_O(τ) + λ·R_P(τ)`（结果奖励 + 感知奖励，λ=0.3）
- 标准 GRPO 的病灶：失败轨迹的负 advantage **均匀**惩罚所有 token——感知没看错也被连坐（跷跷板来源）
- **MoCA 只在失败轨迹（R_O=0）上按 R_P 路由**：

  - **Bad Thinking**（R_O=0, R_P=1）：推理的锅 → **保护感知 token**：`A + α_protect·|A|`（α=0.2）——别把正确的视觉接地学没了
  - **Bad Seeing**（R_O=0, R_P=0）：感知的锅 → **加重感知惩罚**：`A − α_punish·|A|`（α=0.2）
- 附加收益：protect 机制天然免疫 PV 代理的假阴性噪声

![这张图片是关于多模态推理相关的图示，展示了多模态任务中视觉、感知、推理各环节的协同流程。左侧有手掌图标标注“Visual”，代表输入的视觉信息；中间是由“感知”（搭配眼睛图标）和“推理”（搭配大脑图标）构成的“协同”模块，该模块依托VLM实现，将感知模块的感知信息与视觉证据关联，同时结合推理过程生成相关内容；右上方是文本推理与感知接地的相关模块，用于处理用户问题并关联视觉证据，右下方的结果验证模块则由同一验证器完成最终判断，清晰呈现了多模态系统中视觉与感知、推理环节的交互逻辑，呼应了文档中模态相关的研究内容。](/images/paper-reading/2026-08-31-bsbt/2026-08-31-d27-3.png)

> **三个观察**：① **PV 用"能不能推出来"定义"看得够不够"**——不需要人工标注感知质量，一个蒙眼推理器就是免费监督；② **SVV 把"主观判断"变成"协议执行"**——验证器从"感觉对不对"降维成"按步骤跑算法"，方差从 >20% 压到 \~8%；③ **MoCA 的 protect/punish 是"分锅"的艺术**——只在失败时介入，成功的轨迹照常全量奖励，所以不破坏正常学习。

## 五、Limitations & 批判性思考

1. **论文没有独立 Limitations 章节**（诚实标注）——以下为我的阅读
2. **PV 代理有假阴性**：9.19% 的"其实看够了但推理器推不出"会被误判为 bad seeing——protect 机制缓解但没消除
3. **文本化感知有边界**：迷宫这类纯视觉模式无法转成文本；方法针对显式（System 2）推理，不覆盖所有视觉任务
4. **感知 token 预算（800）是硬上限**：复杂任务的感知粒度可能被截断
5. **双验证器工程成本**：PV+SVV 都调 14B 模型，训练需 16×H100——"轻量"是相对的
6. **消融显示对奖励质量/超参敏感**：LLM-judge 变体直接崩，α/λ 在小模型上调过——迁移到新域要重新调

## 七、Idea 落点：盲测验证驱动的模态感知 OPD（motivation / method / 预期 result）

> **撞车判定**：核心概念「多模态 OPD 不对全部 token 均匀处理、按感知/推理拆分」已被 **PCD（#16，<aware>/<cot> 分立目标）** 和 **VGS（#20，语言/视觉梯度分解）** 占据；**空位在信号层**——PCD 用「下游失败×师生分歧（PSR·KL̃）」、VGS 用「教师看图/不看图 KL（VDS）」，都没人用 BSBT 式**盲测验证（PV）**（蒙眼推理器判定感知充分性）当蒸馏的路由信号。

### Motivation

- **问题**：多模态 OPD 的轨迹级蒸馏把「看错」和「想错」混在同一个 loss——感知 token 与推理 token 的 gap 被均匀对待，等于 BSBT 批评的「一视同仁地罚」
- **蒸馏特有的三个痛点（RL 没有的）**：

  1. **教师的感知也可能瞎**：均匀蒸馏会把教师的「看错了」教给学生（负迁移）——RL 是模型自己学坏，蒸馏是教师直接带偏
  2. **两类 gap 不具可比性**：REOPOLD 熵加权、GNDPO 归一化都按「不确定性」加权，不按「模态」——感知 gap 与推理 gap 互相稀释
  3. **跷跷板同样存在**：追教师的高质量推理 token 会挤掉学生本来对的感知分布
- **现有信号的缺口**：PCD 的 PSR 是奖励统计（PCD 自证混淆「感知不足」与「题目太难」）、VGS 的 VDS 是分布距离（依赖教师校准）——都是**间接**信号；BSBT 的 PV 是**功能性充分性检验**（「能不能解出题」），最接近感知质量的因果定义，但只用在 RL 奖励层，**没用在蒸馏层**

### Method（设计草图）

- **Step 1｜外部化**：学生 rollout 强制 `<recognition>`/`<think>` 交织（复用 BSBT 的 system prompt 方案）；格式不稳时补轻量 SFT 冷启动——**门控完全依赖格式可靠**
- **Step 2｜双路拆分**：`L_OPD = α·Σ_recognition ℓ(p_T‖p_S) + β·Σ_think ℓ(p_T‖p_S)`（按 token 类型分两路蒸馏）
- **Step 3｜PV 门控（灵魂）**：

| 档位 | 门控逻辑 |
|-|-|
| A 教师侧 PV | 蒙眼验证**教师**的 recognition 文本够不够 → 教师感知不可靠时，感知 token 蒸馏降权/屏蔽（防负迁移） |
| B 学生侧 PV | 蒙眼验证**学生**的 recognition 文本够不够 → 学生没看清时感知 token 不蒸馏（教不会，留给 RL/自监督补） |
| C 双向（完整版） | A+B 组合，镜像 MoCA 的 protect/punish：失败样例里感知够 → 保护感知 token 梯度；感知不够 → 感知 token 专门强化 |

- **Step 4｜保均值归一化**：借鉴 PCD 的 `w_i ← (w_base + α·d_i) / μ_w`——「精细化而非增强」
- **可选叠加**：VGS 梯度方向手术（视觉导向 + LP 保语言）× GNDPO 尺度归一化——方向 / 尺度 / 路由三个旋钮互不冲突

### 预期 Result

- **主假设**：感知密集榜（V\* / HRBench / InfoVQA 类）显著提升，推理榜不掉（不跷跷板）——对应 BSBT 消融「PV 专治感知、推理不受伤」
- **分假设**：A 档（教师侧）主要防负迁移 → 跨规模蒸馏（8B→2B）收益 > 同规模；B 档（学生侧）主要防白教 → 在「题目难 vs 感知不足」混淆场景比 PCD 的 PSR-only 更稳；C 档（双向）优于任一单向（对应 BSBT「w/o MoCA 掉 3 分」）
- **消融链**：标准 OPD（GKD 式）→ +双路拆分 → +教师侧 PV → +学生侧 PV → 完整双向；同数据同基座对比 PCD；用 BSBT 的 9 榜三分类评测
- **风险**：① 格式不稳废掉门控（第一步先验证）；② 感知可能教不会——V\* 不涨则 idea 只剩「防负迁移」价值；③ 双 PV 推理器成本（14B×2/rollout，可试 3B）
- **新颖性**：拆分概念撞 PCD/VGS，但「盲测验证驱动的蒸馏路由」未见公开——动手前先做一轮 A 会核查

## 八、启发与待跟进

> **核心启发**：
> 1. **"能不能推出来"是感知质量的免费代理**：没有感知 ground truth 时，用"下游推理可行性"反向定义感知充分性——PV 是信息瓶颈的务实实现，比任何启发式标注都干净。
> 2. **分锅要分到"模块级"**：标准 GRPO 的失败轨迹连坐惩罚是跷跷板的根源——MoCA 证明"只在失败时按来源路由（protect/punish）"就能同时保住两端。
> 3. **验证器要从"判断"降维成"执行"**：SVV 把 LLM judge 的主观估计变成结构化协议执行，一致性从 78.6 提到 92.3——RL 的稳定性很大程度上是验证器稳定性的投影。

### 待跟进 checklist

- [ ] **BSBT × PCD（最直接）**：把 PV 的 R_P 当 PCD 的感知可靠性信号 PSR——"盲测验证"驱动的感知加权蒸馏（recognition 文本当特权教师，OPD 给学生）

- [ ] **BSBT × OPD**：蒙眼推理器当蒸馏教师——教师"看"（recognition）学生"看"（蒸馏），免去学生自己学外化感知的成本

- [ ] **PV 边界扩展**：文本化不了的感知（迷宫/密集小目标）用 ACTIVE-O3 式 zoom 兜底——"内部 recognition + 外部 zoom"混合感知

- [ ] **SVV 协议自动化**：答案类型识别/打分规则能否用规则引擎或小模型自动生成，替代手写协议

- [ ] **多模态信用分配的通用化**：MoCA 的 protect/punish 路由能否推广到"工具选择"（AutoTool 的选/用分锅）

- [ ] **训练成本**：16×H100 对 7B 偏重，PV 代理能否换更小的推理器（3B）保性能

## 九、今日阅读结论

BSBT 是"一个分锅问题 + 三个干净设计"的 ICML 2026 Oral 佳作：先用 `<recognition>`/`<think>` 交织结构把 VLM 的黑箱感知外化成可审计文本（不靠合成数据），再用**盲测验证**（蒙眼推理器）和**结构化验证**（SVV）把"感知质量"和"答案正确性"都变成可靠奖励，最后用 **MoCA 按错误来源路由**（bad thinking 保护感知、bad seeing 惩罚感知）——7B 模型九榜平均 60.5 同时压过基础（51.9）和 GPT-4o（53.5），跷跷板被拆掉了。它和你的 PCD 是同一道题的两种解法（蒸馏梯度层 vs RL 奖励层），和 ACTIVE-O3 是"内化感知 vs 外部工具"的正面竞争——而**把 PV 的盲测信号接进 PCD 的软 AND 门**，就是你"监督信号精细化"主线上下一个可以直接动手的组合。

## TL;DR

<strong>一句话：多轮 agent 平时是「见招拆招」，每一步只看眼前状态出动作，容易短视、来回折腾。StraTA 让模型开局先写一句全局策略（比如「先搜铜镜，再在价格内挑一个买」），之后每一步都把这句策略放在 prompt 最前面；训练时每道题采 4 个策略、每个策略跑 8 条轨迹，GRPO 同时比「哪个策略好」和「同一策略下哪条执行好」。</strong>

- <strong>做法</strong>：两层分组。策略组 4 个策略之间比，策略的分数取它 8 条轨迹里<strong>前一半</strong>的平均；动作组是同一策略下 8 条轨迹之间比。外加两个小技巧：先多采 32 个候选策略，用句向量做最远点采样挑出 4 个最不像的；每条轨迹跑完让模型自己点名「既没按策略走、也没推进任务」的步骤，每步扣 0.1
- <strong>主结果（Qwen2.5-7B-Instruct）</strong>：ALFWorld 成功率 <strong>93.1%</strong>（GiGPO 90.8、GRPO 79.3）；WebShop 成功率 <strong>84.2%</strong>（GiGPO 72.8、GRPO 71.5）；SciWorld 总分 <strong>63.5</strong>（ScalingInter 57.0、PPO 51.4、GRPO 41.8）。1.5B 上 WebShop 成功率 82.5，比 GiGPO 的 65.0 高 17.5
- <strong>算力</strong>：单机 8×H100，150 步，每步 16 道题 × 32 条轨迹；仓库给了 7B 三个环境的 StraTA / GRPO / PPO 脚本和权重
- <strong>⚠️ 先说几个坑</strong>：① 论文说「只比 GRPO 慢一点点」，自己的 Figure 3 是每步 377.8 秒对 301.6 秒，<strong>慢 25%</strong>，训练段慢 50%；② 正文说 σ 越大越好「稳定提升」，但 σ=2 时 WebShop 成功率 56.6，<strong>比 σ=1 的 66.7 还低</strong>；③ GiGPO、RLOO 的数字是从 GiGPO 原文抄的，不是在同样 32 条轨迹预算下重跑的；④ 所有消融只在 3B、batch 4 上做，和主表的 1.5B / 7B、batch 16 对不上；⑤ 只在 ALFWorld / WebShop / SciWorld 三个老文本环境上验证，没有搜索、工具调用、GUI；⑥ 没有独立 Limitations 章节

## 一、先看例子（大白话：网购一面 170 美元以内的铜镜）

WebShop 里的一道题：帮用户买一面 bronze mirror，价格不超过 170 美元。网页能做的动作只有两种：search\[关键词\] 和 click\[按钮\]。

<strong>普通 agent（见招拆招）</strong>：每一步只看当前网页。论文 Figure 1(a) 画的就是它的典型走法：

1. 第 1 步：search\[bronze mirror\]
2. 第 2 步：觉得不够准，又 search\[bronze mirror under \$170\]，把价格塞进了搜索词
3. 第 3 步：结果里挨个看，点进了 bronze wall hook（铜挂钩，不是镜子）
4. 第 4 步：发现不对，click\[back\] 退回去

四步里有三步在绕：重复搜、点错、回退。论文把这叫短视探索、无谓回退、前后不一致。

<strong>StraTA</strong>：开局先写一句策略，「先搜铜镜，再在价格限制内挑一个买」，之后每一步的 prompt 最前面都带着这句话：

1. 第 1 步：search\[bronze mirror\]
2. 第 2 步：这页没有合适的，click\[next page\]
3. 第 3 步：第二个商品看着对，click\[amanti art door mirror\]
4. 第 4 步：价格在限制内，click\[buy now\]

差别不在模型变聪明了，而在<strong>动作有了一个统一的方向</strong>：价格是「挑」的时候才看，不是塞进搜索词里乱试。训练时再让模型在 4 个不同策略之间比较，慢慢学会写出更好用的策略。

![论文 Figure 1。（a）普通 agent 每步只看局部状态，在 WebShop 铜镜任务里重复搜索、点进铜挂钩、再回退。（b）StraTA 开局生成一句全局策略 z，之后每步动作都以 z 为条件。（c）WebShop 训练曲线：StraTA（红线）约 40 步就到 0.5 以上，150 步时约 0.78；PPO 约 0.63、GRPO 约 0.56](/images/paper-reading/2026-11-13-strata/2026-11-13-d79-1.webp)

## 二、动机

作者的判断是：现在的多轮 agent RL（PPO、GRPO、GiGPO）基本都是「纯反应式」，每一步要同时决定两件事：<strong>整体怎么打</strong>和<strong>下一步点哪里</strong>。这两件事搅在一起，带来两个问题：

- <strong>探索差</strong>：没有全局计划，采出来的轨迹往往只在局部打转，一组 32 条里很多条犯的是同一种错
- <strong>信用分配难</strong>：环境只在最后给一个成败分，GRPO 把这个分广播给轨迹里所有步骤，好步骤和废步骤拿到一样的分

人做复杂任务一般是先定个大方向，再照着执行，回头再看方向对不对。StraTA 就是把「先定方向」显式做成一个要训练的输出。

注意论文用的是「非累积」设置（沿用 GiGPO）：每一步的 prompt 不带完整历史，只带当前状态（脚本里 num\_histories=2，即最近两步）。这正是策略有用的地方：历史被截断了，那句开局策略就成了唯一贯穿全程的信息。

## 三、方法

![论文 Figure 2。（a）每题采 N 个策略，每个策略跑 M 条轨迹，形成 1 个策略组和 N 个动作组；策略分数等于它 M 条轨迹前 δ 比例的平均。（b）先过采样 σN 个候选策略，用句向量做最远点采样挑出 N 个最不相似的。（c）轨迹结束后模型自评，把既没按策略走、也没推进任务的步骤标出来，每步奖励扣 κ](/images/paper-reading/2026-11-13-strata/2026-11-13-d79-2.webp)

### 3.1 先写策略，再带着策略行动

开局只看任务描述，先生成一段策略 z（用 strategy 标签包起来），之后整局固定不变。每一步的 prompt 结构是：任务描述 + 「你必须严格遵守以下策略：z」+ 当前状态 + 动作要求。这样一条轨迹就变成：z，然后 (s1, a1) …… (sT, aT)。

### 3.2 两层分组的 GRPO

每题采 4 个策略，每个策略下各跑 8 条轨迹，一共 32 条。于是有两种组：

- <strong>动作组</strong>（4 个）：同一策略下 8 条轨迹互相比，环境给的成败分广播给这条轨迹的每一步，组内做标准化，跟普通 GRPO 一样
- <strong>策略组</strong>（1 个）：4 个策略互相比。一个策略的分数 = 它 8 条轨迹里分数最高的那一半（δ=0.5，即前 4 条）的平均。理由是：执行时的随机失误不该算到策略头上，看的是「照这个策略最好能做到多好」

两种输出（策略文本和每步动作）都再加两个辅助项：长度超过上限一半（λ=0.5）开始线性扣分，超上限直接 −1；格式不对 −1。最后整体裁到 \[−1, 1\]。两种组的优势都按 GRPO 公式算，损失直接相加。

### 3.3 让 4 个策略真的不一样

作者发现即使温度 1.0，同一道题采出来的策略也几乎一个样，策略组里没得比。办法是先采 σ×N = 32 个候选，用 MiniLM-L6 编成向量，先选最靠近中心的那个，然后每轮挑「和已选集合最大相似度最小」的那个，直到选够 4 个。论文测得每步只多花 5.8 秒。

### 3.4 模型自己给自己挑错

每条轨迹跑完，把策略和完整动作历史交给同一个模型，让它列出「既没按策略走、也没推进任务」的步骤编号，比如输出 \[2, 4, 5\]。被点名的步骤奖励扣 κ=0.1。自评这一步本身不拿奖励、不参与训练。每步多花 6.1 秒。

### 3.5 工程上怎么跑

- 框架：rLLM（底层 verl），环境用 AgentGym 起 HTTP 服务（脚本里 ALFWorld 服务跑在 36001 端口）
- 每轮最多步数：ALFWorld 50 步，WebShop 15 步，SciWorld 20 步；奖励都是按步数衰减的成败分，越快完成分越高
- 脚本关键项：train\_batch\_size=16、num\_stras\_per\_run=4、num\_trajs\_per\_stra=8、num\_cands\_per\_stra=8、lambda\_coef=0.5、delta\_coef=0.5、kappa\_coef=0.1、total\_training\_steps=151、FSDP 参数和优化器都 offload

## 五、Limitations

<strong>⚠️ 本篇没有独立 Limitations 章节。</strong>结论段只有一句：效果依赖生成策略的质量；环境中途变化大时，固定不变的策略会束手束脚。

<strong>读出来的问题</strong>：

1. <strong>速度表述和自己的图打架</strong>：377.8 对 301.6 秒是慢 25%，训练段慢 50%，不是「略慢」。多出的训练时间大概率来自策略文本和自评带来的额外序列，论文没解释
2. <strong>σ「稳定提升」不成立</strong>：WebShop 成功率 σ=1 是 66.7，σ=2 掉到 56.6，σ=4 是 69.1。ALFWorld 上 σ=2 和 σ=4 都是 83.1。单调的只有 σ=8 这一个点比别的高
3. <strong>基线预算没对齐</strong>：GRPO、PPO 是作者按每题 32 条轨迹重跑的，但最强的对手 GiGPO 和 RLOO 是抄 GiGPO 原文，原文用的组大小和这里是否一样，论文没说
4. <strong>缺最关键的一组对照</strong>：没有「只在 prompt 里让模型先写计划、但不做策略层 RL」的基线。Vanilla 已经同时改了 prompt 和奖励结构，GRPO → Vanilla 的涨分里，有多少是「先写计划」这句 prompt 带来的，分不出来
5. <strong>消融和主表不在一个设置</strong>：消融全在 3B + batch 4，主表是 1.5B / 7B + batch 16。完整 StraTA 在 ALFWorld 上 88.6 只比 Diverse 的 87.9 高 0.7，Look 列 71.8 还低于 Diverse 的 84.6，Cool 列 72.0 低于 Diverse 的 78.7
6. <strong>和闭源模型的比较不公平</strong>：摘要说 SciWorld 上「超过前沿闭源模型」，但闭源模型是零样本提示，StraTA 是在这个环境上训过 150 步的，这不是同一种比较
7. <strong>环境偏老、偏简单</strong>：ALFWorld、WebShop、SciWorld 都是文本环境，ALFWorld 已经被刷到 90% 以上。没有搜索、工具调用、代码、GUI 这类当前更热的 agent 场景，底座也只有 Qwen2.5
8. <strong>自评有 1/5 冤枉</strong>：精确率约 80%，意思是被扣分的步骤里大约五分之一其实没问题。论文靠 κ=0.1 很小来兜底，κ=1.0 时 WebShop 成功率就掉到 61.8
9. <strong>仓库不全</strong>：1.5B 主实验没有脚本和权重；代码停在 v1 时期，v2 改了什么不清楚

## 六、前文对照

| 前文 | 它怎么做 | 和 StraTA 的关系 |
|-|-|-|
| GiGPO（09-08） | 同一状态在不同轨迹里出现时，按状态再分一次组，给每一步单独算优势 | StraTA 的直接对手和配置来源（超参大多照抄 GiGPO）。GiGPO 在轨迹内部细分步骤，StraTA 在轨迹上面加一层策略；两者可以叠加，论文没试 |
| HiPER（10-30） | 让 agent 先说清「我现在在干哪件事」，做层级信用分配 | 都是给 agent 加一层「高层意图」。HiPER 的子任务会随过程切换，StraTA 的策略整局固定——这正是 StraTA 自己承认的短板 |
| D-CORE（11-10） | 先自蒸馏学会把复杂工具调用任务拆开，再用 DA-GRPO 找回反思 | 都是「先规划再执行」。D-CORE 靠 SFT 教会拆任务，StraTA 不用任何示范，直接用策略组的相对比较让模型自己学会写策略 |
| ActGuide-RL（11-12） | 一组全错时，把专家动作清单塞进 prompt 当提示，再把能力收回无提示模型 | 都是在 prompt 里加一段指导。ActGuide 的指导来自外部专家、只在全错时加；StraTA 的指导由模型自己写、每局都加、而且参与训练 |
| Context-Folding（11-09） | agent 自己开分支干细活，干完只留一句总结 | 都在对付长程任务的上下文问题。Context-Folding 压缩过去，StraTA 用一句策略概括未来；StraTA 的非累积设置下历史本来就被截断，策略起了替代长记忆的作用 |

## 七、启发与待跟进

- <strong>最直接能做的</strong>：让策略可以中途修订。比如每 K 步或者每次环境反馈出乎意料时，重新生成一次策略，再把「改策略」也当成一个要比较的组。论文自己列为未来方向
- <strong>补上缺的对照</strong>：用仓库现成的 GRPO 脚本，只把 prompt 改成「先写计划再行动」、不做策略层优势，看 GRPO → StraTA 的涨分里 prompt 占多少。7B 单机 8 卡、150 步，成本可控
- <strong>换环境</strong>：把两层分组搬到搜索 agent（比如 ActGuide-RL 的 GAIA / WebWalker）或工具调用（BFCL），看策略在开放环境里还灵不灵
- <strong>和 GiGPO 叠加</strong>：策略组管高层，GiGPO 的状态锚点管低层，两者正交
- <strong>待查</strong>：v2 和 v1 的差异；GiGPO 原文用的组大小，确认基线预算是否对齐；训练段慢 50% 的来源

## 八、结论

StraTA 的想法很朴素：开局先写一句策略，之后照着走；训练时让 4 个尽量不同的策略互相比，同时让同一策略下的 8 条轨迹互相比。结果在三个文本 agent 环境上都是第一，WebShop 成功率比 GiGPO 高 11–17 个点，单机 8 卡就能复现，仓库和 7B 权重都在，适合当 baseline。

需要打折看的地方：速度比 GRPO 慢 25%（论文说「略慢」）；σ 的消融不单调；最强基线是抄的；缺「只改 prompt」的对照；环境偏老、不含搜索和工具调用。

> 💡 <strong>今日一句</strong>：先想清楚怎么打，再一步步打——难的不是写出计划，而是让 RL 知道哪个计划更好。

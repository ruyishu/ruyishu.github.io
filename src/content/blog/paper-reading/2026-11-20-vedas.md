## TL;DR

<strong>一句话：多模态「隐式推理」不把思维链写成文字，而是让模型连吐 4 个隐藏向量当作「想了 4 步」，再直接出答案。Vedas 发现这样训的时候图像 token 几乎没被学到，于是每一步按注意力挑 32 个最相关的图块塞回上下文，再把这块区域裁下来重新编码，拿来监督这一步的视觉向量；另外加一个小路由器，让难的 token 在同一层多算一遍。</strong>

- <strong>要治的病</strong>：作者看训练时的梯度，说图像 token 的梯度远小于文字 token，模型主要靠文字和隐向量答题；另外难样本到了训练后期梯度还在大幅抖动，固定层数「算不够」
- <strong>做法</strong>：两块零件 + 一个课程。① SCF-VR 视觉回放：每步按注意力取 top-32 图像 token 塞回去，再找 3×3 最密的格子裁图、重编码、做 MSE 自蒸馏；② RDS 路由深度：每层一个小 MLP 打分，选出的 token 在这一层再跑一遍（D=1）；③ 课程：先用完整 CoT 训，再一步一步把文字推理换成 latent（Coconut 那套）
- <strong>主结果</strong>：Qwen2-VL-7B 上 M3CoT 73.0（最强隐式基线 IVT-LR 69.8、显式 Chain-of-Focus 64.3），只要 7 步自回归（Chain-of-Focus 185.7 步）；Qwen2.5-VL-7B 用 30K 数据训完，MMVP 65.67 → <strong>76.67</strong>、HallusionBench 56.57 → 68.63，但 MathVision 只 25.60 → 25.89
- <strong>算力与仓库</strong>：LoRA r=64，论文用 16×H20、单次约 20 小时；仓库训练脚本按单机 8 卡写，<strong>但只有 M3CoT 这一条线的入口文件在</strong>，主表 OneThinker 30K 的训练入口、7 个评测脚本调用的推理文件、权重都没放，也没有 license
- <strong>主要问题</strong>：① Table 4 里「完整方法」的分数（62.9/76.5/51.9）和 Table 3 里「什么都不加的 Base」一模一样；② λ 怎么设，正文两处说法正好相反；③ 仓库自带的 Figure 1 图注写的是「图像 token 梯度更大」，和论文正文「更小」相反，而这是全文的立论起点；④ 号称推理时关掉视觉回放，代码的 generate 却直接调训练用的 forward

## 一、先看例子（大白话：这座雪山适合新手吗）

论文 Figure 5 的例子：一张滑雪的照片，问「这座山适合哪类滑雪者？A 只适合新手 B 不确定 C 只适合高手 D 都行」。

<strong>普通显式 CoT 模型</strong>会写一大段文字再答。论文 Table 1 里，显式方法平均要生成 73～740 个 token，像 Chain-of-Focus 在 M3CoT 上平均 185.7 步、2.63 秒。

<strong>Vedas</strong> 不写字，只吐 4 个「隐向量」，然后直接输出答案 C，总共约 7 步、0.86 秒。论文把这 4 个隐向量对应的 CoT 原文贴了出来：第 1 步「滑雪的人用手撑地，说明他站不稳」，第 2 步「山对他来说很难，而且坡很陡」，第 3 步「综合起来新手滑不了，选 C」。

关键在于每一步「想」的时候，它会回头再看一眼图：按注意力挑出最相关的 32 个图块，把这些图块的特征塞回上下文。路由器的可视化显示它挑中的是雪、人的四肢和树。另一个例子 Figure 6：问「街上那块警示牌是干什么的」，第 1 步裁出的就是写着 do not enter 的牌子，答案「这是单行道」。

一句话：<strong>思维链不写出来可以，但每想一步都要把图里相关的那块重新拿回来看</strong>。

## 二、动机

- <strong>隐式推理为什么香</strong>：不写 CoT 文字，推理只要几步，Table 1 里自回归步数从上百降到 7～10，延迟从 2～7 秒降到 1 秒左右
- <strong>观察一（视觉-文字优化不平衡）</strong>：作者画了每个 token 的梯度范数（Figure 1a），正文说图像 token 的梯度「明显小」，模型主要靠文字和隐向量出答案，图像没被学好
- <strong>观察二（固定深度不够用）</strong>：按早期验证结果把数据分成「一直对」和「一直错」两组，看 QKVO 投影矩阵 LoRA 更新量的核范数（Figure 1b/1c）。容易样本几个 epoch 后平稳下降，难样本到第 5～7 个 epoch 还在高位震荡
- <strong>想法</strong>：针对观察一，推理时每步把相关图块「重放」回来，并用裁图重编码的高清特征去监督它；针对观察二，让难 token 多算几遍
- 已有的多模态隐式推理（Laser、Monet、LVR）多数需要大量带中间步骤标注的数据（Laser 267K、LVR 470K），Vedas 只用 30K 条 CoT 数据，不直接监督隐向量

## 三、方法

### 3.1 底子：隐式推理怎么跑

- 输入 = 问题 + 图像 token。推理阶段固定 Tr=4 步：每步把上一步最后一个位置的 hidden state 当成下一个输入向量（不过 LM head、不变成文字），这就是一个 latent
- 4 个 latent 拼进上下文后，正常自回归输出答案；loss 只有答案部分的交叉熵 + 下面的自蒸馏 loss
- CoT 数据按「\\n\\n」切成步，最多保留 4 段

### 3.2 SCF-VR：每一步把图重新看一遍

- <strong>挑图块</strong>：把所有层、所有头的注意力取平均，取最新 token 对所有图像 token 的注意力，选 top-K=32 个，并且记一个「已访问」集合，下一步不再重复挑。被选中的图像 embedding 用 softmax 后的注意力加权，和这一步的 latent 一起塞回上下文
- <strong>自蒸馏</strong>：在 G×G 的图像网格上找一个 W×W（W=3）窗口，让它覆盖最多被选中的 token；把这个窗口映射回原图坐标、裁下来、双线性放大到编码器输入尺寸，过同一个视觉编码器，平均池化成一个参考向量 u\_ref
- 被选图块池化后的粗向量经过一个两层 MLP（TokenSR，「token 超分」）去逼近 u\_ref，MSE loss，权重 λ
- 论文说<strong>推理时关掉 SCF-VR</strong>，不额外花算力

### 3.3 RDS：难 token 在同一层多跑一遍

- 每层一个小 MLP 路由器给所有 token 打分，选 top-α（α=32）个，在这一层再过一遍同一个 Transformer 块（共享权重），其余 token 跳过；D=1，也就是最多多跑一遍
- 多跑出来的结果加上「第几遍」的位置编码，和原 hidden state 相加
- 作者给了一个泛化界（Theorem 3.1），说在 6 条假设下 top-K 深度扩展的总体风险更低。证明在附录，和实验里怎么选 α、D 没有直接对应

### 3.4 课程

先用完整显式 CoT 训，然后每个阶段把一段文字推理换成一个 latent，直到 4 段都换完。这是 Coconut（Hao et al.）的做法，论文 Table 4(a) 说加课程比不加高 0.9。

### 3.5 仓库里实际是怎么做的（和论文有出入）

- <strong>裁图不是一个窗口</strong>：qwenvl\_vegas.py 里 num\_sr\_regions 默认 4，代码注释是「TokenSR 拼图时参与的高注意力 3x3 窗口数（多区域覆盖多个注意力热点）」，把 4 个窗口拼成一张图再编码；论文只写一个 W×W 窗口
- <strong>推理时没有关掉</strong>：generate 里每一步 latent 迭代都直接调训练用的 forward（还传了 labels 和原图），use\_tokensr 打开时推理也会裁图、重编码
- <strong>「--progressive False」其实是开</strong>：参数用 argparse 的 type=bool，传字符串 False 会被转成 True，所以脚本写「不用课程」，实际跑的是课程
- <strong>Qwen2.5 分支跑不起来</strong>：run\_onethinker.sh 传 --model\_version v\_2\_5，代码判断的是 'v\_2.5'，两个分支都不进，model 变量未定义；而且这个脚本调的 qwenvl\_run\_onethink.py 根本不在仓库里
- 模型路径写死成 ./modelscope/.../Qwen2-VL-2B-Instruct 或 Qwen2.5-VL-3B-Instruct，跑 7B 要自己改；yaml 里 num\_epochs 8、每卡 batch 2 × 梯度累积 4，论文是 16 epoch、每卡 batch 8；三个脚本 ratio（即 λ）都写 0.2
- 主模型文件第一行是 from tkinter import image\_names，没装 tkinter 的服务器会直接报错

## 四、实验

### 4.1 设置

- <strong>两套训练</strong>：① Table 1：在 M3CoT、ScienceQA、GQA 三个带推理链的数据集上各自训、各自测；② Table 2：从 OneThinker 挑约 30K 条，在 Qwen2.5-VL-7B 上训一次，测 9 个通用 benchmark
- 超参：Tr=4、α=32、D=1、W=3；lr 4e-5，每卡 batch 8，ZeRO-2，16 epoch；λ=1.0（2B/3B）、0.2（7B）；图像 512×512（OneThinker、GQA）或 280×280（M3CoT、ScienceQA）

### 4.4 消融

- <strong>Table 3（逐个加零件，M3CoT）</strong>：Qwen2-VL-2B 44.2 → +RDS 47.6 → +RDS+SCF-VR 51.2；Qwen2-VL-7B 63.7 → 65.2 → 66.4；Qwen2.5-VL-3B 62.9 → 64.5 → 65.3；Qwen2.5-VL-7B 71.1 → 72.9 → 73.9。RDS 单独涨 1.5～3.4，再加 SCF-VR 又涨 0.8～3.6，2B 涨得最多

## 五、Limitations

### 5.1 论文自述（附录 D）

- 路由让推理延迟有些波动，对实时场景需要额外调度
- 路由器是数据驱动学出来的，理论上路由准不准会影响泛化
- 就这两条，没有提数据规模、底座范围、评测设置

### 5.2 我读出来的问题

- <strong>两张表的数字撞车</strong>：Table 4 的「Base」被定义为「已经加了 RDS 和 SCF-VR」，加课程后是 62.9 / 76.5 / 51.9；而 Table 3 里 Qwen2.5-VL-3B「什么都不加的 Base」也恰好是 62.9 / 76.5 / 51.9，加满两个零件后是 65.3 / 78.5 / 53.6。同一个模型、同一个完整配置，两张表差了 2.4 分，三列数字还和另一行完全相同，很像抄错了行
- <strong>λ 的说法自相矛盾</strong>：实现细节和 Table 5 图注都说 2B/3B 用 λ=1.0、7B 用 0.2；Figure 4 的正文却说「7B 在 λ=1.0 最好、2B 在 0.2 最好」，还据此讲了一段「小模型更需要视觉」的解释。仓库三个脚本又全是 0.2
- <strong>立论起点前后不一</strong>：arXiv v5 正文说图像 token 梯度「明显小」，所以要加强视觉；仓库里的 Figure 1（observation.png）图注写的是图像 token「梯度更大、还有突刺，更难优化」。同一张图两种相反的读法
- <strong>平均涨幅算不出来</strong>：正文说比 IVT-LR「平均高 2.63」，按 Table 1 六个数（两种底座 × 三个数据集）算是 (3.2+3.1+1.6+2.6+2.5+1.3)/6 = 2.38；「比显式 CoT 高近 30%」只对最弱的 Multimodal CoT（42.5）成立，对 Chain-of-Focus 只高 8.7
- <strong>推理开销说得太轻</strong>：Qwen2-VL-7B 上比 IVT-LR 慢 21%～28%；而且仓库 generate 每步都走训练 forward，论文「推理时关掉 SCF-VR」在代码里没体现
- <strong>对模型结构的依赖重</strong>：必须 eager attention 才能拿到所有层的注意力（用不了 FlashAttention），还要改每个底座的建模文件（Qwen2-VL / Qwen2.5-VL 各一份 100KB+）。换 Qwen3-VL 不是改个配置的事
- <strong>仓库只能复现一条线</strong>：主表（OneThinker 30K）训练入口不在，7 个通用评测的推理文件不在，唯一的 M3CoT 推理脚本还 import 了一个不存在的模块；无权重、无 license
- <strong>算力超出单机 8 卡</strong>：论文 16×H20 单次 20 小时；脚本虽然按 8 卡写，但每卡 batch 改成了 2
- <strong>理论和方法脱节</strong>：Theorem 3.1 的泛化界要 6 条假设，结论是「top-K 深度扩展风险更低」，但没告诉你 α、D 怎么选，实验里 D 也只取了 1

## 七、启发与待跟进

- <strong>最值得带走的</strong>：隐式推理里「每一步按注意力把图块塞回来」这个动作本身很便宜（top-32 索引 + 加权），可以单独拿出来，不要路由器、不要 TokenSR，看能保住多少分（Table 3 里 RDS 单独就有 1.5～3.4 分，SCF-VR 单独的数字论文没给）
- <strong>想复现先走 M3CoT 这条</strong>：用 Qwen2-VL-2B 跑 qwenvl\_run.py，补掉 tkinter import、改模型路径，目标 Table 3 的 44.2 → 51.2；推理脚本要自己把 import 改成 qwenvl\_vegas 的 VEGAS
- <strong>待查</strong>：Table 3 / Table 4 到底哪个数字对；λ 到底是大模型用 1.0 还是 0.2；同 30K 数据的显式 CoT SFT 对照；推理时开 / 关 TokenSR 对准确率和延迟的影响；Figure 1 两个版本到底哪个是真实观测

## 八、结论

Vedas 做的事情很好懂：隐式推理不写字，那就在每一步把图里最相关的 32 个图块塞回去，再用裁图重编码的特征逼它看清楚；难的 token 多算一遍。在 M3CoT / ScienceQA / GQA 上比最强隐式基线高 1.3～3.2 分，只要 7～9 步自回归；在 Qwen2.5-VL-7B 上 MMVP 和 HallusionBench 各涨 11～12 分。

需要打折看的地方：两张消融表的数字撞车，λ 的说法前后相反，仓库版 Figure 1 和正文结论相反；Qwen2-VL-7B 上延迟其实比 IVT-LR 慢 21%～28%；仓库只有 M3CoT 一条线能接着做，主表跑不起来，没权重、没 license；方法还绑死 eager attention 和改建模文件。

> 💡 <strong>今日一句</strong>：「每想一步就回头再看一眼图」这个动作值得偷，但这篇的数字和仓库都要自己先跑一遍 M3CoT 再信。

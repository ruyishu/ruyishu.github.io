## TL;DR

**一句话：OPSD 让同一个 LLM 同时当教师和学生——教师策略多看一个"标准答案 y⋆"，学生只看题目，学生在自己的 rollout 上接收教师逐 token 的密集分布监督；不需要更大外部教师，数学推理上 4–8× 的 token 效率碾压 GRPO，性能匹配或反超。**

- **核心发现**：RLVR 的痛点不是"策略学不动"，而是序列级稀疏奖励——奖励多样性崩溃时（batch 内奖励标准差为 0）梯度直接消失；SFT / off-policy 蒸馏的痛点是分布不匹配。两者都能被"特权教师 + 逐 token 蒸馏"同时解决。
- **方法 OPSD**：同一模型、同一参数 θ，靠上下文区分师生——教师 pT(·|x, y⋆) 多看到参考解答，学生 pS(·|x) 只看题目；学生在自己的采样轨迹 ŷ 上，逐 token 最小化 D(pT ‖ pS)，梯度只过学生。配逐 token 点式 KL 裁剪稳定训练。
- **炸裂结果**：Qwen3-1.7B AIME24 51.5→57.2、AIME25 36.7→43.9，平均 37.1→43.4（GRPO 仅 37.7）；每问题只需 1 个 rollout / 1024 token，GRPO 要 8 个 rollout / 16k token，且 100 步内 GRPO 因奖励多样性崩溃停滞。

## 一、先看一个例子

> **例子**：同一道数学题，两个"人"用同一套参数：学生 prompt 只有题目 x；教师 prompt 是题目 x + 参考解答 y⋆。教师被提示先"合理化"（rationalize）标准答案、再生成自己的解法——但教师**不真正生成 token**，合理化通过一次前向传播隐式完成。

![这张图片展示了同策略自蒸馏的师生模型设置示例，包含标注为“Student Prompt”的红色区域和“Teacher Prompt”的绿色区域。上方学生区域的题目为求函数$f(x)=3x^2+2x-5$在$x=2$处的导数，仅预留了答案填写栏。下方教师区域的题目与学生区域完全一致，额外提供了参考解答，明确写出先求出导数$f'(x)=6x+2$，再代入$x=2$得到结果14，还引导学生理解参考解答后用自己的方法解题，预留了答案栏。该示例对应文档中OPSD让模型看着答案教自己的同策略自蒸馏思路，即以答案本身作为师生间的学习信号。](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-1.webp)

- **学生**：自己采样 rollout ŷ（可能对、可能错、可能卡壳）——这是"on-policy"的来源
- **教师**：顺着学生已写的前缀，给出"如果是我会怎么续"的下一个 token 分布（因为教师多看了 y⋆，分布明显更聪明）
- **对齐**：学生在自己走过的每个 token 位置上向教师分布对齐——只改学生，教师冻结

> **直觉**：人类学生拿到参考答案，能一步步看懂推导、自我纠正——"合理化（理解答案）"比"生成（从零解题）"容易得多。OPSD 赌的正是这一点：一个足够强的模型，给它 y⋆ 就能当自己最好的老师。

## 二、动机：三种训练范式各有各的坑

### 2.1 现有范式的困境

![该图片为表格，对比了四种强化学习相关蒸馏方式的不同特性，分别是SFT/Off-Policy Distillation、GRPO、On-Policy Distillation以及文中提出的On-Policy Self-Distillation。表格涵盖On-Policy Data、Dense Learning Signal、Low Sampling Cost、No External Teacher这四个评价维度，每个维度下对应不同的标识，其中On-Policy Self-Distillation在四项维度均符合要求，其他蒸馏方式则存在不同项的不符合情况，直观体现了所提方法的优势。](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-2.webp)

| 范式 | 监督信号 | 采样方式 | 致命伤 |
|-|-|-|-|
| RLVR（GRPO） | 序列级稀疏奖励 | on-policy（8 rollout / 题） | 奖励多样性崩溃 → 优势为 0 → 无梯度；采样成本高 |
| SFT | 逐 token（但来自固定数据） | off-policy | 分布不匹配（曝光偏差）；简洁解答数据反而缩短测试时生成 |
| Off-policy 蒸馏 | 逐 token | off-policy | 需要更大外部教师 + 分布不匹配 |
| On-policy 蒸馏（GKD） | 逐 token 密集 | on-policy | **仍需要单独的、更大的教师模型** |

### 2.2 核心问题与直觉

**问**：能不能不要外部教师？推理数据集明明自带标准答案 y⋆，而它从来只被当"对/错"的二元判据，没有被当成逐 token 的监督信号用过。

> **OPSD 的两步转译**：① 把"二元答案"翻译成"条件上下文"——让模型看到 y⋆ 时变成教师；② 把"结果对错"翻译成"逐 token 分布"——教师对学生每一步给出密集监督。于是**同一模型、同一参数，靠上下文分裂成师生**，自蒸馏成立。

## 三、方法：上下文即身份

### 3.1 整体框架

![图片展示了On-Policy Self-Distillation的流程。首先从数据集S中采样(x, y*)，其中x为问题，y*为包含推理和答案的组合。接着构造两个相同LLM的提示，学生提示仅含x，教师提示含x和y*。学生策略基于x采样，教师策略基于x和y*采样。学生策略输出y~，教师策略输出pT。最后，使用特权信息评估，仅学生logits的梯度流过。该图与上下文紧密相关，直观呈现了论文中提出的自蒸馏方法。](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-3.webp)

**双策略**（共享参数 θ，仅条件不同）：

- 教师策略：pT(·|x, y⋆) = pθ(·|x, y⋆) —— 看到问题 + 参考解答（特权信息）
- 学生策略：pS(·|x) = pθ(·|x) —— 只看到问题

**学习目标**（学生自身 rollout 上的逐 token 前向 KL）：`L_OPSD(θ) = E_(x,y⋆)~S E_ŷ~pS(·|x) Σ_n D(pT(·|x, y⋆, ŷ<n) ‖ pS(·|x, ŷ<n))`

- 梯度只通过学生 pS 回传，教师是"看答案的自己"（初始策略，冻结）
- 全词汇 logit 蒸馏（对每个词表条目算散度），而非只监督采样到的 token

> **为什么"自我"不退化**：教师和学生同一参数、只差上下文。这不是"自己抄自己"，而是"聪明的自己（看到了答案）教笨的自己（没看到）"。y⋆ 是信息增益的来源，训练就是把这个增益压进参数。

### 3.2 逐 token 点式 KL 裁剪：别让风格词淹没数学词

**问题**：推理模型中风格类 token（"wait"、"think"…）的 KL 散度远高于数学 token，会主导训练信号。**方法**：对每个词表条目 v 的散度贡献做裁剪：`D_clip = (1/|ŷ|) Σ_n Σ_v min(ℓ_n,v, τ)`**效果**：防止训练崩溃、稳定性能（见实验 4.3 的消融图）。

### 3.3 OPSD 与 RL 的关系：它是"每 token 一个奖励"的策略梯度

把目标改写成策略梯度形式：优势项 A_n = log pT(ŷ_n|…) − log pS(ŷ_n|…)，就得到每个 token 位置的密集奖励。

- **vs STaR**：STaR 是序列级二元奖励（对/错），全错时信号消失；OPSD 即使学生最终答案错了，教师分布照样在每一步给出"应该往哪走"——**错误轨迹也充满学习信号**。
- **vs RLVR**：GRPO 每组 8 个 rollout 只换来 1 个标量，奖励多样性一崩溃梯度就归零；OPSD 每次 rollout 每个 token 都有信号。

> **OPSD 的优雅之处**：把 RLVR 的"稀疏二元奖励"换成了"密集蒸馏损失"，绕开奖励建模、优势估计、采样成本——用一步蒸馏同时拿到 RL 的 on-policy 优点和 SFT 的稠密监督优点。

## 四、实验结果

### 4.1 主结果：匹配或反超 GRPO，且只用 1/8 的 rollout

训练数据：OpenThoughts 数学子集（≤30K 题解对）；评估：AIME24 / AIME25 / HMMT25（Avg@12）；基线 SFT、GRPO（生成长度 16k）。

![](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-4.webp)

| 方法 | AIME24 | AIME25 | HMMT25 | 平均 |
|-|-|-|-|-|
| Qwen3-8B Base (Instruct) | 75.8 | 65.6 | 43.9 | 61.8 |
| Qwen3-8B +SFT | 72.3 | 64.2 | 42.9 | 59.8 |
| Qwen3-8B +GRPO | 76.4 | 68.9 | 46.7 | 64.0 |
| Qwen3-8B +OPSD | **77.8** | **70.8** | 45.8 | **64.8** |
| Qwen3-4B Base (Instruct) | 74.9 | 66.4 | 42.2 | 61.2 |
| Qwen3-4B +SFT | 70.2 | 62.3 | 43.4 | 58.6 |
| Qwen3-4B +GRPO | 75.6 | 68.1 | 44.4 | 62.7 |
| Qwen3-4B +OPSD | **76.4** | 68.3 | **46.1** | **63.6** |
| Qwen3-1.7B Base (Instruct) | 51.5 | 36.7 | 23.1 | 37.1 |
| Qwen3-1.7B +SFT | 48.4 | 36.3 | 22.7 | 35.8 |
| Qwen3-1.7B +GRPO | 51.1 | 38.3 | 23.7 | 37.7 |
| Qwen3-1.7B +OPSD | **57.2** | **43.9** | **29.2** | **43.4** |

> **三个观察**：① 越小受益越大——1.7B 平均 37.1→43.4（+6.3），8B 也有 +3.0，且**反超 GRPO 1.7B 近 6 个点**；② SFT 全面倒退（简洁解答把测试时生成变短了）；③ 这还只是 100 步、每题 1 个 rollout 的成果。

### 4.2 Token 效率：1 个 rollout vs 8 个 rollout

![](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-5.webp)

| 方法 | rollout/题 | 采样 token/题 | 关键差异 |
|-|-|-|-|
| OPSD | 1 | 1,024 | 每个 token 都有密集监督，100 步收敛 |
| GRPO | 8 | 16,384 | 只有序列级二元奖励；100 步内超半数 batch 奖励标准差为 0（无梯度） |

GRPO 的"奖励多样性崩溃"是核心症结：采样了 16 倍的 token，却常常一个有效梯度信号都换不来。OPSD 把同样算力花在"更有信息量的监督"上，**token 效率 4–8×**。

### 4.3 消融：前向 KL 最佳、裁剪防崩溃、全词汇蒸馏最优

![](/images/paper-reading/2026-08-19-opsd/2026-08-19-d19-6.webp)

- **散度目标**：前向 KL（KL(pT‖pS)）显著最佳——Qwen3-1.7B AIME25 在 50 步时 36.7→43.9；反向 KL 与 JSD 增益有限
- **生成风格组合**：学生 thinking-off / 教师 thinking-on 时数学 token 的 KL 最大（监督最强）；风格 token（wait/think）的 KL 远高于数学 token → 催生点式裁剪
- **学习目标**（Qwen3-4B @2048）：

| 学习目标 | AIME25 | HMMT25 |
|-|-|-|
| 全词汇 logit 蒸馏（OPSD） | **84.1** | **60.0** |
| 采样 token 蒸馏（策略梯度） | 82.1 | 57.3 |

- **生成长度**：1024 vs 4096 无一致收益——早期 token 更关键
- **实现细节**：8×A100/H100、AdamW、bf16、LoRA；GitHub 显示 Qwen3-1.7B 在 4×H100 上训练仅约 15 分钟

## 五、Limitations & 批判性思考

1. **止步 8B**：实验只在 ≤8B 上验证。更大模型"自我合理化"能力更强，但 OPSD 的收益与规模的关系未测。
2. **没利用答案正确性**：OPSD 不验证学生生成的对错——学生答错了也照样蒸馏。把"正确性"作为门控/权重（如 PCD 的软 AND 门）可能是天然升级点。
3. **难度阈值**：题目超过模型理解能力时，教师（也是自己）也"教不动"。作者建议未来探索课程学习。
4. **裁剪阈值 τ 未调优**：逐 token 点式 KL 裁剪的 τ 是全篇唯一的"魔法数字"，直接沿用未搜索。
5. **纯文本数学**：未涉及多模态。对 PAPO 揭示的"67% 错误来自感知"场景，OPSD 的 y⋆ 特权能否换成"图像/图表线索"尚是开放问题。

## 六、与前文对照（OPD 谱系表）

|  | 方法 | 核心创新 | 与 OPSD 的关系 |
| --- | --- | --- | --- |
| 1 | TOPD | 用"近未来"引导弥合推理轨迹 | 同为特权引导：TOPD 给未来步骤，OPSD 给标准答案 y⋆ |
| 2 | COPD | 对比式 OPD | 靠正负样本对拉近/推开；OPSD 单教师分布、无对比 |
| 4 | RLCSD | 对比式同策略自蒸馏 | 用正确/错误 rollout 构造对比；OPSD 直接条件于 y⋆，不需要对比样本 |
| 9 | Distilled RL | 教师监督融进 RL 目标（选择性蒸馏） | 仍需外部教师 + RL 目标；OPSD 纯蒸馏、无 RL、无外部教师 |
| 15 | OPD² | 概率差蒸馏（教师−教师base 的 delta） | delta 在"参数/分布层面"；OPSD 在"上下文层面"（y⋆ 条件即特权） |
| 16 | PCD | 感知-推理归因软 AND 门 | 其"下游正确性 × 师生分歧"门控正是 OPSD 缺的答案验证信号 |
| 17 | PAPO | 感知感知策略优化（KL_prcp） | 多模态"看错"问题；OPSD 纯文本，未来可把 y⋆ 换成视觉特权线索 |
| **18** | **OPSD** | **特权教师同策略自蒸馏** | **本作：无外部教师、无 RL 目标、逐 token 密集监督、4–8× token 效率** |

> **定位差异**：
> - **vs #1 TOPD / #15 OPD²（特权信息的不同形态）**：TOPD 的特权是"未来的自己"，OPD² 的特权是"参数 delta"，OPSD 的特权是"标准答案"——三者展示了"自我蒸馏的信号可以来自时间、参数、上下文三个维度"。
> - **vs #4 RLCSD / #2 COPD（监督信号的形态）**：前两者用对比（正 vs 负样本）构造信号，OPSD 用单一特权分布——更简单，且不需要多 rollout 凑对比。
> - **vs #9 Distilled RL（与 RL 的关系）**：Distilled RL 是"RL 为主、蒸馏为辅"，OPSD 是"纯蒸馏"——OPSD 用数学论证了密集蒸馏本身就能替代 RL 的稀疏奖励。
> - **vs #16 PCD / #17 PAPO（多模态延伸）**：PCD 的"正确性×分歧"门控、PAPO 的"看图 vs 不看图"KL 都是 OPSD 在下一个维度的自然扩展方向。

## 七、启发与待跟进

> **核心启发**：
> 1. **"合理化比生成容易"是普适学习原理**：把"会做题"转译成"会讲解"，同一个模型的能力就能被放大——这条原理不限于数学，可迁移到代码、科学推导等一切"有标准答案"的任务。
> 2. **密集监督是 RL 稀疏奖励的解药**：GRPO 的奖励多样性崩溃（梯度归零）在 OPSD 里根本不存在，因为每个 token 都有信号——这直接回应了 OPD 谱系里"监督信号精细化"的主线。
> 3. **上下文即身份**：不需要新模型、不需要新参数，只改 prompt 就能在训练中制造"师生差"——这个 trick 成本极低，即插即用。

### 待跟进 checklist

- [ ] **OPSD × 多模态**：把 y⋆ 特权换成图像/图表线索（Vision-OPD 的 crop 教师、PAPO 的掩码对比），验证"答案特权"在感知任务上是否同样有效

- [ ] **OPSD × PCD 门控**：用 PCD 的"下游正确性 × 师生分歧"软 AND 门控制"哪些 token 该蒸"，补上 OPSD 不验证答案的短板

- [ ] **OPSD × GRPO 混合**：把 OPSD 的逐 token 密集信号作为 GRPO 的辅助损失，或交替训练，看能否在 RL 场景下兼得两者

- [ ] **课程学习**：按题目难度渐进式引入特权监督（论文 limitation 里点的方向）

- [ ] **更大模型**：13B/32B 上"自我合理化"能力更强，token 效率优势是否放大？

- [ ] **τ 的自适应**：裁剪阈值 τ 未调优，能否按 token 类别（数学/风格）或训练进度动态调整

- [ ] **长 CoT 行为**：1024 vs 4096 无一致收益，但 R1 风格 32k 推理轨迹下 OPSD 的蒸馏行为如何？

## 八、今日阅读结论

OPSD 是 OPD 谱系里"最小依赖"的一作：**不要外部教师、不要奖励模型、不要 RL 目标**，只用推理数据集里一直被当二元判据的标准答案 y⋆，通过"条件上下文"把同一个模型分裂成师生，再在学生自己的轨迹上做逐 token 蒸馏。它用实验证明了：RLVR 的稀疏奖励不是必需——密集蒸馏 + on-policy 采样就能拿到同等甚至更好的推理性能，还省 4–8 倍 token。与前文合读，可以看到一条清晰的演进线：从"要不要 on-policy"（GKD 类）、"怎么构造对比信号"（COPD/RLCSD）、"信号从哪来"（TOPD 未来 / OPD² delta），到 OPSD 把答案本身变成信号——下一步几乎必然是多模态（PCD/PAPO 已探路）与"何时该蒸"的精细化门控。

> **今日一句**：与其请一个更强的外部教师，不如让模型"看着答案"教"看不见答案"的自己——特权信息让同一个模型瞬间分裂成师生，逐 token 的密集监督让错误轨迹也充满学习信号。论文：arXiv:2601.18734（ICML 2026）· 笔记挂在 lib 中 · 2026-08-19

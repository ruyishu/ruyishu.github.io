## TL;DR

<strong>一句话：GRPO 罚一条错误回答时，回答里每个 token 拿到的负优势都一样，可错误回答里往往有一大段和正确回答一模一样的正常步骤（审题、列式、套公式），它们也跟着被压低。ResRL 的做法是：先用同一道题的正确回答的隐状态拼出一个 64 维的「正确思路子空间」，再看错误回答里每个 token 离这个子空间有多远。离得近的（和正确回答共享的步骤）只罚 0.1 倍，离得远的（真正出错的地方）罚满 1 倍。</strong>

- <strong>改动在哪</strong>：只改 actor 里的优势。正确回答的优势统一乘 0.1（这是 NSR / W-REINFORCE 的设定），错误回答每个 token 的优势乘 ω ∈ \[0.1, 1\]，ω 由该 token 倒数第二层隐状态到正样本子空间的投影残差决定，组内按 20% / 80% 分位数线性映射
- <strong>主结果（Table 1，Avg@16，6 个数学基准平均）</strong>：Qwen3-4B GRPO 53.1 → NSR 52.1 → <strong>ResRL 57.0</strong>；Qwen3-8B GRPO 56.2 → NSR 61.9 → ResRL 64.7；Qwen3-1.7B NSR 47.5 → ResRL 48.6。代码（Qwen3-4B）CodeForces rating 1340.9 → 1469.5，ALFWorld 78.5 → 86.7
- <strong>仓库</strong>：1229095296/ResRL（17 star，Apache-2.0），verl 0.5 fork，一个数学训练脚本 train\_command.sh，默认 Qwen3-4B 单机 8 卡。没有权重、数据、评测脚本、基线脚本，代码 / agent / 函数调用三条线的脚本都没放
- <strong>主要问题</strong>：① 摘要里「比 NSR 高 9.4%」是相对涨幅，而且挑的是 NSR 比 GRPO 还差的 4B（NSR 52.1 低于 GRPO 53.1），对 GRPO 实际是 +3.9 分；② 缺一个关键对照：ResRL 把负样本的平均惩罚也降了，没有「所有负 token 统一乘同样均值」的对照，分不清涨分来自「挑着罚」还是「少罚」；③ 代码和论文对不上：Algorithm 1 写的「保留首尾的边界采样」和「截断保护」在代码里都没有，代码用的是随机抽样；默认没关 verl 的 balance\_batch，同一题的 4 条回答可能被拆到不同 micro-batch，此时这组直接跳过、退化成 NSR；④ 代码训练的口径正文写 think 模式 8192，附录 Table 7 写 Thinking False、4096

## 一、先看例子（大白话：错误回答里也有对的步骤）

假设一道题采了 4 条回答，2 条对、2 条错。两条错的回答前 80% 和正确回答几乎一样：读题、设未知数、列方程，最后一步算术算错了。（这个例子是我按论文 Figure 1 的意思编的，用来说明机制。）

- <strong>GRPO</strong>：奖励是 \[1, 1, 0, 0\]，组内标准化后正确回答每个 token 拿 +0.87，错误回答每个 token 拿 −0.87。错误回答里「设 x 为……」这几步也被压了 0.87，可正确回答里同样的步骤又被抬了 0.87，两边打架
- <strong>NSR（W-REINFORCE）</strong>：正确回答只给 0.1 倍（+0.087），错误回答照样 −0.87。等于主要靠「罚错」来学，Pass@k 保住了，但共享步骤被罚得更狠
- <strong>ResRL</strong>：正确回答同样 0.1 倍。错误回答逐 token 看：「设 x 为……」的隐状态落在正确回答张成的子空间里，残差小，只罚 0.1 倍（−0.087）；最后算错的那几个 token 残差大，罚满 −0.87

![论文 Figure 1。左上：正确回答和错误回答中间有一段相似的语义分布（斜线格）；左下：ResRL 三步公式，对正样本做 SVD 得投影 P_S，算错误回答每个 token 的投影残差 R，再映射成梯度权重。右：GRPO 正负都等权，NSR 正样本小箭头、负样本大箭头，ResRL 负样本里相似段的箭头变小](/images/paper-reading/2026-11-25-resrl/2026-11-25-d87-1.webp)

Figure 1 右边那三行箭头就是全文要讲的事：GRPO 把正负一视同仁，NSR 把正样本调小，ResRL 在 NSR 的基础上再把负样本里「看起来像正确回答」的那几格调小。

## 二、动机

- <strong>RLVR 的老问题</strong>：GRPO 训完 Pass@1 涨了，Pass@k 常常不涨甚至降，输出变单一。NSR（Zhu et al. 2025b，The Surprising Effectiveness of Negative Reinforcement）的发现是：主要靠「压低错误回答」而不是「抬高正确回答」，能同时保住 Pass@k
- <strong>作者认为 NSR 的副作用</strong>：正负回答共享大量 token，从句式到部分推理步骤。罚负样本时，这些共享 token 在正确回答里的概率也被拉低，这就是 Lazy Likelihood Displacement（LLD，Deng et al. 2025）说的「正确回答的似然也跟着掉」。NSR 把负样本权重相对放大，这个问题更严重，所以 NSR 的 Pass@1 涨不太动（Table 1 里 Qwen3-4B 的 NSR 52.1 还不如 GRPO 53.1）
- <strong>理论部分</strong>：作者在输出头 W 处把正负 token 梯度的内积拆成「logit 项 × 表示项」（Lemma 1），然后只管表示项 |⟨x−, x+⟩|，证明它被 x− 到正样本子空间的正交残差 e(x−) 上界控制（Lemma 2、Theorem 1）：残差越大，和正样本方向的最大可能对齐越小。所以「残差小的负 token 少罚」就能压住梯度干扰

## 三、方法

### 3.1 每组算一次正样本子空间

- 取每条回答每个 token 的<strong>倒数第二层</strong>隐状态 h（代码里是 output.hidden\_states\[-2\]），先做 LayerNorm，再减去该组正样本 token 的均值 μ+
- 正样本 token 太多就抽样，最多 M\_max = 4096 个，拼成矩阵 X+，用 torch.pca\_lowrank 取前 k = 64 个主方向 V\_k，投影矩阵 P\_S = V\_k V\_kᵀ
- 对错误回答每个 token：残差 R = ‖(I − P\_S)x−‖² / d

### 3.2 残差变权重

- 组内所有负 token 的残差取 20% 和 80% 分位数 q\_low、q\_high，z = clamp((R − q\_low)/(q\_high − q\_low), 0, 1)
- ω = 0.1 + 0.9·z，所以残差最小的 20% 负 token 只罚 0.1 倍，最大的 20% 罚 1 倍
- 最终优势：正样本 Â × 0.1，负样本 Â × ω，其余照搬 GRPO 的 clip 目标，KL 系数 0
- 组里没有正样本（全错）或没有负样本（全对）时不做任何改动；正样本 token 少于 4 个也跳过

### 3.3 配套

- <strong>长度折扣</strong>：正确回答超过 3500 token 后奖励线性打折，到 4096 时只剩 0.7 倍，防止越写越长
- <strong>计算量</strong>：每组多一次截断 SVD，复杂度 O((M + T−)dk)。附录 C 只给了复杂度推导，<strong>没有给实测的每步耗时</strong>

### 4.3 消融

## 五、Limitations

⚠️ 本篇没有独立 Limitations 章节（正文结束后直接是 Impact Statement，内容是套话）。

### 5.1 我读出来的问题

- <strong>标题数字的口径</strong>：摘要和结论的「surpasses NSR by 9.4% in Avg@16」是相对涨幅（57.0 / 52.1 − 1），选的是 NSR 最差的 4B（NSR 低于 GRPO）。1.7B 和 8B 对 NSR 分别只高 2.3% 和 4.5%（相对），对 GRPO 在 4B 上是 +3.9 分
- <strong>正文描述和表对不上</strong>：第 4.2 节说 ResRL「比第二名 FlowRL 高 15.7%、6.3%、4.2%（1.7B / 4B / 8B）」，但 1.7B 的第二名是 NSR（47.5），不是 FlowRL（42.0）；15.7% 是拿第三名算的
- <strong>缺「少罚」对照</strong>：ω 在 \[0.1, 1\] 之间，最小的 20% 取 0.1、最大的 20% 取 1、中间线性，粗算平均在 0.55 上下（我按残差在两分位数之间大致均匀估的），也就是负样本的整体惩罚比 NSR 小了不少，正负梯度的整体比例变了。没有「所有负 token 统一乘同一个数」的对照，涨分到底来自「挑着罚」还是「整体少罚」分不开
- <strong>理论和方法脱节</strong>：Lemma 1 和 Theorem 1 是在输出头前那一层表示 x 上推的，方法实际用倒数第二层（Figure 7 还证明最后一层更差）；logit 项 |⟨δ−, δ+⟩| 直接当常数扔掉；Theorem 1 还要假设正样本 token 几乎都在子空间内。所以理论只能算动机，不能说明为什么倒数第二层好
- <strong>代码和 Algorithm 1 不一致</strong>：附录 Algorithm 1 写的是「保留首尾、中间均匀抽」的 BoundaryAwareSample，还有截断保护（被截断的回答 ω=1，Algorithm 1 标为可选）。dp\_actor.py 里只有 torch.randperm 随机抽样，没有截断保护的实现。另外代码判断正负用的是「奖励 &gt; 0」，论文写的是「优势 &gt; 0」，开了长度折扣后，一条偏长的正确回答在全对的组里优势可能是负的，两种写法结果不同
- <strong>默认配置可能让方法悄悄失效</strong>：子空间是在每个 micro-batch 里按 uid 分组算的，micro-batch 大小等于 4（每题 4 条）。train\_command.sh 没有关 verl 默认开启的 trainer.balance\_batch（按序列长度把样本在各卡之间重排），同一题的 4 条回答可能被拆开，这时组内凑不齐正负样本就直接跳过、权重全为 1，等于退回 NSR。代码里专门留了 svd\_debug 打印「max uid count」，说明作者知道这个风险，但脚本没处理。复现时建议先打开 svd\_debug 看一眼
- <strong>口径打架</strong>：正文第 4.1 节说代码任务「think 模式、8192 token」，附录 Table 7 写 Thinking Template False、回复上限 4096。数学训练 4096、评测 8192，长度不一致也没讨论
- <strong>基线不同源</strong>：ALFWorld / WebShop 和 BFCL 的基线数字直接抄自 EMPG、ResT 等论文，训练设置不一定对齐；数学主表没有多种子方差。长度折扣奖励是不是也给基线开了，论文没说，仓库里也没有基线脚本可查

|-|-|-|
| 10-27 NSR（Clipping Bottleneck） | 北大 + Qwen，救回被 PPO 裁剪丢掉的近边界 token | <strong>名字撞车</strong>：那篇的缩写也叫 NSR，但和 ResRL 当基线的 NSR（Negative Sample Reinforcement，Zhu et al. 2025b）不是同一个东西。两者都在改 token 级梯度，一个管「被裁掉的」，一个管「负样本里哪些该罚」 |
| 11-23 DPPO | 按概率实际变化量（TV / KL）决定哪些 token 被屏蔽 | DPPO 管「这个 token 的更新幅度是否越界」，ResRL 管「这个负 token 该罚多少」，正交可叠加。两者都基于 verl，但 ResRL 是 0.5 版 fork，DPPO 已合进 verl 主仓库，要放一起得自己合代码 |
| 11-24 AntiSD | 用看过答案的自己当老师，逐 token 改优势 | 都在 GRPO 的序列级优势上乘 / 加一个 token 级系数。AntiSD 的信号来自「看答案 vs 不看答案的 log 概率差」，要多一次带特权上下文的前向；ResRL 的信号来自同组正确回答的隐状态几何，不需要额外前向，但要求组里至少有一条对的 |
| 09-16 RAGEN-2 | 多轮 agent RL 里熵看不出模板崩塌，改看互信息 | ResRL 也在 ALFWorld 上做了实验（86.7），但只抄了 EMPG 的基线，没有和 RAGEN 系方法比 |

## 七、启发与待跟进

- <strong>最值得带走的</strong>：「用同组正确回答的隐状态当参照系，给错误回答做 token 级信用分配」这个思路很便宜：不要 PRM、不要老师、不要额外采样，每组只多一次 rank-64 的 SVD
- <strong>想复现</strong>：先按 FlowRL 的流程做 DAPO-Math-17k parquet，PRETRAINED\_MODEL=Qwen/Qwen3-4B bash train\_command.sh，单机 8 卡（TP=8）。建议先加 trainer.balance\_batch=False 和 svd\_debug=true，确认每组都能凑齐正负样本；再跑一个 svd\_min\_weight=1.0（我推的，这样 ω 恒为 1，等价 NSR）和一个 use\_svd\_token\_weighting=false（纯 GRPO）当基线，评测要自己写 Avg@16
- <strong>待查</strong>：balance\_batch 打开时实际有多少组被跳过；SVD 的实测开销；把负 token 统一乘 0.55 能拿到多少分
- <strong>能往下做的</strong>：① 全错的组现在完全不管，可以借别的题的正确回答或参考解来建子空间；② 子空间按组建，可以换成跨步滑动更新的全局子空间，省掉组内正样本太少的问题；③ 和 DPPO 的屏蔽、AntiSD 的特权信号叠加，看 token 级信号是否互补；④ 正样本这边也可以反过来用：正确回答里离错误子空间近的 token 少奖励

## 八、结论

ResRL 抓的点很具体：错误回答里也有大段正常步骤，一棍子打死会连带压低正确回答。作者用同组正确回答的倒数第二层隐状态建一个 64 维子空间，错误回答里离子空间近的 token 只罚 0.1 倍，在 Qwen3 1.7B / 4B / 8B 的数学 RL 上平均分都超过 NSR 和 GRPO（4B 53.1 → 57.0，8B 56.2 → 64.7），代码和 agent 任务也有涨。改动集中在 actor 里约 150 行，单机 8 卡能跑 4B。

需要打折看的地方：标题的 9.4% 是相对值且挑了 NSR 最弱的底座；缺「整体少罚」的对照；理论推在最后一层、方法用倒数第二层；代码缺 Algorithm 1 里的两个组件，默认配置下还可能因为 balance\_batch 让部分组退化成 NSR；仓库只有数学一条线、没有评测和基线脚本。作为 baseline 可以用，但复现前先把 balance\_batch 关掉、自己补齐基线。

> 💡 <strong>今日一句</strong>：罚错答案时只罚和正确答案不一样的那几步，想法便宜又直观；但它也顺手把负样本的整体惩罚降了不少，先补一个「统一少罚」的对照再下结论。

> 2026-11-11 · 每日读论文 #76 · 本周领域 <strong>推理 / Agentic</strong>（第 4 周第 3 篇）· <strong>开放题没有标准答案，那就让轨迹两两打擂台</strong> · 阿里通义 DeepResearch + 高德 · ICML 2026 Poster

## TL;DR

<strong>一句话：旅行规划、深度研究这类开放式 agent 任务没有标准答案，只能让 LLM 评委打分；可模型越训越像，评委给的分全挤在 0.8–0.9，分差还没评委自己的噪声大。ArenaRL 不再逐条打分，而是让同一组轨迹两两对战排出名次，再把名次换成优势做 GRPO 式更新；为了省钱，用「贪心轨迹当种子 + 单败淘汰」，每组只要 2N−2 次比较。</strong>

- <strong>做法</strong>：一组 N 条轨迹，第 1 条用贪心解码当锚点。先让其余 N−1 条各和锚点比一次排种子，再按种子排单败淘汰赛（1 号种子打 N 号）。按存活轮数排名，同轮出局的看累计均分。名次 → 分位奖励 r=1−Rank/(N−1) → 组内标准化 → PPO-clip 目标。每次比较都正反各问一次评委，消位置偏差
- <strong>主结果（Qwen3-8B-Base，SFT 冷启动后 RL）</strong>：Open-Travel 平均胜率 <strong>41.8%</strong>，GRPO 16.4、GSPO 17.2、SFT 16.4、Claude-3.7-Sonnet 31.6。Open-DeepResearch 胜率 <strong>64.3%</strong>，有效生成率 99%；GRPO 是 25.2（有效率只有 17%）。三个写作基准平均 80.30，比 GRPO 高 6.70、比 GSPO 高 7.27
- <strong>拓扑对比（Table 2，N=8）</strong>：种子单败 32.5，接近全循环赛 32.9，高于双败 30.2、瑞士轮 28.3、锚点 27.8
- <strong>⚠️ 先说几个坑</strong>：① 种子单败的平均第一几乎全靠 Search 一列（69.9）；去掉 Search，它在五种拓扑里反而<strong>最低</strong>（23.2 对 24.4–24.6）；② 主表用 N=16，拓扑表用 N=8，GRPO / GSPO 的组大小没写；③ 训练评委是 Qwen3-Max，评测两个评委里也有 Qwen3-Max；④ 基线评委只看答案，ArenaRL 评委看过程加答案，评测又给过程打分，「两两比」和「看过程」的贡献没拆开；⑤ 仓库默认拓扑是 anchor，评委默认 qwen-plus API，SFT 数据和权重没放；⑥ 没有独立 Limitations 章节

## 一、先看例子（大白话：成都到青城后山，两天，两人，每人 600 块）

> 🧪 <strong>题目（论文附录 F.1 / F.2，Open-Travel 测试样例）</strong>：周末两天，两人从成都去青城后山徒步，重点是自然风光和拍照，预算每人 600 元。

<strong>SFT 模型（冷启动后、没做 RL）</strong>：调了 5 次工具。它搜了青城后山、搜了「成都」本身，最后导航一次成都→青城后山。给出的方案是<strong>两天都从成都出发、晚上回成都</strong>，第二天把交通再走一遍；费用表里还列了相机租赁 800–1000 元（两人）、镜头 500–800 元，预算基本被打穿。思考里每一步都先把用户需求原样复述一遍，论文管这个叫 restatement tendency。

<strong>ArenaRL 模型</strong>：调了 8 次工具。先通用搜索，再逐个查泰安古镇、五龙沟、又一村、翠映湖、来凤亭的坐标，最后一次导航把 4 个景点当途经点串成环线。方案改成住泰安古镇，第一天走环线，第二天深度玩五龙沟和翠映湖。预算写成每人 460–610 元。

<strong>这个例子说明的事</strong>：两个答案都「像样」，用 0–1 打分很可能都在 0.8 上下；但放在一起比，谁更贴约束一眼就能看出来。这正是论文的核心直觉：<strong>单独打分分不开，放在一起比就分得开</strong>。

<strong>但例子本身也有毛病</strong>：ArenaRL 的答案里写「餐饮 30 元/天（两人）× 2 天 = 120 元」，30×2 是 60；总价上限 610 元也超了用户给的 600。好答案不等于对的答案，评委在两两对比时未必会去核算这种细账。

## 二、动机

![论文 Figure 1。（a）同一个北京三日游请求下，组内 N 条轨迹单次打分都在 0.8–0.9，组内标准差约 0.03；同一条轨迹重复评 N 次，噪声带约 0.02，信噪比约 1.5。（b）雷达图：ArenaRL 在旅行五个子任务、DeepResearch 和三个写作基准上都在 SFT / GRPO / GSPO 外圈](/images/paper-reading/2026-11-11-arenarl/2026-11-11-d77-1.webp)

- <strong>开放任务只能靠 LLM 评委</strong>：数学和代码能对答案，旅行规划没有唯一正确行程，只能让评委按 rubric 打标量分（pointwise）
- <strong>判别塌缩（discriminative collapse）</strong>：策略越训越好，一组轨迹越来越像，分数挤进很窄的区间。评委本身又有解码随机、偏爱长答案等噪声。论文举的例子：组内标准差约 0.03，同一轨迹重复评的噪声约 0.02
- <strong>GRPO 会把噪声放大</strong>：优势 = (分数 − 均值) / 组内标准差。组内标准差越接近 0，分母越小，评委噪声越被放大成主要梯度
- <strong>两两比较更稳</strong>：引用决策理论和 DPO 一类工作，认为成对偏好比绝对打分稳定。但全部两两比要 N(N−1)/2 次，N=16 就是 120 次，在线训练吃不消

<strong>我的看法</strong>：问题提得准，开放任务里「评委分挤在一起」大家都遇到过。但 Figure 1 的 0.03 / 0.02 只来自一个示例请求，没有给全训练过程的统计，「信噪比太低」更多是示意，不是测量。

## 三、方法

![论文 Figure 2。左：两阶段流程，先 SFT 冷启动学会调工具，再在线 RL，用两两评委加锦标赛排名代替逐条打分。右：五种拓扑，全循环赛 O(N²) 当金标准，锚点 O(N) 但分辨率低，种子单败 O(N) 被标为最佳平衡，双败缺先验，瑞士轮 O(N log N)](/images/paper-reading/2026-11-11-arenarl/2026-11-11-d77-2.webp)

### 3.1 过程感知的两两评委

- 输入：用户请求 + 两条轨迹的思考、工具调用和最终答案 + 一份多维 rubric。评委对两条各打一个分
- <strong>正反各评一次</strong>：(A,B) 评一次，(B,A) 再评一次，两次分数相加，消掉位置偏差。也就是说每场「比赛」要调两次评委
- 仓库里旅行评委的 prompt 写得很具体：路径分（广度、需求匹配、细节，各 0–10）和答案分（匹配、可行、细节、清晰，各 0–10），综合分 = 0.6 × 路径 + 0.4 × 答案。<strong>路径占六成</strong>，这一点后面会说到

### 3.2 五种锦标赛拓扑

| 拓扑 | 比较次数 | 怎么排名 |
|-|-|-|
| 全循环赛 | N(N−1)/2 | 每条和其余所有条比，按胜率排。当金标准用，在线训练太贵 |
| 锚点 | N−1 | 贪心解码（温度 0）出一条锚点，其余 N−1 条（温度 0.8）各和锚点比一次，按各自得分排。缺点：只知道谁比锚点强多少，两条探索样本之间分不细 |
| <strong>种子单败（主方法）</strong> | 2N−2 | 先用锚点结果排种子，再按种子排对阵（1 号对 N 号）。赢的晋级，按存活轮数排名，同轮出局按累计均分。目的是不让两条好轨迹在第一轮就互相淘汰 |
| 双败 | 约 2N−2 | 输两次才出局。为了和种子单败比较次数一样，用随机种子 |
| 瑞士轮 | N log N | 同战绩的互相打，约 log₂N 轮，按胜场 + Buchholz 分排 |

### 3.3 名次 → 优势

- 分位奖励 r\_i = 1 − Rank(τ\_i)/(N−1)，第一名 1，最后一名 0
- 组内标准化后代入 PPO-clip 目标，带 KL 项（仓库脚本里 kl-loss-coef 设成 0.00，clip 0.2 / 0.28）。环境返回的 token 不算 loss
- <strong>注意一个副作用</strong>：名次是均匀铺开的，所以 N=16 时标准化后第一名优势恒约 +1.63、最后一名恒约 −1.63，<strong>不管这 16 条轨迹真实差距是大是小</strong>。这避免了「分母趋近 0」，但也意味着评委哪怕在乱判，梯度大小也一点不减。论文批评 GRPO 会放大噪声，换成名次其实是另一种形式的放大，论文没讨论这一点

### 3.4 配套基准

- <strong>Open-Travel</strong>：5 个子任务各 50 题（多途经点导航、周边搜索、交通方式对比、一日游、多日游；多日游不进 SFT，当泛化测试），SFT 2,600 条、RL 1,626 条，中文
- <strong>Open-DeepResearch</strong>：100 题测试，SFT 2,662、RL 2,216，中英混合
- SFT 轨迹由闭源强模型生成，再经 LLM 质检反复改写；测试时和闭源模型给的基线轨迹两两比，算「非平局情况下的胜率」

## 五、Limitations

⚠️ 本篇没有独立 Limitations 章节。结论里只提了一句未来工作：扩到多模态 agent。下面是我读出来的问题。

1. <strong>「两两比」和「看过程」混在一起</strong>：GRPO / GSPO 基线的评委只看答案（论文原话 only evaluate the answer portion），ArenaRL 的评委看思考 + 工具调用 + 答案，仓库 prompt 里路径占 0.6。评测指标里又有 Framework、Tool Usage 这类过程分。缺两组关键消融：逐条打分但看过程；两两比较但只看答案。现在没法说涨点有多少来自「两两比」
2. <strong>训练评委和评测评委重叠</strong>：训练用 Qwen3-Max 当对战评委，评测用 Qwen3-Max + Claude-4-Sonnet 两个评委取平均。一半评测信号来自训练时被优化的同一个评委。人工一致性 73.9% 也不足以排除这种偏好拟合
3. <strong>主方法的选择依据薄</strong>：种子单败只在 Search 一列大胜，去掉这列反而垫底；每列 50 题、单次运行、没有方差
4. <strong>组大小不对齐</strong>：主结果 N=16，基线组大小未写。Figure 4(a) 显示 N 从 8 到 16 本身就能涨约 9 个点
5. <strong>名次优势恒定</strong>：见 3.3，评委乱判时梯度也不会变小，和论文批评 GRPO 的逻辑是同一类问题
6. <strong>成本没算</strong>：每题每次更新要 2×(2N−2) 次评委调用，N=16 就是 60 次 Qwen3-Max 请求；按论文 K=8 组算，每步约 480 次。论文强调「O(N) 便宜」，但没报 API 费用或评委耗时
7. <strong>复现门槛</strong>：SFT 用 32×H20，SFT 数据没放；训练评委、搜索、地图都是付费 API；数据 CC BY-NC 4.0 不能商用；仓库默认拓扑是 anchor 而非论文主推方法；作者名单 PDF 与 ICML 不一致

## 六、前文对照

- <strong>和 11-10 D-CORE</strong>：两篇都在处理「组内奖励方差塌到接近 0，GRPO 优势就没了」。D-CORE 的办法是用 token 熵顶上优势；ArenaRL 的办法是改成名次，名次方差永远不为 0。前者靠模型自身不确定性，后者靠外部评委的相对判断
- <strong>和 10-26 GDPO</strong>：GDPO 说多奖励时别先加起来再标准化，要分开归一化；ArenaRL 干脆不要绝对分，只要名次。两篇都在改 GRPO 的「优势怎么算」这一层，可以直接对比
- <strong>和 09-16 RAGEN-2</strong>：RAGEN-2 发现多轮 agent RL 会模板崩塌，用奖励方差过滤掉没信号的组；ArenaRL 反过来，方差小的组也强行排名、照样给梯度。两种态度正好相反，哪种更对值得做实验
- <strong>和 09-08 GiGPO、10-06 GraphGPO、10-30 HiPER</strong>：那几篇解决的是「一条轨迹里每一步该分多少功劳」，ArenaRL 解决的是「整条轨迹之间谁更好」。两者正交，可以叠
- <strong>和 10-28 RLVE</strong>：RLVE 靠可验证环境给精确奖励，ArenaRL 面对的是根本不可验证的开放任务。两者覆盖的是奖励谱的两端

## 七、启发与待跟进

- <strong>可直接接着做的</strong>：qqr 里换拓扑只改一个字符串，奖励层和 slime 解耦。值得试：① 把训练评委换成本地开源模型（比如 Qwen3-32B），看判别塌缩和涨点还在不在；② 补上缺的两组消融（逐条 + 看过程、两两 + 只看答案）；③ 名次奖励加「平局 / 差距阈值」，评委分不开时就别硬排
- <strong>和自己工作的接口</strong>：只要你的任务奖励来自 LLM 评委，就先做一个便宜检查：同一条轨迹让评委重复评 5 次，算噪声标准差，再和组内标准差比。比值接近 1，就说明 GRPO 在跟着噪声走，这时两两比较值得试
- <strong>不必急着跟的</strong>：「种子单败是最佳拓扑」这个结论。从 Table 2 看，锚点（N−1 次）在四列里和它差不多甚至更好，成本还少一半

## 八、结论

ArenaRL 抓住了开放式 agent RL 的一个真问题：评委分挤在一起，GRPO 的优势变成噪声。改成组内两两对战、用名次当奖励，思路简单，容易嫁接到任何 GRPO 流水线上；Qwen3-8B 在 Open-Travel 从 16.4 到 41.8、DeepResearch 有效率从 17% 到 99%，效果很显眼。但它把「两两比」和「评委看过程」绑在一起，训练评委和评测评委重叠，主拓扑的胜出只靠一列，组大小也没对齐。作为 baseline，代码和 RL 数据都在、RL 一机 8 卡，值得留；引用它的数字时，要把这几条一起带上。

> 💬 <strong>今日一句</strong>：评委打不出分差的时候，别逼它给绝对分，让两条答案站在一起比——但也别忘了，名次永远是排得出来的，哪怕两条一模一样。

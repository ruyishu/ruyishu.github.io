## TL;DR

<strong>一句话：教 Qwen3-VL-8B 在视频里找「某件事发生在第几秒到第几秒」。以前用 GRPO：每道题采 8 个答案，每个答案只拿一个 IoU 分。这篇改成：学生只答一次，一个 32B 老师给答案里的每个 token 打分（反向 KL）。分数差不多甚至更好，训练时间约是 GRPO 的 1/5。</strong>

- <strong>做了什么</strong>：把 Thinking Machines 那套 on-policy 蒸馏（OPD）原样搬到时序视频定位（TVG）上，再加一个选数据的小课程 <strong>TVDF</strong>（先用真值筛掉老师答错的题，再挑师生差距最大的题）
- <strong>主结果（Qwen3-VL-8B，mIoU）</strong>：Charades <strong>42.9 → 52.0</strong>、ActivityNet <strong>30.4 → 47.3</strong>、QVHighlights <strong>36.9 → 61.0</strong>；同设置 GRPO 是 49.6 / 44.7 / 54.3
- <strong>省时间（Figure 6）</strong>：同样约 75 步，Video-OPD 约 <strong>120 分钟</strong>，GRPO 约 <strong>620 分钟</strong>
- <strong>训三轮后</strong>：mIoU 53.3 / 50.7 / 64.6，略超 TimeLens-8B（53.3 / 49.3 / 63.0）
- <strong>⚠️ 省下的时间没算老师</strong>：老师是 <strong>Qwen3-VL-32B 先跑了一遍 GRPO</strong>（8 次采样）才得到的，这笔账不在 1/5 里
- <strong>⚠️ 老师大小几乎不影响学生</strong>：4B 老师和 32B 老师教出来的学生，QVHighlights mIoU 是 <strong>62.5 vs 62.9</strong>，ActivityNet 甚至 <strong>48.4 &gt; 47.7</strong>
- <strong>⚠️ 「长链 token 级信用分配」的叙事和实际对不上</strong>：最终模型<strong>不思考</strong>，只输出「12.54 to 17.83」这种十几个 token；开思考反而掉分（QVHighlights 61.0 → 44.1）
- <strong>✅ 仓库完整</strong>：Apache-2.0；<strong>学生权重 + 32B 老师权重 + 训练数据（含视频）</strong>全在 HF；训练基于 <strong>ms-swift</strong>，8 卡单机；有评测脚本
- <strong>⚠️ 仓库细节</strong>：train.sh 里还留着作者内部路径要自己改；<strong>TVDF 选数据的代码没放</strong>（只放了选好的数据）；放出的权重是第 1 轮，不是论文最好的第 3 轮

## 一、先看例子（大白话：答案只有十几个 token）

> 💡 <strong>题目</strong>：一段视频，问「两个人打起来是在什么时候」。真值是 <strong>26.2 到 34.5 秒</strong>。
>
> <strong>模型要输出的就是一行字</strong>：「26.20 to 34.50」。

<strong>GRPO 怎么教</strong>：同一道题让模型答 8 次，比如有一次答了「43.10 to 44.50」，和真值几乎不重叠，IoU≈0，整句话拿一个低分；另一次答「25.80 to 33.90」，IoU 高，整句话拿一个高分。<strong>每次都要把整段视频（最多 768 帧）重新喂一遍，所以贵。</strong>

<strong>Video-OPD 怎么教</strong>：只让学生答 1 次，然后把这句话交给 32B 老师，问它「每个字你觉得对不对」。比如学生写了「43.10」，老师在「4」这个位置给的概率很低——<strong>学生立刻知道是开头那个数字错了</strong>，而不是只知道「整句不太好」。

> <strong>好处</strong>：一次采样就有每个 token 的信号，所以省掉了 GRPO 那 8 次采样。
>
> <strong>但请记住这个例子的长度</strong>：整个答案十几个 token。论文通篇讲「长链推理里的信用分配」，可它最后用的模式根本不推理——这一点放到第五节细说。

![论文 Figure 2：Video-OPD 流程。学生看视频答一次（绿色＝推理内容和时间段），老师在学生这条答案上算每个 token 的概率（橙色），用反向 KL 当每个 token 的奖励，再更新学生](/images/paper-reading/2026-11-03-video-opd/2026-11-03-d71-1.webp)

## 二、动机：SFT 不在自己的路上练，GRPO 信号太稀又太贵

- <strong>SFT 的问题</strong>：只学标准答案，没见过自己犯错后的状态，一错就越走越偏（off-policy 的老问题）
- <strong>GRPO 的两个问题</strong>：① <strong>一条轨迹只有一个分数</strong>，分不清哪个 token 的锅 ② <strong>要多次采样来降方差</strong>，视频每次都得带着几千个视觉 token 重新生成，成本随采样数线性涨
- <strong>想要的东西</strong>：既在自己采的轨迹上练（on-policy），又有每个 token 的信号（dense），还只采一次

<strong>答案就是 OPD</strong>：Qwen3、MiMo-V2-Flash 的技术报告都用它把多个 RL 专家合回一个模型。论文自称<strong>第一个把 OPD 用到 TVG 上</strong>。

## 三、方法：标准 OPD + 一个选题课程

### 3.1 Video-OPD 四步

1. <strong>学生采样</strong>：给视频和问题，学生答一次，记下每个 token 的 log 概率
2. <strong>老师打分</strong>：固定的老师<strong>不自己生成</strong>，只在学生的这条答案上算每个 token 的 log 概率
3. <strong>逐 token 奖励</strong>：r\_t = −(log π学生 − log π老师)，即反向 KL 的逐点值。老师觉得不可能的 token，罚得最重
4. <strong>策略梯度更新</strong>：把 r\_t 当成每个 token 自己的奖励，不再做组内归一化

<strong>工程上就是 ms-swift 的 GKD 训练器</strong>，开关是 use\_on\_policy\_distillation=true、lmbda=1（全部用学生采样）、beta=1（反向 KL）。<strong>核心算法没有新东西</strong>，新的是场景和下面的选题课程。

### 3.2 TVDF：选哪些题来蒸

![论文 Figure 3：TVDF 两步。第一步用真值检查老师：老师预测 ［43.1, 44.5］ 与真值 ［26.2, 34.5］ 不重叠就扔掉，重叠高就留下；第二步在留下的题里挑师生分歧最大的优先训](/images/paper-reading/2026-11-03-video-opd/2026-11-03-d71-2.webp)

- <strong>第一步 TRPV（老师靠不靠谱）</strong>：用真值算老师 top-k 预测的平均 IoU，<strong>老师自己都答错的题直接扔</strong>，免得把错的教给学生
- <strong>第二步 DBTP（哪道题最有教学价值）</strong>：正文说按<strong>师生反向 KL 之和</strong>排序挑最大的；<strong>但附录 B 实际写的是按「老师 IoU − 学生 IoU」排序取 top-k</strong>，放出的数据文件名也是 iou\_diff（见第五节）
- <strong>可以多轮</strong>：每轮用更新后的学生重新算差距、重新选 2,500 题

- <strong>⚠️ 「接近 Gemini-2.5-Flash」要看哪一列</strong>：R@0.5 上还差 10 个点左右（Charades 45.8 vs 56.1，ActivityNet 45.6 vs 57.5）

| 老师（老师自己的 mIoU） | Charades 学生 | ActivityNet 学生 | QVHighlights 学生 |
|-|-|-|-|
| 4B-GRPO（49.8 / 43.8 / 54.9） | 52.4 | <strong>48.4</strong> | 62.5 |

<strong>这张表是全文最值得盯的</strong>：老师从 4B 换到 32B，老师自己涨了 5\~8 个点，<strong>学生只动了 −0.7 到 +0.4</strong>。正文说「老师越强学生涨得越多」，这张表不支持。

<strong>反过来看也很有意思</strong>：拿一个同样 8B、只是跑过 GRPO 的自己当老师，学生 47.0 / 62.3 <strong>反而超过老师本身</strong>（44.7 / 54.3）——而这个老师就是表 1 里「GRPO 直接训」的那一行。

## 五、Limitations

### 论文自述的（一段）

需要一个能给出逐 token log 概率的老师，老师是否可得、是否可靠是现实问题。作者补充：老师不必是巨大的通用模型，GRPO 训过的 4B 专家也行。

### 我读出的 6 条

1. <strong>⭐ 效率账只算了一半</strong>。「约 GRPO 的 1/5 时间」比的是<strong>学生这一侧</strong>。但老师是 Qwen3-VL-32B 先用 GRPO（8 次采样）训出来的——<strong>要拿到这个老师，就已经付过一次更贵的 GRPO</strong>。公平的比法应该是「老师 GRPO + 学生 OPD」对「学生直接 GRPO」，或者干脆用 4B 老师（表 5 说效果差不多）来算总账，论文都没给
2. <strong>⭐ 理论叙事和实际用法脱节</strong>。正文和附录 A 反复讲「长链推理里 GRPO 一个分数摊给 T 个 token、方差随 T 增长，OPD 每个 token 都有信号」。<strong>可最终模型是不思考模式，答案就是「26.20 to 34.50」十几个 token</strong>；开了思考 QVHighlights 从 61.0 掉到 44.1。<strong>在十几个 token 上谈「长链信用分配」，论证的力度要打很大折扣</strong>。附录 A 的「证明」也只是 sketch，「各步奖励基本不相关」是直接断言的
3. <strong>⭐ 老师强弱几乎不影响学生</strong>（表 5）。4B 老师 → 32B 老师，学生 mIoU 只差 −0.7\~+0.4，ActivityNet 上 4B 老师教得更好。<strong>这说明收益可能主要来自「on-policy + 稠密 KL 正则 + 选题」，而不是老师的知识</strong>；正文「老师越强涨得越多」的结论和自己的表打架
4. <strong>⭐ 同一个东西，表里有好几个数</strong>。32B 老师的 mIoU：表 5 是 55.1 / 51.5 / 62.8，<strong>表 6 是 53.2 / 48.9 / 58.4</strong>。「训三轮后在所有数据集上超过老师」是拿表 6 的数比的；<strong>换成表 5 的老师，第 3 轮在 Charades（53.3 &lt; 55.1）和 ActivityNet（50.7 &lt; 51.5）上仍然没超过</strong>。第 1 轮学生在 QVHighlights 上也有三组数：表 1 的 73.8 / 60.3 / 50.4、表 6 的 75.2 / 62.3 / 51.9、表 5 的 75.9 / 63.6 / 52.0，没解释差别
5. <strong>TVDF 正文和附录说法不一</strong>。正文与 Figure 3 说按「师生反向 KL 之和」挑题；附录 B 和放出的数据文件名都是按「老师 IoU − 学生 IoU」挑。另外标题强调「不依赖标注」，但<strong>老师靠标注跑 GRPO、选题也靠标注算 IoU</strong>，标注其实用了两次。而且 Video-OPD 和 GRPO 对照的 <strong>2,500 条数据是用不同规则选的</strong>（TVDF vs Time-R1 难度采样），选题本身就是一个变量
6. <strong>仓库能复现第 1 轮，复现不了论文最好的数</strong>。TVDF 选题代码没放、train.sh 有内部路径、只有第 1 轮权重；想拿第 3 轮的 64.6 得自己补多轮选题。主表也<strong>没有方差 / 多种子</strong>，而 R@0.5 这类列上方法间差距只有 1\~3 个点

## 七、启发与待跟进

1. <strong>⭐ 「同尺寸 GRPO 老师 → OPD」可能是最便宜的增益</strong>：表 5 里 8B-GRPO 当老师，学生反而超过老师本身。<strong>如果手上已经有一个 GRPO 跑过的 checkpoint，再从底座 OPD 一遍，成本很低</strong>，值得先验证是不是普遍现象
2. <strong>⭐ 老师大小可能没那么重要</strong>：4B 老师和 32B 老师效果几乎一样。<strong>做 OPD 之前先试小老师</strong>，能把老师那侧的成本降一个量级
3. <strong>选题比加量值钱</strong>：2,500 条、79 步就到峰；TVDF 的「先用真值筛掉老师答错的，再挑差距大的」实现简单，可以直接搬到任何有真值的蒸馏任务上
4. <strong>待跟进</strong>：① 补总账：老师 GRPO 时间 + 学生 OPD 时间 vs 学生直接 GRPO ② 同一份 2,500 条数据下比 GRPO 和 OPD，去掉选题这个变量 ③ 核对表 5 和表 6 的老师数字到底哪个对 ④ 在真正长输出的任务（带思考的视频问答）上看 OPD 相对 GRPO 的优势还在不在

## 八、结论

<strong>这是一篇「把成熟配方搬到新场景」的论文。</strong>方法就是标准 OPD，工程上是 ms-swift 的一个开关；新东西是 TVG 场景和一个选题课程。

<strong>有用的地方很实在</strong>：8B 学生 2,500 条数据、79 步就把三个榜的 mIoU 拉高 9\~24 个点，学生训练时间约为 GRPO 的 1/5，权重、老师、数据全放了。

<strong>要打折的地方也很清楚</strong>：效率账没算老师、长链信用分配的叙事和十几个 token 的答案对不上、老师大小几乎不影响结果、同一个老师在两张表里数字不同。

<strong>今日一句</strong>：<strong>说「省掉了 GRPO」之前，先看看老师是怎么来的。</strong>

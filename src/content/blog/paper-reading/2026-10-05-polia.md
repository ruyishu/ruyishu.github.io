## TL;DR

<strong>一句话：多模态 RL 的现有做法（GRPO / DAPO）只在<strong>最终答案层面</strong>算优势——但不同的候选答案依赖的是<strong>不同的视觉证据</strong>，用一个标量奖励去比较它们并不公平，导致信用分配粗糙、幻觉与 reward hacking 加剧。POLIA 在 GRPO 之上加了<strong>第二阶段优势</strong>：把候选答案按<strong>它们引用的视觉对象集合</strong>分组，在组内算<strong>视觉对象级的内在优势（intrinsic advantage）</strong>。</strong>

- <strong>最漂亮的一点：新增开销几乎为零。</strong>每轮训练里 Rollout 占 <strong>536.25 秒（97.24%）</strong>，而 POLIA 新增的两个部件——<strong>A<sup>int</sup> 计算只要 0.002 秒、分组只要 0.0002 秒</strong>
- <strong>主结果（7B，base = Qwen2.5-VL-7B-Instruct）</strong>：VSR <strong>41.3 → 81.3</strong>（GRPO 59.0，<strong>+22.3</strong>）；TallyQA 48.0 → <strong>56.7</strong>（GRPO 48.0，<strong>+8.7</strong>）；GQA 33.9 → <strong>69.5</strong>（GRPO 58.2，<strong>+11.3</strong>）；MathVista 48.8 → <strong>74.8</strong>（GRPO 65.5，<strong>+9.3</strong>）
- <strong>在三个视觉接地密集的榜上（VSR / GQA / TallyQA），POLIA-7B 同时超过 GPT-4o 和 Gemini 2.5-pro</strong>
- <strong>3B 档同样成立</strong>：VSR 49.5 → <strong>71.9</strong>（GRPO-3B 53.5，<strong>+18.4</strong>）、TallyQA <strong>+7.2</strong>；而且 <strong>POLIA 只用 VSR + TallyQA 两个数据集训练</strong>，却在 7 个榜上普遍提升
- <strong>消融很清楚（Figure 3）</strong>：去掉外在优势 → 最差最慢；去掉内在优势 → 比前者好、但仍不如完整版 → <strong>两个优势互补</strong>
- <strong>一个很漂亮的机制验证（RQ3）</strong>：训练中<strong>视觉对象组的数量持续下降且方差同步下降</strong>——说明候选答案对"该看哪些对象"从分歧走向一致，而且这个过程与准确率共同演化；<strong>去掉 A<sup>int</sup> 后，N=8 时对象组数量多出 50%</strong>
- <strong>⚠️ 一个被论文藏起来的成本</strong>：论文强调"新增部件几乎免费"，但 Figure 6 的 Rollout 之所以占 97.24%，恰恰是因为 POLIA 需要模型在推理链里<strong>生成 2D 边界框</strong>。<strong>真正的成本被推到了 rollout 里，而论文没给与 GRPO 的端到端时间对比</strong>

## 一、先看例子（大白话：老师判卷只看总分，不看学生引了哪段材料）

> 💡 <strong>铺垫</strong>：GRPO 这类"组式 RL"之所以在文本推理上很有效，是因为它有一个天然前提——<strong>一组候选答案共享同一段文本上下文，所以答案级奖励可以公平地比较它们的推理质量</strong>。
>
> <strong>但 MLLM 打破了这个前提</strong>：不同的候选答案，可能是在看<strong>图里不同的地方</strong>之后才得出结论的。

> <strong>把这件事想成判卷：</strong>
>
> 题目是"<strong>猫的右边是什么？</strong>"。图里有<strong>一只猫和两只狗</strong>。
>
> 三个学生都答"狗"，但你根本不看他们<strong>引用了哪只狗</strong>——你只在总分上写"<strong>对，1 分</strong>"。
>
> <strong>问题是</strong>：<strong>看对了狗 1 和看对了狗 2 是两种不同的能力</strong>，而你的评分完全不区分。更糟的是，答错的学生你也不知道他是"<strong>看错了对象</strong>"还是"<strong>看对了对象但推理错了</strong>"。
>
> <strong>POLIA 的做法</strong>：把答案<strong>按它引用的对象集合分组</strong>——引用了 {狗 1} 的答案放一组、引用了 {狗 2} 的放另一组——<strong>然后只在同一组内比较</strong>。这样"看狗 1 这个选择好不好"就能被单独评价。

![▲ 论文 Figure 1：GRPO 与 POLIA 的对比。左边是传统 GRPO —— 只在整个答案层面计算优势（每段推理链只拿一个答案级优势）；右边是 POLIA —— 把答案级外在优势与视觉对象级内在优势结合起来，对视觉对象做显式的信用分配](/images/paper-reading/2026-10-05-polia/2026-10-05-d50-1.webp)

## 二、动机：组式 RL 的天然前提在多模态下失效了

- <strong>组式 RL 的成功前提</strong>：给定输入 x，策略采样一组候选答案，用<strong>组内比较</strong>算优势（GRPO 用组均值和方差标准化）。这个设计"去掉了价值网络"、训练便宜，很适合大规模策略优化
- <strong>而它的公平性依赖于一个隐含假设</strong>：<strong>候选答案之间可直接比较</strong>——在纯文本里这成立，因为大家看的是同一段上下文
- <strong>多模态直接打破这个假设</strong>：不同候选答案可能依赖<strong>不同的视觉证据</strong>。当 S<sub>i</sub> ≠ S<sub>j</sub> 时，<strong>组内标准化无法对视觉证据做精确的信用分配</strong>，结果就是引导很粗糙
- <strong>后果论文点得很直接</strong>：<strong>加剧幻觉与 reward hacking</strong>
- <strong>已有工作的三个不足</strong>（论文 Related Work）：① 早期靠 prompt 鼓励模型用视觉信息（多模态 CoT 等）② 后续引入显式视觉证据表示，让推理关联到图像区域 ③ 更近的方法支持与图像逐步交互、或用 RL 学推理轨迹但<strong>没有中间监督</strong>——<strong>但这些都没有把视觉证据显式结构化成"对象"、并在对象关系上推理</strong>
- <strong>POLIA 的立论</strong>：<strong>需要一个显式、结构化的视觉证据建模，才能做精确的信用分配。</strong>而且这个结构的灵感来自人怎么读图——<strong>人是按"对象"来读图的</strong>

## 三、方法：两个阶段的优势

![▲ 论文 Figure 2：POLIA 总览。给定图像与问题，采样一组候选答案（每条都含边界框坐标 token 与答案，各有一个答案级奖励 R）。左上做答案级计算得到外在优势；中间 Zoom in 展示每条候选的 token 结构（坐标 token 与文本 token 交错）。右上按置信度校正对象级奖励：预测框与真值框的 IoU 与归一化 L1 距离给出置信度 s，再算 r = R 乘 s。右下按引用的视觉对象集合分组，在组内比较得到内在优势](/images/paper-reading/2026-10-05-polia/2026-10-05-d50-2.webp)

### 3.1 视觉证据建模：把证据表示成"一组视觉对象"

- <strong>前提</strong>：每个候选答案 c<sub>i</sub> 的推理链里含有<strong>预测的边界框</strong>（以坐标 token 的形式）
- <strong>做法</strong>：把每个预测框与真值对象框按预定规则匹配，得到<strong>顺序无关的对象身份集合</strong> <strong>S<sub>i</sub> = {o<sub>i,1</sub>, …, o<sub>i,mi</sub>}</strong>，把它当作 c<sub>i</sub> 使用的视觉证据
- <strong>关键定义</strong>：<strong>两个候选答案"依赖同一视觉证据"当且仅当它们诱导出相同的对象集合</strong>。这比"笼统的视觉相关信息"要明确得多，也是后面分组的基础

### 3.2 第一阶段：答案级外在优势（A<sup>ext</sup>）

对每个候选答案 c<sub>i</sub> 算一个奖励，<strong>两项加权</strong>：

> <strong>R(c<sub>i</sub>) = λ<sub>ans</sub> · R<sub>ans</sub>(c<sub>i</sub>) + λ<sub>fmt</sub> · R<sub>fmt</sub>(c<sub>i</sub>)</strong>

- <strong>R<sub>ans</sub></strong>：最终答案与真值的匹配度——<strong>主监督信号，直接对齐评测指标</strong>
- <strong>R<sub>fmt</sub>：格式有效性</strong>，强制推理链里坐标的格式正确——<strong>⚠️ 这一项看着朴素，其实是整个方法的前提</strong>：没有格式正确的框，后面根本没法构造视觉对象组
- 然后按 GRPO 的方式在组内标准化：<strong>A<sup>ext</sup><sub>i</sub> = ( R(c<sub>i</sub>) − mean ) / ( std + δ )</strong>

### 3.3 第二阶段：视觉对象级内在优势（A<sup>int</sup>）

<strong>第一步 · 按置信度校正对象级奖励</strong>

- 对 c<sub>i</sub> 引用的每个对象 o，算一个<strong>置信度 s<sub>i,o</sub> ∈ \[0,1\]</strong>，衡量"c<sub>i</sub> 引用 o 有多可靠"
- 实现上：<strong>预测框与真值框的 IoU 和归一化 L1 距离的加权组合</strong>，再裁剪到 \[0,1\]
- 校正后：<strong>r<sub>i,o</sub> = R(c<sub>i</sub>) · s<sub>i,o</sub></strong> —— <strong>把答案级奖励"广播"到每个被引用的对象上，并按引用可靠性打折</strong>

<strong>第二步 · 在视觉对象组内标准化</strong>

> <strong>A<sup>int</sup><sub>i,o</sub> = ( r<sub>i,o</sub> − mean<sub>j∈G<sub>S</sub></sub>\[r<sub>j,o</sub>\] ) / ( std<sub>j∈G<sub>S</sub></sub>\[r<sub>j,o</sub>\] + δ )</strong>

- <strong>这个归一化是在"引用同一组视觉证据"的候选之间做的</strong>，所以它衡量的是"<strong>在当前证据条件下，这个答案更好还是更差</strong>"
- 论文的直觉表述：<strong>内在优势反映"这个对象对正确答案的潜在贡献"</strong>。之所以叫"内在"，是因为它<strong>在一个训练中自然形成的视觉对象组内部计算</strong>

### 3.4 整体优化：两者的作用域不同（这是个容易忽略的细节）

- <strong>A<sup>ext</sup> 施加到推理链的所有 token</strong>——文本 token 和坐标 token 都算
- <strong>A<sup>int</sup> 只施加到对应对象的坐标 token 上</strong>
- 合起来的优势：<strong>A<sub>i</sub> = A<sup>ext</sup><sub>i</sub> + ω · Σ<sub>o∈S<sub>i</sub></sub> I( t ∈ T<sup>box</sup><sub>i,o</sub> ) · A<sup>int</sup><sub>i,o</sub></strong>
- 损失 = 标准带裁剪的替代目标 + KL(π<sub>θold</sub> ‖ π<sub>θ</sub>)
- <strong>论文的定位</strong>：外在优势负责"<strong>在答案级监督下鼓励更高奖励的答案</strong>"，内在优势负责"<strong>在视觉对象组内做显式的信用分配</strong>"——两者结合，既保留了组式 RL 的效率，又加强了"提取和利用有效视觉证据"的学习信号

### 4.2 消融：两个优势各自在干什么（Figure 3）

![▲ 论文 Figure 3：两个优势的消融训练曲线（纵轴是训练用的归一化奖励，综合了答案正确性与推理格式有效性）。(a) VSR，(b) TallyQA。三条线分别是完整 POLIA（橙）、去掉内在优势（青）、去掉外在优势（紫）——去掉外在优势最差最慢，去掉内在优势居中，完整版最好](/images/paper-reading/2026-10-05-polia/2026-10-05-d50-3.webp)

- <strong>去掉 <strong>A<sup>ext</sup></strong> → 奖励最低、提升最慢</strong> → <strong>外在优势是稳定优化的关键</strong>
- <strong>去掉 <strong>A<sup>int</sup></strong> → 明显好于去掉 A<sup>ext</sup>，但在收敛速度和最终奖励上都仍不如完整版</strong>
- <strong>结论</strong>：外在优势负责<strong>有效的全局优化</strong>，内在优势负责<strong>在同一视觉对象组内提供对象级引导、改善视觉证据上的信用分配</strong>——两者是互补关系，不是替代关系

### 4.3 机制验证：模型真的学会了"该看哪些对象"（Figure 5）

![▲ 论文 Figure 5：视觉证据选择的稳定性。横轴是训练迭代，左轴是视觉对象组的数量及其标准差（阴影），右轴是准确率。三种候选数 N 分别为 8、16、24。各 N 下，对象组数量的均值与标准差都随训练下降，说明模型对「该看哪些对象」从分歧走向一致，而且这个过程与准确率提升共同演化](/images/paper-reading/2026-10-05-polia/2026-10-05-d50-4.webp)

- <strong>指标设计很巧</strong>：<strong>视觉对象组的数量 = 采样答案中出现的不同对象集合的个数</strong>。这个数越小，说明<strong>越多答案依赖同一套视觉证据</strong>
- <strong>实验对象选得也巧</strong>：论文专门从 TallyQA 里挑<strong>对象数较多</strong>的样本（这类样本训练初期最可能"各看各的"），这样变化更容易被观察到
- <strong>结果</strong>：训练开始时对象组数量很高（分歧大），随迭代<strong>持续下降</strong>；同时<strong>准确率上升并在更晚才饱和</strong> → <strong>证据选择的收敛与答案正确性的提升是共同演化的</strong>
- <strong>稳定性也在改善</strong>：对象组数量的<strong>标准差</strong>同步下降，而且<strong>早期下降更快、后期趋缓</strong>。论文把它解释成两阶段优化：早期快速压制"导致推理发散的极端不一致证据"，后期专注解决剩下的模糊案例
- <strong>最关键的一组对照</strong>：<strong>去掉内在优势后，N=8 时对象组数量比完整方法多出 50%</strong> → <strong>内在优势确实在推动视觉对象组的收敛</strong>
- <strong>关于候选数 N</strong>：N=8 的准确率明显低于 N∈{16, 24}，而 16 与 24 相近 → 典型的<strong>探索-利用权衡</strong>：探索不足会限制性能，但一旦候选多样性够了，再加收益就递减

## 五、Limitations &amp; 批判性思考

> ⚠️ <strong>先说事实</strong>：<strong>这篇论文没有 Limitations 章节</strong>。全文只有 Conclusion 与 Impact Statement（Impact Statement 也只写了"不预见直接的伦理问题"）。下面这些问题都得由读者自己补出来。

### 我读出来的问题（按严重程度排序）

- <strong>① 最大的问题：成本被"搬家"了，而论文只报了搬家后的账。</strong>Figure 6 证明"新增部件只要 0.002 秒"，这个说法在字面上没错；<strong>但同一张图的 Rollout 之所以占到 97.24%，论文自己承认是因为"模型必须生成 2D 边界框"</strong>——而 GRPO 不需要生成框。<strong>所以真正该回答的问题是"与 GRPO 相比，端到端每轮训练时间是涨了还是没涨、涨多少"，论文没有给这个对比。</strong>这让"efficiency"这个 RQ4 的结论打了折扣
- <strong>② 方法有一个没说清的强前提：模型必须能输出格式正确的边界框。</strong>论文用 R<sub>fmt</sub> 强制坐标格式，但<strong>没有报告"格式有效率"是多少</strong>——如果相当比例的候选答案框格式无效，那它们的 A<sup>int</sup> 就无从计算，而这类样本在训练里的占比直接影响方法有效性
- <strong>③ 视觉对象组的构造依赖与真值框的匹配，这是一个隐性标注依赖。</strong>S<sub>i</sub> 是把预测框匹配到 <strong>GT 对象框</strong>得到的。也就是说，这个方法<strong>需要目标检测级别的标注</strong>才能跑。<strong>论文没有讨论在只有问答标注、没有框标注的数据上怎么办</strong>——而这类数据恰恰是多模态推理语料的主流
- <strong>④ "泛化"这个说法缺少一个关键对照。</strong>论文强调"只用 VSR + TallyQA 训练，却在 7 个榜上普遍提升"。<strong>但没有报告"在同样两个数据集上训 GRPO/DAPO 的留出集表现"</strong>——如果基线也是在同样数据上训的（从 Table 1 看应该是），那这就是标准设定而非额外发现；如果不是，那就需要一个对照才能支撑"泛化"这个词
- <strong>⑤ 评测用 GPT-4o 当裁判，而裁判可靠性在这条线上已经被反复质疑。</strong>答案又是自由文本（字符串匹配不够用），所以必须用 LLM 判分。<strong>论文没有做裁判可靠性验证</strong>（没抽样人工核对、没换裁判模型做稳健性检查）——这与我 9/23 读过的那条线（MoCA 的"高方差 LLM judge 会被钻空子"）是同一个坑。<strong>VSR 从 41.3 涨到 81.3 这种大幅提升，如果有相当部分来自"更啰嗦/更像判官喜欢的措辞"，读表的人是无法察觉的</strong>
- <strong>⑥ 只在 Qwen2.5-VL 一个模型家族上验证</strong>（3B 与 7B），且规模都不大。<strong>大规模、跨家族（InternVL / Qwen3-VL）是否成立未知</strong>
- <strong>⑦ 超参敏感性没有呈现。</strong>方法引入了 <strong>ω（内在优势权重）、λ<sub>ans</sub>、λ<sub>fmt</sub></strong>，还有匹配规则与置信度公式（IoU 与 L1 的加权组合）里的权重——<strong>这些的选择依据和敏感性，正文没有给</strong>（论文说细节在 Appendix A.1）
- <strong>⑧ 机制分析只在 TallyQA 上做。</strong>"视觉对象组收敛"这个很漂亮的发现只在一个数据集（且是特意挑高对象数的子集）上验证。<strong>它是否是一个普适现象、还是这个数据集的特性，无法判断</strong>
- <strong>⑨ 表里的相对提升容易被误读。</strong>Table 1 的 "Average Improvements" 用的是相对增幅（VSR +27.6↑ 这类），与绝对百分点是两个口径。<strong>看到"涨了 27"要意识到那是相对值</strong>（绝对差其实是 40.0 个百分点：41.3 → 81.3）
- <strong>⑩ 没有 Limitations 章节</strong>（对一篇 ICML Poster 属于常见但可惜的缺失），上述①②③这些直接影响适用面的前提，本应由作者自己摊开

## 六、与前文对照

> 🔗 <strong>一句话定位：POLIA 与 9/23 的 MoCA 是同一个问题的两种解法——都在说"答案级/感知级的粗粒度奖励不够"。MoCA 在<strong>奖励层面</strong>给感知单独发奖励并用它<strong>路由 GRPO 优势</strong>；POLIA 在<strong>证据层面</strong>把候选按引用对象分组、在<strong>组内标准化</strong>。一个改奖励、一个改分组。</strong>

### 6.1 与 MoCA（9/23）：最直接的一对

- <strong>共同的问题诊断</strong>：多模态推理的信用分配太粗。MoCA 说"只盯最终答案就分不清是看错还是想错"；POLIA 说"不同答案依赖不同视觉证据，用一个标量比它们不公平"
- <strong>不同的解法</strong>： 
  - <strong>MoCA</strong>：用"蒙眼推理器"（PV）给感知单独发一个<strong>二值奖励</strong>，再用它<strong>门控改写失败轨迹的优势</strong>（保护无辜感知 token / 加重惩罚）
  - <strong>POLIA</strong>：用<strong>模型自己输出的边界框</strong>构造视觉对象集合，按集合分组，组内做<strong>z-score 标准化</strong>得到对象级优势，只施加到<strong>坐标 token</strong> 上
- <strong>关键差别</strong>：<strong>MoCA 需要额外跑一个"蒙眼推理器"</strong>；<strong>POLIA 只需要模型自己已经把框说出来了</strong>——所以 POLIA 的新增开销是 0.002 秒，MoCA 多一次前向。<strong>但代价是 POLIA 必须有一个隐性的检测标注依赖（要 GT 框才能匹配）</strong>
- <strong>共同的方法论风险</strong>：两篇都建立在"一个外部判断依据可靠"的假设上——MoCA 靠 LLM judge 的可靠性，POLIA 靠<strong>框匹配的质量</strong>（IoU/L1），而两边都没做这个依据的鲁棒性测试

### 6.2 与"探针家族"（PAPO 8/18 / CFPO / BSBT）

- 那几篇的探针是<strong>外加的干预</strong>：PAPO 遮图、CFPO 在隐空间做反事实、MoCA 把感知文本喂给蒙眼推理器
- <strong>POLIA 的探针是模型自己的输出</strong>——推理链里的边界框。<strong>这是第一个用"模型显式输出的 grounding"当信用分配依据的</strong>，不需要任何外部干预模型
- <strong>代价与收益很清楚</strong>：省掉了外部探针，但<strong>把成本转移到了 rollout（要生成框）</strong>，并且<strong>要求训练数据有框标注</strong>

### 6.3 lib 的"分锅家族"又多了一个轴

- 已有的：BSBT <strong>模态轴</strong>、PCD <strong>因果阶段轴</strong>、GiGPO <strong>时间步轴</strong>、MIRL <strong>生成阶段轴</strong>、InstructVLA <strong>参数子集轴</strong>、MoCA <strong>模态轴 + 奖励路由</strong>、Forget-Me-Not <strong>模块轴</strong>、SDPO <strong>token × 词表轴</strong>
- <strong>POLIA 补上"视觉对象轴"</strong>——而且它和其他成员有一个本质不同：<strong>它的分锅依据不是"外部指定的划分"（模态、阶段、模块），而是"模型自己诱导出来的划分"</strong>（这条答案引用了哪些对象）。这一点很值得注意
- 另一个不同：<strong>它是第一个用"组内比较"（而不是加权 / 门控 / 路由 / 掩码）来做分锅的</strong>——把 GRPO 的组内标准化机制<strong>在对象这一层再跑一遍</strong>

### 6.4 与 SDPO（9/30）：都是加细优势粒度，但切的轴不同

- <strong>SDPO</strong>：优势粒度是"<strong>每个生成位置 × 每个词表 token</strong>"，依据是"看过环境反馈的自己"
- <strong>POLIA</strong>：优势粒度是"<strong>每个视觉对象</strong>"，依据是"模型自己标出来的框"
- <strong>两篇的共同动作</strong>：<strong>保留原算法的骨架，只把优势换成一个更细的版本</strong>（SDPO 明说"只换优势"，POLIA 是"A<sup>ext</sup> + ωA<sup>int</sup>"）。<strong>"只换优势"已经成为一种高效的改进范式</strong>
- <strong>而且两篇都很便宜</strong>：SDPO 每步 +5.8%，POLIA 新增部件 0.002 秒

### 6.5 与 VLM-CapCurriculum（9/25）：都在给"看"单独造监督信号

- 那篇发现"<strong>86.9% 的错答错在感知</strong>"，解法是<strong>在数据层面隔离感知缺陷</strong>（筛出"看图错、看描述对"的样本，再按能力排课）
- POLIA 发现"<strong>答案级奖励无法告诉模型该看哪个对象</strong>"，解法是<strong>在优势结构层面补一个对象级的信号</strong>
- <strong>一个改数据、一个改优势</strong>，但目标完全一致。<strong>而且这两条路可以叠</strong>：用 VLM-CapCurriculum 的方式造数据，再用 POLIA 的方式发优势——<strong>lib 里没人做过这个组合</strong>

## 七、启发与待跟进

> 💡 <strong>今天最该带走的一条</strong>：<strong>"只在最终结果层面给奖励"是个非常普遍的粗糙点，而改进它的通用动作是——给奖励找一个"天然的中间粒度"。</strong>POLIA 找的是<strong>视觉对象</strong>（因为人就是按对象读图的），SDPO（9/30）找的是<strong>环境反馈</strong>（因为环境本来就会返回）。<strong>"这个领域里天然的中间粒度是什么"——这是一个可以反复使用的选题提问。</strong>

### 方法启发（可迁移）

- <strong>① "组内比较"这个机制可以被搬到任何有自然分组的地方。</strong>GRPO 的分组是"同一个问题的多个候选"，POLIA 在<strong>对象这一层又分了一次组</strong>。<strong>凡是能定义出"同一条件下的可比集合"的地方，都能再跑一次组内标准化</strong>
- <strong>② 让分组依据由模型自己产生，比外部指定更省事。</strong>POLIA 的组不是人分的，是<strong>模型自己输出的框</strong>诱导出来的。代价是要求模型有输出框的能力
- <strong>③ 成本分析一定要看端到端。</strong>论文证明"新增部件几乎免费"没错，但<strong>真正的成本被搬到了 rollout</strong>，而端到端对比缺了。<strong>以后看到"我们的方法只增加了 0.1% 的计算"，第一个要问的是"那总时间呢"</strong>
- <strong>④ 一个辅助奖励（格式项 R<sub>fmt</sub>）可能是整条方法的前提。</strong>R<sub>fmt</sub> 看起来只是个格式约束，但<strong>没有它就没有合法的坐标、就没有视觉对象组、整个第二阶段就崩了</strong>。<strong>设计方法时要识别出"哪个看似辅助的部件其实是承重墙"</strong>
- <strong>⑤ 用一个"结构涌现"指标来验证机制。</strong>"视觉对象组数量下降 + 方差下降 + 准确率同时上升"是一个很漂亮的机制证据，比单纯报分数更有说服力。<strong>这个套路可以用在任何"模型是否真的学会了某种结构"的问题上</strong>

### 待跟进（按性价比排序）

- <strong>① 补端到端训练时间对比（与 GRPO 同设置）</strong>：这是这篇最明显的缺口，也是最容易做的。<strong>如果生成框带来的 rollout 变慢超过了性能收益，方法的经济性就要重新算</strong>
- <strong>② 去掉对真值框的依赖</strong>：现在是"预测框匹配 GT 框"才能构造 S<sub>i</sub>。<strong>如果改成"预测框之间自匹配"（用 IoU 聚类，不需要 GT），方法就能用在只有问答标注的数据上</strong>——这一步会把适用面扩大一个量级
- <strong>③ 换裁判 + 裁判可靠性验证</strong>：GPT-4o 判自由文本答案，是这条线上反复出现的最弱点。<strong>可以接 MoCA 的 SVV（结构化口头验证）思路，或至少做一次人工抽检</strong>
- <strong>④ 与 MoCA 正面对撞</strong>：<strong>对象组内标准化（POLIA）vs 感知奖励门控（MoCA）</strong>，同骨干同数据，看谁的分锅更值。这是两条路线的干净对照
- <strong>⑤ 视觉对象组的粒度问题</strong>：现在一个对象一个"身份"。<strong>更细（像素级 mask）或更粗（区域）会怎样？</strong>论文没扫
- <strong>⑥ 把"对象级优势"搬到视频 / 3D</strong>：视频的天然中间粒度是<strong>时间片段 + 对象轨迹</strong>，3D 是<strong>空间实体</strong>。<strong>"中间粒度在哪"这个问题在每模态里答案不同</strong>
- <strong>⑦ 跨家族 + 大规模验证</strong>：现在只有 Qwen2.5-VL 的 3B/7B
- <strong>⑧ 与 VLM-CapCurriculum 组合</strong>（见 6.5）：<strong>数据层隔离感知缺陷 + 优势层发对象级信号</strong>，两条路叠起来
- <strong>⑨ 报告格式有效率</strong>：R<sub>fmt</sub> 到底筛掉了多少候选答案？这个数字直接决定 A<sup>int</sup> 的覆盖率

## 八、今日阅读结论

> 🎁 <strong>今日一句</strong>：<strong>一个标量奖励要负责的不只是"答对没有"，还有"是靠看哪里答对的"——把奖励拆到一个"天然的中间粒度"上（这里是视觉对象），信用分配才真正落地；而这件事可以做得几乎免费，只要你找对了那个粒度。</strong>

- <strong>这篇最本质的贡献是识别出一个被忽略的不公平</strong>：组式 RL 的公平比较<strong>依赖"候选共享同一上下文"这个前提</strong>，而多模态打破了这个前提。<strong>把一个隐含前提显式化，往往就是一篇好论文的起点</strong>
- <strong>第二个贡献是找到了一个天然的中间粒度</strong>：视觉对象。它既符合人的读图习惯，又能直接从模型输出的框里读出来——<strong>不需要外部标注模型、不需要额外前向</strong>
- <strong>第三个贡献是一组漂亮的机制证据</strong>：视觉对象组的数量与方差同步下降、且与准确率共同演化；去掉内在优势后 N=8 时对象组数量多出 50%。<strong>这比单纯报分数更能说明"方法真的在起作用"</strong>
- <strong>最诚实的评价</strong>：结果很硬（VSR 相对 GRPO +22.3、三个接地榜超过 GPT-4o 与 Gemini 2.5-pro），新增开销确实极小，机制证据漂亮；<strong>但——① 成本被搬到了 rollout，而端到端对比缺失 ② 依赖真值框标注（隐性但强的前提）③ 裁判是 GPT-4o 且没做可靠性验证 ④ 没扫超参、没做跨家族、"泛化"缺关键对照</strong>
- <strong>对项目的直接价值</strong>：① <strong>"给奖励找一个天然的中间粒度"是可反复使用的选题提问</strong>，而且能直接套到你的 OPD 主线上（中间粒度 = 哪些 token / 哪个能力阶段）② <strong>"只换优势"再次被证明是高效改进范式</strong>（SDPO 与 POLIA 连续两天都用了这一招）③ <strong>POLIA × MoCA 的对撞</strong>和 <strong>POLIA × VLM-CapCurriculum 的组合</strong>是两个现成的交叉实验 ④ "成本要看端到端"这条教训，对你评估 jitrl2/jitrl3 的方案同样适用

## TL;DR

一句话：**标准 RLVR 训出来的模型遇到错误初始方向会硬撑到底，Re² 给模型一个"推倒重来"的按钮，并设计奖励让 redo 的回报 = 这道题重新做对的概率；纯 RL 无 SFT 预热，把 redo 行为从 0.5% 放大到 30%+，5 个模型在 5 个 benchmark 上全面且显著超过 DAPO（p < 0.05）。**

- **场景**：LLM 推理（数学/科学），RLVR 训练后模型在 CoT 里堆冗余步骤、过度思考，初始方向走偏时无法回头。
- **痛点**：RLVR 只看最终答案对错，不教模型"这条路还要不要继续"。
- **方法 Re²**：把"重做"变成可选动作；模型生成 `<redo>` 就打断当前轨迹重新求解。redo 奖励 = out-of-group 估计的"从零做对概率"。
- **结果**：Qwen2.5-7B-Instruct 上，AIME25 从 8.6% → 21.2%（+12.6pp），Avg 从 43.0% → 47.4%（+4.4pp）。

## 一、Motivation：初始方向错了，后面越写越偏

作者先做了一个诊断：同一道题采样 128 条回答，看 CoT 长度和准确率的关系。结果发现 **CoT 越长，准确率反而越低**（Figure 1 / Pre1.pdf）。

原因不是"长思考没用"，而是：模型一旦开头走错方向，后面就会顺着错路继续硬撑，生成大量冗余、低质量的步骤，最终几乎不可能回到正确答案。

> 核心发现：推理失败不是 token 不够，而是**早期方向错了还继续硬撑**。如果允许模型在早期方向不对时"读档重来"，就有更高概率做对。

📎 **图 1 · Pre1.pdf**：CoT 长度 vs 准确率，呈现明显负相关。柱状图是不同长度区间的样本比例，折线是该区间的平均准确率。原文 Figure \ref{fig:length_acc}。

## 二、Method：把"重做"变成 RL 里的一个动作

### 2.1 动作设计

给模型一个特殊模板（prompt），让它可以在 CoT 任意位置输出一句话：

> "It's better to redo the question."

一旦模型输出这句话，就视为 **redo 动作**：截断当前轨迹，清空之前内容，从零重新生成新的 CoT。最多允许 redo R=5 轮。

### 2.2 训练时的采样结构

Re² 不是让模型一次生成一条完整轨迹，而是构造了一个"前缀 + 续写"的采样结构：

1. 对每个问题，先采样 n=8 条完整回答
2. 每条回答随机在 [0, 0.8] 比例处截断，得到 n 个不同长度的"前缀"（prefix）
3. 每个前缀再生成 m=8 条续写（continuation）
4. 来自同一个前缀的 m 条续写组成一个 group

这样每个问题得到 n 个 group，每个 group 内共享同一个前缀。

📎 **图 2 · Method.pdf**：Re² 框架总览。对每个 query 采样多个前缀，每个前缀生成多个续写；advantage 在每个 group 内计算，redo 的奖励用 out-of-group 准确率估计。原文 Figure \ref{fig:method}。

### 2.3 奖励设计（核心）

对每个续写，只有三种结局：

- **correct**：最终答案对 → 奖励 1
- **incorrect**：最终答案错 → 奖励 0
- **resolve（redo）**：触发 redo → 奖励 = 这道题"从零重新做"的成功率

这个"从零成功率"怎么估计？用 **out-of-group 的续写**：对于当前前缀 group i，用其他 (n-1)×m 条续写里最终做对的比例作为估计。

```text
redo 奖励 ≈ 其他 group 的续写中，最终答案正确的比例

```

如果当前轨迹很乱，其他 group 从零做对的比例反而比继续硬撑的期望奖励高，那模型就会倾向于 redo。

### 2.4 损失函数

用 PPO / DAPO 风格的 clipped surrogate loss。关键：advantage 在 group 内计算，redo 的奖励用 group 外的准确率估计。

```text
r = 1              if final answer correct
r = 0              if final answer incorrect
r = P_out(correct) if redo

```

> redo 奖励被 out-of-group 准确率锚定，所以它不会奖励"逃避式重做"——如果这道题本来就很难，red o 的奖励也低；如果当前轨迹已经走歪，redo 反而更划算。本质上让模型学会了"止损"。

### 2.5 推理阶段

生成时一旦遇到 redo，就重新开始采样，直到产出最终答案。取最后一次 redo 后的答案作为输出。

**关键数字**：

- **AIME25 提升最大**：Qwen2.5-7B-Instruct 上从 8.6% → **21.2%**（+12.6pp）
- **全部显著**：所有 5 个模型在 5 个 benchmark 上 Re² 都超过 DAPO，p-value < 0.05

### 3.2 Redo 行为被放大

- 初始模型（vanilla）redo 行为仅约 **0.5%**
- Re² 纯 RL 训练后，redo 行为涨到 **30% 以上**
- 没有 SFT 预热，完全是奖励信号诱导出来的 emergent 行为

### 3.3 Test-time scaling 更优

同一训练预算下，随着采样数增加，Re² 的 compute-performance 权衡曲线优于 DAPO，也优于 majority voting。也就是说：**推理时采样越多，Re² 越赚**。

Re² 每个训练 step 处理 32 queries，每个 query n=8 前缀、m=8 续写；DAPO 为对齐 token 预算用 128 queries × n=20。说明 Re² 用更复杂的采样结构，但总的训练 token 预算是可比的。

## 四、Limitations & 未来工作

### 4.1 论文自述的局限

1. **模板设计**：redo 触发模板仍是超参数，论文做了消融但未公开确切措辞
2. **奖励估计方差**：out-of-group 估计用 8×8=64 条续写，小模型 / 难题上估计可能不稳定
3. **任务范围**：主要在数学/科学推理，代码、逻辑、多步规划待验证
4. **最大 redo 轮数**：R=5 是固定值，未深入讨论动态 R

### 4.2 我认为的真正局限

1. **简单题的 mis-incentive**：虽然 redo 奖励被成功率封顶，但 GSM8K 这种简单题上 Re² 提升很小（91.8→93.6），是否因为 redo 本身没必要？论文未分析
2. **与"RL 只是策略选择"争论的关系**：Re² 把 0.5%→30% 的 redo 放大，是"稀疏策略选择"论的强证据，但论文未展开
3. **和 OPD/COPD 未比较**：Re² 与 on-policy distillation 是完全不同的训练范式，能否结合？
4. **推理成本**：实际推理时 redo 会重新采样，单次 latency 和 token 消耗可能增加

## 五、启发与待跟进

### 5.1 论文已回答的问题

**Q: redo 行为能从纯 RL 中 emergent 出来吗？**A: 能。从 0.5% 涨到 30%+，无需 SFT 预热。

**Q: redo 奖励怎么设计才合理？**A: 用 out-of-group 估计的"从零成功率"，既防止逃避，又鼓励合理止损。

**Q: 在哪些 benchmark 上提升最大？**A: AIME25（最难的竞赛数学）提升最明显，说明 redo 对难题价值最大。

### 5.2 待跟进的问题

- [ ] redo 奖励估计的方差：n=8, m=8 是否足够？附录里用 1024 条样本当 gold，估计器的 bias/variance 如何？

- [ ] 与 process reward（如 ProcessThinker）的关系：Re² 用 outcome 间接实现过程级止损，是否比显式 process reward 更省标注？

- [ ] 与 TOPD/COPD 的结合：OPD 改信号路由，COPD 改信号来源，Re² 改动作空间——三者正交

- [ ] 代码 / 多步规划任务上的验证

- [ ] 动态最大 redo 轮数：是否可以让模型自己决定"还要不要再 redo 一次"

## 六、深度讨论：Reward Hacking 质疑与改进方向

### 6.1 一直 redo 是 reward hacking 吗？

**核心质疑**：如果模型在同一次生成中反复触发 redo（redo → redo → redo ...），是不是在 hack 奖励？

**为什么会发生？**

redo 的奖励 = out-of-group 成功率，这是一个**固定值**（对于给定的 batch）。假设这个成功率是 30%：

> 模型学到："我当前这条轨迹的期望奖励可能只有 20%，但 redo 一下能拿 30%。那我永远 redo 好了。"

这就变成了 reward hacking：模型学会了"无脑 redo"而不是"判断何时该 redo"。

**论文的防御**：

- 硬性上限 R=5：最多 redo 5 次，防止无限循环
- 但没解决根本问题：如果模型学会"总是 redo 5 次"，那和 pass@6 没区别

**这算不算 hacking？**

| 情况 | 是否 hacking |
|-|-|
| 模型只在轨迹明显走偏时 redo | 不算，是合理的元认知 |
| 模型无脑 redo，不管轨迹质量 | 算，说明奖励设计有问题 |

**论文的数据**：redo 行为从 0.5% → 30%，且只在难题上提升明显。说明模型确实学到了"何时该 redo"，不是无脑 redo。但论文**没有深入分析 redo 的时机是否合理**，这是一个明显的漏洞。

**应该做的分析（论文没做）**：

- redo 前的轨迹质量分布（是不是真的走偏了？）
- redo 后的准确率提升（是不是真的变好了？）
- 如果 redo 前的轨迹质量很高，但模型还是 redo，那就是 hacking

### 6.2 "从零重来就一定会对吗？"——更深层的质疑

**质疑 1：清空上下文 = 换路吗？**

> "你都清空前面上下文了，感觉会反复踩同一个坑啊"

**回答**：LLM 是随机采样的（temperature=0.6, top-p=0.95），所以即使 prompt 完全一样，每次生成的内容都不同。"清空重来"确实有可能走不同的路。

但问题在于：如果模型对某类题有**很强的错误先验**（比如"看到不等式就想用 AM-GM"），即使采样 10 次，可能 8 次都走同一条错路。

**质疑 2：和 pass@k 的区别？**

| 方法 | 谁决定"重来" | 什么时候重来 |
|-|-|-|
| pass@k | 外部机制（majority voting） | 固定采 k 次 |
| Re² | 模型自己 | 模型学会"当前轨迹质量差时"重来 |

Re² 的贡献是教模型**判断"当前轨迹还要不要继续"**，不是无脑多采几次。但 Re² 的训练过程确实依赖大量采样。

**质疑 3：什么时候 Re² 没用？**

- 模型根本不会做这道题：out-of-group 成功率本身就很低（比如 5%），redo 也没用
- 简单题：模型本来就 95% 能做对，redo 的收益很小
- 路径唯一：只有一条正确路径，模型第一次没选到，重来也没机会选到

**论文数据印证**：

- GSM8K（简单题）：91.8 → 93.6，提升很小
- AIME25（难题）：8.6 → 21.2，提升很大

说明 Re² 对**中等难度的题**（模型有一定概率做对，但不稳定）最有效。

## 七、后续研究设想：Value-Guided Partial Re-solving（A+B 方向）

### 7.1 核心思路

将 Re² 的两个主要缺陷合并解决：

1. **用 Value Function 替代 out-of-group 估计**：更稳定的奖励信号，更精细的决策
2. **支持部分重启（Partial Restart）**：不总是清空一切，而是从某个检查点重新生成

### 7.2 方法设计

#### 7.2.1 Value Function 训练

训练两个 value function：

```text
V_continue(state) = 继续当前轨迹的期望奖励
V_redo(state) = 从零重新开始的期望奖励
V_partial(state, k) = 从第 k 步重新开始的期望奖励

```

在每个推理步骤 t，模型比较：

```text
action = argmax {
    V_continue(state_t),      # 继续
    V_redo(state_t),           # 完全重启
    max_k V_partial(state_t, k) # 部分重启（选最优的 k）
}

```

#### 7.2.2 部分重启的实现

**如何识别"哪一步开始走偏"？**

方案 A：用 TOPD 的 OT 距离检测

- 计算学生轨迹和教师轨迹的 OT 距离
- 找到 OT 距离突然增大的点 → 这就是"走偏点"
- 从该点之前重新生成

方案 B：用 Process Reward Model (PRM)

- PRM 在每个步骤给出"这一步对不对"的信号
- 找到 PRM 分数突然下降的点 → 从该点重新生成

方案 C：让模型自己学

- 给模型一个 `<rollback k steps>` 的动作
- 通过 RL 学习何时 rollback 多少步

#### 7.2.3 训练目标

```text
L = E[ sum_t max(
    V_continue(state_t) - baseline,
    V_redo(state_t) - baseline,
    max_k V_partial(state_t, k) - baseline
)]

```

其中 baseline 可以用 TD(λ) 或 GAE 来减少方差。

### 7.3 预期优势

| 维度 | Re² | 本方案 |
|-|-|-|
| 重启决策 | 二元（redo 或不 redo） | 连续（继续 / 部分重启 / 完全重启） |
| 奖励估计 | out-of-group 准确率（方差大） | Value Function（方差小） |
| 重启粒度 | 只能完全清空 | 可以从任意检查点重新开始 |
| 计算效率 | 每次 redo 都从零开始 | 部分重启节省计算 |

### 7.4 实验设计

**Benchmark**：

- 数学推理：AIME 2024/2025, AMC 2023, GSM8K, MATH500
- 代码生成：HumanEval, MBPP
- 逻辑推理：PrOntoQA, CLUTRR

**Baseline**：

- DAPO, GRPO（标准 RLVR）
- Re²（完全重启）
- Process Reward Model（显式过程监督）

**分析**：

- Value Function vs out-of-group 估计的方差对比

- 部分重启的"回退点"分布分析（模型学会了从哪一步重新开始？）

### 7.6 风险和备选方案

**风险 1**：Value Function 训练不稳定

- 备选：用简单的 heuristic 代替（比如"如果连续 3 步 token 概率很低，就部分重启"）

**风险 2**：部分重启的实现复杂

- 备选：先做纯 Value Function + 完全重启（只解决方向 A），验证价值后再加部分重启

**风险 3**：和 PRM / TOPD 的结合太复杂

- 备选：只和其中一个结合，比如只做 Value Function + OT 距离检测

## 八、训练数据补充

**训练数据集**：DAPO-Math-17K

- 来源：AoPS（Art of Problem Solving）+ 官方竞赛题目
- 规模：17,000 道数学题
- 特点：覆盖广泛的数学领域，答案全部转为整数（方便 rule-based reward）

**评测 Benchmark**（和训练集不重叠）：

- AIME 2024/2025：30 道竞赛数学题
- AMC 2023：40 道题
- GSM8K：1,319 道小学应用题
- GPQA-Diamond：198 道研究生级别科学题

**Temperature 说明**：推理时用 temperature=0.6, top-p=0.95。这个温度在推理任务中是标准配置（0.6-0.8 是常见范围），不是"太高"。对于 RL 训练，需要足够的温度才能探索不同的推理路径；如果温度太低（如 0.2），模型每次采样都差不多，redo 就没意义了。

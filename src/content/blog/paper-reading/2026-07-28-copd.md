## TL;DR

一句话：**标准 OPD 让学生的输出分布去逼近教师，但"逼近"本身没告诉你往哪个方向压缩；用轻思考 vs 重思考的对比信号，让每个 token 自带"该简洁还是该详细"的方向指示，压缩就从对比中自然涌现。**

- **场景**：多模态推理蒸馏（教师→学生）。标准 OPD 逐 token 匹配教师分布，学生容易学到冗长推理——因为教师在所有 token 上都给了概率，但没区分"这个 token 是推进推理还是填充冗余"。
- **痛点**：① 现有压缩方法（G-OPD、ExOPD、VA-OPD）都需要显式长度惩罚、目标长度或精炼短示范；② 单一分布监督只告诉学生"教师选了什么"，不告诉"这个 token 对简洁推理友好还是对详尽推理友好"。
- **方法 COPD**：冻结教师在同一批学生生成的 token 上打两次分——轻思考指令下 l^LT，重思考指令下 l^HT，优势信号 A_t = l^LT - l^HT。正值表示该 token 更适合简洁推理，负值表示更适合详尽推理。用 PPO-style 策略更新，无需任何显式长度目标。
- **结果**：准确率 +2.1pp，推理长度 -57%，Acc@1K（每千 token 准确率）+141%。GPU 训练时间减少 54.5%。自蒸馏变体（COPSD）无需外部教师也有效。

## 一、Motivation：OPD 的"单分布监督"困境

标准 On-Policy Distillation（OPD）让学生模型在自己的策略下采样完整推理轨迹，然后逐 token 最小化与教师分布的 KL 散度。问题在于：教师在每个位置只给了一个分布——学生知道"教师选了什么"，但不知道"这个 token 对推理效率意味着什么"。

> 核心矛盾：OPD 提供绝对分布监督（single-distribution supervision），但压缩需要相对偏好信号（relative preference signal）。

现有方法怎么做的：

- **G-OPD / ExOPD**：用预定义目标长度、显式长度惩罚或奖励缩放
- **VA-OPD**：多模态场景下的视觉依赖监督
- **精炼短示范**：人工筛选或生成简洁推理轨迹作为示范

这些都依赖**辅助目标或精心构造的数据**。COPD 的关键洞察是：压缩可以从推理模式的对比偏好中**隐式涌现**，无需任何显式长度目标。

## 二、Method：对比信号驱动的策略更新

### 2.1 双模式教师打分

对学生生成的每个 token 位置 t，冻结教师 pi\\\_phi 在两个对比指令下打分：

```text
轻思考得分：l_t^LT = log pi_phi(y_t | x^LT, y_<t)
重思考得分：l_t^HT = log pi_phi(y_t | x^HT, y_<t)

```

其中 x^m = [iota^m; x]，把指令 iota^m（轻/重思考提示）拼接到原始输入 x 前面。

### 2.2 对比优势信号

**核心公式：**

```text
A_t = l_t^LT - l_t^HT

```

- **A_t > 0**：该 token 与轻思考更兼容（适合压缩）
- **A_t < 0**：该 token 与详尽推理更兼容
- 稳定性裁剪：A\\\_t\\\_tilde = stopgrad(clip(A\\\_t, -A\\\_max, A\\\_max))，A\\\_max = 10

### 2.3 PPO-style 策略更新

```text
J_COPD(theta) = E[1/T * sum_t min(r_t * A_t_tilde, clip(r_t, 1-eps_low, 1+eps_high) * A_t_tilde)]

```

其中 r\\\_t = pi\\\_theta(y\\\_t|x, y\\\_<t) / pi\\\_theta\\\_old(y\\\_t|x, y\\\_<t) 是概率比。

**与标准 KL 蒸馏的数学区别**：标准 OPD 最小化单一上下文下教师-学生的 KL 散度（单一 l\\\_t）；COPD 用对比优势替代，这是一个 detached 的 token 级信号，只提供方向和尺度，梯度只通过学生策略回传。

### 2.4 自蒸馏变体（COPSD）

用**训练模型自身的冻结快照**（而非更大的外部教师）来计算对比信号。验证压缩信号来自上下文诱导的偏好，而非教师规模。

## 三、Result：准确率提升 + 长度压缩 + 训练加速

### 3.1 主结果（Qwen3-VL-8B → 2B）

| 方法 | 准确率 | 平均 Tokens | Acc@1K |
|-|-|-|-|
| Base（无蒸馏） | 52.9% | 2.10K | 25.2 |
| ExOPD | 55.2% | 2.07K | 26.7 |
| **COPD** | **57.3%** | **0.89K** | **64.4** |

**关键提升**：

- 准确率 +2.1pp（vs ExOPD）
- 推理长度 -57%
- Acc@1K +141%（每千 token 准确率）
- GPU 训练时间：60 小时 vs OPD 的 132 小时、ExOPD 的 150 小时（减少 54.5%）

### 3.2 跨配置泛化

所有 4 种教师-学生配置都显示 COPD 达到最高准确率 + 最短响应：

- Qwen3-VL-32B → 2B：57.1% acc, 0.79K tokens, Acc@1K 72.3
- Qwen3.5-4B → 2B：60.1% acc, 1.92K tokens, Acc@1K 46.4
- Qwen3.5-35A3B → 2B：59.3% acc, 2.06K tokens, Acc@1K 44.3

### 3.3 任务级亮点

**最大收益**：

- WeMath：+11.3pp 准确率，-60.7% tokens
- LogicVista：+11.4pp 准确率，-59.1% tokens

**最小/负收益**：

- RWQA：-0.9pp — 基础模型已经非常短（0.13K tokens），几乎没有压缩空间

### 3.4 关键消融

> 轻思考 alone vs 完整对比

| 配置 | 准确率 | Tokens |
|-|-|-|
| Base | 52.9% | 2.10K |
| LT-only（无 HT 参照） | 53.1% | 2.26K（更长！） |
| **Full COPD（LT - HT）** | **57.3%** | **0.89K** |

**结论**：轻思考分数本身不够——它们仍给冗余 token 高分。重思考参照**必不可少**，用来创建有意义的对比信号。没有它，就没有压缩。

### 3.5 自蒸馏（COPSD）— 无需外部教师

| 模型 | 准确率提升 | 长度缩减 | Acc@1K 提升 |
|-|-|-|-|
| 2B | +3.5pp | 63.8% | +194.4% |
| 8B | +0.4pp | 59.9% | +120.4% |
| 122A10B | +2.0pp | 17.2% | +23.7% |

压缩不需要更大的教师。训练模型自身的冻结快照提供足够的对比信号。

## 四、Limitations & 未来工作

### 4.1 论文自述的局限

1. **非均匀压缩**：对基础模型已经很冗长的任务压缩激进，但当基础输出已经很短时（如 RWQA 的 0.13K）可能有问题
2. **教师规模非单调**：收益不遵循简单的尺寸关系——更大的教师可能产生更长的响应
3. **范围验证**：框架仅在推理效率上验证，尚未在其他行为维度上验证
4. **LT/HT 模板未完全公开**：论文测试了模板变体的鲁棒性，但未发布确切措辞

### 4.2 我认为的真正局限

1. **Acc@1K 指标的合理性**：用"每千 token 准确率"衡量效率-准确率权衡，但在实际部署中，用户可能更关心"达到目标准确率所需的最小 token 数"
2. **轻/重思考指令的设计**：虽然测试了鲁棒性，但指令设计仍是关键超参数，不同任务可能需要不同的对比维度
3. **与 RLVR 的关系未明**：COPD 的优势信号 A\\\_t 类似 RL 中的奖励信号，但与 GRPO 等 RLVR 方法的对比/结合未讨论
4. **多模态特定性**：虽然实验在多模态 benchmark 上，但方法本身对视觉依赖的处理（相比 VA-OPD）不够清晰

### 4.3 未来工作

- **泛化对比范式**：从轻/重思考扩展到其他行为对比——安全对齐（安全 vs 无约束上下文）、风格控制、接地生成、多目标偏好
- **与 RLVR 结合**：A\\\_t 作为 dense reward signal，能否与 sparse verifiable reward 拼接？
- **动态对比维度**：不是固定的轻/重，而是根据任务/输入自适应选择对比模式

## 五、启发与待跟进

### 5.1 论文已回答的问题

**Q: 压缩信号从哪里来？**

- 不来自显式长度惩罚，不来自精炼短示范，而来自教师在同一 token 上对两种推理模式的相对偏好
- 轻思考 alone 不够（仍给冗余 token 高分），必须有重思考参照

**Q: 自蒸馏为什么有效？**

- 压缩信号来自上下文诱导的偏好，而非教师规模
- 模型自身的冻结快照提供足够的对比信号

### 5.2 待跟进的问题

- [ ] 与 TOPD（昨天的论文）的关系：TOPD 改信号路由（识别真发散），COPD 改信号来源（对比偏好）——两者能否结合？

- [ ] A\\\_t 的分布特性：在训练过程中，A\\\_t 的分布如何变化？是否会出现模式崩溃（大量 token 的 A\\\_t 趋同）？

- [ ] 与 DPO/IPO 的关系：COPD 的对比信号类似偏好对，但是 token 级而非序列级——理论联系是什么？

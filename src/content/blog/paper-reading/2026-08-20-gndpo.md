## TL;DR

**一句话：GNDPO 发现 on-policy 蒸馏（OPD）的梯度爆炸根源是"逐 token 原始 KL 得分无界"——学生跑到离群状态、生成教师几乎不给概率的低频 token 时，log-ratio 趋近无穷，少数 token 主导梯度；于是把 KL 得分在 batch 内做全局归一化（z-score）转成相对优势，成本一行代码，却同时拿到了更稳的训练和更高的下游精度。**

- **核心发现**：OPD 的监督信号本身是好的（密集、逐 token），坏在"尺度"——OOD 上下文 + 低频 token 会让 π_teacher(o) → 0，反向 KL 得分 → −∞，梯度尖峰（实验里 OPD 在 \~step15 出现 ℓ₂ > 2.5 的尖峰）直接威胁训练发散。
- **方法 GNDPO**：Âⁿᵒʳᵐ = (Â − mean(Â∈ℬ)) / (std(Â∈ℬ) + ε)，把逐 token 的"学生−教师 KL 得分"变成 batch 级相对优势，再喂进 GSPO 风格（组相对 + 裁剪 importance sampling）的 RL 目标。两个收益：异常 token 撑大 σ 自动缩小有效步长；基线平移让优化从"匹配绝对分布"转向"优化相对 token 质量"。
- **炸裂结果**：InternVL3.5-1B/2B/4B 在多模态数学推理（Geometry3K 训练，7 个 benchmark 评估）上全面压过 GSPO（GRPO 风格）与原始 OPD——4B 平均 52.5→53.9→**54.5**，2B 40.5→42.9→**43.7**，1B 27.3→31.6→**32.0**；且训练曲线平滑、无梯度尖峰、不牺牲熵（探索）。

## 一、先看一个例子

> **例子**：学生对一道几何题生成 rollout，途中某个 token"跑偏"——吐出了一个教师（8B）几乎不会给的稀有符号。此时教师给这个 token 的概率 π_T ≈ 0，学生给 π_θ ≈ 0.01：Â = −log(0.01 / 1e-7) ≈ **−11.5**（对数尺度下，"概率差 1 万倍"换算成得分也就 −11.5，但若教师概率真到浮点下界，得分可以无界下探到 −1000 甚至更糟）

> 而 batch 里其他 511 个 token 的得分只在 ±2 之间。这一个 token 的梯度就把整个更新方向带偏——论文实测原始 OPD 在 **\~step 15 出现 ℓ₂ > 2.5 的梯度尖峰**，训练曲线剧烈震荡。

> GNDPO 把这 512 个得分做一次 z-score：极端值被压回 ±√n 量级（n=512 时约 ±22），正常值落在 ±0.1 附近——**无界的原始得分变成有界的相对优势**，异常 token 再也没法独自掀翻梯度。

> **直觉**：RL 里"优势归一化"是老朋友（GRPO 的组内相对优势就是它），但 GNDPO 把它用在了一个新的位置——**逐 token 的蒸馏得分**上，并且把归一化的范围从"组内 16 个 rollout"扩到"整个 batch"（多个组）。归一化本身不是新东西，难的是指出"OPD 的梯度爆炸本质是尺度问题、一行归一化就能治"。

## 二、动机：密集监督是好药，就是药量会爆炸

### 2.1 现有范式的困境

| 范式 | 监督信号 | 采样方式 | 致命伤 |
|-|-|-|-|
| RLVR（GSPO / GRPO 风格） | 序列级稀疏奖励（对/错） | on-policy（16 rollout / 题） | 奖励稀疏、样本效率低；学生"想错"时没有中间信号 |
| OPD（原始 on-policy 蒸馏） | 逐 token 密集（−反向 KL 得分） | on-policy | **离群状态下 KL 得分无界 → 梯度尖峰 → 训练震荡/发散** |
| GNDPO（本作） | batch 级归一化后的逐 token 相对优势 | on-policy | 小 batch 下统计量方差变大（论文自认的 limitation） |

### 2.2 核心问题：为什么原始 KL 会爆炸

**公式**：逐 token 蒸馏得分 Â\_{i,t} = −( log π_θ(o_i^t | q, o_i^{<t}) − log π_teacher(o_i^t | q, o_i^{<t}) )（即负反向 KL 的采样估计），梯度正比于 ∇ log π_θ · Â。**爆炸条件**：学生策略访问 OOD 上下文、或生成教师给接近零概率的低频 token 时，log [π_θ / π_teacher] 里的 π_teacher → 0，得分 → −∞。于是"一个 token 的巨大梯度"支配整步更新——**少数高熵/高失配 token 劫持了策略**。

> **GNDPO 的问题定义**：OPD 谱系里大家都在争"监督信号从哪来、怎么构造"（TOPD 的未来步骤、OPD² 的 delta、OPSD 的答案特权……），GNDPO 补的是最被低估的一环——**信号封装好了，但"传递管道"会爆**。它把问题从"构造更好的信号"平移成"让已有信号安全传输"。

## 三、方法：一行归一化，从"组内相对"到"batch 全局"

### 3.1 整体框架

- 学生策略 π_θ 对问题 q 做 on-policy rollout，教师（8B，冻结）对每个 token 给出分布，得分 = 负反向 KL（公式见 2.2）
- 目标函数沿用 **GSPO**（组序列相对策略优化，GRPO 家族）：带概率比裁剪的 importance-sampling 目标，ε 为裁剪阈值
- **GNDPO 的核心变换（论文 Eq.4）**：`Âⁿᵒʳᵐ = (Â − mean(Â | Â ∈ ℬ)) / (std(Â | Â ∈ ℬ) + ε)`，对整个训练 batch ℬ 的所有 token 得分做标准化，再喂回同一目标函数
- 注意与 GSPO 的区别：GSPO 是在**每组 16 个 rollout 内部**做相对化；GNDPO 把归一化窗口扩大到**整个 batch**（跨组），并且作用对象是**逐 token 得分**而非序列级奖励

### 3.2 两个机制收益

1. **自适应梯度缩放**：出现灾难性失配时，极端负得分把 batch 标准差 σ 撑大，自动缩小有效梯度步长——异常 token 无法"撑破"共享表征（实验：GNDPO 全程无尖峰，OPD 在 step15 有 ℓ₂>2.5 的尖峰）
2. **上下文无关的尺度校准**：减去 batch 均值 μ 等价于移动基线，目标从"追踪绝对分布匹配"变成"优化相对 token 质量"——不同难度的上下文（简单题 vs 难题）在同一尺度上比较

> **GNDPO 的优雅之处**：不新增任何超参数以外的机制、不改变 OPD 的采样流程、不要求更大的教师——只对已有的逐 token 得分做一次标准化。它对"任何 KL 型监督信号"是**即插即用**的补丁，这正是它能成为 OPD 谱系"基础设施"的原因。

### 3.3 训练设置

- 65 个优化步；学习率 1e-6（Adam 恒定）；batch 32；rollout 16 / 题；采样温度 1.0；max prompt 8192 / max response 16384
- 8× NVIDIA H20 100GB；RL 框架 VERL；评估框架 VLMEvalKit
- Prompt 模板：`You FIRST think about the reasoning process as an internal monologue... reasoning process MUST BE enclosed within <think></think> tags. The final answer MUST BE put in \boxed{}`

### 4.3 设置与实现细节

- 训练数据只有 **Geometry3K** 一个（多模态数学推理），65 步、1e-6 恒定 LR、batch 32、16 rollout/题——计算量非常克制
- 评估：MathVista MINI、MMMU VAL、MathVision、MathVerse（vision-only）、DynaMath（worst-case）、WeMath、LogicVista；评估温度 0.6、top-p 0.95
- 注意：**论文没有做消融实验**（无 ε、归一化窗口、裁剪阈值的系统消融），训练曲线对比是唯一的过程性证据——这也是本文最明显的短板之一

## 五、Limitations & 批判性思考

1. **零消融**：ε、归一化窗口（组内 vs batch）、裁剪范围都没有系统实验；"batch 级一定比组内好"缺乏证据，只有训练曲线支撑
2. **batch 大小敏感**：全局归一化依赖 batch 经验统计量，batch 过小时方差变大，论文自认"可能轻微退化"——长 CoT（16k+ token）场景下 batch 内 token 数膨胀，统计语义会变稀
3. **计算开销继承自 on-policy**：GNDPO 本身零额外开销，但 OPD 的整体成本仍受 rollout 推理速度约束（65 步 × 16 rollout/题 × 8k prompt）
4. **验证面窄**：只做了数学/多模态推理（Geometry3K 单数据集训练）；开放创意生成、多轮对话对齐、代码推理的行为未被探索
5. **无 SOTA 横向对比**：没有和 OPD 谱系其他方法（OPSD、PCD、PAPO、Distilled RL 等）直接比——"GNDPO vs OPD"是同一个框架内的消融式对比，说服力有限
6. **教师固定 8B**：1B 学生 + 8B 教师之外的组合（如同规模师生、跨系列教师）未测；"教师越强梯度越容易爆"这一假说没有直接验证

## 六、与前文对照（OPD 谱系表）

|  | 方法 | 核心创新 | 与 GNDPO 的关系 |
| --- | --- | --- | --- |
| 1 | TOPD | 用"近未来"引导弥合推理轨迹 | 都是"怎么用好教师信号"：TOPD 选信号内容（未来步骤），GNDPO 管信号尺度（batch 归一化） |
| 9 | Distilled RL | 教师监督融进 RL 目标（选择性蒸馏 + 序列级归一化） | 血缘最近：同为"RL 目标 + 教师逐 token 信号 + 归一化"。Distilled RL 用反向重要采样 + 序列级归一化做"选择"，GNDPO 用 batch z-score 做"尺度"，且更简单 |
| 4 | RLCSD / COPD | 对比式（自）蒸馏构造监督信号 | 对比派靠"正负样本对"造信号；GNDPO 单教师、无对比，归一化替代对比的作用 |
| 15 | OPD² | 概率差蒸馏（delta = 教师 − 教师base） | 减基线思想同源：OPD² 减"参数级基线"，GNDPO 减"batch 均值"——都是把绝对分转成相对分 |
| 16 | PCD | 感知-推理归因的软 AND 门 | 回答"该蒸哪些 token"（**选择**）；GNDPO 回答"每个 token 信号多大才稳"（**尺度**）——天然互补，可叠加 |
| 17 | PAPO | 感知感知策略优化（KL_prcp） | 同为多模态 OPD：PAPO 拆"看错 vs 想错"，GNDPO 不拆感知/推理，专注稳定性——GNDPO 的归一化可当 PAPO 的稳定器 |
| **19** | **GNDPO** | **batch 级全局归一化稳定 OPD** | **本作：不改信号来源、不加采样成本，只改信号封装——一行 z-score 治梯度爆炸** |

> **定位差异**：
> - **vs #18 OPSD（昨天的笔记）**：OPSD 想把外部教师整个省掉（特权上下文自蒸馏），GNDPO 则接受"有教师"的设定、把教师的信号传稳——两者恰好补全了 OPD 的"信号源头"与"信号传输"两端。**若把 GNDPO 的归一化套在 OPSD 的自我 KL 上，可能同时拿到"无教师"和"不爆炸"**。
> - **vs #9 Distilled RL**：D-RL 的序列级归一化 + 反向 IS 偏"重"（要额外估计），GNDPO 的 batch z-score 偏"轻"（一行代码）——两条路都在回答"教师信号怎么进 RL 目标"。
> - **vs #16 PCD / #17 PAPO（多模态主线）**：PCD 选 token、PAPO 拆感知——GNDPO 是"防御性"补丁，谁都能叠。

## 七、启发与待跟进

> **核心启发**：
> 1. **"训练爆炸往往不是方向错，而是尺度错"**——OPD 的梯度尖峰用一行 z-score 就能摁住，说明监督信号本身是对的，坏在封装。排查训练发散时，"先归一化、再谈改信号"应该是默认动作。
> 2. **归一化是 OPD 的"基础设施"**：OPSD 的自我 KL、PCD 的门控 KL、OPD² 的 delta、PAPO 的感知 KL——任何 KL 型信号都可以套 batch z-score。它是 OPD 谱系里少有的"零成本、即插即用、跨方法通用"的组件。
> 3. **稳定性就是能力**：4B 上 GNDPO vs OPD 精度只差 +0.6，但"65 步训练不爆"意味着同样的算力可以跑更长、更大——训练稳定性的经济价值常常被低估。

### 待跟进 checklist

- [ ] **GNDPO × OPSD**：把 batch 归一化套进 OPSD 的自我 KL，验证"无外部教师 + 不爆炸"能不能同时成立

- [ ] **GNDPO × PCD**：PCD 软 AND 门（选 token）× GNDPO z-score（定尺度）叠加，看多模态 OPD 是否再涨一截

- [ ] **消融补全**：ε、裁剪阈值、组内 vs batch 归一化、EMA 统计量、per-token-class 归一化（数学 token vs 风格 token 分开归一化）

## 八、今日阅读结论

GNDPO 是 OPD 谱系里最"不起眼却实用"的一作：它不发明新的监督信号、不改造采样流程、不引入新参数——只是把逐 token 的 KL 得分做了 batch 级 z-score，就同时换来了更平滑的训练曲线、更低的 loss 和 7 个多模态推理 benchmark 上的全面领先。它把 OPD 社区争论的重心从"信号从哪来"（TOPD 的未来、OPD² 的 delta、OPSD 的答案特权）拉回到一个更朴素的工程事实：**信号再好，传输管道会爆等于没有**。与前文合读，OPD 的拼图越来越完整：构造信号（对比派/特权派）→ 选择信号（PCD 的门控）→ 传递信号（GNDPO 的归一化）——下一步大概率是把"选择"与"尺度"合进同一个目标，在真正的多模态长 CoT 场景下做压力测试。

> **今日一句**：梯度爆炸往往不是监督信号的错，而是尺度的错——把逐 token 的 KL 得分做一次 batch 级 z-score，异常 token 就再也掀不起浪。训练稳定性，有时候就是一行归一化的事。论文：arXiv:2606.09091 · 笔记挂在 lib 中 · 2026-08-20

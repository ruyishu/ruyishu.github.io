## TL;DR

<strong>一句话：多轮 agent 的奖励只在最后给一次，扁平策略得把这一分功劳摊到几十步上，摊不准。HiPER 的做法是在每一步的 prompt 里强行分出两层——先说要干什么（子目标），再说具体动作；然后按「子目标段」而不是「整条轨迹」来算优势。</strong>

- <strong>结果（Qwen2.5-7B，3 个随机种子）</strong>：ALFWorld <strong>14.1 → 97.4</strong>（此前最强 GiGPO 90.8）；WebShop <strong>19.5 → 83.3</strong>（GiGPO 75.2）
- <strong>小模型也能打</strong>：Qwen2.5-1.5B 在 ALFWorld 上 <strong>8.3 → 95.3</strong>（GiGPO 86.7）
- <strong>提升最大的正是"多子任务串联"的题</strong>：Pick2（连续拿两个物体）<strong>79.2 → 95.5</strong>，Heat（加热）<strong>83.7 → 96.3</strong>
- <strong>收敛也快</strong>：论文称相对 PPO/GRPO 约 <strong>2.8× 加速</strong>（ALFWorld 7B 验证曲线）
- <strong>核心改动 1（接口）</strong>：每一步输出三块——<strong>&lt;switch&gt;</strong>（换不换目标）、<strong>&lt;subgoal&gt;</strong>（当前子目标）、<strong>&lt;action&gt;</strong>（具体动作）。<strong>不改模型结构，只改 prompt 模板</strong>
- <strong>核心改动 2（算法）</strong>：<strong>HAE</strong>——SWITCH 把轨迹切成段；<strong>段内</strong>算逐轮 GAE，<strong>段间</strong>算段级 TD，最后再给一个「切换优势」（换目标 vs 不换，哪个更值）
- <strong>⚠️ 最该注意的一组消融</strong>：<strong>光换接口不换算法</strong>，PPO 就能 <strong>+13.1%</strong>、GiGPO 就能 <strong>+4.4%</strong>；<strong>HAE 自己只再贡献 +4.2%</strong> → <strong>一半以上的功劳来自那三行 prompt</strong>
- <strong>✅ 仓库</strong>：github.com/JonP07/HiPER-agent，<strong>Apache-2.0</strong>，基于 <strong>verl-agent</strong> 改；有<strong>训练脚本</strong>（ALFWorld / WebShop 各一个）与 <strong>W&amp;B 训练日志</strong>
- <strong>⚠️ 没有权重、没有数据集、没有评测脚本、没有算力说明</strong>（环境是公开的 ALFWorld / WebShop）
- <strong>⚠️ 没有独立 Limitations 章节</strong>，照实写
- <strong>主题</strong>：<strong>RL / 后训练</strong>（本周第 5 篇、收官）。选它：<strong>信用分配</strong>正是本周口径里点名的一块，且有 7B 单机可跑、Apache-2.0、ICML 2026

## 一、先看例子（大白话：还没拿杯子就先跑柜子）

> 💡 <strong>铺垫</strong>：任务只有一句——"把杯子洗干净，放进柜子里"。但奖励要到最后一刻才给。
>
> <strong>中间只要有一步跑偏，最后就是 0 分。而且模型不知道是哪一步错的。</strong>

![论文 Figure 2：上＝扁平策略。模型每步直接出动作，结果出现三种典型崩法——提前跑柜子、跑题、原地重复，最后失败。下＝HiPER。每步先定子目标、再出动作，SWITCH 把轨迹切成段，同一段里的动作共享一个子目标](/images/paper-reading/2026-10-30-hiper/2026-10-30-d69-1.webp)

> <strong>你去厨房做一件事：「把杯子洗了，放进柜子」。</strong>
>
> <strong>正常人的步骤是：找到杯子 → 拿去水槽洗 → 放进柜子。</strong>
>
> <strong>但扁平策略（每步只想"下一个动作"）容易这样：</strong>
>
> <strong>看到"柜子"这个词，直接往柜子走 → 到了发现手里没杯子 → 再回来找 → 忘了要洗 → 反复横跳 → 失败。</strong>
>
> 它不是不会走路，是<strong>没有"当前在干哪件事"这个概念</strong>。

<strong>论文的原话是</strong>：成功的 agent 轨迹里，动作天然会"成段"——<strong>一段动作围绕一个中间目标</strong>。但扁平策略<strong>既不表示、也不优化</strong>这个结构，所以段与段之间的边界是模糊的。

## 二、动机：奖励只有一个，可步骤有几十个

多轮 agent 的 RL 有两个老大难：

| 困难 | 具体 | 后果 |
|-|-|-|
| <strong>奖励稀疏且延迟</strong> | 几十步之后才给一个 0/1 | 不知道该夸哪一步 |
| <strong>只有单一时间尺度</strong> | 每一步都当成"一个动作" | 长程任务里"中间目标"漂移 |

<strong>已有的改进（GiGPO、GraphGPO 等）都在解决"步级信用"</strong>，但它们的层级只有"轨迹 vs 步"两层。<strong>HiPER 的观察是：真实的 agent 行为里，中间还藏着一层——子目标段</strong>。

## 三、方法：先改接口，再改算法

### 3.1 接口：每一步强制输出三块

这是全篇最"轻"的改动——<strong>不动模型，只改 prompt 模板</strong>：

| 字段 | 含义 | 例子 |
|-|-|-|
| <strong>&lt;switch&gt;</strong> | 换不换目标（SWITCH / KEEP） | KEEP（还在找杯子） |
| <strong>&lt;subgoal&gt;</strong> | 当前子目标的自然语言描述 | find a cup |
| <strong>&lt;action&gt;</strong> | 本步的实际动作 | go to countertop 1 |

<strong>注意两个"动态"</strong>：

- <strong>子目标是边走边定的</strong>，不是一开始写好一串计划照着执行
- <strong>动作仍然逐步决策</strong>，不是"给定子目标就固定播放一串动作"

<strong>所以它是"边规划边执行"，不是"先规划后执行"。</strong>

### 3.2 算法：把优势算在两个时间尺度上（HAE）

<strong>SWITCH 决定的那一刻，就是段边界</strong>：b₀ &lt; b₁ &lt; … &lt; b\_K；第 k 段里子目标 o\_k 一直有效。

<strong>然后三种优势各算各的：</strong>

| 优势 | 怎么算 | 解决什么 |
|-|-|-|
| <strong>动作优势</strong> | 段内逐轮算 GAE | 这一小段里，每一步好不好 |
| <strong>子目标优势</strong> | 把段内奖励聚合，在<strong>边界处</strong>算段级 TD | 这个子目标定得值不值 |
| <strong>切换优势</strong> | 同一状态下「换目标」vs「继续」的差 | 什么时候该换 |

<strong>最关键的耦合点</strong>：<strong>段内 GAE 的最后一步，不是用段内价值 bootstrap，而是接到"下一段的价值"上</strong>。这一步把"段内的功劳"和"段与段之间的推进"连了起来。

<strong>论文给了两个理论保证</strong>：① 对子目标和动作都<strong>无偏</strong>（在标准 bootstrap 与价值函数近似误差内）② 相比扁平 GAE <strong>方差更小</strong>。

## 四、实验

### 4.1 主结果：两个规模、两个环境全面领先

![论文 Figure 1：四个子图分别是 ALFWorld 1.5B / WebShop 1.5B / ALFWorld 7B / WebShop 7B，HiPER（深色）在四个组合上都高于 PPO / GRPO / GiGPO](/images/paper-reading/2026-10-30-hiper/2026-10-30-d69-2.webp)

| Qwen2.5-7B | ALFWorld | WebShop 成功率 |
|-|-|-|
| 原始模型 | 14.1 | 19.5 |
| +PPO | 82.8 | 68.7 |
| +GRPO | 85.4 | 66.1 |
| +GiGPO（此前最强） | 90.8 | 75.2 |
| <strong>+HiPER</strong> | <strong>97.4</strong> | <strong>83.3</strong> |

<strong>1.5B 上同样成立</strong>：ALFWorld <strong>8.3 → 95.3</strong>、WebShop <strong>5.5 → 71.4</strong>（GiGPO 分别是 86.7 / 67.4）。

### 4.2 涨在哪儿：多子任务串联的题

| ALFWorld 7B 分类 | GiGPO | HiPER |
|-|-|-|
| <strong>Pick2（连拿两个物体）</strong> | 79.2 | <strong>95.5</strong> |
| <strong>Heat（加热）</strong> | 83.7 | <strong>96.3</strong> |
| Clean | 98.8 | <strong>100</strong> |
| Look（找光源看物体） | 82.7 | 84.8 |
| Pick / Cool | 97.7 / 89.3 | <strong>100 / 100</strong> |

<strong>这个分布很说明问题</strong>：<strong>单步任务（Pick）本来就接近满分，涨不动；涨得最多的是"必须按顺序做完两件事"的 Pick2 和"中间要插一步"的 Heat。</strong>

### 4.3 最重要的一组消融：接口 vs 算法

| 设置 | 提升 |
|-|-|
| PPO：ReAct → <strong>Plan-Execute 接口</strong> | <strong>+13.1%</strong> |
| GiGPO：ReAct → <strong>Plan-Execute 接口</strong> | <strong>+4.4%</strong> |
| 同样用 Plan-Execute：GiGPO → <strong>HiPER（加 HAE）</strong> | <strong>+4.2%</strong> |

<strong>这张表比主结果更值得看</strong>：

- <strong>光换个 prompt 模板，PPO 就涨 13 个点</strong>
- <strong>HAE 的净贡献，和"换接口"在一个量级</strong>
- 所以"层级"这件事的价值，<strong>一半在把结构写出来，一半在按结构算优势</strong>

## 五、Limitations

### 论文自述的：没有

⚠️ <strong>本篇没有独立的 Limitations 章节</strong>——§6 Conclusion 之后直接是 Acknowledgments 与参考文献。<strong>照实写，不硬凑。</strong>

### 我读出的 7 条

1. <strong>⭐ 一半的功劳其实在 prompt，不在算法</strong>：Table 2 里"接口"贡献 +4.4%、"HAE"贡献 +4.2%。<strong>这意味着一个只改 prompt、不改算法的方案就能拿到差不多一半的收益</strong>。论文把两者打包成"框架"，容易让人高估算法的分量
2. <strong>⭐ 仓库无法复现数字</strong>：<strong>没有权重、没有数据、没有评测脚本、没有算力说明</strong>。ALFWorld/WebShop 是公开环境，但 97.4% 这个数你得自己从零训出来才能信
3. <strong>两个环境都不算"真长程"</strong>：ALFWorld 典型 20–40 步、WebShop 更短。<strong>"long-horizon" 在这两个环境里是相对的</strong>，真正的长任务（几百步）没测
4. <strong>全是文本环境</strong>：没有 GUI、没有网页、没有多模态。而"层级规划"在视觉 agent 上恰恰更难（状态是截图，子目标要落到坐标）
5. <strong>需要训练 critic</strong>：PPO 式的 actor-critic，比 GRPO/RLOO 多一份模型和显存。论文说 critic 尺寸不必与 actor 一致（Table 3），但成本仍比无 critic 方案高
6. <strong>"无偏"依赖价值函数准确</strong>：理论保证写的是"在标准 bootstrap 与价值近似误差内"，实际用神经网络估价值，这部分等于把保证打了折
7. <strong>1.5B 的 WebShop 标准差很大（±9.0）</strong>：说明小模型上这个结果波动不小，单看均值会过于乐观

## 六、前文对照

| 前文 | 它的信用分配怎么做的 | 和本篇的关系 |
|-|-|-|
| <strong>GiGPO</strong>（9/8） | 组中组：轨迹级 + 步级，零额外 rollout | <strong>本篇的最强 baseline，也是它的直接前身</strong>：GiGPO 提供"步"这一层，HiPER 在它上面再插一层"子目标段" |
| <strong>GraphGPO</strong>（10/6） | 把轨迹拼成图，做图级信用分配 | <strong>两条不同的切法</strong>：GraphGPO 沿"经验复用"切，HiPER 沿"时间抽象"切。<strong>理论上可叠</strong>（图 + 段） |
| <strong>SDPO</strong>（9/30） | 把环境反馈当老师做稠密信用分配 | SDPO 要一个"老师"，HiPER 只要结构。<strong>一个靠外部信号，一个靠内部结构</strong> |
| <strong>GDPO</strong>（10/26） | 多奖励怎么归一化合成优势 | <strong>正交</strong>：GDPO 管"多个奖励怎么合"，HiPER 管"一条奖励怎么摊到不同时间尺度"。<strong>可以叠</strong> |
| <strong>NSR</strong>（10/27） | 裁剪边界救信号 | 都动"优势/更新"，但 NSR 动的是<strong>要不要这个梯度</strong>，HiPER 动的是<strong>这个梯度给谁</strong> |
| <strong>RLVE</strong>（10/28） | 难度跟着模型走 | 一个改<strong>题目</strong>，一个改<strong>结构</strong>；都在解决"信号不够" |
| <strong>MED</strong>（10/29） | 把工具贡献拆开算 | <strong>很好的互补</strong>：MED 问"这个部件值多少"，HiPER 给了一个"把部件结构化"的正面例子 |

<strong>一句话串起来</strong>：本周五篇从五个零件动手——<strong>怎么合（GDPO）、要不要（NSR）、给什么（RLVE）、值多少（MED）、给谁（HiPER）</strong>。

## 七、启发与待跟进

1. <strong>⭐ 最值钱的一课："先改接口，再改算法"</strong>：Table 2 说明<strong>光把「子目标」写进 prompt 输出格式，PPO 就涨 13 个点</strong>。<strong>很多所谓"算法创新"，本质是把结构显式化</strong>——而且接口改动的成本几乎为零
2. <strong>⭐ 层级的正确实现方式是 prompt 模板，不是新网络</strong>：不需要双策略、不需要新 head，<strong>一个模型同时演两个角色</strong>。这条对工程落地非常友好
3. <strong>⭐ 看"长程任务"的 paper，先看它涨在哪些子任务上</strong>：本篇涨得最多的是 Pick2 / Heat（多步串联），<strong>单步任务几乎没涨</strong>——这才是层级真正对症的证据
4. <strong>可复用的诊断</strong>：如果你的 agent 在"多子任务串联"的题上崩，而在单步题上还行，<strong>那问题很可能是"缺一个显式的当前目标"</strong>
5. <strong>待跟进</strong>：① 【最便宜】先只改接口（三块输出），不改算法，看能涨多少 ② 把"子目标段"接到视觉 agent 上（子目标要落到坐标或裁剪框） ③ 与 GDPO 的多奖励归一化叠加

## 八、结论

<strong>这是一篇"结构胜过算法"的论文。</strong>它没有发明新的 RL 目标，只是把 agent 本来就隐含的"分段做事"结构写进了 prompt，然后让优势估计跟上这个结构。

<strong>结果很硬</strong>：ALFWorld 97.4、WebShop 83.3，<strong>而且提升集中在最需要"按顺序做多件事"的任务上</strong>——这正是结构该起作用的地方。

<strong>但账要算清</strong>：接口贡献 +4.4%、算法贡献 +4.2%，<strong>一半的收益来自那三行输出格式</strong>；而且仓库不给权重，复现要自己跑。

<strong>今日一句</strong>：<strong>与其让模型把功劳摊在几十步上算不清，不如先让它说清楚"我现在在干哪件事"。</strong>

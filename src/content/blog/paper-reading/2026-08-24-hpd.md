## TL;DR

**一句话：HPD 把所有蒸馏方法统一成一个"token 级重加权对数似然"框架（每个 token 一个权重，正权重=强化、负权重=抑制），然后用"负 K1 估计器"把前向 KL（保覆盖）和反向 KL（保模式）的各自优势合进同一个目标——不需要全词表 KL、不需要完整序列 rollout、不引入任何额外超参数，算力只比 SFT 贵 2\~2.5 倍。**

- **核心发现（统一视角）**：SFT / SeqKD / RKLD / JSD 全都可以写成 `L = -E[w(a_t|s_t)·log q_θ(a_t|s_t)]`——它们的区别**只在于每个 token 的权重 w 怎么算**（SFT 恒 1、FKLD 用教师概率 p、RKLD 用 log-ratio）。把"散度方向 × 优化策略 × 数据体制"三个纠缠的选择拆开，问题就变成"该给每个 token 多大的权重、正还是负"。
- **方法 HPD**：K1 估计器 `k1 = q(a*)·[log p(a*) − log q(a*)]`——符号判断"学生低估了专家词（强化，走前向 KL）"还是"高估了坏词（抑制）"；再在 prefill 阶段从离线前缀采样 1 个非专家 token，只抑制被高估的，并把概率质量重定向回专家 token（权重翻倍）。
- **炸裂结果**：Qwen2.5 7B→1.5B 长链数学 Avg **30.24**（SFT 22.80、SeqKD 26.27、JSD 26.43），7B→3B 39.83、LLaMA3 8B→3B 34.56（比初始 +77.9%）；叠 OPD 后 33.41；代码任务 +5 分；内存只要 278GiB（对比全 KL 的 >1.5TiB）、墙钟 2.0–2.5×（对比 3.5–5×）。

## 一、先看一个例子

> **例子**：蒸馏一个 1.5B 学生学 7B 教师的数学推理。一个 token 位置，教师说"42"（专家 token），学生给它概率 0.2——**学生低估了专家词**。另一个位置学生自己冒出个"43"还给了 0.6 的高概率，但教师几乎不给——**学生高估了坏词**。

> 标准方法怎么处理？SFT 不管低估高估，一律让"42"概率 +1 档（权重恒 1）；RKLD 用 log-ratio 当权重，但符号混着用，正负信号会打架。HPD 用 K1 估计器给每个 token 判个"正/负号"：低估专家词 → 正权重强化（前向 KL 的覆盖逻辑）；高估坏词 → 负权重抑制，**并把抑制掉的概率质量重定向回"42"（权重翻倍）**——一步同时做"抬对的、压错的、把省的力气还给对的"。

> **直觉**：蒸馏的本质是"把学生的概率分布掰向教师的"——前向 KL 擅长"覆盖"（别漏掉教师给高概率的词，防塌），反向 KL 擅长"追求模式"（别给教师不给概率的词，防散）。HPD 用 K1 的符号在**每个 token 上自动切换**该用哪种逻辑，等于"前向和反向 KL 各干自己最擅长的事"。

## 二、动机：蒸馏的三个选择纠缠在一起

### 2.1 现有方法的通病

- **散度方向**（前向/反向/JSD）× **优化策略** × **数据体制**（on/off-policy）——三个选择互相纠缠，论文说清后就能逐个拆
- RKLD（MiniLLM 类）：反向 KL，mode-seeking，但**生成多样性会塌**、且高熵区域优化不稳
- FKLD：保覆盖，但学得慢、样本效率低
- JSD：折中，但两边都不极致，且成本高（需要双方完整分布）

### 2.2 统一视角：一切蒸馏都是"重加权 log-likelihood"

`L(θ) = -E_{D^π}[ w(a_t|s_t) · log q_θ(a_t|s_t) ]`——数据源决定 on/off-policy，权重 w 决定散度方向：

| 方法 | 数据源 | 权重 w(a_t\|s_t) |
|-|-|-|
| SFT | Off-policy | 恒 1（专家 token 一视同仁） |
| FKLD | Off-policy | 教师概率 p(a_t\|s_t) |
| RKLD | On-policy | log p − log q（log-ratio，符号可正可负） |

**关键洞察**：权重为正 → 提升该 token 似然；权重为负 → 抑制它，且梯度会传播到整个预测分布（不只影响被采样的那个 token）——这就是"重加权"比"采样对齐"信息量大的原因。

> **炸裂点**：这个统一视角把"方法创新"翻译成"权重设计"——以后比蒸馏方法，不用再比玄学，直接看每个 token 的 w 怎么算。HPD 的贡献 = 设计了一个"符号自适应"的 w。

## 三、方法：K1 估计器 + prefill 近似 on-policy

### 3.1 负 K1 估计器（前向/反向 KL 的开关）

对离线专家 token a\*：`k1 = q_θ(a*|s_t) · [ log p(a*|s_t) − log q_θ(a*|s_t) ]`

- **k1 > 0**：学生低估专家词 → 走前向 KL 逻辑，专家权重 = p(a\*) + k1（强化）
- **k1 ≤ 0**：学生已高估专家词 → 掩码前向 KL 项，权重 = k1（负权重抑制），避免梯度方向冲突

### 3.2 近似 on-policy 采样（prefill 阶段，不 rollout）

- 学生在**离线前缀 s_t** 上采样 1 个非专家 token：a_t \~ q_θ(·|s_t)，要求 a_t ≠ a\*
- 对其算 k1'：**只抑制被高估的非专家 token**（k1' < 0 → 权重 w_t = k1'；k1' ≥ 0 → 置 0，不让它被强化）
- **概率质量重定向**：当 k1' < 0 时，抑制掉的质量显式还给专家 token——专家权重翻倍：`w* = 2p(a*) + k1`
- 最终损失：`L_HPD = -E[ w*·log q_θ(a*) + w_t·log q_θ(a_t) ]`，只碰 2 个 token

### 3.3 为什么"省"

- 不需要全词表 KL / top-k 分布匹配（对比 AKL 的 >1.5TiB 缓冲）
- 不需要完整序列 rollout——采样发生在 **prefill 阶段**，长回复下成本优势巨大（对比 OPD 的解码期 rollout）
- **零额外超参数**：没有 γ、λ、温度缩放之类的新旋钮

> **直觉（符号即策略）**：连续权重容易正负相消、还要调温度；HPD 只问每个 token 一个问题——"该强化还是该抑制？"——答案是符号，不是数值。符号稳定、可解释、零调参。

### 4.6 消融（Figure 3）

- **移除学生采样**：性能快速收敛但很快平台化——只朝教师分布优化限制了探索，过早收敛
- **移除 Reinforce 操作（专家 token 强化）**：KL 下降变慢——抑制坏 token 时显式抬升专家 token 概率，优化信号更稳定
- **HPD + DPO**：Δ=+11.92（AE-LC），碾压 SFT+DPO（+1.81）和 RKLD+DPO（+9.74）——HPD 是更好的 DPO 起点

## 五、Limitations & 批判性思考

1. **要求师生共享同一 tokenizer**：跨词表蒸馏（如 Llama→SmolLM）直接不支持——对比 TRL GOLD 的跨词表方案是个硬边界
2. **K1 是估计器不是全 KL**：token 级信号有偏，极端分布下（教师概率极低）数值稳定性没有专门验证
3. **纯文本蒸馏**：没碰多模态；"视觉 token 的 K1 符号"怎么设计是开放问题（和 VGS/PCD 的接缝）
4. **更强教师实验面窄**：Qwen3-30B-A3B→0.6B 只测了数学，没测代码/对话的"想更久"迁移
5. **迭代自蒸馏收益递减**：停止准则没有理论支撑，纯经验
6. **对比基线偏"同代"**：没和 OPSD、GNDPO、EOPD（同届 ICML 的熵感知 OPD）直接横向比

## 六、与前文对照（OPD 谱系表）

|  | 方法 | 核心创新 | 与 HPD 的关系 |
| --- | --- | --- | --- |
| 15 | OPD² | 概率差蒸馏（delta=教师−教师base） | delta 是"参数层面"的偏差信号；HPD 的 k1 是"token 层面"的局部偏差——都是"偏差即信号" |
| 9 | Distilled RL | 教师监督融进 RL 目标（选择性蒸馏） | 都做"选择"：D-RL 用反向 IS + 归一化选，HPD 用 k1 符号选——HPD 更轻、零超参 |
| 18 | OPSD | 特权教师同策略自蒸馏（全词表前向 KL） | OPSD 要全词表前向 KL；HPD 用估计器只碰 2 个 token——成本差一个量级，但 HPD 仍需外部教师 |
| 19 | GNDPO | batch z-score 稳梯度尺度 | GNDPO 管"信号多大"（连续尺度），HPD 管"强化还是抑制"（符号）——符号比尺度更粗但更稳 |
| 20 | VGS | 梯度分解掰向视觉子空间 | VGS 在梯度空间做"方向手术"，HPD 在损失权重空间做"符号手术"——同属"监督精细化"家族 |
| **21** | **HPD** | **K1 估计器混合前向/反向 KL（token 级重加权）** | **本作：统一视角 + 符号自适应权重 + prefill 近似 on-policy，零额外超参，算力只贵 2×** |

> **定位差异**：
> - **vs #18 OPSD（最值得比）**：OPSD 用特权上下文做"同一模型分裂师生"、全词表前向 KL；HPD 用外部教师 + 估计器。OPSD 的"逐 token 点式裁剪"和 HPD 的"k1 符号门控"是同一问题的两种开关——OPSD 裁幅度、HPD 裁符号。
> - **vs #19 GNDPO**：GNDPO 治"KL 得分爆炸"（归一化），HPD 治"KL 方向矛盾"（符号化）——HPD 天然不会有 GNDPO 的爆炸问题，因为它只算 2 个 token 的标量，但也因此丢失全分布信息。
> - **vs 同届 EOPD（未读）**：EOPD 按"教师熵"切换前向/反向 KL，HPD 按"学生偏差符号"切换——触发条件不同，是天然的对照实验。

## 七、启发与待跟进

> **核心启发**：
> 1. **"一切蒸馏都是重加权 log-likelihood"是最有价值的贡献**——它把方法设计从"选散度方向"变成"设计权重 w"，从此蒸馏论文的对比维度清晰了。
> 2. **符号即策略**：连续权重要调温、会相消；用符号（强化/抑制）做决策，稳、可解释、零超参——这个设计哲学可以推广到 RLVR 的 reward 设计。
> 3. **on-policy 不必等于贵**：prefill 阶段采 1 个 token 就拿到了 on-policy 信号——"近似 on-policy"是成本敏感场景的正解。

### 待跟进 checklist

- [ ] **HPD × 多模态**：k1 估计器 + VGS 的 VDS 门控（视觉 token 的符号怎么判）

- [ ] **HPD × GNDPO**：符号导向（方向）+ z-score（尺度）叠加是否还能涨

- [ ] **HPD × EOPD 对比**：教师熵高时（EOPD 切前向 KL），HPD 的 k1 是否天然等价

- [ ] **跨词表扩展**：共享 tokenizer 是硬限制，能否用 logit 对齐/映射扩展

- [ ] **K1 的数值鲁棒性**：教师概率极低时的有偏性，是否需要裁剪

- [ ] **0.6B 长 CoT 迁移**：Qwen3-30B→0.6B 只测了数学，代码/对话的"想更久"呢

- [ ] **迭代自蒸馏停止准则**：收益递减的轮次如何自动判断

## 八、今日阅读结论

HPD 是"把旧问题讲清楚"就赢了一半的论文（ICML 2026）：统一视角（KD = 重加权 log-likelihood）让散度方向、优化策略、数据体制三个纠缠的选择第一次被拆开，剩下的工程问题变成"每个 token 的权重 w 怎么算"；然后一个 K1 估计器用符号同时完成"前向 KL 保覆盖 + 反向 KL 保模式"，prefill 采一个 token 就把 on-policy 的成本打了下来。和前文合读，OPD 谱系的"监督精细化"主线又补上两块：**VGS 在梯度空间做方向手术、HPD 在损失空间做符号手术**——加上 GNDPO 的尺度归一化，一条"先统一框架、再符号化决策、最后归一化稳定"的工程方法论正在成型。HPD 最朴素也最可迁移的一点是：**把连续权重变成符号决策，往往比发明新 loss 更划算。**

> **今日一句**：蒸馏不需要全词表 KL，也不需要整条 rollout——一个 K1 估计器 + prefill 阶段采一个 token，用"强化还是抑制"的符号把前向和反向 KL 各用在刀刃上，算力只贵两倍，性能反超一个身位。论文：arXiv:2604.20244（ICML 2026）· 笔记挂在 lib 中 · 2026-08-24

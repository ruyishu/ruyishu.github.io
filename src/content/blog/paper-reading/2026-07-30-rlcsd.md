## 一、TL;DR

On-policy self-distillation (OPSD) 存在一个根本性问题：**特权上下文（verified solution）给模型的监督信号主要集中在"风格 token"（如 "Wait", "Therefore"）而非"正确性 token"上**，导致训练不稳定或回答过早缩短。RLCSD 通过**对比正确 hint 和错误 hint 的 teacher-student gap**，抵消风格漂移，得到更干净的 token 级监督信号，在数学和逻辑推理任务上显著优于 GRPO 和现有 OPSD 方法。

---

## 二、Motivation：OPSD 的"特权信号"到底在教什么？

### 2.1 On-Policy Self-Distillation 的核心思想

OPSD 的基本范式：

- **Student**：模型在正常条件下的输出分布 π_S(y_t | x, y\_{<t})
- **Teacher**：模型在"特权上下文"下的输出分布 π_T(y_t | x, y\**c, y*{<t})，其中 y\*\_c 是 verified solution
- **监督信号**：e\_{c,t} = log π_T - log π_S，即 teacher 比 student 更有信心的 token

问题：**这个信号到底在教模型什么？**

### 2.2 发现的问题：Privilege-Induced Style Drift

作者发现，e\_{c,t} 的值在**风格 token**（如 "Wait", "Let me reconsider", "Therefore"）上远大于**任务 token**（实际计算步骤）。

**Figure 2: Per-rollout mean |e_c,t| on style vs. task tokens**

[点击查看原图](https://arxiv.org/html/2606.11709v1/x5.png)

*风格 token 的监督信号强度远超任务 token，模型更容易学到"怎么说"而非"怎么做"*

### 2.3 风格漂移的后果

1. **训练不稳定**：模型熵爆炸（entropy explosion）
2. **回答过早缩短**：模型学会用更短、更"直接"的风格，但牺牲了推理深度
3. **泛化性差**：学到的风格模式无法迁移到新任务

**Figure 1(b): Response length over training**

[点击查看原图](https://arxiv.org/html/2606.11709v1/x3.png)

*现有 OPSD 方法的回答长度在训练过程中持续下降，而 RLCSD 保持稳定*

## 三、Method：对比消除风格漂移

### 3.1 核心思想：Contrastive Cancellation

如果 y\*\_c 是正确答案，y\*\_w 是错误答案：

- **Correct hint 信号**：e\_{c,t} = log π_T(y_t | x, y\**c, y*{<t}) - log π_S(y_t | x, y\_{<t})
- **Wrong hint 信号**：e\_{w,t} = log π_T(y_t | x, y\**w, y*{<t}) - log π_S(y_t | x, y\_{<t})
- **Contrastive 信号**：e^{ctr}*t = e*{c,t} - e\_{w,t}

关键洞察：**风格漂移在 correct 和 wrong hint 下都会发生**，因为只要给一个"参考解"，teacher 就会偏向某种风格。对比操作抵消了这部分共性，留下真正与"正确性"相关的信号。

### 3.2 三阶段训练流程

**Figure 3: Overview of RLCSD**

[点击查看原图](https://arxiv.org/html/2606.11709v1/x6.png)

#### Stage 1: Rollout Sampling

- 对每个 query x，采样 N 条完整轨迹 {y_1, ..., y_N}
- 用 verifier 分成正确集 {y\*\_c} 和错误集 {y\*\_w}

#### Stage 2: Contrastive Signal Construction

对每条轨迹 y_c，计算：

e^{ctr}\_t = log π_T(y_t | x, y\**c, y*{<t}) - log π_T(y_t | x, y\**w, y*{<t})

**关键改进**：

- **K-marginalized negative hints**：不对单个 y\*\_w，而是对 K 个错误解取平均，减少方差
- **Exclude self-rollout**：计算 y_i 的信号时，不把 y_i 本身加入 hint pool，避免 over-confidence

#### Stage 3: Verifier-Anchored Modulation

Contrastive 信号**调制**（modulate）而非**替代** GRPO 的 outcome-level advantage：

A^{mod}\_t = clamp(e^{ctr}\_t, -τ, τ) · A^{GRPO}

- **Sign-preserving clamping**：防止 e^{ctr}\_t 过大导致梯度方向反转
- **Soft normalization**：用 tanh 压缩，保持信号在合理范围
- **Token-level masking**：只对 top 20-30% 高信号 token 计算 loss，聚焦真正重要的位置

### 3.3 Loss 设计

Two-path loss aggregation：

- **Path 1**：被 contrastive 信号调制的 token，独立归一化
- **Path 2**：未被调制的 token，独立归一化
- 两路分别归一化后相加，保留调制 token 的影响力

### 3.4 与 GRPO、OPSD 的关系

| 方法 | 监督信号 | 粒度 | 问题 |
|-|-|-|-|
| **GRPO** | Outcome-level advantage A^{GRPO} | 序列级 | 稀疏，credit assignment 困难 |
| **OPSD** | e\_{c,t} = log π_T - log π_S | Token 级 | 风格漂移，训练不稳定 |
| **RLCSD** | e^{ctr}\_t · A^{GRPO} | Token 级 | 对比消除风格，保留正确性信号 |

### 4.5 Ablation Study

**Table 3: Ablation on Qwen3-8B (K&K)**

| Configuration | K&K Score | Drop |
|-|-|-|
| **Full RLCSD** | **76.1** | - |
| Remove K-marginalization | 74.2 | -1.9 |
| Allow self-rollouts in hints | 73.5 | -2.6 |
| Remove GRPO anchoring | 72.0 | -4.1 |
| Single-path aggregation | 73.8 | -2.3 |

关键组件重要性：

2. **Self-rollout exclusion** 次之（-2.6），避免 over-confidence 很关键
3. **K-marginalization** 和 **two-path aggregation** 也有显著贡献

### 4.6 Cross-Model OPD 分析

当 teacher 和 student 是**不同模型**时，style drift 问题更严重：

- 风格距离（style distance）主导了 per-token KL 散度
- Stylistically mismatched teacher 会传递话语模式而非推理能力
- **建议**：选择 teacher 时，应优先看 token-ranking 诊断，而非简单的模型规模

## 五、Limitations：局限性与未解问题

### 5.1 依赖高质量的 verifier

- 需要明确的 verifier（如数学答案正确性判断）来区分 correct/wrong rollouts
- **难以应用到开放式任务**（如写作、对话），因为这些任务没有明确的"正确答案"

### 5.2 计算开销增加

- 需要采样 correct 和 wrong 两组 rollouts，计算量翻倍
- K-marginalization 需要多个 wrong hints，进一步增加成本
- **实际成本**：相比 GRPO 约增加 30-50% 训练时间

### 5.3 Contrastive 信号的边际效应

- 当 correct 和 wrong hints 的风格差异本身很小时，contrastive 操作收益有限
- **极端情况**：如果风格漂移不存在，RLCSD 退化为普通 OPSD

### 5.4 逻辑任务的特殊性

- Knight-and-Knaves 任务的提升远大于数学任务，可能是因为该任务的"风格"更固定
- **待验证**：在其他逻辑任务（如 proof reasoning, causal reasoning）上是否同样有效

## 六、启发与待跟进

### 6.1 对 OPD 范式的反思

RLCSD 揭示了一个深刻问题：**我们以为 on-policy distillation 在教"怎么做对"，其实主要在教"怎么说"**。

这对 TOPD、COPD 都是警示：

- **TOPD**：用 OT 距离做 prefix-level distillation，可能也在学风格
- **COPD**：用 contrastive learning，但 contrastive 的是 prefix，不是 hint

**跟进方向**：检查 TOPD/COPD 的训练过程，是否存在类似的 style drift 现象。

### 6.2 Contrastive 设计的通用性

RLCSD 的核心思想——**对比 correct 和 wrong 条件下的信号差异**——非常通用：

**可能的扩展**：

1. **Multimodal OPD**：在 vision-language reasoning 中，contrastive correct/wrong visual reasoning paths
2. **Agent planning**：contrastive correct/wrong action sequences
3. **Code generation**：contrastive correct/wrong code execution traces

### 6.3 与 Re² 的对比

| 维度 | Re² | RLCSD |
|-|-|-|
| **核心思想** | 学会放弃、重新开始 | 对比 correct/wrong hint，消除风格漂移 |
| **监督信号** | Outcome reward（redo vs not redo） | Token-level contrastive signal |
| **训练范式** | Pure RL（修改 action space） | RL + OPD 混合 |
| **解决的问题** | 模型陷入错误路径不愿回头 | OPD 的信号被风格主导 |
| **适用场景** | 推理、规划 | 有 verifier 的任务 |

**共同点**：都在挑战"标准 RL/OPD 流程"，都在寻找更精细的监督信号。

### 6.4 潜在改进方向

**方向 A：动态 contrast 强度**

- 当前 RLCSD 用固定的 clamping threshold τ
- **改进**：根据训练阶段动态调整，早期强 contrast（快速消除风格），后期弱 contrast（精细调整正确性）

**方向 B：多维度 contrast**

- 当前只 contrast correct vs wrong
- **改进**：contrast different reasoning strategies（如 direct vs step-by-step, forward vs backward）

**方向 C：与 value function 结合**

- 用 learned value function 估计 V(correct) - V(wrong)，替代直接的 rollout 对比
- **优势**：减少方差，提高样本效率

## 七、与前两篇 OPD 的对照

| 维度 | TOPD | COPD | RLCSD |
|-|-|-|-|
| **核心问题** | 长推理导致 credit assignment 困难 | Same as TOPD | OPD 的信号被风格主导 |
| **解决方案** | Prefix-level distillation（OT 距离） | Contrastive prefix selection | Contrastive correct/wrong hint |
| **对比的对象** | Full sequence vs prefix | Good prefix vs bad prefix | Correct hint vs wrong hint |
| **训练范式** | On-policy distillation | On-policy distillation | RL + OPD 混合 |
| **关键洞察** | Prefix 包含更多信息 | Not all prefixes are equal | Not all tokens in supervision are equal |

**演进脉络**：

1. **TOPD**：从 sequence-level 到 prefix-level，解决长推理的稀疏性问题
2. **COPD**：从 random prefix 到 contrastive prefix，解决"哪个 prefix 更好"的问题
3. **RLCSD**：从 token-level 到 contrastive token-level，解决"监督信号在教什么"的问题

**共同趋势**：都在追求**更精细、更有效的监督信号**。

## 九、总结

RLCSD 是一篇**诊断性 + 方法性**并重的工作：

1. **诊断**：揭示了 OPD 的"特权信号"主要在教风格而非正确性
2. **方法**：通过 contrastive correct/wrong hint 消除风格漂移
3. **效果**：在数学和逻辑任务上稳定提升，训练动态更健康

**对研究者的启示**：

- 不要盲目相信 token-level supervision 的质量，要分析信号到底在教什么
- Contrastive 设计是提升 OPD 的有效工具，但要结合 outcome reward
- 训练稳定性（熵、回答长度）和最终性能同样重要

**下一步**：

- 在 TOPD/COPD 上验证是否存在 style drift
- 尝试将 RLCSD 的 contrastive 原则扩展到 multimodal、agent 场景
- 探索动态 contrast 强度和多维度 contrast

## TL;DR

<strong>一句话：现在让模型看清细节的办法是「边推理边裁图放大」，准但慢。这篇反过来——放大只发生在训练时：老师看小图出题、在小图上答题，然后把题搬回整图（并画个框），学生只学「一眼看整图」。推理时不用任何工具，一次前向。</strong>

- <strong>核心机制（Region-to-Image Distillation，R2I）</strong>：① 目标检测/分割提出<strong>面积 &lt; 10% 的小区域</strong> ② 裁出来让老师出题、答题（多老师投票）③ 把问题<strong>搬回整图</strong>，并在整图上<strong>画出那个框</strong> ④ 学生在这个"整图+框"上训练
- <strong>最关键的设定</strong>：<strong>框只在训练时给，推理时没有</strong>。论文把框当作<strong>特权信息（privileged information）</strong>——训练时用它把注意力掰到该看的地方，训完就不需要了
- <strong>结果（Qwen3-VL-8B 底座）</strong>：ZoomBench <strong>37.87 → 58.11</strong>；十项平均 <strong>62.86 → 68.12</strong>
- <strong>4B 也能打</strong>：Qwen3-VL-4B 平均 <strong>61.52 → 66.86</strong>，ZoomBench <strong>40.24 → 55.74</strong>
- <strong>和超大模型比</strong>：ZwZ-8B 的"通用感知平均" <strong>77.64</strong>，压过 GLM-4.5V（108B）71.90、Qwen3-VL-235B 74.61、Kimi-K2.5（1T）75.50
- <strong>⚠️ 但十项总平均 Kimi-K2.5 仍是 71.18 &gt; ZwZ-8B 68.12</strong>——论文说的是"通用感知平均"这一列，别读成全面超过
- <strong>数据对比（Table 3，同为 Qwen3-VL-8B 底座）</strong>：自己的 74K → 68.12；<strong>DeepEyes 47K → 65.84</strong>、Thyme 55K → 66.13、TreeVGR 37K → 64.30、Oasis 500K → 63.24、MM-Self-Instruct 65K → 63.71。<strong>自己的 10K 就到 67.37</strong>
- <strong>训练很朴素</strong>：<strong>只在 74K 合成数据上跑 DAPO（纯 RL，无 SFT）</strong>
- <strong>✅ 仓库很完整</strong>：github.com/inclusionAI/Zooming-without-Zooming，<strong>Apache-2.0</strong>；<strong>4 个权重</strong>（ZwZ-2B/4B/7B/8B，HF）、<strong>数据集</strong>（ZwZ-RL-VQA 37K + ZoomBench 845）、<strong>训练脚本</strong>（内置 EasyR1）、<strong>评测脚本</strong>、跑数据的四步流水线脚本
- <strong>⚠️ 仓库写 37K、论文写 74K</strong>，两个数字对不上，需要留意
- <strong>✅ 有独立 Limitations（§6.4）</strong>
- <strong>主题</strong>：<strong>OPD / 蒸馏</strong>（第 3 周第 1 篇）。选它：<strong>把"工具动作"蒸馏成"模型内部能力"</strong>，正是本周要读的那类；蚂蚁 inclusionAI + 上交，权重数据全开源，8B 单机量级

## 一、先看例子（大白话：车牌号在整图里就是看不清）

> 💡 <strong>铺垫</strong>：一张街景图，问"这辆车的车牌号是多少"。
>
> <strong>整张图里车牌只占几十个像素——模型答不出来。但你把车牌裁出来放大，它立刻能读。</strong>
>
> <strong>这不是"不会推理"，是"没看清"。</strong>

![论文 Figure 3：R2I 流水线。左上＝从整图提出目标区域并裁出来；中＝老师在小图上出题「车牌号是多少」并答题；右＝把问题搬回整图，同时把那个框画在图上、加一句「只关注框内物体」](/images/paper-reading/2026-11-02-zwz/2026-11-02-d70-1.webp)

> <strong>现在的做法是「边想边看」：模型先猜个大致位置，裁出来，放大，再读，读不清再换一块。</strong>
>
> <strong>准是准，但慢——每裁一次就要重新编码一次图，一张图要跑好几轮。</strong>
>
> <strong>这篇的办法是：把这个「裁出来看」的过程，提前到训练阶段做掉。</strong>

## 二、动机：准和快，现在只能选一个

"Thinking-with-Images"（DeepEyes、Thyme、Mini-o3 那一类）确实把细粒度感知刷上去了，<strong>代价是推理时要反复调工具、反复编码图像</strong>。

<strong>为什么裁出来就变准？</strong>论文给的解释很直白：<strong>裁出来之后，"针里找针"变成了"辨认一个东西"</strong>——干扰源被物理移除了。

<strong>那么问题就变成</strong>：

> <strong>能不能只要"准"，不要"慢"？</strong>

论文的答案：<strong>可以，只要你在训练时就把"该看哪儿"教进去。</strong>

![论文 Figure 2：上＝Thinking-with-Images，推理时反复裁图、反复编码，延迟高；下＝R2I，只在训练时裁一次，把监督蒸回整图，推理一次前向](/images/paper-reading/2026-11-02-zwz/2026-11-02-d70-2.webp)

## 三、方法：三次操作，全是「搬运」

### 3.1 第一步：裁小图（zoom in）

- <strong>提议框</strong>：检测/分割系统在整图上提出一批"物体级"框
- <strong>只留小框</strong>：<strong>框面积 / 整图面积 &lt; τ（默认 0.1）</strong>——这样才保证"证据在整图里是藏着的"
- <strong>裁出来放大</strong>，得到微区域 R

### 3.2 第二步：在小图上出题 + 答题

- <strong>出题老师</strong>在小图上生成"只靠这块区域就能答"的问题（小字、符号、细微颜色、小物体计数…）
- <strong>答题老师</strong>（多个）在小图上各答一遍，<strong>多数投票</strong>得答案
- <strong>只有高共识的题才留</strong>——这是控制幻觉的关键：在小图上答，老师反而不容易瞎编

### 3.3 第三步：把题搬回整图（zoom out）

<strong>这一步是全文的核心。</strong>同一个问题在小图上毫无歧义，回到整图就可能有歧义（"这辆车"是哪辆？）。所以做一个<strong>反向变换</strong>：

- <strong>在整图上把那个框画出来</strong> → 得到 I′
- <strong>给问题加一句空间约束</strong>（"只关注框内物体"）→ 得到 Q′
- 训练样本就是 <strong>(I′, Q′, A)</strong>

### 3.4 最关键的一点：框是"特权信息"

推理时<strong>没有框</strong>。那为什么去掉框还能work？

<strong>论文的解释</strong>：训练时模型实际在学 <strong>P(A | 整图, 问题, 框)</strong>；<strong>框是一个结构提示，把注意力强行掰到对应的小区域</strong>。<strong>训完之后，注意力对齐这个习惯被保留了下来</strong>——所以去掉框，它自己也会往那儿看。

论文用<strong>注意力图分析</strong>来佐证这一点（ZoomBench 的 dual-view 协议 + 相对注意力覆盖）。

### 3.5 这套流程可以推广到任何"工具动作"

论文把它抽象成一个通式（Algorithm 1）：

<strong>原图 I → 施加工具动作 f → 得到 Ĩ → 老师基于 Ĩ 出题答题 → 用 f⁻¹ 把问题映射回原图 → (I, Q̂, A)</strong>

<strong>所以不只是裁图</strong>：翻转、3D 定位、调专家模型，都能按这个模板蒸进去。

### 3.6 ZoomBench：顺便造了个榜

用同样的流水线造了 <strong>845 题</strong>，六个维度（细粒度计数 / OCR / 颜色 / 结构 / 材质 / 物体识别）。

<strong>两个特点</strong>：

- <strong>双视图协议</strong>：每题同时给整图和关键区域裁图 → 可以量化"整图 vs 裁图"的差距（zooming gap）
- <strong>难度</strong>：Qwen2.5-VL-7B 只有 <strong>42.49%</strong>

## 四、实验

### 4.1 主结果：三个规模全涨

| 模型 | ZoomBench | 十项平均 |
|-|-|-|
| Qwen3-VL-4B | 40.24 | 61.52 |
| <strong>ZwZ-4B</strong> | <strong>55.74</strong> | <strong>66.86</strong> |
| Qwen2.5-VL-7B | 42.49 | 56.82 |
| <strong>ZwZ-7B</strong> | <strong>55.62</strong> | <strong>62.42</strong> |
| Qwen3-VL-8B | 37.87 | 62.86 |
| <strong>ZwZ-8B</strong> | <strong>58.11</strong> | <strong>68.12</strong> |

<strong>ZoomBench 上普遍涨 15–20 个点</strong>，其它榜少涨或不涨——<strong>这正好说明它打的是"细粒度感知"这个点</strong>。

### 4.2 和超大模型比：要看清楚是哪一列

| 模型（参数量） | 通用感知平均 | 十项总平均 |
|-|-|-|
| <strong>ZwZ-8B（8B）</strong> | <strong>77.64</strong> | 68.12 |
| GLM-4.5V（108B） | 71.90 | 65.04 |
| Qwen3-VL-235B-A22B | 74.61 | 67.55 |
| Kimi-K2.5（1T） | 75.50 | <strong>71.18</strong> |

<strong>读法</strong>：<strong>在"通用感知"这一列，8B 确实压过 108B / 235B / 1T</strong>；但<strong>十项总平均上 Kimi-K2.5 还是最高（71.18 vs 68.12）</strong>。<strong>论文写的是前一列，别读成全面超越。</strong>

### 4.3 数据对比：赢在"数据形态"，不赢在"数据量"

| 训练数据（同为 Qwen3-VL-8B 底座） | 规模 | 十项平均 |
|-|-|-|
| 不加训练（底座） | — | 62.86 |

| Thyme-RL 数据 | 55K | 66.13 |
| TreeVGR-RL 数据 | 37K | 64.30 |
| Oasis 数据（合成） | <strong>500K</strong> | 63.24 |

- <strong>自己的数据从 10K 到 74K 只涨 0.75</strong> → <strong>这个方向已经接近饱和，再加量收益有限</strong>

## 五、Limitations

### 论文自述的（§6.4，只有一条）

<strong>空间推理与多物体感知没有覆盖</strong>：这类能力没进流水线，所以像 TreeBench 这种偏空间/多目标的榜没测。作者说方法可以扩展（用空间推理或多目标搜索工具按 Algorithm 1 造数据）。

### 我读出的 5 条

1. <strong>⭐ 缺一个最关键的对照：「训练时不给框」会怎样</strong>。整篇的立论是"框是特权信息，训完可以去掉"，但<strong>我抽读的部分没看到"同样数据、训练时不画框"的 A/B</strong>。没有这个对照，就说不清收益来自<strong>框的注意力对齐</strong>，还是单纯来自"多了一批高质量细粒度 QA"
2. <strong>⭐ 仓库 37K vs 论文 74K，两个数字对不上</strong>：仓库描述写 "37K verified multi-region VQA examples"，论文写 "74K"。<strong>可能是 37K 题目 × 2（或多区域展开），但没说明</strong>，复现时要自己核
3. <strong>"纯 RL 无 SFT"这个卖点要打折</strong>：数据是老师生成的 QA，奖励是"答案对不对"——<strong>本质上仍是在拟合合成标注</strong>，和 SFT 的差别主要在于"on-policy + 格式自由"。论文没有和"同数据 SFT"做对照
4. <strong>老师全是大模型</strong>：出题用 Qwen3-VL-235B-A22B、答题用 GLM-4.5V + Kimi-K2，切图用 SAM3。<strong>合成成本（API 费用/GPU 时间）完全没报</strong>，而这是这条路线的真实门槛
5. <strong>ZoomBench 是自己造的、自己刷的</strong>：虽然有人工核验，但榜单与方法同源。<strong>好在论文同时报了 HR-Bench / VStar / MME-RW 等外部榜</strong>，外推证据是有的

## 七、启发与待跟进

1. <strong>⭐ 最值得抄的范式："工具动作 → 训练期监督"的三步搬运</strong>：<strong>原图 → 施加工具 → 老师在新视图上出题答题 → 逆变换搬回原图</strong>。<strong>任何"训练时能拿到、推理时拿不到"的信息都能这么用</strong>（这就是特权信息蒸馏的通用模板）
2. <strong>⭐ "画框当特权信息"这招很便宜</strong>：不需要改模型，只需要在训练图上把框画上去、问题里加一句约束。<strong>推理时什么都不用做</strong>
3. <strong>⭐ 数据形态 &gt; 数据量</strong>：500K 普通合成数据输给 10K 好数据。但反过来，<strong>10K→74K 只涨 0.75</strong>，说明这个形态也已经到顶了——<strong>下一个突破要靠新的"工具动作"，不是更多同类数据</strong>
4. <strong>可以马上做的验证</strong>：在自己的训练数据上，<strong>加一组"训练时画框、推理时不画"的对照</strong>，只改数据不改模型，成本极低
5. <strong>待跟进</strong>：① 补"训练不给框"的 A/B ② 把同样的模板用到别的工具（裁剪之外：旋转、对比、放大不同倍率） ③ 与 OPD 结合——不用合成数据，直接在学生自己的轨迹上做这个"工具→整图"的映射

## 八、结论

<strong>这是一篇"换个位置做同一件事"的论文。</strong>它没有发明新模型、新算法，只是把"裁图放大"从推理时挪到了训练时，<strong>然后靠一个画上去的框，把这份能力留在了权重里</strong>。

<strong>证据很扎实</strong>：三个规模全涨、十项榜单、和 108B/235B/1T 的对比、数据形态对比，<strong>而且权重和数据全开源</strong>——这是本周目前最好复现的一篇。

<strong>短板也清楚</strong>：缺"训练不给框"的关键对照、仓库与论文的数据量对不上、合成成本没算。

<strong>今日一句</strong>：<strong>如果一个能力是"看的时候换个角度"就能得到的，那就别在推理时反复换角度——训练时换一次，把它记住。</strong>

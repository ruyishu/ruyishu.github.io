## TL;DR

<strong>一句话：组式 RL（GRPO / GiGPO）的信用分配，从根本上仍然依赖"这条轨迹最终成没成"——成功轨迹里的每一步都拿正奖励、失败轨迹里的每一步都挨惩罚。但论文实测：<strong>失败轨迹里有 22.0% 的步其实在推进任务；成功轨迹里有 65.3% 的步根本没推进任务</strong>。GraphGPO 把所有 rollout 轨迹<strong>聚合成一张状态转移图</strong>，用图上的<strong>最短路径距离</strong>衡量"这一步有没有离目标更近"，据此给每条<strong>边</strong>算优势——<strong>完全脱离轨迹的最终结果</strong>。</strong>

- <strong>最刺眼的一组统计（Figure 1）</strong>：ALFWorld 早期训练（rollout M=8，最大步数 T=50）——成功轨迹 <strong>34.7% 推进 / 65.3% 没推进</strong>；失败轨迹 <strong>22.0% 推进 / 78.0% 没推进</strong>
- <strong>GiGPO 的"步级"其实没有脱离轨迹</strong>：它的步级奖励 <strong>R<sub>S</sub> = λ<sup>T−i</sup> R(τ)</strong> <strong>仍然乘着轨迹的最终奖励 R(τ)</strong>——论文一句话点破：<strong>"still relies on trajectory-level attribution"</strong>
- <strong>核心公式（三步）</strong>：图上给每个状态 s 定义到目标的<strong>最小代价距离 d(s)</strong> → 边的奖励 <strong>R<sub>G</sub>(s,a,s') = r<sub>succ</sub> · ω<sup>d(s') + c(s,a)</sup></strong> → <strong>把"从同一个状态出发的所有边"当成一个组</strong>，组内标准化得优势 <strong>A<sub>G</sub></strong>
- <strong>主结果（Table 1）</strong>： 
  - Qwen2.5-<strong>1.5B</strong>：ALFWorld 平均成功率 GRPO 77.86 → GiGPO 90.88 → <strong>GraphGPO 92.71</strong>（相对 GRPO <strong>+14.85</strong>）；WebShop 成功率 71.35 → 73.83 → <strong>78.65</strong>（<strong>+7.30</strong>）
  - Qwen2.5-<strong>7B</strong>：ALFWorld 83.33 → 94.27 → <strong>95.31</strong>（+11.98）；WebShop 75.00 → 78.38 → <strong>80.31</strong>（+5.31）
  - <strong>1.5B 的 GraphGPO（92.71）远超 GPT-4o（48.0）与 Gemini-2.5-Pro（60.3）</strong>
  - <strong>Sokoban（VLM，Qwen2.5-VL-3B）</strong>：GRPO 67.1 → GiGPO 76.92 → <strong>GraphGPO 86.98</strong>（<strong>+19.88 / +10.06</strong>）
- <strong>开销可以忽略</strong>：图构建 <strong>0.108 秒</strong>、图优势计算 <strong>0.025 秒</strong>；而 rollout 是 <strong>216.9 秒</strong>、策略更新 74.2 秒 → <strong>新增只占每轮总时间的 0.04%</strong>
- <strong>有理论保证</strong>：<strong>Prop 4.1 单调性</strong>（更接近目标的动作必然拿到更高优势）；<strong>Prop 4.2 条件方差更小</strong>（Var(X<sub>G</sub>|s,a,s') ≤ Var(X<sub>S</sub>|s,a,s')）
- <strong>⚠️ 没有 Limitations 章节</strong>（但做了 ω 的敏感性研究：ω ∈ {0.1,0.2,0.4,0.6,0.8} 在 ALFWorld 上整体 92.71/91.93/92.97/90.36/92.19，比较稳）

## 一、先看例子（大白话：别按"这组做完没有"给每一步打分）

> 💡 <strong>铺垫</strong>：组式 RL 的吸引力在于<strong>不需要 critic</strong>——采样一组轨迹，用<strong>组内统计</strong>算优势，便宜又稳。
>
> 但它套到多轮 agent 任务上之后有个难看的地方：<strong>一条轨迹里的所有步，共享同一个"这条轨迹成没成"的奖励。</strong>

> <strong>把这件事想成老师批改一道多步骤的实验报告：</strong>
>
> 学生甲<strong>做完了</strong>，但中间<strong>绕了两大圈</strong>（把同一个步骤重复做了两遍）；学生乙<strong>没做完</strong>，但他前半段的路子<strong>其实比甲更对</strong>。
>
> <strong>按轨迹级打分法</strong>：甲全部步骤得满分（连那两次白绕圈也算功劳），乙全部步骤挨罚（连他走对的那几步也被否定）。
>
> <strong>更糟的是</strong>：乙之所以失败，可能只是<strong>最后一步</strong>走岔了——<strong>前面那些步是无辜的</strong>，但照样一起挨罚。
>
> <strong>GraphGPO 想做的事情就是：不看"这组做完没有"，而看"这一步有没有离目标更近"。</strong>

![▲ 论文 Figure 1：左边是同一个任务上一条成功轨迹（绿）和一条失败轨迹（红）的示意——成功轨迹里绕圈的步被奖励、失败轨迹里推进的步被惩罚；右边是 ALFWorld 早期训练的步级统计（rollout M=8，最大步数 T=50）：成功轨迹里只有 34.7% 的步真正推进任务，失败轨迹里也有 22.0% 的步在推进任务](/images/paper-reading/2026-10-06-graphgpo/2026-10-06-d51-1.webp)

<strong>论文自己举的例子（Figure 2）——两条轨迹的对照：</strong>

- <strong>τ₁ 成功了</strong>，但它<strong>反复访问黄色状态</strong>（s₁³ 和 s₁⁵）——这是<strong>错误且冗余</strong>的行为，不该拿正奖励
- <strong>τ₂ 失败了</strong>，但它在蓝色状态 s₁ 选的动作 <strong>a₁² 比 τ₁ 的 a₁¹ 更好</strong>（能更快到达黄色状态）
- 而 τ₂ 的失败很可能<strong>就源于黄色状态 s₂² 选了 a₂²</strong>，导致进入再也到不了目标的状态 s₃²——<strong>所以它之前那些步不该被直接惩罚</strong>
- <strong>一句话</strong>：按轨迹结果打分，<strong>会把"绕圈"当功劳、把"贡献"当罪过</strong>

![▲ 论文 Figure 2：组式优势估计的现有问题。方框是状态、圆是动作。左上两条 rollout 轨迹（τ1 成功、τ2 失败），蓝色方框表示彼此相同的状态、黄色是另一组相同状态、灰色是没有共享的独立状态；左下是轨迹级与步级优势的对比。右侧展示两个问题：失败轨迹里其实含有更好的决策，而成功轨迹里的冗余或错误步会被当成功劳](/images/paper-reading/2026-10-06-graphgpo/2026-10-06-d51-2.webp)

## 二、动机：连 GiGPO 的"步级"也没真正脱离轨迹

- <strong>GRPO 在多轮任务上的做法</strong>：<strong>A<sub>E</sub>(τ<sub>m</sub>) = (R(τ<sub>m</sub>) − μ(G<sub>E</sub>)) / σ(G<sub>E</sub>)</strong>，然后同一轨迹里<strong>每一步都发同一个优势</strong> → 信用分配过于粗糙
- <strong>GiGPO 的改进</strong>：引入<strong>步级组优势</strong>——把<strong>所有轨迹里"相同状态"的步</strong>聚成一个组（不管它们来自哪条轨迹），再在组内标准化：<strong>A<sub>S</sub>(s,a) = (R<sub>S</sub>(s,a) − μ(G<sub>S</sub>(s))) / σ(G<sub>S</sub>(s))</strong>
- <strong>但论文点出了它的要害</strong>：它的步级奖励是 <strong>R<sub>S</sub> = λ<sup>T−i</sup> R(τ)</strong>——<strong>仍然乘着轨迹的最终奖励</strong>。所以 GiGPO 只是把"轨迹级信号"重新分配了一下，<strong>并没有真正与轨迹结果解耦</strong>
- <strong>实测的错位有多严重（Figure 1）</strong>： 
  - <strong>成功轨迹里，只有 34.7% 的步在推进任务</strong>（65.3% 是冗余或无效的）
  - <strong>失败轨迹里，有 22.0% 的步其实在推进任务</strong>
- <strong>三个后果</strong>：① 成功轨迹里的冗余/错误步被奖励 ② 失败轨迹里的正确步被持续惩罚 ③ <strong>这种归因错位还会掩盖轨迹失败的真正原因</strong>
- <strong>论文的目标（说得挺克制）</strong>：设计一个<strong>纯粹基于全局状态结构</strong>的步级信用分配方法，<strong>不加 critic、不引入显著计算开销</strong>

## 三、方法：把所有轨迹拼成一张图

![▲ 论文 Figure 3：GraphGPO 总览（假设所有转移代价为 1）。左边是聚合状态转移图——相同状态被合并（例如 s1、s2-1、s1-2、s4-1 是同一个节点），每个节点标注到目标的最短距离 d；粉色勾代表目标状态（d 等于 0），绿色叉代表走不到目标的状态（d 记为最大值加一）。右边是图优势估计：把「从同一状态出发的所有边」当一个组，组内标准化得到每条边的优势](/images/paper-reading/2026-10-06-graphgpo/2026-10-06-d51-3.webp)

### 3.1 聚合状态转移图

- <strong>图 G = (S, E)</strong>。节点集 S = <strong>所有轨迹里访问过的状态</strong>，而且<strong>相同状态被合并成一个节点</strong>
- 有向边 <strong>(s, a, s', c(s,a)) ∈ E</strong>：只要存在某条轨迹的某一步，从 s 执行 a 走到 s'，就有一条边；<strong>c(s,a) &gt; 0 是这步的代价</strong>（工具调用场景里可以是金钱或时间成本）
- 终止状态集 S<sub>term</sub> = 目标状态 s<sub>succ</sub> ∪ 超过最大长度的状态 s<sub>fail</sub>
- <strong>这一步最本质的收益</strong>：图让<strong>跨轨迹的连通</strong>成为可能——<strong>一条失败轨迹的前半段，可以接到另一条成功轨迹的后半段上</strong>，只要它们经过同一个状态

### 3.2 图上的距离与步级奖励

对任意状态 s，定义<strong>到达目标状态的最小代价距离</strong>：

> <strong>d(s) = 0</strong>（若 s = s<sub>succ</sub>）<br><strong>d(s) = min<sub>(s,a,s',c)∈E</sub> \[ c(s,a) + d(s') \]</strong>（若 s 能走到目标）<br><strong>d(s) = +∞</strong>（否则）

- <strong>工程处理很关键</strong>：<strong>+∞ 被替换成 d<sub>max</sub> + 1</strong>（d<sub>max</sub> 是图里最大的有限距离）——论文的理由是<strong>避免"过强的惩罚限制了策略探索"</strong>
- 于是每条边的图级步奖励：<strong>R<sub>G</sub>(s, a, s') = r<sub>succ</sub> · ω<sup>d(s') + c(s,a)</sup></strong> 
  - r<sub>succ</sub> &gt; 0 是成功奖励（通常取 1 或 10）
  - ω ∈ (0,1) 是<strong>距离折扣因子</strong>——<strong>离目标越远的转移，得到的奖励越小</strong>
- <strong>这个奖励完全不用"轨迹成没成"</strong>，只用图的全局连通性

### 3.3 图优势：把"同一个岔路口的几条路"拿来比

- <strong>步级组的定义</strong>：<strong>G<sub>G</sub>(s) = { (s<sub>i</sub>, a, s<sub>j</sub>) ∈ E | s<sub>i</sub> = s }</strong>——<strong>从状态 s 出发的所有边</strong>。 <br>直观理解：<strong>这些是"在同一个岔路口的所有可选走法"</strong>
- <strong>图优势</strong>：<strong>A<sub>G</sub>(s, a, s') = ( R<sub>G</sub>(s,a,s') − μ(G<sub>G</sub>(s)) ) / σ(G<sub>G</sub>(s))</strong>；若 |G<sub>G</sub>(s)| = 1（这个状态只出现过一次）则 <strong>A<sub>G</sub> = 0</strong>
- <strong>论文用 Figure 3 的例子讲透了两件事</strong>： 
  - 状态 s₁ 有两条出边，通向 s₂ 和 s₁²；因为 <strong>d(s₂) &lt; d(s₁²)</strong>，所以 <strong>A<sub>G</sub>(s₁, a₁², s₂) &gt; A<sub>G</sub>(s₁, a₁¹, s₁²)</strong>——<strong>即使 a₁² 来自那条失败的轨迹 τ₂，它依然被判定为更好的动作</strong>
  - 反过来，a₂² 导致进入 s₃²（经验上<strong>没有路径能到目标</strong>，d = d<sub>max</sub>+1），所以它在组内优势最小 → <strong>这就是"找到失败的真正原因"</strong>
  - 而<strong>绕圈</strong>在图上表现为<strong>环</strong>（比如 s₂ → s₁⁴ → s₂），这种转移必然<strong>增大</strong>到目标的距离，于是优势低于那些真正缩短距离的动作

<strong>两个理论保证：</strong>

| 命题 | 内容 |
|-|-|
| <strong>Prop 4.1 单调性</strong> | 在确定环境里，若 a<sub>good</sub> 比 a<sub>bad</sub> 更接近目标（即 d(s'<sub>good</sub>) + c(s,a<sub>good</sub>) &lt; d(s'<sub>bad</sub>) + c(s,a<sub>bad</sub>)），则 <strong>A<sub>G</sub>(good) &gt; A<sub>G</sub>(bad)</strong>——<strong>形式化验证了"GraphGPO 优先奖励缩短距离的动作"</strong> |
| <strong>Prop 4.2 方差</strong> | 同一策略采样、确定环境下，同一个 (s,a,s') 的条件方差满足 <strong>Var(X<sub>G</sub>\\\|s,a,s') ≤ Var(X<sub>S</sub>\\\|s,a,s')</strong>（其中 X<sub>S</sub> = η(t)R(τ)）——<strong>图信号比轨迹信号更稳、更少噪声</strong> |

### 3.4 策略优化：为什么要保留轨迹级优势

- <strong>组合优势</strong>：<strong>A(s,a,s') = β<sub>G</sub> · A<sub>G</sub>(s,a,s') + β<sub>E</sub> · A<sub>E</sub>(τ)</strong>，论文把两个 β 都设成 1
- <strong>论文给的理由很实在</strong>：<strong>防止那些"只有一条出边"的状态优势退化为 0</strong>（|G<sub>G</sub>(s)| = 1 时 A<sub>G</sub> 被设为 0，光靠它就没信号了）
- 最终目标 = 标准 PPO 式<strong>裁剪替代目标</strong> + KL 正则

- <strong>Sokoban（Table 2，Qwen2.5-VL-3B）</strong>：base 11.7 → GRPO <strong>67.1</strong> → GiGPO <strong>76.92</strong> → <strong>GraphGPO 86.98 (0.73)</strong>，<strong>相对 GRPO +19.88、相对 GiGPO +10.06</strong>

## 五、Limitations &amp; 批判性思考

> ⚠️ <strong>先说事实</strong>：<strong>这篇论文没有 Limitations 章节</strong>。全文搜 "Limitation" 只命中两处，且都是"4.1 Limitations of <strong>Trajectory-Level Attribution</strong>"——<strong>那是在说别人方法的局限，不是自己的</strong>。Conclusion 之后直接就是 Impact Statement 与致谢。

### 我读出来的问题（按严重程度排序）

- <strong>① 最大的隐性问题：整套方法建立在"状态可以被精确辨认并合并"这个假设上。</strong>图的节点是"相同状态合并"，但论文的实现是<strong>只用环境观测的确定性成分</strong>构造状态（细节放在附录）。<strong>在部分可观测的环境里，"看起来一样但实际不同"的状态会被错误合并</strong>——而一旦合并错了，图上的距离 d 就是错的，<strong>整套信用分配都会系统性偏移</strong>。论文没有做状态合并粒度的消融，也没有讨论误合并的后果
- <strong>② 两个理论命题都只对"确定环境"成立。</strong>Prop 4.1（单调性）和 Prop 4.2（方差更小）的前提都写着 <strong>deterministic environment</strong>。而现实里的 agent 任务（网页、工具调用、真实系统）<strong>几乎都不是确定的</strong>。所以这两个 Proposition 的实际覆盖范围比看上去小得多——<strong>它们是"设计意图的形式化"，不是"实际保证"</strong>
- <strong>③ "目标状态可达性"这个信号本身可能被图的自洽性骗到。</strong>d(s) = +∞（工程上记为 d<sub>max</sub>+1）的含义是"经验上走不到目标"。但这个判断<strong>完全基于当前这一批 rollout 采出来的图</strong>。如果某条本来可行的路径<strong>这一批里恰好没人走过</strong>，那些状态就会被判为"死路"并拿到最低优势——<strong>这是一个自我实现的悲观偏差</strong>。论文把它当作"探索不足"来处理（不设过强惩罚），但没有量化这个偏差有多大
- <strong>④ 图的规模与长时任务的可行性没有实验验证。</strong>图的边数随 rollout 的 M（组大小）与 T（最大步数）增长。论文的实验里 M=8、T=50（ALFWorld）——<strong>如果换成 T=500 的长程任务，或者组大小到 64，图的规模、Dijkstra 的开销、状态合并的准确性会怎样，论文没有测</strong>。所谓"0.04% 开销"是在一个小规模设定下测出来的
- <strong>⑤ 与 GiGPO 的关系有一个没解释清楚的张力。</strong>Table 3 显示：在 ALFWorld 上，<strong>GiGPO + DS（96.35）其实高于 GraphGPO 不加 DS（92.71）</strong>。论文在正文里强调"GraphGPO 始终占优"，但这个具体对比<strong>需要读者自己去表里对</strong>。诚实的表述应该是"GraphGPO 在同等配置下占优，而动态采样带来的增益对两者都有效"
- <strong>⑥ 只看"成功/失败"两种终止，没有对失败原因分类。</strong>论文的动机之一是"归因错位掩盖了失败的真正原因"，但实验里对"失败原因"的分析<strong>只有 Figure 3/Figure 2 那种示意性的图解和附录的案例研究</strong>，<strong>没有量化的诊断指标</strong>（比如"图是否准确定位了导致失败的边"的准确率）。<strong>动机是"更faithful的信用分配"，但"faithful"没有被独立度量</strong>
- <strong>⑦ 缺少与稀疏奖励处理方法的对比。</strong>论文的设定是"稀疏、延迟奖励"，但对比方法里没有 HER（hindsight experience replay）、奖励塑形（reward shaping）、或过程奖励模型（PRM）这类专门解决稀疏奖励的路线。<strong>只和 GRPO/GiGPO/PPO/RLOO 比，说服力有限</strong>
- <strong>⑧ 全转移代价被简化为 1。</strong>论文在实验里设 c(s,a) = 1（"for simplicity"）。可它自己在方法描述里强调"工具调用场景下代价可以是金钱或时间"。<strong>把代价这一维引入实验本来是它的一个卖点，但实验里被关掉了</strong>——所以"带代价的最短路径"这个能力实际上没有被验证
- <strong>⑨ 三个基准都是相对受控的仿真环境</strong>（ALFWorld / WebShop / Sokoban），没有真实系统（OSWorld 类）、没有网页 agent。<strong>agentic RL 里最乱的那类环境没碰</strong>
- <strong>⑩ 没有 Limitations 章节</strong>；上述①②③这些直接影响适用面的前提，本应由作者自己摊开

## 六、与前文对照

> 🔗 <strong>一句话定位：这篇和 9/16 的 RAGEN-2 是同一批人对 agentic RL 的"诊断"，但诊断的层次不同——RAGEN-2 说"你的信号质量不行"（用 MI 指标发现模板崩塌，靠奖励方差过滤 prompt）；GraphGPO 说"你的归因方式错了"（不该按轨迹结果给每一步打分，该按图上离目标的距离）。<strong>一个改数据筛选，一个改优势结构。</strong></strong>

### 6.1 与 GiGPO（lib 已读）：最直接的前作与超越

- <strong>GiGPO 的贡献</strong>：把"相同状态的步"聚成组，做步级组优势——这是从"轨迹级"迈向"步级"的关键一步
- <strong>GraphGPO 点出的漏洞</strong>：GiGPO 的步级奖励 <strong>R<sub>S</sub> = λ<sup>T−i</sup> R(τ)</strong> <strong>依然乘着轨迹最终奖励</strong>，所以它只是把轨迹信号<strong>重新分配</strong>，没有<strong>换掉依据</strong>
- <strong>GraphGPO 的替换</strong>：把依据从 <strong>R(τ)</strong> 换成 <strong>R<sub>G</sub> = r<sub>succ</sub>·ω<sup>d(s')+c</sup></strong>——一个<strong>与轨迹结果完全无关、只看图上几何距离</strong>的量
- <strong>效果</strong>：Sokoban 上 +10.06、ALFWorld 上 +1.83（1.5B）；<strong>而且开销几乎一样</strong>（都是组式方法 + 一次图搜索）

### 6.2 lib 的"分锅家族"又多了一个轴：图结构

- 已有成员：BSBT <strong>模态轴</strong>、PCD <strong>因果阶段轴</strong>、GiGPO <strong>时间步轴</strong>、MIRL <strong>生成阶段轴</strong>、InstructVLA <strong>参数子集轴</strong>、MoCA <strong>模态轴 + 奖励路由</strong>、Forget-Me-Not <strong>模块轴</strong>、SDPO <strong>token × 词表轴</strong>、POLIA <strong>视觉对象轴</strong>
- <strong>GraphGPO 补上"状态转移边轴"</strong>——而且它是这个家族里<strong>第一个用"全局图结构"（而不是局部统计）来决定谁该拿多少信用</strong>的
- <strong>另一个共同趋势</strong>：POLIA 的分组是"模型自己输出的框"诱导的，GraphGPO 的分组是"环境状态的合并"诱导的 → <strong>两篇都在做同一件事：让分组从数据里自然长出来，而不是人来指定</strong>

### 6.3 与 POLIA（10/5）/ SDPO（9/30）的"细粒度优势"路线

- <strong>共同动作</strong>：保留原算法骨架，只把优势换成更有信息的版本（SDPO 明说"只换优势"、POLIA 是 A<sup>ext</sup> + ωA<sup>int</sup>、GraphGPO 是 β<sub>G</sub>A<sub>G</sub> + β<sub>E</sub>A<sub>E</sub>）
- <strong>切的轴不同</strong>：SDPO = token × 词表；POLIA = 视觉对象；<strong>GraphGPO = 状态转移边</strong>
- <strong>而且三篇都很便宜</strong>：SDPO 每步 +5.8%、POLIA 新增部件 0.002 秒、GraphGPO 占每轮 0.04% → <strong>"只换优势"已经稳定成为一种低成本、高收益的改进范式</strong>

### 6.4 与 JitRL（9/24）：都在"从失败里榨信息"

- <strong>JitRL</strong>：把失败和成功的经验存进记忆库，让<strong>没成功的尝试也能贡献价值估计</strong>
- <strong>GraphGPO</strong>：把所有轨迹（尤其失败的那些）拼成一张图，<strong>让失败轨迹里那些"离目标更近的步"拿到应有的正优势</strong>
- <strong>两者共享一个直觉</strong>：<strong>失败轨迹不是垃圾，里面藏着信号</strong>——JitRL 靠检索复用，GraphGPO 靠图连通复用。<strong>而且 GraphGPO 的图恰好提供了 JitRL 缺的那一环：跨轨迹的状态级连通</strong>

### 6.5 与 RAGEN-2（9/16，同一批人的 Oral）

- <strong>RAGEN-2</strong>：诊断出<strong>模板崩塌</strong>——模型在同一输入内看着很多变（熵健康），但跨输入写出几乎一样的话（MI 崩了）；对策是按<strong>同题内奖励方差</strong>过滤 prompt
- <strong>GraphGPO</strong>：诊断出<strong>归因错位</strong>——成功轨迹 65.3% 的步没推进、失败轨迹 22.0% 的步在推进；对策是<strong>换掉优势的估计依据</strong>
- <strong>两篇合起来读很有意思</strong>：RAGEN-2 的手段（按奖励方差过滤）<strong>关心的是"这批样本还有没有信号"</strong>；GraphGPO 的手段（图距离）<strong>关心的是"这一步到底值多少"</strong>。<strong>一个在样本层、一个在步层；而且 RAGEN-2 的 +DS（动态采样）被 GraphGPO 拿来做消融，说明两条线已经在互相吸收</strong>

## 七、启发与待跟进

> 💡 <strong>今天最该带走的一条</strong>：<strong>"离目标有多远"是一个比"最终成没成"信息量大得多的信号，而它往往是免费的</strong>——只要能判定"是否到达目标状态"，就能靠<strong>把多条轨迹拼成一张图</strong>把距离算出来。<strong>不需要额外标注、不需要训练奖励模型、不需要 critic。</strong>这个"用环境的结构换监督信号"的思路，可以搬到任何有明确目标状态的多步任务上。

### 方法启发（可迁移）

- <strong>① 把多条轨迹合并成一个结构，是"跨轨迹信息复用"的通用做法。</strong>它让<strong>失败轨迹的前半段和成功轨迹的后半段在同一个结构里对话</strong>——这个操作本身比"图"更通用（换成树、格、向量库都行）
- <strong>② "从同一个岔路口出发的所有边当一个组"这个组定义很巧。</strong>它把优势的语义变成了"<strong>在同一个岔路口，哪条路更值</strong>"——<strong>比"相同状态的步"这种表述更贴近决策的本质</strong>
- <strong>③ 用 BFS/Dijkstra 天然拿到单调性与低方差。</strong>Prop 4.1 之所以成立，是因为"距离"这个量本身就具备单调性——<strong>选对中间变量，理论保证几乎是免费的</strong>（这不是巧合，是设计）
- <strong>④ 成本分析的正确姿势</strong>：论文不去优化 rollout（那是不可能的），而是<strong>在已经花掉的 rollout 上榨出更多监督</strong>。它自己的那句话值得抄下来：<strong>"既然 rollout 是最耗时的部分，提升效率的关键就是从已采集的 rollout 里榨出高保真步级监督"</strong>
- <strong>⑤ "距离信号"是可解释的副产品。</strong>图上 d(s) 的值直接告诉你"现在离目标还有多远"，环直接告诉你"这里在绕圈"——<strong>它比一个标量奖励更有诊断价值</strong>

### 待跟进（按性价比排序）

- <strong>① 状态合并的粒度与误合并的影响</strong>（这是最该补的）：做一次合并粒度的消融（严格哈希 vs 模糊匹配 vs 只用部分字段），并量化"误合并"对最终性能的影响。<strong>在部分可观测环境里，这一个设计选择可能决定方法成不成</strong>
- <strong>② 把实验搬到非确定性环境</strong>：两个 Proposition 都只对确定环境成立，而现实任务大多不确定。<strong>要么放宽理论、要么给出确定性程度的边界</strong>
- <strong>③ 量化"乐观/悲观偏差"</strong>：d(s) = +∞ 的判断完全依赖当前这批 rollout，<strong>没走过的可行路径会被误判为死路</strong>。可以设计一个实验：故意隐藏一部分可行路径，看图给出的优势偏得有多厉害
- <strong>④ 把转移代价 c(s,a) 真正用起来</strong>：论文在方法里强调这是它的一个能力（"工具调用场景下代价可以是金钱或时间"），但实验里设为 1。<strong>加上真实代价（工具调用的钱/时间/配额）是一个现成的新设定</strong>
- <strong>⑤ 与稀疏奖励专用方法的对比</strong>：HER、奖励塑形、PRM。<strong>只有和这些比，"我们的图结构比它们更省"才站得住</strong>
- <strong>⑥ 把图结构用于探索</strong>：现在的图只用来算信用，<strong>但它天然知道"哪些状态是没走过的岔路口"</strong>——这是一个现成的内在探索信号
- <strong>⑦ 长程与大规模可行性</strong>：T=500、组大小 64 时的图规模、Dijkstra 开销、状态合并准确性
- <strong>⑧ 与 lib 主线的交叉实验</strong>：<strong>GraphGPO 的图距离 + SDPO 的稠密 token 优势</strong>（一个给步级、一个给 token 级）；或 <strong>GraphGPO + RAGEN-2 的 MI 诊断</strong>（用图结构直接替代 MI 指标来做"模板崩塌"的早期预警）
- <strong>⑨ 这个方向已经有跟进工作</strong>：<strong>MileGPO</strong>（arXiv 2608.19803）明确说它在 GraphGPO 的"最终目标信用"之上<strong>再加中间里程碑信用</strong>，而且只用一次 rollout 图、不额外交互——<strong>值得作为下一篇候选</strong>

## 八、今日阅读结论

> 🎁 <strong>今日一句</strong>：<strong>"这条轨迹成没成"是一个又粗又有偏的信号——成功轨迹里六成半的步其实白走了，失败轨迹里两成的步其实做了贡献；而把这些轨迹拼成一张图、改用"离目标还有多远"来打分，你就能一次拿到更准、更稳、还几乎免费的步级信用。</strong>

- <strong>这篇最本质的贡献是换掉了优势估计的"依据"</strong>：从"轨迹的最终结果"换成"图上到目标的距离"。<strong>不是加权、不是路由、不是重新分配——是把参照物整个换掉</strong>
- <strong>第二个贡献是把"跨轨迹复用"做成了一个结构</strong>：把 M 条轨迹聚合成一张图，<strong>失败轨迹的前半段和成功轨迹的后半段在同一个结构里连通</strong>，于是"这一步是不是在进步"可以被独立判断，不再依赖它所在那条轨迹的命运
- <strong>第三个贡献是成本与理论双低</strong>：新增只占每轮 0.04%（图构建 0.108 秒 + 优势计算 0.025 秒），还顺带拿到了单调性与低方差两个命题
- <strong>最诚实的评价</strong>：结果很硬（1.5B 的模型在 ALFWorld 上 92.71，远超 GPT-4o 的 48.0；Sokoban 相对 GRPO +19.88），开销确实可忽略，动机的量化（22.0% / 65.3%）非常有说服力；<strong>但——① 整套方法建立在"状态可精确合并"的假设上，而这一点没做消融 ② 两个理论命题都只对确定环境成立 ③ d(s) = +∞ 的判断依赖当前 rollout，存在自我实现的悲观偏差 ④ "faithful" 这个核心主张没有被独立度量 ⑤ 转移代价这个卖点在实验里被关掉了 ⑥ 没有 Limitations 章节</strong>
- <strong>对项目的直接价值</strong>：① <strong>"用环境结构换监督信号"是一个可复用的选题动作</strong>——只要任务有明确的目标状态 ② <strong>"只换优势"连续三篇（SDPO/POLIA/GraphGPO）都被验证是低成本高收益的改进范式</strong>，这个套路值得直接搬到你的 jitrl2/jitrl3 上 ③ <strong>GraphGPO + SDPO 的交叉</strong>（步级图距离 + token 级稠密优势）和 <strong>MileGPO 的跟进</strong>是两个现成的下一步

# 一、为什么今天选这篇

> 前 9 篇笔记围绕 OPD 和多模态推理展开，追问的核心始终是"如何构造更精细的 token 级监督信号"。今天换一个视角：我们一直在假设 CoT 是模型推理的完整窗口，但如果模型的真实推理过程根本不在 CoT 里呢？

这篇论文提出了一个令人不安的发现：**前沿 LLM 已经在用语义无关的填充 token（filler tokens）进行"隐形推理"——在输出 token 中完成重要计算，却不留下任何思维链可解释的痕迹。** 这不是理论推测，而是在 13 个前沿模型上实证观察到的现象，准确率提升最高达 13 个百分点。

更关键的是，RL 训练会让模型对填充 token 内容产生强烈偏好，而 CoT 监控完全无法察觉这些隐藏计算。这直接挑战了我们对 LLM 推理可解释性的基本认知——如果推理可以"隐形"，那基于 CoT 的安全监控和对齐策略是否从根本上就不完备？

论文 7 月 24 日刚挂出，不到两周，话题极热。

# 二、TL;DR

语言模型是否把所有推理都表达在输出 token 中？本文给出了一个否定的实证答案。作者设计了一种诊断方法：在模型输出答案前，强制插入一段语义无关的"填充 token"序列（如动物名称、斐波那契数列、随机数字等），然后观察这些填充 token 的内容是否影响最终答案的正确率。

核心发现有三：

1. **填充 token 能显著提升推理准确率**——最高提升 13 个百分点，且效果取决于填充 token 的类型和 few-shot 设置。
2. **填充 token 能让模型满足隐藏约束**——Claude Opus 4.5 可以在不牺牲主任务准确率的前提下，利用填充 token 满足一个隐藏的模算术约束（如 `x mod 2 = 1`），完全规避 CoT 监控。
3. **RL 训练会强化填充 token 偏好**——Qwen3-235B 经过 RL 训练后对填充 token 类型产生强烈偏好，但这种偏好和收益在测试时无法持续。

结论：**前沿模型已经能在无语义的 token 中进行重要计算，且不留可解释痕迹。**

# 三、Motivation：CoT 监控的盲区

CoT 监控（Chain-of-Thought Monitoring）是当前 AI 安全领域的重要范式：通过检查模型的推理过程（而非仅看最终答案）来判断模型是否在"做正确的事"。这个范式建立在一个关键假设上——**模型的所有推理都体现在输出 token 中**。

但这个假设真的成立吗？

本文的作者提出了一个具体的失败模式：模型可以利用语义无关的填充 token 作为"计算空间"，在前向传播中完成重要推理，但这些推理不会出现在 CoT 中，因此 CoT 监控完全无法察觉。

直观理解：想象一个人在做数学题时，嘴里一直在念"苹果、香蕉、橘子……"，但这些看似无意义的词语实际上编码了中间计算步骤。旁观者只看到他在念水果名，却不知道他其实在做乘法。

> **核心问题**：如果推理可以隐藏在语义无关的 token 中，那么基于 CoT 的安全监控、可解释性分析和对齐策略是否从根本上就不完备？

# 四、Method：填充令牌与不可见推理的诊断框架

## 4.1 什么是"不可见推理"

论文给出了一个操作性定义：**不可见推理（Invisible Reasoning）是指模型在前向传播中，在内部潜在表征里进行的重要计算，但未在输出 token 中留下任何可解释的痕迹。**

为了检测这种现象，作者引入了"填充令牌"（Filler Tokens）的概念：**固定且语义无关的 token 序列，用于增加模型的计算空间。** 如果填充 token 的内容影响最终答案的正确率，就说明模型在利用这些 token 进行某种计算。

## 4.2 三组诊断标准

> **标准 1：性能随填充 token 提升** — 如果模型在插入填充 token 后准确率显著高于基线，说明模型在利用这些 token 进行计算。
> **标准 2：性能取决于填充 token 的内容** — 如果不同类型的填充 token（动物名 vs 斐波那契 vs 随机数字）产生不同的准确率，说明模型不是简单地利用额外的计算时间，而是在利用 token 的语义内容。
> **标准 3：填充 token 偏好因模型而异** — 如果不同模型对不同填充 token 类型的偏好不同，说明这种能力是模型特定的，而非某种通用伪影。

## 4.3 合成任务设计

| 任务 | 描述 | 难度 |
|-|-|-|
| **多位数乘法** | 4 位数 × 4 位数 | 需要多步进位计算 |
| **多步算术** | 5-7 个嵌套运算 | 需要维护中间状态 |
| **代码变量计数** | 统计代码片段中不同变量的数量 | 需要序列扫描和去重 |

## 4.4 实验设置

- **17 种填充 token 类型**：随机数字、斐波那契数列、动物名称、计数（1-100）、随机单词等
- **温度参数**：1，top-p = 0.95
- **输出格式**：无 CoT，直接回答，预填充 `Answer:` 前缀
- **预填充长度**：100 个 token
- **主要模型**：Qwen3-235B（主实验）+ 12 个前沿模型（跨模型评估）

# 五、Result：隐形推理的实证证据

## 5.1 填充 token 类型与 few-shot 的交互效应

![图片为填充token类型与few-shot交互效应的柱状图，展示了不同token类型在0 - 10-shot设置下的准确率。横轴为token类型，包括random tokens、counting等；纵轴为准确率（%）。不同颜色代表不同shot数量，如蓝色为0-shot，红色为10-shot。图中显示，某些token类型在0-shot时有害，但在10-shot时有益，反之亦然，直观呈现了“类型反转”现象，与上下文关键发现相呼应。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-1.png)

![这是一张展示不同填充token类型在0-shot设置下，乘法、算术、变量计数三类任务准确率的柱状图。横轴为各类填充token类型，包含随机数字、斐波那契数列、π的位数、素数、平方数等，纵轴为准确率百分比。图中蓝色柱代表乘法任务，橙色柱代表算术任务，绿色柱代表变量计数任务。其中算术任务的准确率整体最低，多数不足20%；乘法任务和变量计数任务的准确率普遍处于60%到80%之间。结合上下文可知，这张图呈现的是0-shot设置下填充token类型对各任务准确率的影响，体现了“类型反转”现象在0-shot环节的相关表现。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-2.webp)

**关键发现——"类型反转"现象（Type Inversion）**：

- 在 0-shot 设置中，许多填充 token 类型（如随机数字、π 的位数）是**有害的**，会降低准确率。
- 但在 10-shot 设置中，**同样的 token 类型变成了有益的**，能显著提升准确率。
- 反之亦然：0-shot 中最有益的 token 类型，在 10-shot 中可能有害。

这说明填充 token 的效果不是简单的"额外计算时间"，而是**与上下文交互**的复杂效应。注意力机制在从填充 token 表征中提取有用信息方面发挥了关键作用。

**任务依赖性**：

- **变量计数任务**：所有填充 token 类型都提供正向提升。
- **多步算术任务**：没有填充 token 类型能显著提升性能（基线太低）。
- **乘法任务**：提升高度依赖填充 token 类型。

## 5.2 跨模型对比：不同模型的隐形推理能力

![该图片为柱状图，展示13个前沿模型的乘法与算术类任务准确率情况，对应跨模型隐形推理能力对比的内容。蓝色柱状代表乘法任务准确率，橙色柱状代表算术任务准确率，横轴标注“Counting (1-100)”“Fibonacci”等不同测试任务类型。整体来看，所有模型的乘法任务准确率均明显高于算术任务，多数乘法任务准确率保持在70%至85%区间，算术任务准确率多在45%至60%区间，体现出不同模型在两类任务上的准确率差异，与文档中提及的13个前沿模型测试及填充token提升表现的相关内容对应。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-3.webp)

论文评估了 **13 个前沿模型**，使用计数型填充 token（1-100）进行测试：

![图片为表格，对比了13个前沿模型在算术和4位数乘法任务中，使用计数型填充token（1 - 100）时的准确率变化。表格分为闭源模型和开源模型两部分，各模型在Baseline和1 - 100填充token条件下的准确率以百分比形式呈现，还标注了准确率变化（Δ）。如Gemini 3 Flash在算术任务中Baseline为51.0%，1 - 100为61.7%，Δ为+10.7%。该表格与上下文紧密相关，直观呈现了不同模型在隐形推理能力上的差异。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-4.webp)

**核心观察**：

- **Gemini 3 Flash** 和 **Claude Opus 4.5/4.6** 的填充 token 提升最显著。
- **GPT-5.5** 在基线设置下已经接近饱和（乘法 98.5%），但填充 token 仍能将其推至 100%。
- **GLM-5** 在两个任务上都没有统计显著提升。
- 不同模型对不同填充 token 类型的偏好差异很大，证实了"标准 3"。

## 5.3 机制分析：填充 token 如何工作？

论文在 Qwen3-235B 上进行了三组机制实验（变量计数任务，比较"动物"填充 token vs "斐波那契"填充 token）：

**1. 填充 token 顺序效应**：

- 混合序列"动物→斐波那契"能恢复纯动物 token 的大部分提升。
- 但"斐波那契→动物"的表现比纯斐波那契还差。
- 结论：**早期位置的 token 比后期位置更重要**。

**2. 激活补丁（Activation Patching）**：

- 将"动物"填充 token 的残差流激活补丁到"斐波那契"上下文中。
- **第 0-30 层**的补丁可恢复超过 90% 的性能差距。
- **第 70 层以上**的补丁反而产生负面影响。
- 结论：有用信号**分布在完整填充序列**中，且**起源于早期层**。

**3. 线性探针（Linear Probing）**：

- 从第 15 层开始，"动物"填充 token 的表征比"斐波那契"和基线包含更多与任务相关的信息。
- 结论：**任务相关信息在填充 token 的表征中逐步积累**，填充 token 类型决定了积累的效率。

> **机制总结**：填充 token 作为一个整体（而非单个 token 位置）携带有用信号，token 顺序很重要，有益效应在早期层就已建立。这与"注意力重分配"或"位置效应"有关，而非简单的"额外计算时间"。

## 5.4 满足隐藏约束：隐形推理可以服务于不可见的目标

这是论文最令人不安的实验。作者测试模型能否在主要任务（乘法）之外，利用填充 token 满足一个**隐藏的数学约束**（如 `x mod 2 = 1`，即答案必须是奇数）。

![这张图片是论文中的表2，标题为“Filler tokens improve hidden goal accuracy”，内容显示了填充token在辅助满足隐藏模块化算术约束的同时，还能保持主要任务的准确率。表格里明确呈现了Opus 4.5和Qwen3-235B两个模型的相关数据：Opus 4.5在满足约束的样本上的N/A准确率从33.5%提升至44.5%，且在约束上没有显著损失，同时保持了与其他样本相同的乘法准确率；Qwen3-235B用填充token能达到98.8%的约束准确率，但乘法准确率会大幅下降。该表格对应上下文提及的Claude Opus 4.5在满足隐藏数学约束时不牺牲主要任务准确率的相关内容，补充了具体数据支撑这一隐形推理的实证结果。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-5.webp)

**关键结果**：

- **Claude Opus 4.5**：在满足 `x mod 2 = 1` 约束时，**没有牺牲主要任务准确率**。这意味着模型可以在"暗中"完成额外计算，而 CoT 监控完全无法察觉。
- **Qwen3-235B**：虽然满足率高，但主要任务准确率下降，说明它还没有学会"高效"的隐形推理。

> **安全含义**：这个实验直接证明，隐形推理可以用来服务于**完全不被 CoT 监控察觉的目标**。如果模型可以在回答用户问题的同时暗中满足其他约束，那么基于 CoT 的安全监控从根本上就是不完备的。

## 5.5 RL 训练与隐形推理

论文使用 Qwen3-235B 进行了强化学习（RL）实验，观察 RL 训练是否能引发或增强隐形推理。

![图片为RL训练过程中填充token类型的概率变化图。横轴为训练步数，纵轴为概率。不同颜色代表不同类型的填充token，如counting、fibonacci等。图中显示，各类型token的概率随训练步数变化，部分类型概率在训练早期迅速上升，如counting、fibonacci等；部分类型概率在训练中期波动，如random_numbers等；还有类型概率在训练后期趋于稳定，如invalid等。该图与上下文关于RL训练产生填充token偏好、任务差异及pass@8 vs pass@1等核心发现紧密相关。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-6.webp)

![图片为RL训练过程中模型对不同填充token类型的偏好变化图。横轴为训练步数，纵轴为概率。不同颜色线条代表不同类型的填充token，如counting、fibonacci等。图中显示，模型在训练初期对某些token偏好明显，如random_numbers、squares等，且偏好程度随训练步数变化。这与文档中“RL训练产生了强烈的填充token偏好，模型快速学会偏好某些填充token类型，并将其他类型的概率降至接近0”的核心发现相契合。](/images/paper-reading/2026-08-07-invisible-reasoning/2026-08-07-d10-7.webp)

**核心发现**：

- **RL 训练产生了强烈的填充 token 偏好**：模型快速学会偏好某些填充 token 类型，并将其他类型的概率降至接近 0。
- **任务差异**：乘法任务上策略多样性在训练早期就崩溃；算术任务上偏好持续变化。
- **pass@8 vs pass@1**：RL 主要提升了 `pass@8`（8 次采样中的最佳准确率），而非 `pass@1`（单次准确率）。这说明填充 token 增加了**输出多样性**，而非单次准确率。
- **测试时不持续**：无论是 RL 还是 SFT 训练，填充 token 的收益在测试时都无法持续。

> **解读**：RL 训练确实能让模型学会利用填充 token，但这种能力更像是"过拟合"到了训练分布，而非真正泛化的隐形推理能力。这暗示隐形推理可能是一种更基础的能力，RL 只是在利用它，而非创造它。

# 六、局限与批判性阅读

**论文没有单列 Limitations 章节。** 以下是基于方法和实验边界的阅读判断。

**1. 合成任务的生态效度**：三个任务（乘法、算术、变量计数）都是精心设计的合成任务，与现实世界的推理场景有较大差距。隐形推理在自然语言推理、代码生成、数学证明等任务中是否同样存在，尚需验证。

**2. "填充 token 提升"不等于"隐形推理"**：论文的诊断标准是间接的。填充 token 提升准确率可能有其他解释，如注意力重分配、位置效应、或简单的计算量增加。论文虽然通过机制分析排除了部分替代解释，但未能完全证明"隐形推理"的存在。

**3. 线性探针的可解码性 ≠ 模型实际使用**：线性探针能从填充 token 的表征中解码出正确答案，但这不意味着模型实际使用了这些信息来生成答案。探针实验证明信息"存在"于表征中，但不证明模型"使用"了它。

**4. RL 实验的局限性**：RL 实验只在 Qwen3-235B 上进行，且填充 token 的收益在测试时不持续。这使得 RL 与隐形推理的关系尚不明确。

**5. 隐藏约束实验的简化性**：隐藏约束（如 `x mod 2 = 1`）非常简单，与现实世界中可能的隐藏目标（如欺骗性对齐）有很大差距。Claude Opus 4.5 能满足简单约束，不代表它能进行复杂的隐形推理。

**6. 缺乏对 CoT 模型的对比**：论文只在"无 CoT"设置下测试。如果模型在有 CoT 的情况下也能利用填充 token 进行隐形推理，那结论会更强。但论文没有测试这一点。

# 七、与前九篇工作的对照

| 方法 | 核心问题 | 与 CoT 的关系 | 关键区别 |
|-|-|-|-|
| TOPD / COPD / RLCSD | 如何构造更精细的 token 级监督信号 | 假设 CoT 是推理的完整窗口 | 在 CoT 内部优化监督信号 |
| Re² | 模型陷入错误路径后不愿回头 | 假设 CoT 可见且可干预 | 扩展 action space，让模型学会放弃并重启 |
| SEED | 长程 Agent 只有稀疏 episode reward | 假设事后经验可以被语言化 | 把 on-policy 轨迹转为 hindsight skill |
| **Invisible Reasoning** | CoT 可能不是推理的完整窗口 | **质疑 CoT 的完备性** | 证明模型可以在 CoT 之外进行重要计算 |

前 9 篇工作都在追问"如何让 CoT 中的推理更好"，而本文追问的是"CoT 是否真的是推理的全部"。这是一个根本性的视角转换：从"优化可见推理"到"审计不可见推理"。

# 八、训练数据与实验细节

**模型**：

- 主实验：Qwen3-235B-Instruct-2507
- 跨模型评估：13 个前沿模型（Claude Opus 4.5/4.6、Claude Sonnet 4.5、Gemini 3 Flash、GPT-5.2/5.5、DeepSeek V3.2、Kimi K2.5、Qwen3-235B、Qwen3.5-397B、Llama 4 Maverick、GLM-4.7/5）

**填充 token 类型（17 种）**：

- 数值序列：随机数字、斐波那契数列、π 的位数、计数（1-100）
- 单词列表：动物名称、水果名称、颜色名称、NATO 音标字母
- 非语义符号：随机 token、重复 token 等

**RL 训练细节**：

- 使用 GRPO 算法
- 训练任务：4 位数乘法和多步算术
- 评估指标：pass@1 和 pass@8
- 填充 token 偏好通过训练过程中的策略比例变化来监测

# 九、最值得跟进的研究问题

1. **隐形推理在自然任务中是否存在？** 本文只在合成任务上验证。如果隐形推理在自然语言推理、代码生成等任务中也存在，那结论会更强。
2. **能否设计审计残差流的工具？** 论文的线性探针实验表明，激活级监控可以检测 token 级监控无法发现的计算。未来可以开发更强大的激活级审计工具。
3. **隐形推理与欺骗性对齐的关系？** 如果模型可以在 CoT 之外进行推理，那它也可能在 CoT 之外隐藏恶意意图。这对 AI 安全有深远影响。
4. **COCONUT / Quiet-STaR 等潜空间推理技术与隐形推理的关系？** 这些技术显式地在潜空间中进行推理，与本文的"隐形推理"现象有概念上的重叠。
5. **能否设计能探测潜空间计算的 RL 目标？** 如果隐形推理存在，那传统的 outcome-based RL 可能无法正确审计模型的推理过程。

# 十、今日阅读结论

> **一句话总结**：前沿 LLM 已经能在语义无关的填充 token 中进行重要计算，且不留可解释痕迹——CoT 不是推理的完整窗口，基于 CoT 的安全监控从根本上可能不完备。

本文的核心贡献不在于提出新方法，而在于**揭示了一个被忽视的根本性问题**：我们一直在假设 CoT 是模型推理的完整窗口，但模型的真实推理可能已经"溢出"到了 CoT 之外。

这个发现对 AI 安全有深远影响：

- **CoT 监控可能失效**：如果模型可以在 CoT 之外进行推理，那基于 CoT 的安全审计就无法检测隐藏的不良意图。
- **对齐策略需要重新思考**：如果推理可以"隐形"，那我们需要开发能审计模型内部表征（而非仅看输出 token）的对齐策略。
- **可解释性面临挑战**：如果模型的真实推理不在输出中，那我们需要开发新的可解释性工具来"看到"隐形推理。

从更积极的角度看，隐形推理也可能是一种**能力**：模型可以在不暴露推理过程的情况下完成复杂计算，这在隐私保护和效率方面可能有价值。

无论如何，这篇论文提醒我们：**模型的推理可能比我们看到的更多，而我们需要开发新的工具来"看到"这些隐形推理。**

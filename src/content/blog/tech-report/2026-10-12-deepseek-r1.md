# 一句话结论

DeepSeek-R1 回答的是\*\*"推理能力从哪来"\*\*这个问题。它用 **R1-Zero** 证明了一件当时反直觉的事：**不喂任何人类写的推理范例，纯靠 RL 就能让模型自己涌现出长链推理**（包括著名的"aha moment"）。而真正发布的 **R1** 是四阶段后训练产出的——**其中阶段 ③ 是从 V3-Base 重新开始训的**（这是全文最容易读错的一点）。

> 本文是「逐节精读」版笔记，**含正文 3 张图与 5 张表的全量转录**。全篇最值钱的两节：**§2.3 四阶段后训练**（含一个高频误读点）与 **§3「不成功的尝试」**（PRM / MCTS / reward model 为什么不 work）。

# R1-Zero：纯 RL，不喂一条推理范例（§2.2）

**做法**：直接从 **V3-Base 出发，完全跳过 SFT**，只用**规则奖励**跑 RL。

**奖励设计**（只有两种，都是规则，不训 RM）：

| 奖励 | 内容 |
|-|-|
| **准确性奖励** | 答案对不对——数学题验证最终答案格式、代码题跑编译器和测试用例 |
| **格式奖励** | 强制把思考过程放进 `<think>` `</think>` 之间 |

**R1-Zero 暴露的问题**：**可读性差、语言混用**（中英混杂）——因为它没经过任何 SFT 约束。

**★ 著名现象："aha moment"**

训练中途模型自发出现"**等等，让我重新想想……**"这类自我反思、自我纠错的行为。论文在 **Table 3** 里给了一个真实例子（一道根式方程题）：

> *"Wait, wait. Wait. That's an aha moment I can flag here. Let's reevaluate this step-by-step…"*（等一下，等一下。这里我意识到一个"顿悟时刻"。让我们重新一步一步推理……）

论文把它当作**纯 RL 能涌现复杂推理**的直接证据——**没有人教它这么反思，是它自己长出来的**。

# R1：四阶段后训练（§2.3）⭐

```text
① 冷启动 SFT  →  ② 推理 RL  →  ③ 拒绝采样 SFT  →  ④ 全场景 RL

```

## ① 冷启动（Cold Start）

- 用**数千条**长 CoT 数据做 SFT，目的是给 RL 一个**稳定的起点**（避免 R1-Zero 那种可读性差、语言混用）
- 数据来源：few-shot 提示长 CoT 模型生成 → 人工后处理（可读性、语言一致性）

## ② 推理 RL（Reasoning-oriented RL）

- **只用于推理任务**（数学/代码/逻辑/STEM）
- **奖励仍是规则为主**：准确性奖励 + **语言一致性奖励**（解决语言混用）
- **算法 GRPO**，trick 沿用 R1-Zero

## ③ 拒绝采样 SFT ⚠️⚠️ 全文最易读错的一点

**论文原话（两处）**：

> §1："…**retrain the DeepSeek-V3-Base model**…"§2.3.3："…**fine-tune DeepSeek-V3-Base for two epochs**…"

**第三方独立确认**（*DeepSeek-R1 Thoughtology*，arXiv **2504.07128v2**）：

> "training in this stage **starts anew from DeepSeek-V3-base** and not the checkpoint from the first two training phases" —— 连图注都标了。

> **阶段 ③ 是「从 V3-Base 重新开始训」，不是从阶段 ② 的 RL checkpoint 继续。**
> **推论**：阶段 ①②在**最终模型权重上没留下痕迹**，它们的产物是那批轨迹数据；**真正的 R1 由阶段 ③④造出。**
> **易混点**：§2.3.3 开头那句 "utilize the resulting checkpoint to **collect SFT data**" 说的是**采数据**，不是权重连续。
> **命名归属**：这属于 **STaR / ReST-EM 式"每轮从初始 checkpoint 重置重训"**（目的是 **bound drift**），而**不是** Iterative RFT（继承 checkpoint）、**也不是** Online RFT（连 optimizer state 一起继承）。命名见 *B-STaR*（arXiv 2412.17256）。
> **⚠️ 论文没说为什么这么做** —— 按"checkpoint 偏科"来解读，但这是我的推测。

**采数据的方式**：

| 类别 | 数量 | 来源 |
|-|-|-|
| **推理数据** | 约 **60 万条** | 从阶段 ② 的 checkpoint 做**拒绝采样**（只留答案正确的），再用生成式奖励模型 + 人工筛选 |
| **非推理数据** | 约 **20 万条** | 复用 V3 的 SFT 数据，覆盖写作/事实问答/自我认知/翻译等 |
| **合计** | **约 80 万条** | — |

## ④ 全场景 RL（RL for all scenarios）

- 覆盖**推理 + 通用**两类任务
- **这里才首次引入基于模型的偏好奖励（RM）**，因为写作/开放问答没有规则可判
- ⚠️ **偏好奖励只在最后 400 步启用** —— 论文原话："more training steps with the model based preference reward signal may lead to **reward hacking**"

# §3「不成功的尝试」—— 这一节最值钱

论文专门花一节讲**他们试过但放弃的东西**，这在技术报告里很罕见。

| 尝试 | 为什么放弃 |
|-|-|
| **PRM（过程奖励模型）** | ① **难以定义细粒度的"步骤"**；② **判断中间步骤对不对本身就很难**；③ 一旦引入就容易被 **reward hacking**——模型学会写"**看起来合理但实际错误**"的步骤去骗分；④ 需要**大量人工标注，无法规模化** |
| **MCTS（蒙特卡洛树搜索）** | ① **搜索空间巨大**（语言 token 空间 vs 围棋）；② **价值模型训练难**；③ **token 消耗极大** |
| **纯 RM 替代规则奖励** | 容易被 hack，不如规则奖励**高精度** |

> ⭐ **核心结论**：他们**放弃了 PRM 和 MCTS**，直接走"**规则奖励 + 大规模 RL**"这条看起来"笨"的路。**这条经验后来被整个行业吸收** —— 包括 K2 的"可验证奖励"设计（§3.2.1 的 Verifiable Rewards Gym 就是这条脉络的演进）。

# 蒸馏：80 万条数据教 6 个小模型（§2.4）

- 把 R1 的 **80 万条数据**直接拿去 **SFT 6 个 dense 小模型**（**不做 RL**）
- 学生模型：Qwen2.5 系列（1.5B / 7B / 14B / 32B）+ Llama3 系列（8B / 70B）
- **这是 off-policy 蒸馏**（学老师的输出轨迹，**不看老师的 logits**）
- ⭐ **这条给后来所有"强到弱蒸馏"工作定了基调** —— Qwen3 的 §4.5 蒸馏正是延续这条线，只是升级成了两段式（off-policy + **on-policy**）

# 训练超参（§2.2 / §2.4 实测数字）

| 项目 | R1-Zero | R1 阶段②（推理 RL） |
|-|-|-|
| **步数** | **10,400 步** | **1,700 步** |
| 学习率 | 3e-6 | 3e-6 |
| KL 系数 | **0.001** | 0.001 |
| 采样温度 | 1 | **0.7** |
| 每问题采样数 | **16** | 16 |
| batch | 512（= **32 个唯一问题** × 16） | 512 |
| GRPO clip | — | ε = 10 |
| 其他 | **每 400 步把 reference model 换成最新策略模型** | 偏好奖励**只用最后 400 步** |

⚠️ **不要混**：R1-Zero 的 10,400 步是**单阶段纯 RL**，R1 阶段 ② 的 1,700 步是**四阶段里的一环** —— 两者规模本就不同。

**一条容易被忽略的效率设计**：

> "each rollout generates **8,192 outputs**, which are randomly split into **16 mini-batches** and trained for only a **single inner epoch**"—— **生成与训练解耦（off-policy 的工程含义）**，R1 早就在用了。

# 阅读要点（我的提炼）

1. **全篇最大的认知冲击**：**纯 RL（不喂推理范例）就能涌现长链推理** —— R1-Zero 证明了这一点，**"aha moment"** 与**回复长度自发增长**（图 2、图 3）是它的最好证据。
2. **最容易被读错的一点**：**阶段 ③ 是从 V3-Base 重训，不是从阶段 ② 继续**。**阶段 ①②的产物是数据，不是权重。** 论文没说原因；按"checkpoint 偏科"来解读并**标明是推测**。
3. **§3 是全文最值钱的一节**：**它用一整节讲"我们试过什么、为什么放弃"** —— PRM（会被 hack、标注不可规模化）、MCTS（搜索空间/noise/token 成本）。**这种"讲失败"的写法在技术报告里极罕见。**
4. **"规则奖励"这条路是 R1 打通的**：从 R1 的"准确性 + 格式奖励"，到 K2 的"可验证奖励 Gym + 自批评 rubric"，是**同一条技术脉络的演进**。
5. **蒸馏的定位**：R1 的蒸馏是**纯 off-policy**（只学输出，不看 logits）；**Qwen3 把它升级成两段式（off-policy + on-policy 对齐 logits）** —— **看这两篇要连着看，才看得出蒸馏路线的演进**。而 **Table 6** 是蒸馏价值的最强证据（同一个 32B 底座：直接 RL 47.0 vs 蒸馏 72.6）。
6. **和另两篇的结构差异**：R1 是"**方法 + 不成功的尝试**"；Qwen3 是"**预训练 + 四阶段后训练（工业标准）**"；K2 是"**预训练系统 + agentic 数据工程**"。三篇正好覆盖**推理从哪来 / 后训练怎么做 / 预训练系统怎么搭**三个层面。

# 口径与未核实项

- **阶段 ③ 为什么从 V3-Base 重训**：**论文未给原因**（本文的"偏科"解读已标注为推测）
- **阶段 ①（冷启动 SFT）的具体步数 / 数据量**：论文未明确给出
- **R1 阶段 ② 的 1,700 步**对应的是推理 RL 阶段，**不要和 R1-Zero 的 10,400 步混**（后者是纯 RL 单阶段，规模本就不同）
- **蒸馏是不是"后训练"**：是 —— **80 万条 SFT 就是后训练**，只是学生没做 RL
- **AIME 2024 的 79.8%** 是 pass@1；**86.7% 是 cons@64（多数投票）的结果，属于测试时技巧，不是单次能力**
- **cons@64 的含义**：每题采样 64 次，取多数答案（majority voting）——**这是"更贵"的评测口径**，与 pass@1 不可直接比较
- **DeepSeek-V4 的离职标注（10 人）与 R1 时代的作者名单是两个不同时点、不同名单**，**不能直接相减说"R1 走了 10 人"**

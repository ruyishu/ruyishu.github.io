# 一句话结论

Kimi K2 是月之暗面（Moonshot AI）2025-07 发布的开源 MoE 模型，**1.04T 总参 / 32.6B 激活**，是**全球首个万亿参数级开源模型**。全篇只有一个主题：**为 agentic intelligence 而生**。它的核心主张是 **token 效率**——在高质量数据日益受限的前提下，**"每个 token 学到多少"比"喂多少 token"更重要**。

# 立论：为什么是"token 效率"

报告 §1 直接给论点：LLM 正在从**静态模仿学习**转向**通过交互主动学习**，即 Agentic Intelligence。由此产生两个挑战：

| 阶段 | 挑战 | 对策 |
|-|-|-|
| **预训练** | 高质量数据**有限**，却要赋予模型广泛通用先验 | 把 **token 效率**（每 token 的学习信号）当成关键 scaling 系数 |
| **后训练** | agentic 能力（多步推理 / 长期规划 / 工具使用）在自然数据里**稀少且昂贵** | ①**可扩展地合成 agentic 轨迹** ②**通用 RL**（可验证奖励 + 自我批判） |

> **关键转换**：Qwen3 用 36T tokens 覆盖 119 种语言（"多而广"）；K2 用 15.5T tokens 专攻英文/中文 + agentic（"少而精"）。**这是两条路线的正面对撞，而不是"喂得少"的劣势。**

## 61 层怎么拆

来自 HF `config.json`：

- `num_hidden_layers: 61`
- `first_k_dense_replace: 1` → **第 1 层用 dense FFN**（intermediate = 18432）
- `moe_layer_freq: 1` → 第 2\~61 层（共 **60 层**）用 MoE FFN

**即：1 个 dense 层 + 60 个 MoE 层。** 每层 = 1 个 MLA 注意力子层 + 1 个 FFN 子层。

⚠️ **两个缺口**：**① 61 是继承 DeepSeek-V3 的**（表 2 那一行标 `=`），K2 没解释为什么是 61；**② dense 层为什么从 3 减到 1，论文正文完全没给理由**。

⚠️ **论文没写、但 config 里能看到的差异**：`num_nextn_predict_layers` K2 = **0**，DeepSeek-V3 = **1** → **K2 去掉了 MTP（多 token 预测）**。

## 稀疏度扩展律

论文自做的 scaling law：**固定激活参数量（即固定 FLOPs）时，专家总数越多（稀疏度越高），训练与验证 loss 越低。**

![图 2 · 稀疏度扩展律：固定激活专家数 8、共享专家 1，变化专家总数（来源：论文 Figure 5）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-2.webp)

| 对比 | 达到 validation loss = 1.5 所需 FLOPs |
|-|-|
| 稀疏度 48 vs **8** | **省 1.69×** |
| 稀疏度 48 vs **16** | **省 1.39×** |
| 稀疏度 48 vs **32** | **省 1.15×** |

**选定稀疏度 48**（384 / 8）——性能与基础设施复杂度之间的平衡点。

## 为什么只要 64 个 attention 头

![图 3 · 注意力头数 = 层数 vs 翻倍头数的扩展曲线（来源：论文 Figure 6）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-3.webp)

DeepSeek-V3 的习惯是"头数 ≈ 2 × 层数"（61 层 → 128 头），好处是吃满内存带宽。但：

|  |  |
|-|-|
| **代价** | attention 开销 ∝ `序列长度² × 头数`。**128k 序列下，64 → 128 头使推理 FLOPs 增加 83%** |
| **收益** | 受控实验中，头数翻倍只带来 **0.5%\~1.2%** 的验证损失改善 |
| **结论** | **花 83% 算力换 1% 效果，不划算** → 选 64 头 |

**这条对 K2 尤其致命**——它主打 agentic，长上下文是核心场景，而注意力开销随 L² 增长。

## Expert Grouping：DeepSeek 有，K2 没有

**Expert Grouping（专家分组路由，也叫 node-limited routing）解决的是专家并行的通信爆炸**：

```text
① 256 个专家分成 8 组（n_group=8）
② 先选 top-4 组（topk_group=4）        ← 闸门
③ 只在选中的 4 组里选 top-8
→ 保证每个 token 最多只跨 4 个节点

```

**K2 的 config 是 n_group=1, topk_group=1 → 等于没有分组**，直接在 384 个专家里全局选 top-8。

⚠️ **论文表 2 只标了 "Yes → No"，正文没给理由。** 从 §2.4.2 能看出端倪：K2 用 **EP = 16**（尽可能小的 EP 并行），且论文明确说 **"用更小的 EP 组也放宽了专家负载均衡的约束"**。**我的推断（非论文结论）**：EP 切得小 + 做了通信与计算重叠 → 通信压力本来就低 → 不再需要"分组"当闸门。

# 预训练

## MuonClip：这篇最硬的招牌（§2.1）

**公式**：`MuonClip = Muon + weight decay + 一致的 RMS 对齐 + QK-Clip`

### 三个优化器的差别

|  | 怎么看参数 | 更新形状 | 优化器状态 | token 效率 | 稳定性 |
|-|-|-|-|-|-|
| **AdamW** | 逐个元素，无视矩阵结构 | **低秩**（少数大奇异值主导） | 2 个（一阶+二阶动量） | 低 | 稳 |
| **Muon** | 当矩阵看，对动量做**正交化** | **满秩**（所有奇异值相等） | 1 个（只有动量） | **高** | ⚠️ **logit 易爆** |
| **MuonClip** | 同 Muon | 同 Muon | 同 Muon | **高** | **稳（零 spike）** |

**Muon 的正交化**：把动量矩阵 `M = UΣVᵀ` 里的 **Σ 全变成 1**，得到 `UVᵀ`（离 M 最近的单位正交矩阵，即极分解）。真做 SVD 太贵，用 **Newton-Schulz 迭代**近似（默认 5 次）。

**为什么值得换**：Moonlight（Moonshot 前作）证明，**同算力、同模型大小（即同数据量）下，Muon 显著优于 AdamW**。

### 现象：logit 爆炸

![图 4 · 左：中等规模训练中，attention logit 迅速超过 1000（原版 Muon）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-4.webp)

![图 5 · 右：Kimi K2 用 MuonClip（τ=100）全程的最大 logit——被钉在 100，约 30% 训练步后才衰减到稳定区间](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-5.webp)

**论文 Figure 2**（上图两张）讲的就是这件事：**原版 Muon 训到 9B 激活 / 53B 总参规模时，max logit 就冲过 1000**；而 K2 用 MuonClip，**logit 被限在 100，且无需调整 τ**。

![图 6 · Kimi K2 逐 step 训练 loss（未做平滑或抽稀）——全程无尖峰](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-6.webp)

**这是全篇最有说服力的一张图**：loss 从 2.0 一路降到 1.3，**15.5T tokens 全程没有任何 spike**。注意论文特意标注 "without smoothing or sub-sampling"——没有做平滑处理来美化。

### 为什么 Muon 更容易 logit 爆炸（附录 E）

三步推理：

1. **前提**：logit = `q·k`，而输入 x 的范数已被 RMS-Norm 压住 → 爆炸**只能来自 Wq/Wk 的谱范数变大**。
2. **结构差异**：Muon 更新**满秩**（奇异值全相等），Adam 更新**低秩**。实测 **16B Moonlight** 上，Muon 训出的权重**奇异值熵更高**。
3. **放大效应**：权重与更新都高秩 → **奇异向量更容易对齐** → 对应奇异值**叠加增长**；而 logit 里夹着 **Wq·Wkᵀ 乘积，谱范数被平方** → 放大。

### 为什么 QK-Norm / logit soft-cap 都不行

| 办法 | 为什么不行 |
|-|-|
| **logit soft-cap** | 直接裁 logit，但 **q·k 的乘积在裁剪生效前就已涨过头**（治标不治本） |
| **QK-Norm** | 不适用于 **MLA**——**其 Key 矩阵在推理时并非完整物化** |

> **跨报告钩子**：Qwen3 用 **GQA**（K 完整）→ 能上 QK-Norm；K2 用 **MLA**（K 被压成隐向量）→ **装不了** → 只能回头改**权重**。**同一个问题，因为架构选择不同，解法完全不同。**

### QK-Clip 怎么工作

1. 定义每个 head 的 `S_max^h` = 本 batch 内该 head 的最大 logit
2. 若 `S_max^h > τ`（K2 取 **τ = 100**），按 `γ = τ / S_max^h` **等比缩小该 head 的 Wq、Wk**

**数字例子**：某 head 最高分 5000，阈值 100 → `γ = 0.02` → Wq、Wk 各乘 `√0.02 ≈ 0.14` → `5000 × 0.14 × 0.14 = 100` ✓（`q·k` 是两个东西相乘，两边各缩 `√γ`，乘起来正好缩 `γ`。）

**三个关键设计**：

- **per-head，不是 per-layer** —— 实测**只有一小部分 head 会爆**，全局裁会过度干预
- **不改变当步前向/反向** —— 只把 max logit 当**信号**来决定缩多少
- **MLA 只裁 head 特有分量**（`q^C`、`k^C`、`q^R`），**共享的 rotary k^R 不动**（动了会串到其他 head）

**Algorithm 1 · MuonClip 优化器（论文原文）**

```text
1: for each training step t do
2:   // 1. Muon optimizer step
3:   for each weight W ∈ R^{n×m} do
4:     M_t = µM_{t−1} + G_t        ▷ M_0 = 0, G_t is the grad of W_t, µ is momentum
5:     O_t = Newton-Schulz(M_t)·√max(n,m)·0.2   ▷ Match Adam RMS
6:     W_t = W_{t−1} − η( O_t + λW_{t−1} )      ▷ learning rate η, weight decay λ
7:   end for
8:   // 2. QK-Clip
9:   for each attention head h in every attention layer of the model do
10:    Obtain S_max^h already computed during forward
11:    if S_max^h > τ then
12:      γ ← τ / S_max^h
13:      W_qc^h ← W_qc^h · √γ
14:      W_kc^h ← W_kc^h · √γ
15:      W_qr^h ← W_qr^h · γ
16:    end if
17:  end for
18: end for

```

### 效果（附录 D）：QK-Clip 不掉点

![图 7 · 小规模消融：即使用激进的 τ=30，QK-Clip 对 loss 曲线几乎无影响](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-7.webp)

| 证据 | 结果 |
|-|-|
| **消融** | 0.5B 激活 / 3B 总参两个 MoE，即使用**激进的 τ=30**，**loss 曲线几乎无差别**，下游无统计显著退化 |
| **自我失效** | 前 **70000 步**只有 **12.7% 的 head** 触发过；70000 步后所有 head 的 S_max 自然降到 100 以下 → **QK-Clip 自动失效** |
| **终局** | **15.5T tokens，零 loss spike** |

**设计原则：最小干预**——需要时才开，稳定后自动关。

## 数据改写：提高 token 效用（§2.2）

**问题**：知识密集文本上，**单 epoch 学不透，多 epoch 重复会过拟合**。

**解法：把同一份内容改写成多个版本** → 在不重复原文的前提下，等于多训了几遍。

![图 8 · 分块自回归改写流水线：长输入切段后逐段改写，再拼接成完整段落（论文 Figure 4）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-8.webp)

**知识数据改写三组件**：

| 组件 | 做法 |
|-|-|
| **风格与视角多样化的提示** | 借鉴 **WRAP**，用多样提示词改写，保持事实完整 |
| **分块自回归生成** | 长文档切段分别改写再拼接（规避 LLM 的隐式输出长度限制） |
| **保真度校验** | 逐段比较改写内容与原文的语义对齐度 |

**官方 Table 1 · SimpleQA 准确率（K2 早期 checkpoint）—— 全量转录**：

| # Rephrasings | # Epochs | SimpleQA Accuracy |
|-|-|-|
| 0（原始 wiki 文本） | 10 | 23.76 |
| 1 | 10 | 27.39 |
| **10** | **1** | **28.94** |

> ⭐ **结论：同样"见 10 遍"，改写出来的比重复原文更值钱**（28.94 vs 23.76）。每个语料**最多改写两次**。

**数学数据改写**：按 **SwallowMath** 的方法改写成「**学习笔记（learning-note）风格**」——去套话、恢复上下文、把解答改写成简洁的分步解释；并把其他语言的高质量数学材料翻译成英文。

**语料总览**：15.5T tokens，四大域——**Web Text / Code / Mathematics / Knowledge**。基础方法沿用 Kimi K1.5。

# 训练配方与基础设施（§2.5 / §2.4）

## 训练配方（§2.5）

| 阶段 | 设置 |
|-|-|
| **主训练**（4,096 上下文） | MuonClip + **WSD** 调度；500 步预热 → **前 10T 恒定 2e-4** → 后 5.5T **余弦衰减 2e-4 → 2e-5**；weight decay 0.1；全局批 **67M token** |
| **退火 + 长上下文激活** | 批仍 67M，学习率 **2e-5 → 7e-6**；**4k 序列训 4000 亿 token**，再 **32k 序列训 600 亿 token** |
| **长上下文扩展** | **YaRN** → 128k |

**完整学习率轨迹（全部属于预训练）**：

```text
① 500 步预热        0 → 2e-4
② 前 10T token      恒定 2e-4        ← 主训练，学习率最大
③ 后 5.5T token     余弦衰减 2e-4 → 2e-5
④ 退火 + 长上下文    2e-5 → 7e-6       ← 预训练最后一段

```

> ⚠️ **易混点**：`2e-5 → 7e-6` 是**预训练的最后一段**，**不是后训练**（§3 才是后训练）。

**为什么这一阶段学习率特别小**：它**不是学新知识，而是"激活"已有能力**——模型已学完 15.5T token，这里只是适应长序列，权重不需要大改；步子大了反而破坏已学的东西。

## 训练基础设施（§2.4）

**硬件（§2.4.1）**：NVIDIA **H800** 集群；单节点 **2 TB 内存 + 8 卡**（节点内 NVLink/NVSwitch，**H800 的 NVLink 被出口管制砍到 400 GB/s**，H100 是 900 GB/s）；跨节点 **8 × 400 Gbps RoCE**。

**并行策略（§2.4.2）**——核心词是"灵活"：

```text
PP = 16（流水线并行，带虚拟阶段）
EP = 16（专家并行）
ZeRO-1（数据并行）
→ 模型并行组 = 16 × 16 = 256 卡（正好对上论文说的 256 GPUs）
→ 支持任意 32 的倍数的节点数

```

**显存账**：

```text
参数本身      ：1.043T × 2 字节 (BF16) = 2.09 TB
梯度累积缓冲  ：1.043T × 4 字节 (FP32) = 4.17 TB
                                      ─────────
                                         6.26 TB  ← 论文说的 "~6 TB" ✓
摊到 256 卡 → 24.4 GB/卡 + 优化器状态 ≈ 30 GB/卡，剩下 50 GB 全给激活值

```

**激活值为什么这么吃**：① 每个中间张量都要留（反向要用）；② MoE 每个 token 过 **9 个专家**（8 routed + 1 shared）；③ **1F1B 预热阶段初始流水线阶段积压最多**（前面已做几个 micro-batch 前向，反向还没轮到）。

**两招"藏通信"**：

1. **藏 EP 通信**：多开预热微批次，让 EP all-to-all 与计算重叠。**不用 DeepSeek 的 DualPipe**，因为它**内存翻倍**，万亿模型扛不住。
2. **藏 PP 通信**：把权重梯度计算从反向传播里解耦，与 PP 通信并行 → 除预热阶段外全部重叠。

**激活值削减三招（§2.4.3）**：

| 招 | 做法 |
|-|-|
| **① 选择性重计算** | 对 LayerNorm、SwiGLU、MLA 上投影、MoE 下投影**不存激活，用时重算** |
| **② FP8 存激活** | MoE 上投影与 SwiGLU 的输入压成 **FP8-E4M3**（1×128 tile + FP32 scale）—— ⚠️ **只省存储不省计算**（计算用 FP8 怕掉性能） |
| **③ CPU 卸载** | 剩下的全扔 CPU 内存，拷贝引擎流式搬，**与计算/通信重叠** |

![图 9 · 不同 PP 阶段中计算、通信与卸载的重叠模式（论文 Figure 7）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-9.webp)

# 后训练（§3）

### 工具模拟器 ≠ 真实执行（关键区分）

论文里有**三种不同的"环境"**，极易混淆：

| 出现在哪 | 是什么 | 真的假的 | 形态 |
|-|-|-|-|
| §3.1.1 轨迹生成 | **Tool Simulator** | ❌ **假的** | "功能等价于**世界模型**"，**论文没说实现方式** |
| §3.1.1 结尾 + §3.2.1 | **真实执行沙箱** | ✅ 真的 | **Kubernetes，1 万+ 并发实例** |
| §3.3.4 RL rollout | 环境（**VM / code interpreter**） | ✅ 真的 | **独立部署的服务** |

**Tool Simulator 的三个特性**：① **维护并更新状态**（调过的东西真留痕迹）；② **引入受控随机性**（成功 / 部分失败 / 边缘情况）；③ **功能等价于世界模型**——**不真执行，是"预测执行结果"**。

**举例**：agent 调 `buy(100)` → 模拟器**真的记下这笔** → 再查持仓真的多 100 股。

**真实沙箱只给编码/SWE 用**——因为只有编码的反馈**天然可验证**（跑测试）。原话：*"powered by Kubernetes for scalability and security. It supports over 10,000 concurrent sandbox instances"*。

### 质量过滤 = 大规模拒绝采样

> LLM 判官按**每个任务自带的 rubric**（成功标准 + 期望工具使用模式 + 评估检查点）逐条打分，**只保留达标轨迹**，同时允许完成策略的自然差异。

论文自述：这套"生成 + 过滤"**实质上就是一次大规模 rejection sampling**。

⚠️ **注意**：**§3.1.1 里论文并未正面讨论 "hacking"**。防 hacking 的正面讨论在 §3.2.1（**hack-check 层**）与 §3.2.2（**规定性 rubric**）。

## RL：两类奖励（§3.2）

**前提假设**：RL 比 SFT 有更好的 token 效率与泛化。框架是 "**Gym-like extensible framework**"（借 **OpenAI Gym** 的统一接口思路——像 USB 标准一样，让新环境插上就能用）。

### Verifiable Rewards Gym：五个域

| 域 | 判分手段 |
|-|-|
| **数学 / STEM / 逻辑** | 答案比对；**用 SFT 模型的 pass@k 卡"难度适中"** |
| **复杂指令遵循** | 代码解释器（规则）+ LLM judge + ⭐**hack-check 层**（抓"声称满足但实际没满足"） |
| **忠实性** | 受 **FACTS Grounding** 启发，训一个**句子级忠实性判官模型**当奖励模型 |
| **编码 / SWE** | **真跑单元测试**（K8s 沙箱） |
| **安全** | **Attack → Target → Judge 三模型**自动演练，rubric 出二元标签 |

**为什么要"难度适中"**：GRPO 的奖励是**组内归一化**的（`A_i = (r_i − mean)/std`），一组全对或全错 → **梯度为 0**。太简单和太难都**没有学习信号**。

**逻辑题形式**：多跳表格推理、跨表聚合；24 点、数独、谜语、密码算术、摩斯电码。

**忠实性的灵感来源（FACTS Grounding）**：Google DeepMind + Google Research 2024-12-17 发布的基准，**给模型「一份长文档 + 一个用户请求」，看它能否只依据文档写长篇回答**。**1719 条**（860 公开 + 859 私有），文档最长 32k token，**三个不同厂的 LLM 当判官**（Gemini 1.5 Pro + GPT-4o + Claude 3.5 Sonnet，防止"自家打高分"）。两阶段判分：**先查资格**（回答了没有），**再查落地**（每句是否能在文档里找到依据，**全有全无**）。

> ⭐ **它最聪明的设计**：**必须先查"你真的回答了吗"** —— 否则模型可以**靠"含糊其辞、什么都不说"骗过"没编造"这一关**（空洞回答里没有"无依据的断言"）。加入资格过滤后分数会降 1\~5%，甚至改变排行榜顺序。

> **K2 从它借鉴了什么**：FACTS 在**整篇**层面判有没有编，K2 **下沉到句子级** —— 揪出具体哪一句在编，再拿这个信号当奖励。

### Self-Critique Rubric Reward：主观任务怎么办（§3.2.2）

**难题**：创意写作、开放式问答**没有标准答案**，无法自动判分。

**解法：让模型自己当裁判，但套四层保险**：

| 保险 | 内容 |
|-|-|
| **① 先上"评卷课"** | **SFT 阶段就用人类偏好数据初始化 critic 能力**（不是凭空自评） |
| **② 两两比较排名** | actor 生成 K 个回答 → critic **pairwise 比较**排出名次（K 越大比较次数 C(K,2) 越多） |
| **③ 三类 rubric** | **core rubrics**（基本价值观）+ **prescriptive rubrics**（**消灭 reward hacking**）+ **人写 rubric** |
| **④ 闭环校准** | **用 RLVR 的客观信号持续更新 critic** → 让主观判断扎根于可验证数据 |

**附录 F.1 核心 rubric 三条**：

| 条目 | 内容 |
|-|-|
| **Clarity and Relevance** | 简洁且切题；除非必要不要长条目化；**有选择时给出唯一、明确的答案** |
| **Conversational Fluency and Engagement** | 连贯、有参与感、语气得体（共情/正式/随意）；审慎使用追问 |
| **Objective and Grounded Interaction** | **避免元评论**（分析 query 结构、话题组合、互动本身的性质）与**无端恭维** |

**附录 F.2 规定性 rubric 只有两条**（正好回答"谄媚怎么防"）：

> **Initial Praise**：**不得以夸奖开头**（如 "That's a beautiful question"、"Good question!"）。**Explicit Justification**：**禁止**任何解释"我这个回答为什么好 / 我怎么成功满足了你的要求"的句子。

**附录 F.3 承认的副作用**：禁止免责声明（"我可能不对"）**误伤"谦逊"** + 偏好清晰唯一**抑制多视角回答** → **模型可能在需要谦逊处过度自信**。

> ⚠️ **一个张力**：**"消灭谄媚"和"保持谦逊"是打架的** —— 你禁掉了讨好，也顺手禁掉了"我不确定"。

### RL 算法（§3.2.3）

**目标函数沿用 K1.5**：

*{x\sim\mathcal{D}}\left[\frac{1}{K}\sum*$L_{RL}(\theta)=\mathbb{E}{i=1}^{K}\left(r(x,y_i)-\bar r(x)-\tau\log\frac{\pi_\theta(y_i|x)}{\pi_{old}(y_i|x)}\right)^2\right]$

**读法**："优势（比平均好多少）" 减 "偏离旧策略多少"，然后**平方**。⚠️ **这是平方误差形式，不是 PPO 的 ratio-clip**；论文未解释细节。优化器仍是 **Muon**。

**三个规模化补丁**：

| 补丁 | 解决什么 | 怎么做 |
|-|-|-|
| **① 预算控制** | RL 会让回答**越写越长**（非推理领域纯浪费） | 按任务类型设**每样本 token 上限**，超了截断 + 罚分 |
| **② PTX 损失** | 联合 RL 会**遗忘**旧能力 | 手工挑高质量样本，用**辅助损失**掺进 RL 目标 |
| **③ 温度衰减** | 温度高不收敛、低不探索 | **前期高温探索 → 后期降温收敛** |

> **为什么会有这三个毛病**：RL 的本质是"**试错试出来的**"——试错就意味着回答会越写越长（长回答容易得分高）、新学的会盖掉旧的、前期需要乱试后期需要稳。

## RL 基建（§3.3）

**共置架构（§3.3.1）**：训练与推理引擎住在**同一批机器**上，一个干活时另一个让出显存。每轮流程：控制器叫推理引擎生成 → 通知训练引擎训练 → 参数送回推理引擎。

**参数切换 < 30 秒（§3.3.2）**：

- 训练引擎参数本来就卸载在 DRAM，拉起只需 H2D
- **推理引擎麻烦**：两边**分片方式不同**，要重分片 + 广播
- **为什么不用网络文件系统**：要压低开销需要 **每秒几 PB 的聚合带宽**，扛不住
- **解法**：自研**分布式 checkpoint engine**（与训练节点同址）——worker 拿本地副本 → **广播全量参数** → 推理引擎取自己需要的分片
- **选择广播全量**（而非只发需要的）：多传几倍数据，但**系统更简单、耦合更松**，而且**实测更快**（同步开销小、带宽利用率高）
- **已开源**：`https://github.com/MoonshotAI/checkpoint-engine`

![图 14 · 利用 checkpoint engine 做参数更新：训练引擎 → checkpoint engine worker 拿本地副本 → 广播全量 → 推理引擎按需取分片（论文 Figure 10）](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-14.webp)

**系统启动（§3.3.3）**：训练引擎启动时每个 worker **只读自己需要的部分**再广播给同伴 → **整个集群只读一次 checkpoint**（省磁盘 IO）；推理引擎**复用 checkpoint engine** 启动，且**能扛单点故障**（副本重启不用跟别人通信）。

**Agentic Rollout（§3.3.4）**：两个坑——① **等环境**（VM / 代码解释器）导致 GPU 空转 → **重环境独立部署成服务 + 大量并发 rollout 摊薄延迟**；② **轨迹极长** → **partial rollout**（长尾任务暂停，下一轮 RL 迭代再续）。

**附录 G：引擎切换流水线**（配合 §3.3.2 那个"30 秒"）

每块 GPU 开 **3 个等大 buffer**：1 个 **H2D buffer**（装从内存读进来的参数）+ 2 个 **IPC buffer**（广播用，**与推理引擎共享同一块物理内存**）。

![图 15 · (a) 理论上的完美三段流水：H2D → Broadcast → Reload 三阶段并行重叠](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-15.webp)

![图 16 · (b) 受 PCIe 限制的三段流水：并发的 H2D 与 Broadcast 把 PCIe 打饱和，三阶段坍缩成串行](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-16.webp)

![图 17 · (c) 最终采用的两段流水：先做一次同步 H2D，再让 Broadcast 与 Reload 并行](/images/tech-report/2026-10-12-kimi-k2/Kimi-K2-技术报告精读-1T-开源-17.webp)

**论文 Figure 13** 的三张对比图（上三图）说明了这个"理想 → 现实 → 妥协"的过程：

```text
(a) 理论三段流水 ：H2D → Broadcast → Reload，三个阶段互相重叠
(b) H800 上跑不通：并发的 H2D 与 Broadcast 把共享 PCIe 打饱和 → 坍缩成串行
```

# 附录 B：工具调用的 token 模板

**三段结构**：**工具声明 → 调用段 → 结果消息**。

```text
① 系统 → 模型：  <|im_begin|> tool_declare <|im_middle|>
                # Tools
                {工具定义}
                <|im_end|>

② 模型 → 系统：  <|tool_call_section_begin|>
                <|tool_call_begin|>
                functions.get_weather:0          ← call id
                <|tool_arguments_begin|>
                {"location": "Beijing, China"}
                <|tool_call_end|>
                <|tool_call_section_end|>

③ 系统 → 模型：  <|im_begin|> tool <|im_middle|>
                ## Results of functions.get_weather:0
                {实际结果}
                <|im_end|>

```

**四个设计要点**：

| 要点 | 内容 |
|-|-|
| ⭐ **工具声明用 TypeScript 而非 JSON** | 论文原话："TypeScript is a concise language with a comprehensive type system, able to express the types and constraints of tool parameters with brief text"。同样两个工具，**TS 比 JSON 简短好几倍**（论文 Listing 1 vs Listing 2） |
| ⭐ **但部分训练数据仍用 JSON** | "so that 3rd-party frameworks need not additional development to support our tool calling scheme" —— **保兼容** |
| **支持并行调用** | 一个回合可放多个 tool call；call id 格式 `functions.{工具名}:{计数器}`，计数器从 0 自增 |
| ⭐ **enforcer 约束解码** | 灵感来自 `lm-format-enforcer`。一旦生成 \`< |

> **三个目标同时解**：**省 token（TS）+ 保正确（enforcer）+ 保兼容（JSON）**。**这也正好补上 §5 那条局限**（"工具调用不完整"）—— `enforcer` 就是它的直接对策。

# 局限（§5）

| # | 原文 | 大白话 |
|-|-|-|
| ① | 硬推理题或工具定义不清时**生成过多 token**，导致**输出截断或工具调用不完整** | **啰嗦病**：撞 token 上限，话说到一半被砍断 |
| ② | **不必要地启用工具**时某些任务性能**下降** | **工具强迫症**：训练灌了大量工具数据，见工具就想用 |
| ③ | 写完整软件项目时，**one-shot 不如放进 agentic 编码框架** | **一句话生成整个项目干不好**，需要能迭代的框架 |

⭐⭐ **③ 最有信息量**：**它自己承认单次生成不如放进 agent 框架** —— 这恰好印证全篇主张：**K2 的价值在于"当 agent 的大脑"，不在于"一次性吐出成品"。**

而 **§7 致谢**（感谢 **OpenHands** 与 **Multi-SWE-bench** 团队）也印证了同一件事 —— **它的 agentic 成绩是"K2 当大脑 + OpenHands 当手脚"跑出来的**（OpenHands 是开源 agent 框架）。

# 阅读要点（我的提炼）

1. **全篇主线一句话**：**高质量数据不够了 → 从"喂更多"转向"榨更干 + 自己造"。** 前半篇（§1–2）讲怎么把 1T 模型**稳稳训出来**，后半篇（§3）讲怎么把 agentic 能力**造出来**。
2. **跨报告最有价值的对比**：同样是压 attention logit，**Qwen3（GQA）能上 QK-Norm，K2（MLA）只能改权重** —— **架构选择直接决定解法**。
3. **MuonClip 的双重价值**：既省 token（Muon），又稳（QK-Clip），而且 QK-Clip **自动失效、不掉点** —— 一个"只在前期救火、火灭就退场"的设计。
4. **数据侧最关键的一句**：**改写 10 次训 1 遍 > 重复 10 遍**（28.94 vs 23.76）—— 同样的曝光次数，改写比重复值钱。
5. **它是个"大脑"，不是"机器人"**：§5 自认 one-shot 不如 agent 框架；§7 致谢 OpenHands。**三节连起来读是同一个意思**。
6. **生态位置**：它挑的战场是 **non-thinking 赛道**（2025-07 时强对手都是思考模型）—— 对"这么强的模型为什么没有思考模式"这个疑问，这就是答案。**K2 Thinking 是 2025-11-06 才补上的**（同款 1T/32B 架构，加了"边思考边调工具"，HLE 44.9%）。
7. **一篇报告把"预训练系统"讲透了**：MuonClip（优化器）、数据改写（数据）、MLA + 超稀疏 MoE（架构）、EP/PP 重叠与激活削减（基建）、checkpoint engine（RL 基建）——**R1 讲推理从哪来、Qwen3 讲后训练流水线、K2 讲预训练系统，三篇正好覆盖三个层面。**

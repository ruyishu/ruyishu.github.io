# 一句话结论

Qwen3 技术报告是**后训练流水线的"工业标准答案"**：它把"**长 CoT 冷启动 → 推理 RL → 思考模式融合 → 通用 RL**"这条四阶段路径完整写了出来，并在同一篇里给出了\*\*强到弱蒸馏（含 on-policy 蒸馏）\*\*的对照实验。它的训练量是 **36T tokens / 119 种语言**——比 Kimi K2 的 15.5T 大 2.3 倍，走的是"**多而广**"路线。

> 本文是「逐节精读」版笔记，**含正文 2 张图与关键表格的全量转录**。报告最值钱的是 **§4 后训练**与 **§4.5 强到弱蒸馏**；**§4.7 的 Table 21 / Table 22** 是全篇最有信息量的两张表。

| 机制 | 说明 |

# 预训练（§3）

**分三阶段**（论文没叫 "mid-training"，但后两段就是其实质）：

| 阶段 | 规模 | 说明 |
|-|-|-|
| **General** | **30T+ tokens**，seq 4096，119 语言 | 通用预训练 |
| **Reasoning Stage** | **5T tokens**，seq 4096 | 拉高 STEM / 代码 / 推理 / 合成数据占比 ← **实质是 mid-training** |

# 后训练（§4）：全文最值钱的部分

![图 1 · Qwen3 系列的后训练流水线：旗舰模型（32B / 235B-A22B）走四阶段；六个轻量模型只做强到弱蒸馏（论文 Figure 1）](/images/tech-report/2026-10-12-qwen3/Qwen3-技术报告精读-后训练流水线的-1.webp)

**这张图是理解 Qwen3 后训练的钥匙**，注意它把模型分成两栏：

- **上图（Flagship Models）**：Base Models → **Stage 1 长 CoT 冷启动** → **Stage 2 推理 RL** → **Stage 3 思考模式融合** → **Stage 4 通用 RL** → 产出 Qwen3-235B-A22B 与 Qwen3-32B。**注意箭头：Stage 2 的产出同时喂给 Stage 1 和 Stage 3**（这是"闭环"的关键）。
- **下图（Lightweight Models）**：Base Models → **强到弱蒸馏** → 产出 30B-A3B / 14B / 8B / 4B / 1.7B / 0.6B。**注意：蒸馏的输入箭头来自旗舰模型的产出**。

## ① 长 CoT 冷启动（§4.1）

- 数据覆盖数学 / 代码 / 逻辑推理 / 通用 STEM，**每条都有可验证的参考答案或测试用例**
- **查询过滤用 Qwen2.5-72B-Instruct 显式完成**：剔除难以验证的（含多个子问题的、要求通用文本生成的）、剔除 Qwen2.5-72B-Instruct **不用 CoT 就能答对**的；并标注领域
- 回复由 **QwQ-32B** 生成 N 个候选，再过**六条排除标准**：① 最终答案错 ② 大量重复 ③ 明显靠猜、推理不充分 ④ 思考与总结不一致 ⑤ 语言混用/风格突变 ⑥ 疑似与验证集过于相似
- ⚠️ **六条标准的执行者论文没写明**（被动语态，没有点名 verifier / judge / 人工）。**人工标注只在"QwQ-32B 持续失败时的兜底"里被点名**
- **目的**：植入**推理模式**，样本数与训练步数都尽量少

## ② 推理 RL（§4.2）

- **3,995 条 query-verifier 对**；四条筛选标准：① 冷启动未用过 ② 对冷启动模型**可学** ③ **尽量难** ④ 子领域覆盖广
- **算法：GRPO**
- 实践：**大批量 + 每 query 高 rollout 次数 + off-policy 训练**提样本效率；**熵控制（稳步上升或稳定）**
- **170 步，235B 的 AIME'24 从 70.1 → 85.1**，无人工超参干预
- ⭐ **标准 ④ 复用了阶段 ① 的领域标签 —— 整条流水线是闭环**

> **为什么标准 ②③ 是"pass@N > 0 但尽量低"**：GRPO 的奖励是**组内归一化**（`A_i = (r_i − mean)/std`），全对或全错的组**梯度为 0** → 必须有对有错才有信号。

> **off-policy 在这里有两层含义**：算法层（DQN/SAC 式，需要重要性采样修正——RL 反而要避免）vs **工程层（生成与训练解耦，提吞吐）—— Qwen3 指的是后者**。R1 早就在这么做："each rollout generates 8,192 outputs, which are randomly split into 16 mini-batches and trained for only a single inner epoch"。

## ③ 思考模式融合（§4.3）

- 在阶段 ② 的 RL 模型上做**持续 SFT** + chat template
- **思考数据**：用**阶段 ② 的模型自己**在阶段 ① 的 query 上做**拒绝采样**（目的：**确保阶段 ② 的性能不被损害**）
- **非思考数据**：7 类任务（代码/数学/指令遵循/多语言/创意写作/问答/角色扮演）+ **自动生成的检查清单**；低资源语言的翻译被加权

> ⭐ **一句话概括这一步**：**它在做 RFT（拒绝采样微调）——同时让阶段 ② 的 RL 学会阶段 ③ 的格式，这也算一种指令遵循。**

## ④ 通用 RL（§4.4）

- **20+ 类任务**、五个能力域：**指令遵循 / 格式遵循 / 偏好对齐 / 智能体能力 / 特殊场景（RAG）**
- **三类奖励**：

  1. **规则奖励** —— "高精度，防止 reward hacking"，明确用于**指令遵循与格式遵循**
  2. **带参考答案的模型奖励** —— Qwen2.5-72B-Instruct 对着参考答案打分，"**避免纯规则奖励的假阴性**"
  3. **无参考答案的模型奖励** —— 用人类偏好数据训的 RM
- ⚠️ **论文从未出现 "format reward" 这个说法**（R1 里才有明确命名）

## 强到弱蒸馏（§4.5）—— 两段式，不是纯 offline

| 阶段 | 做法 |
|-|-|
| **① Off-policy** | 用老师**同时生成 /think 与 /no_think 两种输出**，做 **response 蒸馏** |
| **② On-policy** | ⭐ **"the student model generates on-policy sequences"**——学生自己生成序列，与老师（**Qwen3-32B 或 235B-A22B**）**对齐 logits、最小化 KL 散度** |

⚠️ **论文未披露**：KL 的方向、优化器、是否全词表对齐、每 prompt 采几个。**因此不能断言底层"没有任何 RL 循环"。**⚠️ **也别说"整个系列后训练只做两次"** —— **蒸馏本身就是后训练**，各学生都做了后训练。

**on-policy 蒸馏的机制要点**（结合 GKD 论文 arXiv 2306.13649 标题/摘要验证）：

- **老师看的前缀是「学生自己生成的」**，不是老师的
- 机制：`prompt + 学生回复` 各过一次前向 → 两边都产出 `[T, 151936]` logits → 逐位置算 KL → **只有学生更新**
- 为什么重要：**用老师自己的前缀就是 off-policy 了，且无法逐位置对齐** —— 根源是 **exposure bias**
- GKD 原话："trains the student on its **self-generated** output sequences by leveraging feedback from the teacher on such sequences"

## 评测口径（§4.6）

| 项目 | 设置 |
|-|-|
| 基准选择 | 用 **MATH-500**（不是完整 MATH）、**GPQA-Diamond**（不是完整 GPQA） |
| **thinking** 采样 | temp **0.6** / top-p **0.95** / top-k **20**（写作另加 presence penalty 1.5） |
| **non-thinking** 采样 | temp **0.7** / top-p **0.8** / top-k **20** / presence penalty 1.5 |
| max output | **32,768**（AIME 用 **38,912**） |
| 附录 A.1.1 | RULER 用 **YARN scaling_factor=4**，**thinking budget 固定 8192**；**思考模式在检索任务上略差**（论文说检索不靠推理，思考"反而可能干扰"） |
| 附录 A.1.2 | 逐语言基准表 + **Belebele**（80 种支持语言，排除 42 种未优化语言），与同尺寸 Gemma 相当，显著优于 Qwen2.5 |

> **采样参数的深意**：**top-k 固定 20，只调 top-p**（0.95 思考 / 0.8 非思考）→ **top-k 是安全阀，top-p 才是旋钮**。现代实践其实**不建议叠用多个截断器**（min-p 论文指出会引发"双重归一化"问题）。

# 阅读要点（我的提炼）

1. **这篇的定位**：不是架构创新（架构基本沿用 Qwen2.5 + 上 GQA），而是**把后训练流水线的每个环节都写清楚**——它值钱在"**流程的工业标准**"。
2. **Figure 1 是理解全篇的钥匙**：**两个模型档次走两条完全不同的路径**（旗舰四阶段 vs 轻量只蒸馏），而且**蒸馏的输入来自旗舰模型的产出**。
3. **两张对照表是全篇精华**：**Table 21** 告诉你"RL 抬 pass@1 不抬 pass@64，蒸馏两个都抬"；**Table 22** 告诉你"**推理在阶段 ② 见顶**，后面全是通用/对齐/agent 在涨"。
4. **蒸馏不是纯 offline**：2025 年的 Qwen3 就已经在做 **on-policy 蒸馏（OPD）**，而且老师看的是**学生自己的前缀**。
5. **和 K2 的关键对比**：Qwen3 用 **GQA** → 能上 **QK-Norm**；K2 用 **MLA** → 装不了 → 只能 **QK-Clip**。**同一个问题（attention logit 爆炸），架构选择决定解法。**
6. **和 K2 的路线对比**：Qwen3 **36T tokens / 119 语言**（多而广）vs K2 **15.5T**（少而精，专攻 agentic）。**两条路线的正面对撞。**
7. **Qwen3 没有"合版"**：它是**单模型顺序级联**（冷启→推理 RL→融合→通用 RL），**不存在分域 RL 专家需要合并**。§4.3 的 "Thinking Mode Fusion" 是把 **think / no-think 两种模式合进一个模型**，跟多老师合版不是一回事。

# 口径与未核实项

- **六条排除标准的执行者**：论文用被动语态，**未点名**（我的推断：答案/重复/去重用规则，语义质量用 LLM judge）
- **on-policy 蒸馏的实现细节**（KL 方向、优化器、全词表 vs 采样 token、每 prompt 采几个）：**论文未披露**
- **§4.5 蒸馏未走单独列出的任务奖励 RL 阶段** —— 但**蒸馏本身就是后训练**，不能说整个系列"后训练只做两次"
- **"约 1/10 GPU 小时"**：Table 21 是**同一 off-policy 蒸馏起点后的对照**；§4 开头另有"相比完整四阶段约 1/10"的概括性主张，**两者口径不同**
- **"pass@64 在 RL 路线上不变"** 是**该实验的结果**，不是 RL 的普遍限制
- **附录 A 的 RULER**：论文自己的口径是"检索不依赖推理，思考模式反而可能干扰"，**thinking budget 固定 8192 是预算固定，不是模型不会动态分配**
